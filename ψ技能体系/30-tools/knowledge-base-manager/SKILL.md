# Knowledge Base Manager - 三层知识库管理工具

## 核心定位
让知识活起来 · 能被 AI 理解、快速检索、持续进化、产生复利

---

## 📋 功能概述

### What（这是什么）
三层知识库管理工具，管理 Obsidian/OpcCla/IMA 之间的知识流动与同步。

### Why（为什么需要）
- 知识库专业化不是"把内容放进去"，而是"让知识活起来"
- 三层分工：Obsidian=知识资产，OpcCla=工作记忆，IMA=快速捕获
- 知识需要在三库间流动，产生复利效应

### How（怎么用）
```
1. Ingest（入库）- 新资料进来处理
2. Query（查询）- 问知识库问题
3. Lint（健康检查）- 定期扫描知识库问题
```

## 🔄 知识流动管道设计

### 流向①：IMA → Obsidian（定期整理）

| 项目 | 说明 |
|------|------|
| **触发** | 每周/每月批量整理 |
| **处理** | 提炼结构化知识，存入 Obsidian 对应目录 |
| **示例** | 临时灵感 → 整理为理论文章 → 存入 Obsidian |

### 流向②：Obsidian → OpcCla 知识库（系统同步）

| 项目 | 说明 |
|------|------|
| **触发** | Skills 更新、Rules 更新、身份配置更新 |
| **处理** | 将理论转化为可执行的 Skills 和 Rules |
| **示例** | 五行人格理论 → 封装为五行智能体 Skill |

### 流向③：OpcCla 知识库 → Obsidian（知行合一沉淀）

| 项目 | 说明 |
|------|------|
| **触发** | 每次深度对话后自动执行 |
| **处理** | 对话洞察 → 压缩 → 泛化 → 存入 Obsidian |
| **示例** | 对话新发现 → 沉淀为知识卡片 → 更新知识图谱 |

### 流向④：IMA ↔ OpcCla 知识库（实时同步）

| 项目 | 说明 |
|------|------|
| **触发** | 通过 API 实时同步 |
| **处理** | 移动端记录 ↔ AI 对话上下文 |
| **示例** | IMA 记录待办 → AI 对话中提醒 → 完成后归档 |

## 🔧 三大核心操作

### 操作 1: Ingest（入库）

**流程**:
```
1. 扫描 Notes/ 下所有未处理内容
2. 列出分发方案（文件/建议位置/处理方式/原因）
3. 用户确认后执行
4. 按内容性质分发到目标目录
5. 读原文写摘要，创建/更新页面
6. 给相关文件补上交叉引用
7. 清理原始文件
```

**分发规则**:
| 内容类型 | 目标目录 |
|----------|----------|
| 软件工具、代码技巧 | Software/ |
| 投资、保险、健康、生活事务 | LifeOS/ |
| 方法论、读书笔记、概念解析 | Knowledge/ |
| 内容创作方法论 | Writing/Knowledge/ |
| 选题素材 | Writing/ |
| 判断不了的 | 留在 Notes/ |

### 操作 2: Query（查询）

**流程**:
```
1. 理解用户问题
2. 在相关目录里搜索内容
3. 综合多篇文件给出答案
4. 发现新关联（互补但未链接的文件）
5. 建议补链接，用户确认后执行
```

**价值**:
- 不只是回答问题
- 暴露知识库的结构缺陷
- 查询本身也在改进知识库

### 操作 3: Lint（健康检查）

**四项检查**:
| 检查项 | 标准 | 处理 |
|--------|------|------|
| 孤立页面 | 没有任何链接指向 | 建议添加链接或删除 |
| 过时内容 | 超过 90 天没动过 | 建议更新或归档 |
| 缺失引用 | 讲同一概念但没互相链接 | 建议补链接 |
| Notes/ 积压 | 超过 7 天没处理的输入 | 提醒处理 |

**执行策略**:
- 按目录分别跑，不要一次全跑
- Knowledge/ 是 Lint 真正能发挥价值的地方
- 出报告，不自动修改

## 🎯 设计哲学

### 8 条核心原则

| 原则 | 说明 |
|------|------|
| **1. 一个入口，多个终点** | 所有输入走 Notes/，统一流程分发 |
| **2. 结构够用就行** | 目录分到能找到东西就够了 |
| **3. AI 建议，你拍板** | 分类反映你的思维结构，只有你最清楚 |
| **4. 链接宜少不宜多** | 两三条强关联比十条弱关联有用得多 |
| **5. 对话也是知识** | 跟 AI 的深度讨论本身就在生产知识 |
| **6. 存着不用等于没有** | 知识库的终极检验标准是产出 |
| **7. 索引到目录，不到文件** | 目录结构稳定后几乎零维护 |
| **8. 不绑定工具** | AGENTS.md 兼容多种 Agent |

### 什么时候建链接

**值得建链接的情况**:
- 两篇文章内容互补（获客方法论 + 产品打磨哲学）
- 理论和实践配对（同理心理论 + 同理心实践）
- 读书笔记和应用思考配对
- 人物和方法论配对

**格式**:
```markdown
## 相关页面
- [[链接 1]]
- [[链接 2]]
```

---

## ⚠️ 边界条件与异常

| 异常情况 | 处理方式 |
|----------|----------|
| AI 分类判断不靠谱 | 先列方案，用户确认后再执行 |
| 内容太短无法判断 | 留在 Notes/，等补充后再处理 |
| 多篇内容讲同一主题 | 建议合并，用户确认后执行 |
| 发现矛盾内容 | 标记出来，让用户决定 |

## 📌 使用示例

### 场景 1: 处理 Notes/ 积压

**输入**:
```
处理一下 Notes/ 下的文件
```

**处理**:
1. 扫描 Notes/ 下所有未处理内容
2. 列出发方案表格
3. 等待用户确认
4. 执行分发、加工、清理

**输出**:
```
## 分发方案

| 文件 | 建议位置 | 处理方式 | 原因 |
|------|----------|----------|------|
| xxx.md | Software/Skills/ | 合并到已有文件 | 内容重叠 |
| yyy.md | Knowledge/ | 新建 | 全新主题 |
| zzz.md | 留着 | 等补充 | 内容太短 |

请确认后执行。
```

### 场景 2: 查询知识库

**输入**:
```
创业怎么找前 1000 个用户？
```

**处理**:
1. 在 Knowledge/和 Writing/中搜索相关内容
2. 找到《头 1000 名用户》和《做产品的经验和感悟》
3. 综合两篇内容给出答案
4. 发现两篇互补但没链接，建议补链接

**输出**:
```
## 核心结论
[综合两篇内容的答案]

## 发现
《头 1000 名用户》和《做产品的经验和感悟》内容互补但未互相链接，
建议添加交叉引用。是否执行？
```

### 场景 3: 知识库健康检查

**输入**:
```
运行知识库 Lint 检查
```

**处理**:
1. 按目录分别运行四项检查
2. 生成报告，不自动修改
3. 列出需要处理的问题

**输出**:
```
## Lint 报告 - Knowledge/

### 孤立页面 (3 篇)
- [[页面 1]] - 无任何链接指向
- [[页面 2]] - 无任何链接指向

### 过时内容 (2 篇)
- [[页面 3]] - 95 天未更新
- [[页面 4]] - 120 天未更新

### 缺失引用 (1 对)
- [[页面 5]] 和 [[页面 6]] 讲同一概念但未链接

### Notes/ 积压
- 5 篇文件超过 7 天未处理
```
