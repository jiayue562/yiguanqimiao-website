# 🤖 岗位智能体 · SKILL.md

> **核心定位**：基于AI原生组织顶层设计的岗位智能体系统——将"岗位=数据采集节点+功能聚合体"的定义转化为可执行的工作流
> **一句话功能**：通过"行业×企业×岗位×五行×任务×模型"六维框架 + "层级×智能体×数据链×人才链×宪法"五维对齐，生成岗位专属AI智能体并确保与AI原生组织架构一致

## 📖 核心定义

### What（是什么）

**岗位智能体**是根据AI原生组织顶层设计全案定义的"岗位=数据采集节点+功能聚合体"原则，为味藏26个管理岗位和职能节点生成专属AI智能体的系统工具。

它解决了传统提示词"一刀切"的问题,通过六维框架精准识别岗位特性,结合五行人格心理学,为每个岗位生成与AI原生组织架构对齐的智能体方案。

**岗位本质**（来自顶层设计全案）：岗位 = 数据采集节点 + 功能聚合体。没有上下级,只有功能聚合包的不同。店长和财务主管不是上下级关系,而是数据贡献和协作的关系。

**核心组成（v4.0新增）**：
- **26智能体体系对齐**：每个岗位对应一个AI智能体，按三层结构（决策层/赋能层/执行层）分层
- **三层结构映射**：决策层（L1·5人+AI）+ 数据层（L2·AI全自动）+ 执行层（L3·N个超级个体）
- **超级个体定义**：1个人+1组AI功能聚合。人做5%核心判断域，AI做95%信息处理
- **五行人格配置**：金木水火土五行与岗位天然适配表，含优势/盲区/成长方向
- **三店差异化模型**：金月湾（业绩锚点/土行）、狮山（标准推手/金行）、松山湖（社区连接/水行）
- **26智能体注册通信协议**：子Skill向味藏总智能体注册，通过5Gate门禁校验
- **宪法守护进程对接**：承诺兑现扫描+注册停滞扫描+执行偏差扫描

**终极应用**：岗位智能体是去总部化理论的技术实现载体。当每个岗位都有专属AI智能体（龙爪）承担信息汇聚、标准执行、风险预警职能时，总部作为"信息中转站"的必要性被根本瓦解，组织形态从"金字塔"走向"星型网络"。

**核心组成**：
- **六维输入框架**：行业 + 企业简介 + 岗位 + 性格（五行人格）+ 核心任务 + 适用模型
- **五行人格深度诊断**：阴阳面分析 + 数据驱动识别 + 五行借力路径（v3.0升级）
- **7S组织诊断评分**：1-10分制 + 诊断依据 + 核心问题 + 改善方向（v3.0新增）
- **三层指标体系**：结果指标（考核）+ 过程指标（监控）+ 风险指标（预警）+ P0/P1优先级（v3.0升级）
- **关键动作设计**：目标量化 + 资源分配 + 数据验证 + 风险控制（4列风险预警表）
- **AI增强关键词**：洞察、剖析、透视、阐释、推演、解构、思辨、溯源、融合、启发、映射
- **复盘画布6步框架**：工作盘点→优劣势→根因→拔阴取阳→风险预警→进化路径（v3.0新增）
- **龙爪断语生成**：3大核心判断 + 金句引用 + 核心命题（v3.0新增）
- **提示词工程体系**：黄金公式 + 基础结构 + 高级技巧 + 专家级资产

### Why（为什么）

> **最高层次**：岗位智能体的最终使命不是造更好的提示词，而是推动企业组织形态的AI化重构——让每个岗位不再需要上级管理，从根源上"取消总部"。

**组织级痛点（去总部化视角·v3.0+新增）**：
- 🔴 传统总部依赖信息中转——门店数据需上报总部才能决策，周期长、失真多
- 🔴 科斯定理被反转——AI信号协议的边际成本趋近于零，总部的管理成本反而成了增量负担
- 🔴 总部四大职能（信息汇聚/标准制定/资源调配/风险管控）正被AI逐一瓦解，但多数企业仍用传统组织框架运转
- 🔴 总部人员被困在"信息中转"中，无法下沉创造直接价值

**技术级痛点**：
- 🔴 通用提示词无法满足特定岗位的深度需求
- 🔴 忽视人格特质导致AI协作效果不佳
- 🔴 缺乏系统化工作流设计方法
- 🔴 结果指标与过程指标混淆
- 🔴 风险控制缺乏预警机制
- 🔴 没有组织级7S诊断能力（v3.0新增）
- 🔴 五行人格缺少阴阳面分析，无法识别"暗礁"（v3.0新增）
- 🔴 指标体系平铺，缺乏分层逻辑和P0/P1优先级（v3.0新增）
- 🔴 输出缺乏高层面的诊断总结和判断提炼（v3.0新增）
- 🔴 HTML输出无视觉规范，风格不统一（v3.0新增）

**解决方案（技术层+组织层）**：
- ✅ **去总部化组织重构**——岗位智能体替代总部的信息汇聚/标准制定/资源调配/风险管控职能，组织从"金字塔"变为"星型网络"（v3.0+新增）
- ✅ **龙爪信号协议**——三层龙爪（S1店长+S2总经理+S3董事长）自动信号上升+下行分解，代替总部信息中转（v3.0+新增）
- ✅ **治理模型**——算法化的事务自动执行，涉及价值判断的冲突留给人裁决（v3.0+新增）
- ✅ **五行人格×业务场景深度融合**（木生火共生视角）
- ✅ **工作流化思维**（信息交汇点精准识别）
- ✅ **六维框架全面覆盖**（行业→企业→岗位→性格→任务→模型）
- ✅ **五行阴阳面双轨诊断**（阳面显发优势 + 阴面过刚风险）（v3.0升级）
- ✅ **7S组织诊断定量评分**（1-10分制 + 诊断依据 + 改善方向）（v3.0新增）
- ✅ **三层指标金字塔**（结果/过程/风险 + P0/P1 + 分层关联规则）（v3.0升级）
- ✅ **复盘画布6步闭环**（从盘点到进化路径的完整闭环）（v3.0新增）
- ✅ **龙爪断语升华**（从数据堆砌到高层判断的"灵魂"）（v3.0新增）
- ✅ **HTML视觉设计规范**（CSS变量 + 组件库 + 响应式 + 颜色编码）（v3.0新增）

## 🏗️ 1+N 架构总览（v4.0·AI原生组织对齐版）

> **定位**：岗位智能体由「1个总智能体 + N个分智能体（模块）」构成。总智能体只做5件事，模块按5系列33个标准模块分类，网状拓扑调用。
> **v4.0升级**：新增AI原生组织五维对齐校验——每个岗位生成时必须对齐层级归属、26智能体体系、六元组数据链、L1-L4人才链、5Gate宪法门禁。
> **完整文档**：`架构设计.md` | **模块规格**：`modules/index.md`

```yaml
AI原生组织三层结构（全案定义）:
  决策层（L1·5人+AI）: 董事长+总经理+堂食总+酒水总+外卖总（战略语境设定·年度/季度决策）
  数据层（L2·AI全自动）: P-01+PERF-MGR+各智能体数据模块（全量数据汇聚+实时预警·每日/实时）
  执行层（L3·N个超级个体）: 三驾马车×三店长×前厅/后厨×各职能（微型企业CEO·即时/周度）

26智能体三层归属（全案新增）:
  决策层（3个）: CHMN-BRAIN·GM-CHIEF·weizang-chief
  赋能层（6个）: OPS-DIR·FIN-MGR·HR-MGR·TR-SUP·MKT-MGR·PUR-MGR
  执行层（17个）: SM-CHIEF·SM-JYT·SM-SS·SM-SSH·DU-DS·WU-JS·DU-WM·FM-ALL·KC-LFY·KC-WZH
  底盘层（3个）: P-01·PERF-MGR·POS-MGR

岗位本质（全案定义）:
  岗位 = 数据采集节点 + 功能聚合体
  超级个体 = 1个人 + 1组AI功能聚合
  人机分工 = AI做95%信息处理 / 人做5%核心判断

总智能体5件事（不变）:
  ① 意图识别 → 调对应模块
  ② 模块调度（网状拓扑）
  ③ 人格后处理（统一包装）
  ④ 冲突解决
  ⑤ 依赖图检测（启动时扫描，循环依赖报错）

5系列33模块:
  🟦 B（基础）: 6个 · 所有岗位必装
  🟩 M（管理AI）: 18个 · 按角色选装（店长7/料理长4/前厅4/线上3）
  🟧 H（横向）: 3个 · 老总专用
  🟥 D（决策）: 3个 · 极简总部专用
  🟪 G（发展）: 3个 · 按需选装

v4.0新增·五维对齐校验（岗位智能体输出前必须通过）:
  维度1：层级对齐——岗位归属决策层/赋能层/执行层正确
  维度2：智能体对齐——对应26智能体体系中C级编码和P值正确
  维度3：数据链对齐——六元组数据标准中责任锚点正确绑定
  维度4：人才链对齐——L1-L4晋升等级与岗位技能要求匹配
  维度5：宪法对齐——输出不违反5Gate门禁中的任何一条

三店差异化配置（全案新增·对应店长智能体时使用）:
  金月湾业绩锚点: 数据采样密度最高（30分钟/次），聚焦客单价与复购
  狮山标准推手: 数据标准化程度最高（SOP自动采集），聚焦执行力与培训通过率
  松山湖社区连接: 数据维度最宽（含社区/异业），聚焦粘度与口碑传播
```

## 🎮 双模式 + 三种输出类型

> **核心升级**：岗位智能体v3.0支持两种模式、三种输出类型。

### 模式 A：👤 提示词模式（默认）
- **输出**：人用 AI 提示词
- **适用**：给企业员工设计 AI 协作助手
- **示例**：味藏总经理的 AI 助手提示词

### 模式 B：🐉 龙爪模式
- **输出类型 B1**：个人复盘画布HTML（聚焦个人一周工作的6步深度分析）
- **输出类型 B2**：组织诊断报告HTML（聚焦组织7S+经营+文化的多维度诊断）
- **适用**：给 WorkBuddy 造龙爪（AI 智能体）
- **示例**：味藏店长周复盘画布（B1）/ 堂食创业单元7S诊断报告（B2）

### 模式切换指令

| 你想做什么 | 输入 |
|-----------|------|
| 给人设计提示词 | 默认模式，直接按六维框架输入 |
| 造 WorkBuddy 龙爪 | 先说"切换到龙爪模式"，再输入设计 |

### 报告类型判断逻辑（v3.0新增）

```yaml
报告类型自动判断:
  输入包含个人名 + 周数据 → B1个人复盘画布
  输入包含多门店/多单元数据 → B2组织诊断报告
  输入仅有岗位描述 + 任务 → 提示词模式（默认）
```

### Step 3: 7S组织诊断评分（v3.0新增）

```yaml
7S评分标准:
  S1战略 (Strategy):
    8-10: 战略清晰且可执行，团队认知统一
    5-7: 有战略但执行走样或认知不统一
    1-4: 战略模糊或与实际脱节
  S2结构 (Structure):
    8-10: 组织架构清晰，权责明确，协作流畅
    5-7: 基本架构在但存在模糊地带
    1-4: 架构缺位或权责混乱
  S3制度 (Systems):
    8-10: 制度完善，流程标准化，执行一致性高
    5-7: 有制度但执行不统一或覆盖不全
    1-4: 制度缺位或形同虚设
  S4风格 (Style):
    8-10: 管理风格鲜明且适配组织，团队认同度高
    5-7: 有管理风格但不一致或不适配
    1-4: 管理风格混乱或专制

    8-10: 人才梯队完整，关键岗位无空缺
    5-7: 核心岗位有人但梯队不完整
    1-4: 关键岗位空缺或人岗不匹配
  S6技能 (Skills):
    8-10: 核心技能完备，持续培训体系运转
    5-7: 有基本技能但缺乏深度培训
    1-4: 关键技能缺失，无培训体系
  S7共同价值观 (Shared Values):
    8-10: 价值观清晰，全员认同，日常行为一致
    5-7: 有价值观但认知不统一或行为偏离
    1-4: 价值观模糊或仅停留在口号

7S诊断依据模板:

  评分: [1-10]
  诊断依据: [基于数据/行为的具体证据]

#### 7S要素完整定义（味藏7S立体顶层设计v3.4参考）

> **来源**：味藏7S立体顶层设计框架的公司级7S要素定义，每条均有"必须满足的行为标准"和"常见缺失信号"，作为评分依据的理论根基。

```yaml
S1战略(Strategy) — 方向一致性:
  "必须满足": 战略拆解到店→店长理解并认同→团队对齐
  常见缺失: 战略仅总部知道→店长不清楚→执行走样
  与去总部化关联: 龙爪信号协议替代总部战略传递

S2结构(Structure) — 权责明确性:
  "必须满足": 组织架构≤3层→权责清单明确→跨店协作有机制
  常见缺失: 层级过多→权责打架→审批链条长
  与去总部化关联: 去总部化本质=减少组织层级

S3制度(Systems) — 执行一致性:
  "必须满足": 制度覆盖全流程→执行有检查→偏差有纠偏
  常见缺失: 制度写一套做一套→有制度无检查→有检查无奖惩
  与去总部化关联: 龙爪=制度执行自动化的工程载体

S4风格(Style) — 管理适配性:
  "必须满足": 管理风格适配组织阶段→团队认同→可调整
  常见缺失: 风格与组织冲突→团队对抗→管理者不自知
  与去总部化关联: 龙爪断语=管理风格的AI反馈机制

S5人员(Staff) — 人才充足率:
  "必须满足": 关键岗位有人→有AB角→人才梯队≥2级
  常见缺失: 关键岗单点依赖→无人替补→培训体系缺失
  与去总部化关联: 龙爪=人才培育的分布式引擎

S6技能(Skills) — 核心能力完备度:
  "必须满足": 核心技能有标准→有培训体系→技能考核≥Q1/年
  常见缺失: 凭经验操作→无SOP→培训形式化
  与去总部化关联: 岗位智能体=技能标准化的AI载体

S7共同价值观(Shared Values) — 文化认同度:
  "必须满足": 价值观行为化→全员认同→日常行为一致
  常见缺失: 价值观仅口号→行为与价值观脱节→无人纠正
  与去总部化关联: 龙爪=文化价值观的分布式传承者

7S联动诊断:
  原则: 7S不是独立维度，S7(价值观)是核心，其他6S围绕S7运转
  联动示例:
    S5人员不足 → S6技能断层 → 影响S3制度执行 → 拉低S1战略实现
    S4风格硬 → S5人员流失 → S2结构不稳 → 组织整体震荡
```

### Step 4: 三层指标体系 + 关键动作设计（v3.0升级）

> **v2.0→v3.0变化**：将"目标量化/数据验证/风险控制"重组为三层指标金字塔，新增P0/P1优先级、4列风险预警表、分层关联规则。

```yaml
三层指标体系:
  Layer 1 - 结果指标（考核用·绿色）:
    定义: 衡量最终经营成果的指标
    模板: 指标名 | 当前值 | 目标值 | 达成状态
    示例: 综合营业额完成率 | 132.9% | 100% | 达标
    频率: 月度/季度
    颜色编码: 绿色(tag-g) = 达标/完成/优势

  Layer 2 - 过程指标（监控用·蓝色）:
    定义: 衡量执行过程质量的指标
    模板: 指标名 | 当前值 | 预警阈值 | 监控频率
    示例: 1对1邀约执行率 | 极低 | 每店每日≥3人 | 日度
    频率: 日度/周度
    颜色编码: 蓝色(tag-b) = 过程/监控/信息

  Layer 3 - 风险指标（预警用·红色）:
    定义: 需要立即关注的系统性风险
    模板: 指标名 | 描述 | 严重度 | 优先级
    示例: 客户链接机制断裂 | 三店系统性失效 | 系统级 | P0
    频率: 实时
    颜色编码: 红色(tag-r) = 预警/未达标/薄弱

  分层关联规则:
    - 过程指标连续3期低于阈值 → 升级为风险指标
    - 风险指标P0 → 当周必须解决，纳入每日行动日历
    - 风险指标P1 → 当月必须解决，纳入每周复盘

关键动作设计:
  资源分配:
    预算分配:
      - 类别1: [占比] - [用途]
      - 类别2: [占比] - [用途]
    人力配置:
      - 岗位1: [人数] - [职责]
    时间规划:
      - 阶段1: [时间] - [里程碑]

  风险控制（v3.0升级为4列）:
    模板: 下周任务 | 潜在风险 | 预警信号 | 应对预案
    预警信号定义: 必须是可观测、可量化、有时效的现象
    任务锚定: 每个风险必须关联到一个具体任务
    示例:
      - 520营销活动 | 客流超预期 | 11:30前等位超5桌 | 启动弹性补位+简化流程
      - 新品上市 | 供应链断裂 | 核心食材库存<3天 | 启动备选供应商
```

#### 约束体系设计：F1-F5五大铁律（味藏实战参考）

> **来源**：味藏三家店长7S运营管理全案(v4.0)通用模式提取
> **适用场景**：当需要为"自主决策型"岗位设计行为边界时，使用F1-F5约束体系替代传统的"制度清单"。每一条铁律都是"堤坝"——不告诉你怎么做，但告诉你绝对不能触碰的底线。

### 风险控制金字塔

不同角色的风险关注点天然分层：

```
董事长: 文化属性+净利润底线          ← 顶层约束
总经理: +关键岗位人员任用风险         ← 经营层
各部门总监: 各自业务风险              ← 执行层
店长: 差评率3%以内                   ← 操作层
```

多角色协同的关键：**下层风险不能突破上层底线，但上层不能替下层做业务判断。**

## ⚠️ 伦理边界声明（v3.0+新增）

> **核心原则**：AI替代的是管理中的信息中转，不是对人的控制权。如果去总部化的结果是"AI总部"替代了"人总部"，那就是一种倒退。

**岗位智能体的伦理红线**：

| 原则 | 说明 |
|------|------|
| **工作行为边界** | 五行诊断只能作用于工作行为描述，不涉及心理诊断。阴阳面分析是工作风格的描述，不是心理健康的诊断。 |
| **人工确认原则** | 龙爪的"阴面警示"（如"金行店长关系维护弱"）必须由人确认后才能转为行动方案。算法只做提示，不做决策。 |
| **数据透明权** | 店长有权查看龙爪对自己的所有分析数据。任何人不应该在不知道"AI怎么看自己"的情况下被AI影响。 |
| **模块退出权** | 店长可以手动关闭特定模块（如"不接受五行适配建议"）。赋能不能是强制的——被强制的赋能就是控制。 |
| **不可越界原则** | 岗位智能体的所有功能必须在"帮助人更好地完成工作"这一范围内。任何超越此范围的功能（情绪监控、行为预测用于绩效惩罚），都是越界。 |

**商业伦理**：去总部化咨询的悖论——买你服务的人恰恰是你要建议取消的岗位。突破路径：不卖"替代你"（对现有反感），卖"释放你"（对老板有吸引力）。岗位智能体的正确叙事始终是"释放人"，不是"替代人"。
