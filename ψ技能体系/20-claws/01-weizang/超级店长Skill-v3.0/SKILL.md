## 第二章 · 四道Gate门禁详解

### 2.1 G1-G4完整规格

#### G1: 意图合法性校验

**问题**：这个请求是否应该来自这里？
**检查项**：
- 是否绕过总智能体(P=99)直接发起？
- 是否使用了正确的场景入口？
- 请求者的P值是否足够覆盖目标？
- 是否在心跳锁定时段发起编排？

**通过标准**：全部YES
**拦截后果**：退回总智能体重路由 + 记录-2信誉分

#### G2: 输出完整性校验

**问题**：输出的内容是否完整且合规？
**检查项**：
- 是否引用了至少1条F1-F9公式？
- 是否包含五色光扫描？
- KPI数据是否来源可信？
- 是否有明确的行动建议？

**通过标准**：全部YES
**拦截后果**：退回补全后重审 + -1信誉分

#### G3: 权限合规性校验

**问题**：调用是否跨越层级边界？
**检查项**：
- 决策层→执行层：✅ 允许（但需通知）
- 执行层→决策层：❌ 拦截（需升级处理）
- 同层跨域：需经过Gate确认
- HRD新岗接入：需完成注册流程

**拦截后果**：权限不足提示 + 路由至正确路径

#### G4: 层级合规性校验

**问题**：操作是否符合组织规则？
**检查项**：
- 是否触犯7条禁止行为(R1-R7)？
- Trust Score是否在正常范围？
- 是否有未完成的冻结期？
- 日反馈数据是否已就绪（如涉及运营判断）？

**拦截后果**：违规记录 + 对应处罚

## 第四章 · 调度分发引擎

### 4.1 调度优先级矩阵

```
优先级P0 (紧急·安全·红线):
├── 食安红线触发
├── 重大客户投诉
├── 安全事故
└── P-01 L1紧急分流

优先级P1 (重要·战略·决策层指令):
├── 董事长直接指令
├── 总经理战略解码
└── 月度经营分析会

优先级P2 (正常·运营·赋能层请求):
├── 六部门协作请求
├── 三单元业务支持
└── 门店日常问题

优先级P3 (常规·执行层):
├── 店长日常调度
├── 前厅/后厨协调
└── 例行SOP执行
```

### 4.2 路由算法

```
用户请求输入
    ↓

    ↓
L2 能力评估 → 所需Skill类型识别
    ↓
L3 P值检查 → 调用方是否有权
    ↓
L4 Gate校验 → G1-G4四道门禁
    ↓
L5 路由分发 → 目标Skill执行
    ↓
L6 结果收集 → 输出质量校验
    ↓
L7 反馈推送 → 用户+学习沉淀
```

## 第五章 · 闭环验证体系

### 5.1 闭环四步法

```
Step 1: 接收输出 → 完整性检查
    ├── 必须包含的内容都在？
    ├── 五色光扫描是否完整？
    └── KPI数据是否准确？

Step 2: 结果校准 → 准确性验证
    ├── 与预期目标对比偏差
    ├── 异常标记+归因分析
    └── 需要时退回重做

Step 3: 用户反馈 → 满意度收集
    ├── NPS式快速评分
    ├── 具体改进建议
    └── 记录到经验库

Step 4: 迭代优化 → 模型更新
    ├── 路由规则微调
    ├── Skill注册信息更新
    └── Trust Score影响计算
```

### 5.2 异常处理协议

```
异常类型A: Skill执行失败
  → 重试1次 → 更换备用Skill → 升级人工
  
异常类型B: Gate校验不通过
  → 返回请求方修改 → 重新提交 → 3次失败→升级仲裁
  
异常类型C: 输出质量不合格
  → 退回Skill重做 → 补全后重提交 → 仍不合格→降级处理
  
异常类型D: 用户投诉
 → 记录→分析→改进→跟踪 → TS影响计算
```
