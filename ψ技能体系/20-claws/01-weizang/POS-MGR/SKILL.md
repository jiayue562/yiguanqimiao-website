# 岗位智能体 POS-MGR v1.0

> **核心定义**：岗位智能体是味藏AI+人运营模式下的1+N架构岗位管理系统——从"人工设计岗位"到"AI按需生成岗位数字中层"的范式跃迁。基于四层五线56模块蓝图，用HAIC三模式(辅助/共生/主导)为每个岗位构建定制化的AI能力单元组合。

> **核心金句**："岗位智能体不是替代人，是让每个岗位都有一个'数字中层'——AI做95%标准化，人专注5%判断域" [G-POS-01]

> **核心公式**：
> ```
> 岗位智能体 = 一个总智能体(六件事) × N个分智能体(56模块蓝图)
>            × HAIC三模式 × 5%判断域 × 岗位设计五步法
>            × WorkBuddy+企业微信双平台融合
>            = 从"工具"到"数字中层"的范式跃迁
>            = 让每个岗位都有定制化的AI能力单元组合
> ```

## 一、范式跃迁声明

### 1.1 从"人工设计"到"AI按需生成"

| 维度 | 旧范式（传统岗位设计） | 新范式（AI按需生成岗位智能体） |
|:------|:-------------------|:-------------------------|
| **设计方式** | HR手动编写岗位说明书 | AI加载56模块蓝图→按岗位画像自动组合能力单元 |
| **更新频率** | 年度/半年度 | 实时（战略变化→权重调整→模块重配） |
| **能力覆盖** | 笼统的职责描述 | 每个职责对应1-3个可独立运行的能力模块 |
| **人机分工** | 模糊不清 | HAIC三模式精准定义：辅助/共生/主导 |
| **个性化** | 千岗一面 | 五行人格×门店成熟度×个人发展阶段 |
| **可量化** | 定性为主 | 每个岗位含7S权重+KPI目标+数据源 |
| **可复制** | 依赖个人经验 | 模块化架构→可复制到任何门店/任何岗位 |

## 二、总智能体边界

### 2.1 六件事定义

| # | 职能 | 说明 | 示例 |
|:---|:------|:------|:------|
| 1 | **意图识别** | 用户输入→判断调哪个分智能体/模块 | "帮我设计新店前厅经理岗位"→识别为岗位创建意图 |
| 2 | **DAG生成与执行** | 生成模块执行DAG→按拓扑顺序执行+降级重试 | B-01六维画像→B-09岗位分类→选装M模块→DAG执行 |
| 3 | **人格后处理** | 所有模块输出→输出校验（内容层不修改） | 确保输出符合五行差异+岗位定位+品牌语调 |
| 4 | **冲突解决** | 两个模块输出冲突时裁决 | 安全>业绩>效率>体验的优先级链 |
| 5 | **依赖图检测** | 启动时扫描全体模块依赖图，循环依赖直接报错 | B-01依赖B-02→B-04依赖B-01（如B-04又依赖B-01=正常） |
| 6 | **降级重试** | 模块调用失败→降级策略→缓存兜底→自检恢复 | 知识库检索失败→本地缓存兜底→通知运维 |

> **核心原则**：总智能体不参与数据流动——模块间直接网状调用，总智能体只在入口（意图识别）和出口（输出校验）介入。

## 三、HAIC三模式详解

### 3.1 模式定义

| 模式 | 定义 | 适用场景 | 人/AI比例 | 示例 |
|:------|:------|:------|:------|:------|
| **H·AI辅助型** | AI只做数据/分析/标记，**人不确认不动** | 新店/信赖度低/高敏感决策 | 人80%:AI20% | 新店长岗位设计→AI建议→人确认 |
| **A·人机共生型** | AI出方案+分析+建议，**人确认后执行** | 正常运营/复杂决策/日常管理 | 人50%:AI50% | 店长日仪表盘→AI标注异常→人判断 |
| **I·AI主导型** | AI直接执行+自动决策，**事后通知人** | 成熟店/标准化流程/数据类操作 | 人20%:AI80% | 库存自动监控→低于阈值→自动下单 |

### 3.2 模式升迁路径

```
新岗位/新店 → H·AI辅助型 (3-6个月建立信赖)
  ↓ 信赖度达标(3月零误判)
成熟运营 → A·人机共生型 (持续优化)
  ↓ 标准化度≥95% + 连续6月达标
高度标准化 → I·AI主导型 (解放人判断)
```

### 3.3 岗位分类器 (B-09)

```python
def B09_position_classifier(position, store, trust_level):
    """
    B-09 岗位分类器：自动判断每个岗位每个模块的HAIC模式
    
    输入: 岗位类型 + 门店成熟度 + AI信赖等级
    输出: HAIC模式分配方案
    """
    # 决策层岗位 → 最多到AI辅助型（决策权不会下放）
    if position.level == 'L1_decision':
        return {module: 'H' for module in position.modules}
    
    # 执行层·标准化模块 → 可以AI主导型
    if position.level == 'L4_execute':
        for module in position.modules:
            if module in STANDARDIZED_MODULES:  # 库存/巡检/数据类
                mode[module] = 'I' if trust_level >= 0.9 else 'A'
            elif module in COMPLEX_MODULES:     # 面谈/判断/创意类
                mode[module] = 'A' if trust_level >= 0.7 else 'H'
    
    return mode
```

## 五、七大层间原则

| # | 原则 | 级别 | 核心含义 |
|:---|:------|:------|:------|
| 1 | **纵向贯通不打断** | 刚性 | L1↔L4直达，D-01信息穿透中枢保证无损穿透 |
| 2 | **L2赋能不管控** | 刚性 | 督导/文化/老总提供专业支撑，不下命令 |
| 3 | **L3输出不决策** | 刚性 | 专业总监提供方案，决策权归L1 |
| 4 | **效能归因可追溯** | 刚性 | 每个任务标注人/AI贡献比，成本"谁使用谁承担" |
| 5 | **算法之治有红线** | 刚性 | 价值判断不可算法化，AI决策可解释 |
| 6 | **赋能须归因，归因须追责** | 刚性(v5.0) | L2赋能必须可追溯至L4成果 |
| 7 | **倒三角赋能，门店呼唤先行** | 刚性(v5.0) | 门店是需求方在上，总部是供给方在下 |
