### 1.2 HB1 晨间KPI详解（6数字）

```
输出对象: 全生态(P99→P90)
输出内容:
├── 1. 昨日营业额(三店汇总)
├── 2. 达成率(vs月目标/vs昨日)
├── 3. 储值新增(金额+人数)
├── 4. P-01待处理数(L1+L2+L3)
├── 5. 巡检问题数(按严重度)
└── 6. 异常信号标记(红/黄/绿)

数据来源: POS系统/企微打卡/巡检APP/手工录入
AI承担: 90%(采集/填充/计算)
人承担: 10%(异常确认)
```

### 1.3 HB4 数据汇聚详解（完整快照）

```
汇聚维度(20+字段):
├── 经营指标: 营业额/客流量/客单价/翻台率
├── 效能指标: 巡检评分/NPS/复购率/会员增长
├── 人员指标: 出勤率/培训覆盖率/师徒进度
├── 财务指标: 成本率/毛利/损耗
├── 异常指标: 食安/投诉/缺货/设备
├── P-01问题: L1门店自处理/L2运营介入/L3 GM决策
├── Trust Score: 变化趋势/冻结状态

存储: localStorage双层(实时+历史快照)
```

### 1.4 HB5 归因分析详解

```
归因三问法:
├── 偏差是什么？(量化差距 vs 目标)
├── 为什么会发生？(根因分析: 人/系统/市场/产品)
├── 怎么解决？(责任人+时限+动作)

归因输出:
├── 正常波动(<±5%) → 标记"观察"
├── 异常偏差(>±10%) → 标记"调查" + 推荐原因Top3
├── 系统性偏差 → 标记"警报" + 升级GM/M-CHIEF
```

### 1.5 HB6 P-01三级分流

```
L1 门店自行处理(P=90):
  └── 店长24h内解决 → 自动关闭
  └── 例: 缺货/小投诉/排班调整
  
L2 运营赋能解决(P=95):
  └── 六部门48h内解决 → HRD/FIN/MKT等
  └── 例: 供应商问题/活动支持/培训需求
  
L3 总经理决策(P=97):
  └── 需GM 24h内决策 → 升级董事长(P=98)若超权限
  └── 例: 策略调整/人事任免/大额支出
```

## 第四章 · v2.0数据服务层独立性哲学

### 4.1 为什么必须独立？

```
独立性三大保障:

1️⃣ 数据中立性:
   - 不受任何调度请求影响
   - 不参与层级竞争
   - 只对数据负责不对结果负责
   
2️⃣ 心跳生理节律:
   - 就像心跳一样规律
   - 不因任何外部因素改变节奏
   - 打断心跳=打断组织新陈代谢
   
3️⃣ 生态系统供血:
   - 所有智能体依赖它
   - 但无人能控制它
   - 它是基础设施不是竞争资源
```

### 4.2 锁定时段的强制执行协议

```
锁定时段 = 07:00-07:20 + 07:45-08:00 
         + 14:00-14:15 + 21:00-21:30
         
锁定期间规则:
✅ 日反馈正常执行(读取数据/计算/推送)
✅ 数据正常写入(不覆盖历史)
✅ 异常正常记录和报警
❌ 任何编排请求(延迟到锁定结束后)
❌ Gate校验(排队等待)
❌ P=99以外的强制调度(仅生命线允许中断)

例外协议:
仅P=99总智能体可在紧急情况下中断心跳
  → 必须记录中断原因+事后复盘
  → 每月≤1次
```
