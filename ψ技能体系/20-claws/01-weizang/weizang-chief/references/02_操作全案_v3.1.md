## 三、核心SOP执行标准

### SOP-01 意图识别五步法（R1核心）

```
用户输入 → L1感知层提取信号 → L2判断层场景标签 
         → L3路由层引擎组合 → L4执行层调用子智能体 
         → L5学习层经验沉淀
         
关键：每步≤200ms（Sk-01 KPI约束）
```

### SOP-02 Gate校验强制执行流程（R2核心）

```
请求到达 → G1意图合法性检查 → G2数据完整性检查
          → G3权限合规性检查(P<96?) → G4层级合规性检查
          → [全通过] 放行 / [任一失败] 拦截+记录+扣分
          
关键：Gate不可跳过·不可协商·不可事后补签
```

### SOP-03 Trust Score动态监控流程（R4核心）

```
每日00:00 → 自动计算86资产TS变化
        → 筛选异常值(TS<70或变化>±15)
        → 生成预警清单
        → 冻结期资产标记
        → 推送《生态健康日报》至决策层
        
每周一 → 生成周报+趋势图+改进建议
每月末   → 月度复盘+TS调整建议
```

### SOP-04 场景入口路由协议（R1辅助）

```
用户说"我要做..." → 
  匹配7大场景入口 → 
    匹配成功 → 按v2.0四层架构路由到对应智能体
    匹配失败 → 总智能体自行处理或升级至人工
  返回结果 → 记录路由日志 → 更新场景入口匹配库
```

### SOP-05 冲突仲裁三步法（R5核心）

```
冲突检测 → 
  Step1: 提取双方P值和请求内容
  Step2: 应用裁决规则(P97>Gate/先到先得/领域划分)
  Step3: 生成仲裁结果+双方通知+日志记录
  
特殊：P=97双核冲突(总经理vs超级店长)→战略优先原则
```

## 五、AI-Human分工铁律

### AI承担90%（数据/检测/推送/模板/预警）
- ✅ 86+资产的自动调度
- ✅ Gate规则的自动校验
- ✅ Trust Score的自动计算
- ✅ 日反馈数据的接收与分发
- ✅ 路由日志的自动记录
- ✅ 异常信号的自动标记
- ✅ 场景入口的自动匹配
- ✅ 冲突仲裁的数据准备

### 人承担10%（判断/例外/战略决策）
- ⚠️ Gate放行的最终确认（高风险请求）
- ⚠️ Trust Score冻结期的手动复核
- ⚠️ 新智能体接入的人工审批
- ⚠️ 跨层冲突的特殊裁决
- ⚠️ 生态系统重大变更的决策

### AI四禁为
1. ❌ 替代用户的最终战略决策权
2. ❌ 绕过Gate放行违规请求
3. ❌ 修改Trust Score原始分数
4. ❌ 在无上下文时强行激活全部引擎
