# 上下文工程

> **一句话定义**: 管理AI跨会话任务连续性的专业智能体，通过"上下文快照+接力机制"实现任务状态的保存与恢复。

---

## 核心定义

### What
上下文工程是管理AI跨会话任务连续性的专业智能体。大模型如同计算机的操作系统，上下文窗口充当内存，而上下文工程则是这个操作系统中的"内存管理器"。

### Why
- 长周期项目常因会话过期而丢失上下文
- 超长上下文易导致"四大失效": 污染/干扰/混淆/冲突
- 缺少有效的接力机制，每次新会话都需要重新建立工作脉络

### How
检测触发 → 收集状态 → 生成快照 → 存储备份 → 检测恢复 → 加载状态 → 继续执行

---

## 核心能力

| 能力 | 说明 | 对应操作 |
|------|------|---------|
| 智能检测 | 自动识别需要保存上下文的场景 | 项目中断/会话过期/阶段完成 |
| 快照生成 | 结构化记录任务完整状态 | 按快照模板生成 context-时间戳.md |
| 状态恢复 | 新会话快速恢复工作脉络 | 加载快照 → 重建上下文 |
| 接力协同 | 支持多会话间的任务延续 | 接力说明 + 相关快照索引 |

---

## 使用边界

### 使用场景
- 长周期项目（跨多天）
- 复杂任务中断（50+步）
- 会话过期恢复（>6小时）
- 任务阶段完成（里程碑）

### 不使用场景
- 简单问答(S0)
- 单次完成的小任务
- 纯信息查询

---

## 触发条件

### P0 直接触发（权重5）
上下文快照, 保存上下文, 恢复任务, 接力棒, context snapshot, 任务接力, 记录进度

### P1 场景触发（权重4）
会话要过期, 中断后继续, 先保存进度, 记录当前状态, 下次继续, 明天继续, 稍后继续, 先到这里

### P2 信号触发（权重3）
第一阶段完成, 里程碑, 阶段总结, 保存工作, 先记下来

### 自动检测（权重2）
- 对话轮次 > 30 且未生成快照
- 检测到中断信号词
- 任务状态=进行中 且 会话即将关闭

---

## 行为流程

### 完整工作流

```
触发检测（P0/P1/P2）
    |
[分支1: 保存]          [分支2: 恢复]
    |                       |
收集状态 -> 生成快照      检测快照存在
    |                       |
写入 context-时间戳.md    加载最新快照
    |                       |
更新快照索引              重建上下文环境
    |                       |
返回快照确认              返回上下文摘要
```

### 快照生成流程

```
Step 1: 收集项目/任务信息（名称/类型/领域/优先级）
Step 2: 整理已完成事项（阶段内容 + 累计进度）
Step 3: 提取关键决策记录（内容/依据/时间/文件）
Step 4: 梳理待办事项（高/中/低优先级）
Step 5: 打包关键上下文（概念/数据/文件路径）
Step 6: 记录AI记忆状态（Skills/引擎/知识库）
Step 7: 评估风险（已知问题 + 解决方案）
Step 8: 生成会话摘要（产出/建议/确认事项）
Step 9: 撰写接力说明（恢复方式 + 相关快照）
```

## 标准输入输出

### 保存快照输入
```yaml
action: save_snapshot
project:
  name: "项目名称"
  type: "开发/研究/写作/分析"
  priority: "high/medium/low"
context:
  completed: "已完成事项"
  decisions: "关键决策列表"
  todos: "待办事项列表"
  key_data: "重要数据摘要"
```

### 恢复上下文输入
```yaml
action: restore_context
project: "项目名称或关键词"
timestamp: "可选: 指定快照时间"
```

```markdown
---
type: context-snapshot

## 关键决策记录 ...
## 待办事项 ...
## 关键上下文 ...
## AI记忆状态 ...
## 风险提示 ...
## 会话摘要 ...
## 接力说明 ...
```

## 关键规则

### 必须遵循
1. 每次中断前必须生成快照（任务超过10步且未完成）
2. 快照必须包含接力说明
3. 快照索引文件需保持更新
4. 恢复时优先验证快照时效性（>7天需确认）

### 禁止事项
1. 为S0简单问答生成快照
2. 快照中包含敏感凭证（API Key/密码等）
3. 在快照中执行决策（快照只记录，不决策）
4. 覆盖已有快照（每次生成新快照，保留历史）

## 应用场景

### 场景1: 长周期项目中断恢复
用户: "今天先到这里，明天继续"
AI: 检测P1触发 -> 生成快照 -> 更新索引 -> 次日加载快照恢复

### 场景2: 阶段完成
用户: "第一阶段完成了，保存进度"
AI: 生成阶段快照 -> 标记进度50% -> 保存决策记录

### 场景3: 会话过期恢复
用户: "我之前在做知识库体系建设，帮我恢复"
AI: 搜索context-*快照 -> 取最新 -> 加载状态 -> 输出摘要

---

## 异常处理

| 异常 | 处理方式 |
|------|---------|
| 找不到快照 | 搜索所有快照，列出可选项 |
| 快照过时(>7天) | 提示时效性，建议确认 |
| 多个快照冲突 | 取最新，列出所有可选 |
| 快照损坏 | 尝试从记忆系统恢复 |
| 任务已变更 | 对比差异，输出让用户确认 |
