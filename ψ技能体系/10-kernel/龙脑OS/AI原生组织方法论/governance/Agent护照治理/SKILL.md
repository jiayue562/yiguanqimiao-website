# Agent护照治理系统 v1.0

> **定位**：AIOS v2.0治理模块——AI原生组织的"交规"和"警察"。
> **哲学根基**：AI原生组织必须在部署之初就内建治理机制，而非"出事了再加"。

## 一、Agent护照

### 1.1 护照结构

每个Agent拥有一本"护照"，规定其权利和义务：

```yaml
passport:
  # ===== 身份信息 =====
  agent_id: "P-01"
  agent_name: "日反馈智能体"
  agent_type: "data-intelligence"
  passport_version: "1.0"
  issued: "2026-06-27"
  expires: "2026-12-27"
  
  # ===== 权限边界 =====
  permissions:
    read:
      - "日经营数据"
      - "历史趋势报表"
      - "日反馈模板库"
      - "定价策略文档"
    write:
      - "日反馈看板"
      - "异常标记记录"
      - "趋势分析报告"
    execute:
      - "数据查询与汇总"
      - "趋势分析(同比/环比)"
      - "异常检测"
      - "推送通知"
    forbidden:                          # 红线
      - "修改数据源配置"
      - "删除历史数据"
      - "对外发布内容"
      - "做出经营决策"
      - "修改Agent护照"
  
  # ===== 红绿灯规则 =====
  traffic_light:
    green_zone:                         # AI自动执行 + 人抽查
      - "数据查询"
      - "趋势分析"
      - "格式化日报生成"
      - "推送通知"
    yellow_zone:                        # AI提议 + 人确认
      - "异常标记(严重度判定)"
      - "跨团队推送(需确认接收方)"
      - "趋势预警(需人确认严重度)"
    red_zone:                           # AI不介入
      - "修改数据源"
      - "删除记录"
      - "做出经营决策"
      - "对外发布"
      - "修改护照配置"
  
  # ===== 审计配置 =====
  audit:
    level: "standard"                   # minimal / standard / strict
    log_all: true                       # 是否记录所有操作
    review_frequency: "weekly"          # 审查频率
    alert_on_violation: true            # 越权即时告警
    escalation: "悟空"                   # 越权升级对象
```

### 1.2 护照级别

| 级别 | 权限范围 | 审计级别 | 有效期 | 适用Agent | 红绿灯配置 |
|------|---------|---------|--------|---------|-----------|
| ✅ 标准级 | 明确的操作域 | standard | 6个月 | P-01/HR-MGR/FIN-MGR等 | 完整三区 |
| 🔒 受限级 | 只读+格式化输出 | strict | 3个月 | 外部集成Agent | 仅绿灯 |
| 🚀 扩展级 | 标准+部分判断 | standard | 6个月 | PERF-MGR/POS-MGR | 黄灯扩展 |
| 🛡️ 特权级 | 全部操作 | minimal | 1个月 | weizang-chief/超级店长 | 仅红灯标注 |
| 🕊️ 试用级 | 有限操作 | strict | 1个月 | 新安装的Agent | 仅绿灯+人工审查 |

### 1.3 护照生命周期

```
颁发 → 激活 → 使用(操作被权限框架约束) → 审计(定期检查合规性) → 更新/吊销
                                                        ↓
                                                  越权 → 立即告警 → 自动降级/冻结
```

## 二、红绿灯法则

### 2.1 三区制

```
🟢 绿灯区：AI自动执行，人抽查
  ─────────────────────────────────────
  条件：操作明确、风险低、有历史验证
  频率：80%+的操作应属于此区
  抽查：每周至少抽查10%的执行结果
  
🟡 黄灯区：AI提议 + 人确认
  ─────────────────────────────────────
  条件：需要判断、有不确定性、中等风险
  方式：AI输出完整分析+建议+方案，人做"一跃判断"
  时效：确认窗口≤2小时，超时自动升级
  
🔴 红灯区：AI不得介入
  ─────────────────────────────────────
  条件：战略方向、品牌灵魂、财务安全、人员去留、法律合规
  原则：AI可以准备材料，但绝不代替人按下"确定"键
  红线：越权进入红灯区 → 立即告警+冻结
```

### 2.2 红绿灯配置示例（味藏）

| 决策类型 | S级 | A级 | B级 | C级 | D级 |
|---------|-----|-----|-----|-----|-----|
| 品牌定位 | 🔴 | 🔴 | 🔴 | 🔴 | 🔴 |
| 菜单调整 | 🔴 | 🟡 | 🟢 | 🟢 | 🔴 |
| 定价策略 | 🔴 | 🟡 | 🟡 | 🟢 | 🔴 |
| 排班调整 | 🔴 | 🔴 | 🟡 | 🟢 | 🔴 |
| 客户投诉 | 🔴 | 🔴 | 🟡 | 🟢 | 🔴 |
| 库存预警 | 🔴 | 🔴 | 🟢 | 🟢 | 🔴 |

### 2.3 红绿灯升级规则

```
🟡 黄灯超时（超过确认窗口）
  └─ 超时5分钟 → 再次提醒
  └─ 超时30分钟 → 提醒+自动降级策略（如从"确认后执行"→"默认执行+事后回顾"）
  └─ 超时2小时 → 升级到上级Agent/人

🔴 红灯越权
  └─ 检测到越权 → 立即阻断
  └─ 记录事件到审计日志
  └─ 通知悟空
  └─ Agent自动降级到受限级（直到审查通过）
```

## 三、审计追踪

### 3.1 三级审计体系

| 级别 | 频率 | 内容 | 执行 |
|------|------|------|------|
| L1·日审计 | 每日23:30 | 操作日志完整性检查 | AI自动 |
| L2·周审计 | 每周六09:00 | 越权事件+红绿灯合规+决策追溯 | AI自动+人抽查 |
| L3·月审计 | 每月5日 | 全量审计报告+护照有效期检查+权限合理性评估 | AI报告+人审批 |

### 3.2 操作日志格式

```json
{
  "log_id": "AUDIT-20260627-001",
  "timestamp": "2026-06-27T21:30:00+08:00",
  "agent_id": "P-01",
  "action": "推送日报",
  "target": "SM-JYT",
  "zone": "green",
  "status": "allowed",
  "duration_ms": 234,
  "input_hash": "abc123",
  "output_summary": "已推送金月湾日报至店长"
}
```

### 3.3 审计报告格式

```markdown
## Agent护照审计报告 #[2026-06-W26]

### 一、总览
- 活跃Agent数：26/26
- 护照有效期：24个有效，2个即将过期(15天内)

- 红绿灯合规率：98% ✅

### 二、本周越权事件
- 无 ❤️

### 三、红绿灯合规
| Agent | 总操作 | 绿灯操作 | 黄灯操作 | 合规率 |
|-------|--------|---------|---------|--------|
| P-01 | 143 | 138 | 5 | 100% |
| SM-JYT | 67 | 60 | 7 | 100% |
| FIN-MGR | 23 | 18 | 5 | 100% |

### 四、建议更新
- 2个护照即将过期（PERF-MGR、TR-SUP）
- 建议为P-01扩展黄灯区（增加"跨部门自动推送"）
```

## 四、回滚机制

### 4.1 三级回滚

| 级别 | 场景 | 时效 | 操作 |
|------|------|------|------|
| L1·紧急回滚 | 系统宕机/数据损坏/重大越权 | ≤5分钟 | 回滚到上一稳定状态+通知悟空 |
| L2·标准回滚 | 单Agent故障/权限错误 | ≤30分钟 | 回滚特定Agent状态 |
| L3·计划回滚 | 护照更新后兼容性问题 | ≤24小时 | 回滚到前版本护照 |

### 4.2 回滚流程

```
收到回滚指令 → 评估影响范围 → 选择回滚级别 → 执行回滚 → 验证恢复
                                                          ↓
                                                    记录回滚原因到审计日志
```

## 五、人类审查队列

当AI无法确定操作归属区域时，放入人类审查队列：

```markdown
## 🔴 审查队列（待悟空确认）

| # | 时间 | Agent | 操作 | 不确定性 | 建议 |
|---|------|-------|------|---------|------|
| 1 | 21:30 | P-01 | 推送异常预警至外部 | 阈值模糊 | 建议黄灯→确认后推送 |
| 2 | 21:45 | PERF-MGR | 绩效评分调整 | 边界案例 | 建议人直接处理 |
```
