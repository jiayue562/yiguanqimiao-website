## 第一部分：哲学底层

### 1.1 碳硅合一的组织映射

一个组织也是碳硅合一的。碳的部分是那些需要人的温度、手感、直觉和判断力的领地；硅的部分是数据采集、信息流转、SOP执行和无关决策的自动化领地。AI原生组织的设计目标不是用硅取代碳，而是让碳和硅各自归位。

### 1.2 一元统摄、双维赋能

组织运行需要双重维度的校准。客观实践维负责数据、制度、绩效考核、供应链和财务真实；主观精神维负责文化传承、心性修炼、信任关系和匠心传承。两个维度统一在一个组织框架内，不存在谁替代谁的关系。

### 1.3 组织五大红线

| 红线 | 内容 |
|:----:|------|
| **红线一** | 数据不能替代人的最终判断。所有预测与结论必须附带置信度标注 |
| **红线二** | 杜绝数据教条化，坚持现场感知第一。当数据与现场感知冲突时必须人工核验 |
| **红线三** | 岗位消失≠人消失。岗位从执行单元变为责任容器，但人不被裁 |
| **红线四** | 判断权不可越级。执行层不做长期判断，决策层不做即时止损 |
| **红线五** | 关系信任不可算法化。供应商谈判、大客户维护、文化传承必须由人主导 |

## 第二部分：三层结构

### 2.1 层级定义

| 层级 | 构成 | 核心职能 | 决策尺度 |
|:----|------|---------|:--------:|
| **决策层（L1）** | 5人+AI | 战略语境设定，文化底线守护 | 年度/季度 |
| **数据层（L2）** | AI全自动 + 赋能层并入 | 全量数据汇聚与实时预警 | 实时/每日 |
| **执行层（L3）** | N个超级个体 | 微型企业CEO，向数据层供数据 | 即时/周度 |

三层不是权力层级，而是职能切片。决策层不是高执行层一头，执行层的超级个体也不是听命于决策层的下级。三层是同等级的不同职能分工。

### 2.2 决策层落地

**构成**：董事长 + 总经理 + 堂食创业单元总 + 酒水创业单元总 + 外卖创业单元总

**权力匹配规则**：
- A级决策（战略方向、品牌定位、重大投资）→ 董事长终决
- B级决策（经营策略、价格调整、供应链变更）→ 总经理终决
- C级决策（日常运营、门店执行、客户处理）→ 创业单元总终决

**实时决策机制**：数据层推送三色预警 → 对应级别决策者即时判断 → 指令下达 → 执行跟踪

### 2.3 数据层落地

六元组数据标准连接数据功能、7节点全链路模型覆盖金枪鱼全生命周期，HB日反馈闭环、W周复盘闭环、M月度总结闭环和年度闭环构成四级闭环体系。

数据层是决策级创业单元和超级个体之间透明的连接器，不是控制它们的管理层。

### 2.4 执行层落地

三大创业单元各自独立向数据层供数据，每个单元由N个超级个体组成。不是传统的营销部指挥门店的模式，而是每个创业单元直接到店、直接对接执行层。

### 2.5 三店差异化定位

基于12人连续数周数据的核心发现：味藏三店的差异化不是策略选择，而是天然长成的。

| 门店 | 天然角色 | 定位 | 店长五行 | 经营基线 |
|:----|---------|------|:--------:|:--------:|
| **金月湾** | 业绩锚点 | 旗舰店·稳定产出 | 土行 | 100-110% |
| **狮山** | 标准推手 | 标准店·执行力标杆 | 金行 | 80-105% |
| **松山湖** | 社区连接 | 社区店·资源整合 | 水行 | 85-110% |

## 第三部分：岗位定义

### 3.1 岗位的本质

**岗位 = 数据采集节点 + 功能聚合体**

每一个岗位首先是一个数据采集节点——采集这个环节的真实数据上报到数据层。同时它也是一个AI功能聚合体——通过AI功能模块的调用，让一个人能干以前需要多个岗位才能完成的事。

没有上下级，只有功能聚合包的不同。店长和财务主管不是上下级关系，而是数据贡献和协作的关系。这种水平关系是岗位设计中最根本的转变。

### 3.2 超级个体

**超级个体 = 1个人 + 1组AI功能聚合**

每个人都是一个超级个体，区别不在于级别高低，而在于功能包的构成不同、判断的尺度不同、承担的责任不同。人机分工中AI做数据采集、过滤、提醒、模板生成、预警和流转，人做判断、执行、审批、现场感知和决策。

### 3.3 岗位智能体

每一个真实的管理岗位对应一个AI智能体。智能体随着人的使用不断进化。

## 第六部分：数据系统

### 6.1 六元组数据标准

| 字段 | 说明 |
|------|------|
| **食材周期节点** | 食材从生到灭的物理状态变化阶段 |
| **业务渠道** | 同一节点下的业务动作或销售途径 |
| **数据值** | 具体采集的指标 |
| **时间戳** | 数据发生的时间（精确到分钟） |
| **7S评估维度** | 将该数据值映射至7S框架 |
| **责任锚点** | 绑定对该数据负责的超级个体 |

### 6.2 金枪鱼7节点模型

```
选品 → 采购 → 入库 → 分割(开鱼) → 储存 → 销售调度 → 超期处理
```

每个节点对应数据采集、销售行为和核心目标。

### 6.3 四级闭环体系

| 闭环 | 周期 | 核心动作 |
|:----|:----:|---------|
| **日反馈闭环（HB1-HB7）** | 每日 | 数据汇聚→异常识别→问题路由→方案→执行→回流 |
| **周复盘闭环（W1-W4）** | 每周 | 汇总→归因→优化→验证 |
| **月度总结闭环（M1-M4）** | 每月 | 分析→系统问题→战略校准→7S更新 |
| **年度闭环** | 每年 | 战略定调→总评→储备验证→招培验收 |

### 6.4 实时决策引擎

五步闭环：实时感知→自动分级与路由→决策者即时判断→指令下达→效果跟踪

三色预警：A级红色（红线值·即时分钟级）→ B级橙色（预警值·1小时内）→ C级黄色（预警值·2小时内）

## 第十部分：过渡路径

### 10.1 三阶段

**阶段一（当前→3个月）**：功能数字化。四层架构→三层半。原赋能层核心数据接入数据层，AI预处理90%，三驾马车开始供数据

**阶段二（3-6个月）**：数据层独立运转。三层半→三层。原赋能层并入数据层，原部门人员转为超级个体，创业单元总转为C级终决权超级个体

**阶段三（6-12个月）**：超级个体成型。组织层级从4层到3层，管理层减少约25%，N个超级个体成型，决策周期从月度变为实时

### 10.2 味藏智能体升级路线

**第一周**：走通第1个闭环——DU-DS（堂食创业单元×陈明武），用7周数据编译初始版本，跑一次诊断，对比人与AI的偏差进行校准

**第二周**：复制到2-3个智能体——柳源→DU-WM、李华→FIN-MGR、胡海涛→MKT-MGR，编译各自的人设基座，注册并试运行

**第三周**：扩展到全部10个待开发智能体——赋能层6个+创业单元3个+前厅，全部编译完成并进入试运行

**第四周起**：跑通数据链路，接入真实经营数据，让智能体在真实数据上运行，持续喂新数据，持续校准，持续进化
