# LLM Wiki Linting Skill

> 🔍 自动检测知识库质量 · 发现过时/冲突/低质内容 · 龙心 OS 知识治理

**版本**: v1.0  
**创建**: 2026-04-17  
**标签**: #知识治理 #质量检查 #LLM Wiki

---

## 📋 核心定义

**一句话定义**: 自动检测 LLM Wiki 知识库中的过时、冲突、低质内容，提供修复建议的治理工具。

**三行问题陈述**:
- **What**: 解决知识库质量下降、内容过时、信息冲突的问题
- **Why**: 知识库随使用增长，但质量难以持续保证
- **How**: 规则引擎 + LLM 评估 + 自动修复建议

---

## 🎯 检测维度

### 1. 内容质量检查

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| **空内容检测** | 文件存在但内容为空或过短 | 🔴 高 |
| **格式错误** | Markdown 格式错误、链接失效 | 🟡 中 |
| **重复内容** | 多个文件内容高度相似 | 🟡 中 |
| **结构不完整** | 缺少必要章节（定义/示例/参考） | 🟢 低 |

### 2. 时效性检查

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| **过时内容** | 超过 90 天未更新的知识 | 🟡 中 |
| **版本过期** | 引用了旧版本 API/工具 | 🔴 高 |
| **链接失效** | 外部链接 404 或内容变更 | 🟡 中 |

### 3. 一致性检查

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| **术语冲突** | 同一概念不同命名 | 🟡 中 |
| **信息矛盾** | 不同文件信息冲突 | 🔴 高 |
| **引用断裂** | 引用了不存在的文件 | 🔴 高 |

### 4. 知识完整性检查

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| **孤立节点** | 无引用也无被引用的知识 | 🟢 低 |
| **缺少示例** | 只有理论没有实践示例 | 🟢 低 |
| **缺少参考** | 没有引用来源或延伸阅读 | 🟢 低 |

## 🔄 Linting 流程

```
启动 Linting
    ↓
1. 扫描知识库文件
    ↓
2. 并行执行检查规则
    ├── 内容质量检查
    ├── 时效性检查
    ├── 一致性检查
    └── 完整性检查
    ↓
3. 聚合问题报告
    ↓
4. 生成修复建议
    ↓
5. 输出 Linting 报告
    ↓
6. 可选：自动修复（询问后）
```

## 📊 评分体系

### 整体质量评分

```
总分 = 100 - (高严重度问题 × 10) - (中严重度问题 × 5) - (低严重度问题 × 2)

等级划分:
- A (90-100): 优秀，无需关注
- B (80-89):  良好，少量问题
- C (70-79):  中等，需要关注
- D (60-69):  较差，需要修复
- F (<60):    不合格，立即修复
```

### 维度评分

| 维度 | 权重 | 说明 |
|------|------|------|
| **内容质量** | 40% | 空内容、格式、重复 |
| **时效性** | 30% | 更新时间、版本、链接 |
| **一致性** | 20% | 术语、信息、引用 |
| **完整性** | 10% | 孤立节点、示例、参考 |

```

```

## 📥 输入输出格式

### 输入
```json
{
  "scope": "all",  // 或指定目录/文件
  "rules": ["quality", "freshness", "consistency", "completeness"],
  "severity_threshold": "low",  // 报告阈值
  "auto_fix": false
}
```

### 输出

   - 建议：统一术语
   - 自动修复：需人工确认

### 🟡 中严重度问题 (5)
...

### 🟢 低严重度问题 (15)
...

### 修复建议
- 立即修复：3 个高严重度问题
