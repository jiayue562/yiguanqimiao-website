# LLM Wiki 知识库管理 Skill

> 🧠 龙心 OS 知识编译引擎 · v1.0

**标签**: #LLMWiki #知识编译 #知识管理 #AI 原生

---

## 📋 核心定义

**一句话定义**: 基于 Karpathy LLMification 方法论，实现"机器编译、人类审核"范式的 AI 原生知识库管理系统

**三行问题陈述**:
- **What**: 解决传统 RAG"失忆"缺陷和 pdf-to-text 信息丢失问题
- **Why**: 知识管理需要从"人类编写、机器检索"转变为"机器编译、人类审核"
- **How**: 三层架构 (原始资料层→Wiki 本体层→Schema 配置层) + 录入查询检查闭环

---

## 🎯 核心能力

| 能力 | 描述 | 输出 |
|------|------|------|
| 知识编译 | 将原始资料转化为结构化 Markdown | Wiki 页面 + 双向链接 |
| 三层架构管理 | 原始资料层/Wiki 本体层/Schema 配置层 | 清晰的知识分层 |
| 持久记忆建设 | 知识库随使用不断增厚 | 复利效应 |
| 自我进化 | Linting 机制实现自我修复 | 一致性校验 + 完整性补全 |
| 知识内化 | 将知识库知识内化进模型权重 | 领域专家模型 |

## 📁 三层架构规范

### Layer 1: 原始资料层 (只读的事实来源)
```
raw/
├── articles/        # 文章
├── papers/          # 论文
├── books/           # 书籍章节
├── code/            # 代码
├── data/            # 数据集
└── media/           # 图片/音频/视频
```

**原则**:
- 只读、不修改
- 保持原始格式
- 作为事实来源

### Layer 2: Wiki 本体层 (LLM 维护的知识图谱)
```
wiki/
├── concepts/        # 概念页面
├── entities/        # 实体页面
├── theories/        # 理论页面
├── methods/         # 方法页面
├── comparisons/     # 对比分析
└── syntheses/       # 综合性结论
```

**原则**:
- LLM 创建和维护
- 结构化 Markdown
- 双向链接
- 持续迭代增厚

### Layer 3: Schema 配置层 (机器的行为准则)
```
schema/
├── CLAUDE.md        # AI 助手配置
├── AGENTS.md        # 通用代理指令
├── STRUCTURE.md     # 结构规范
├── LINTING.md       # 校验规则
└── ROUTES.md        # 路由配置
```

**原则**:
- 定义结构规范
- 维护规则
- AI 行为准则

## 🔄 知识生命周期

### 录入 (Ingest)
```
原始素材 → LLM 编译 → 候选 Wiki 页面 → 人类审核 → 持久记忆
```

**操作**:
- 增量编译
- 知识融合
- 去重校验

### 查询 (Query)
```
用户问题 → 检索 Wiki → 调用知识 → 生成答案 → 归档 QA
```

**操作**:
- 从"检索"到"调用"
- 高质量 QA 归档
- 复利效应

### 检查 (Lint)
```
定期扫描 → 一致性校验 → 完整性补全 → 方向建议 → 自我进化
```

**操作**:
- 自我修复
- 断裂链接检测
- 孤立页面识别

### 进化方向
- [ ] 哪些领域需要补充？
- [ ] 哪些链接需要建立？
- [ ] 哪些概念需要合并？
