## Layer 1: 原始资料层

### 定位
**只读的事实来源** - 存放原始资料，保持原始性，不修改

### 目录结构
```
layer1-raw/
├── articles/          # 文章
│   ├── 2026/
│   │   └── 04/
│   └── ...
├── papers/            # 论文
├── code/              # 代码
├── datasets/          # 数据集
└── images/            # 图片
```

### 命名规范
```
格式：YYYYMMDD_HHMMSS_来源缩写_内容哈希.md
示例：20260416_103000_tanstack_a1b2c3d4.md
```

### 元数据要求
```markdown
# 原始资料

**来源**: URL
**类型**: article/paper/code/dataset
**归档时间**: ISO8601
**内容哈希**: md5 前 8 位
**原始标题**: ...

---

[原始内容]
```

### 操作规则
- ✅ 只读：不修改原始内容
- ✅ 完整：保持内容完整性
- ✅ 标注：清晰标注来源和元数据
- ❌ 禁止：修改、删减、重组

## Layer 2: Wiki 本体层

### 定位
**LLM 维护的知识图谱** - 由 LLM 创建和维护的结构化知识

### 目录结构
```
layer2-wiki/
├── entities/          # 实体页面
│   ├── React.md
│   ├── Vue.md
│   └── ...
├── concepts/          # 概念页面
│   ├── 组件化.md
│   ├── 响应式.md
│   └── ...
├── comparisons/       # 对比分析
│   ├── React_vs_Vue.md
│   └── ...
├── summaries/         # 摘要
│   └── ...
└── INDEX.md           # 总索引
```

### 页面类型

#### 实体页面 (entities/)
**定义**: 描述具体事物、技术、产品等实体

**模板**: `templates/entity-template.md`

**核心内容**:
- 核心定义
- 关键特性
- 应用场景
- 相关概念（双向链接）

#### 概念页面 (concepts/)
**定义**: 描述抽象概念、方法、理论等

**模板**: `templates/concept-template.md`

**核心内容**:
- 核心定义
- 核心内涵
- 使用方法
- 相关概念（双向链接）

#### 对比分析 (comparisons/)
**定义**: 两个或多个实体的对比分析

**模板**: `templates/comparison-template.md`

**核心内容**:
- 核心结论
- 对比总览表
- 详细对比（多维度）
- 决策框架

### 命名规范
```
实体/概念：名称.md（中文）或 name.md（英文）
对比：A_vs_B.md
```

### 双向链接规范
```markdown
[[页面名称]]  # 标准双向链接语法

### 链接类型
- 上位概念：更抽象的概念
- 平行概念：同级别的概念
- 下位概念：更具体的概念
```

### 质量要求
| 指标 | 目标值 | 说明 |
|------|--------|------|
| 链接率 | >80% | 有链接页面比例 |
| 孤立率 | <5% | 无链接页面比例 |
| 平均链接数 | ≥3 | 每页面平均链接数 |

## Layer 3: Schema 配置层

### 定位
**机器的行为准则** - 定义 Wiki 结构规范与维护规则

### 目录结构
```
layer3-schema/
├── structure.md       # 结构规范
├── quality-rules.md   # 质量规则
├── triggers.md        # 触发规则
└── lint-config.md     # Linting 配置
```

### structure.md - 结构规范

```markdown
# Wiki 结构规范

## 目录结构
- 定义标准目录结构
- 定义页面组织方式

## 命名规范
- 文件命名规则
- 标题命名规则

## 元数据规范
- 必需元数据字段
- 可选元数据字段
```

### quality-rules.md - 质量规则

```markdown
# 质量规则

## 编译质量
- 原始资料完整性
- 概念提取准确性
- 链接建立充分性

## 页面质量
- 内容准确性
- 结构清晰性
- 链接有效性

## 检查频率
- 每日：新增页面检查
- 每周：全量健康检查
- 每月：质量趋势分析
```

### triggers.md - 触发规则

```markdown
# 触发规则

## 自动触发
- 新资料录入 → 自动编译
- 页面创建 → 自动建立链接
- 健康检查 → 自动修复

## 手动触发
- 用户请求编译
- 用户请求检查
- 用户请求重建索引
```

### lint-config.md - Linting 配置

```markdown
# Linting 配置

## 检查项目
- 一致性校验
- 完整性补全
- 质量评估

## 修复策略
- 自动修复：链接失效、格式错误
- 人工审核：内容冲突、定义模糊

## 报告格式
- 问题列表
- 修复建议
- 自动修复记录
```

## 知识生命周期

### 录入（Ingest）
```
原始资料 → Layer 1
    ↓
LLM 编译
    ↓
Wiki 页面 → Layer 2
```

### 查询（Query）
```
用户查询 → 索引查找 → Layer 2 页面
    ↓
返回完整页面 + 相关链接
```

### 检查（Lint）
```
Layer 2 Wiki → 健康检查
    ↓
问题报告 + 修复建议
    ↓
自动修复/人工审核
```

### 进化（Evolve）
```
使用 → 反馈 → 修正 → 增厚
    ↓
QA 归档 → 知识复利
    ↓
网络效应 → O(n²) 价值增长
```

## 与记忆系统协同

```
LLM Wiki 编译知识 (Layer 2)
    ↓
语义记忆 ← 提取模式/规则
情景记忆 ← 记录编译经历
程序记忆 ← Skills 本身
    ↓
未来自学习调用 Wiki + 记忆
```

## 最佳实践

### ✅ 推荐做法

1. **保持 Layer 1 只读**: 原始资料不修改
2. **丰富 Layer 2 链接**: 每页面至少 3 个双向链接
3. **完善 Layer 3 规范**: 清晰定义规则
4. **定期健康检查**: 每周运行 Linting
5. **QA 归档**: 高质量问答归档到 Wiki

### ❌ 避免做法

1. **修改原始资料**: Layer 1 应保持只读
2. **孤立页面**: 避免创建无链接页面
3. **模糊定义**: 概念定义应清晰准确
4. **忽略 Linting**: 定期检查修复问题
5. **重复内容**: 避免重复创建相似页面
