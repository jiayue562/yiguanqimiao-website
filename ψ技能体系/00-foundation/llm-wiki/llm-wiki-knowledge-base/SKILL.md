# LLM Wiki 知识库编译器

> "将知识管理从'人类编写、机器检索'转变为'机器编译、人类审核'。" — 基于 Karpathy LLMification 方法论

> **第二核心**: "双向链接+图谱是知识学习的本质能力，不是工具功能。" — 基于龙心 OS 知识编译实践

## 📋 核心定义

**一句话定义**: LLM Wiki 知识库编译器是从原始资料到结构化 Wiki 的知识生产底座，实现 Karpathy LLMification 方法论，支持录入编译、查询调用、健康检查、自我进化全生命周期管理。

**三行问题陈述**:
- **What**: 解决传统 RAG 失忆缺陷、pdf-to-text 信息丢失、知识无法复利增长的问题
- **Why**: 知识需要持久记忆与自我进化能力，而非会话结束即清空
- **How**: 三层架构（原始资料层 + Wiki 本体层 + Schema 配置层）+ 四步流程（录入→查询→检查→进化）

---

## 🎯 与记忆系统的关系

| 维度 | LLM Wiki 知识库 | 记忆系统 |
|------|----------------|----------|
| **知识来源** | 外部文档/Web | 内部经验/会话 |
| **编译方式** | 机器编译 + 人类审核 | 经验提取 + 模式抽象 |
| **存储形式** | 三层架构 (原始/Wiki/Schema) | 三层记忆 (L0/L1/L2) |
| **检索方式** | 索引调用 | 语义搜索 |
| **进化方式** | Linting 自我修复 | 记忆更新/遗忘 |
| **核心价值** | 知识复利增长 | 经验跨会话复用 |

**协同流程**:
```
外部知识 → LLM Wiki 编译 → Wiki 本体层
    ↓
语义记忆提取模式
情景记忆记录经历
    ↓
未来自学习调用 Wiki + 记忆
```

## 🔄 知识生命周期

### 四步流程

```
录入 → 查询 → 检查 → 进化
  ↓       ↓       ↓       ↓
编译    调用    修复    增厚
```

---

### 第一步：录入（Ingest）

**功能**: 将原始资料编译为结构化 Wiki

**输入**:
- 原始文档（PDF/DOCX/Markdown）
- Web 文章 URL
- 代码仓库
- 数据集

**处理流程**:
```
1. 读取原始资料
2. 提取核心概念
3. 生成实体/概念页面
4. 建立双向链接
5. 存入 Layer 2 Wiki 本体层
```

**输出**:
- 结构化 Markdown 页面
- 双向链接网络
- 索引更新

---

### 第二步：查询（Query）

**功能**: 从 Wiki 调用知识（非检索）

**与 RAG 的区别**:
| 维度 | RAG 检索 | Wiki 调用 |
|------|----------|----------|
| 方式 | 向量相似度 | 索引导航 |
| 结果 | 片段拼接 | 完整页面 |
| 速度 | 慢（向量计算） | 快（索引查找） |
| 准确性 | 中（可能丢失上下文） | 高（完整语义） |

**查询方式**:
```
1. 索引查找：通过概念索引定位
2. 链接导航：通过双向链接浏览
3. 标签过滤：通过标签筛选
```

---

### 第三步：检查（Lint）

**功能**: 自我修复与进化（类似代码 Linting）

**检查项目**:
```
① 一致性校验：
   - 概念定义是否冲突
   - 链接是否有效
   - 引用是否准确

② 完整性补全：
   - 缺失的概念页面
   - 未建立的链接
   - 过时的信息

③ 质量评估：
   - 页面可读性
   - 链接密度
   - 更新频率
```

**输出**:
- 问题报告
- 修复建议
- 自动修复（可选）

---

### 第四步：进化（Evolve）

**功能**: 知识复利增长

**进化机制**:
```
① QA 归档：
   高质量问答 → 归档到 Wiki → 知识增厚

② 网络效应：
   新页面 → 自动建立链接 → O(n²) 价值增长

③ 持续迭代：
   使用 → 反馈 → 修正 → 再使用

④ Linting 自我进化：
   定期检查 → 自动修复 → 质量提升
```

## 🔧 核心功能

### 功能 1: 知识编译（Ingest）

**使用方式**:
```
编译这篇文档到 Wiki:
- 输入：URL 或文件路径
- 处理：提取概念 → 生成页面 → 建立链接
- 输出：Layer 2 Wiki 页面
```

**编译规则**:
1. 保持原始语义完整
2. 提取核心概念（3-5 个）
3. 建立双向链接（至少 3 个）
4. 标注来源和版本

---

### 功能 2: 知识查询（Query）

**使用方式**:
```
查询 Wiki 中的知识:
- 输入：概念名/实体名/标签
- 处理：索引查找 → 链接导航
- 输出：完整页面 + 相关链接
```

**查询优化**:
- 中等规模（<1000 页面）：直接索引
- 大规模（>1000 页面）：分层索引
- 无需向量数据库（Karpathy 反直觉结论）

---

### 功能 3: 健康检查（Lint）

**使用方式**:
```
检查 Wiki 健康状态:
- 输入：Wiki 目录
- 处理：一致性 + 完整性 + 质量评估
- 输出：问题报告 + 修复建议
```

**检查指标**:
| 指标 | 计算方式 | 健康范围 |
|------|----------|----------|
| 链接率 | 有链接页面/总页面 | >80% |
| 孤立率 | 无链接页面/总页面 | <5% |
| 更新率 | 月更新页面/总页面 | 5-20% |
| 重复率 | 重复内容/总内容 | <5% |

---

### 功能 4: 索引重建（Rebuild）

**使用方式**:
```
重建 Wiki 索引:
- 输入：Wiki 目录
- 处理：扫描页面 → 提取概念 → 构建索引
- 输出：概念索引 + 链接图谱
```

**索引类型**:
- 概念索引：概念名 → 页面
- 标签索引：标签 → 页面列表
- 链接图谱：页面 → 相关链接

## ⚠️ 关键规则

### 编译规则

1. **原始性保护**: Layer 1 原始资料只读，不修改
2. **语义完整**: 编译不丢失核心语义
3. **链接建立**: 每个页面至少 3 个双向链接
4. **版本标注**: 明确标注来源和版本

### 质量规则

5. **一致性**: 概念定义无冲突
6. **完整性**: 核心概念无遗漏
7. **可检索**: 索引完整，支持快速查找
8. **可进化**: 支持 Linting 自我修复

### 协同规则

9. **与记忆系统分工**: LLM Wiki=知识生产，记忆系统=经验沉淀
10. **与 self-learning 协同**: self-learning 学习 → LLM Wiki 编译
11. **与 IMA 协同**: 本地 Wiki → IMA 云端同步
