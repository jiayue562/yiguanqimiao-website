# 人机握手协议 v1.0

> **定位**：L2人机握手层的核心规范——定义味藏组织中每一次人-AI信息交接的标准格式、质量标准、超时处理和反馈闭环。
> **核心理念**：每一次交接都是一次"握手"——握得好，组织流畅；握得差，组织阻塞。

---

## 一、握手原则

### 握手三要素

| 要素 | 含义 | 反例 |
|------|------|------|
| **清晰** | 信息格式标准、边界明确、无歧义 | "你看看这个数据有没有问题" |
| **完整** | 包含决策所需的所有上下文 | 只给数据不给背景和分析 |
| **有时限** | 每次握手都有明确的时间预期 | "有空看一下" |

### 握手铁律

1. **AI给出分析，人做出判断**——AI不替人拍板
2. **人给出方向，AI展开执行**——人不替AI做细节
3. **握手双方都清楚：谁在等谁、等什么、等到什么时候**
4. **超时自动升级，不无声等待**

## 二、标准握手模板

### 模板1：AI → 人（信息推送型）

**场景**：AI完成分析/检测后，将结果推送给人审阅/决策

```markdown
## 🤖→👤 握手 #[编号]

**时间**：YYYY-MM-DD HH:MM
**优先级**：[紧急/重要/常规]
**类型**：[日报/异常/建议/方案]

### 📊 AI已完成
- [具体做了什么分析/检测]
- [关键发现：3-5条bullet]
- [数据支撑：关键数字]

### 🎯 需要你做
- [ ] [具体需要人做什么决策/确认/行动]
- [ ] [如果有多个决策点，分开列出]

### ⏰ 请在 [时间] 前回复
**超时处理**：[超时后的自动动作]

### 📎 附件/详情
[链接或引用]
```

**味藏实例**：
```markdown
## 🤖→👤 握手 #2026-0623-001

**时间**：2026-06-23 07:00
**优先级**：重要
**类型**：日报

### 📊 AI已完成
- 昨日经营数据汇总：营收 ¥42,800（环比+5.2%）
- 异常检测：酒水占比从18%降至12%（↓6个百分点）⚠️
- 客户满意度：4.2/5（2条低分，已标记）
- TOP3菜品：金枪鱼大腹 ¥8,200 / 蓝鳍刺身拼盘 ¥6,500 / 海胆 ¥4,100

### 🎯 需要你做
- [ ] 确认酒水占比下降原因（新品影响/服务员推荐变化？）
- [ ] 查看2条低分评价并决定处理方式
- [ ] 今日采购确认（已自动生成清单）

### ⏰ 请在 10:00 前回复酒水占比问题
**超时处理**：10:00自动升级至总经理

### 📎 详情
- 完整日报：`日反馈/2026-06-22.md`
- 低分评价：`客户反馈/2026-06-22/`
```

### 模板2：人 → AI（任务下达型）

**场景**：人向AI下达分析/执行任务

```markdown
## 👤→🤖 任务 #[编号]

**时间**：YYYY-MM-DD HH:MM
**任务类型**：[分析/报告/方案/执行]
**优先级**：[紧急/重要/常规]

### 🎯 任务描述
[一句话说清楚要做什么]

### 📋 具体要求
- 输出格式：[MD/表格/PPT]
- 数据范围：[时间/门店/指标]
- 特殊要求：[对比维度/关注点]

### ⏰ 完成时限
[YYYY-MM-DD HH:MM]

### 📎 参考
[相关文件/数据/上下文]
```

**当前进度**：[AI已完成的部分]
**分叉点**：[遇到了什么需要选择的情况]

### 选项A：[方案描述]
- 优点：
- 风险：

### 选项B：[方案描述]
- 优点：
- 风险：

### ⏰ 请在 [时间] 前选择
**默认处理**：若无回复，按 [选项X] 执行
```

```

## 三、握手质量标准

### AI→人信息质量标准

| 维度 | 标准 | 不合格示例 |
|------|------|----------|
| 可行动性 | 人看完后知道具体要做什么 | "数据有些异常"→应说"酒水占比下降6个百分点，请确认原因" |
| 压缩率 | 3-5条关键发现 + 1个核心建议 | 丢出20页原始数据 |
| 上下文 | 包含对比基线（同比/环比/目标） | 只说"营收42,800"不提供对比 |
| 紧迫性 | 标注优先级 + 明确时限 | 所有信息都标"重要" |

### 人→AI任务质量标准

| 维度 | 标准 | 不合格示例 |
|------|------|----------|
| 清晰度 | AI不需要追问就能开始执行 | "帮我分析一下"→应说"分析上月各店营收趋势，输出表格+3个关键发现" |
| 边界 | 明确说"要什么"和"不要什么" | 不设边界导致AI过度输出 |
| 格式 | 指定输出格式和结构 | 不指定导致格式不匹配 |
| 时限 | 明确deadline | "有空做一下" |

## 四、反馈闭环

### AI输出质量评分（人每次验收时填写）

```markdown
## 反馈 #[编号]

**任务**：[原任务]
**评分**：[1-5分]
- 信息准确性：⭐×N
- 行动指导性：⭐×N
- 格式规范性：⭐×N
- 时效性：⭐×N

**改进建议**：
[如果有任何不好用的地方]
```

### 反馈效应

| 连续评分 | AI行为调整 |
|---------|-----------|
| 连续5次≥4分 | 维持现有标准 |
| 连续3次3分 | 调整输出格式/详细度 |
| 连续2次≤2分 | 触发握手协议复审，调整该类型任务的AI模板 |

## 五、握手超时处理

### 超时分级

| 握手类型 | 标准时限 | ⚠️ 警告 | 🚨 升级 | 🔴 紧急 |
|---------|---------|---------|--------|--------|
| 日报推送 | 2小时 | 4h提醒 | 8h升级 | - |
| 异常预警 | 30分钟 | 1h提醒 | 2h升级至总经理 | 4h紧急通知 |
| 方案审批 | 1天 | 2天提醒 | 3天升级 | - |
| 应急响应 | 15分钟 | - | 30分钟紧急通知 | 1h启动预案 |
| 任务下达 | 4小时 | 8h提醒 | 24h标记为取消 | - |

### 超时日志

每次超时自动记录到 `瓶颈追踪系统`：

```markdown
| 日期 | 握手类型 | 责任人 | 原定时限 | 实际用时 | 超时倍数 | 影响 |
|------|---------|--------|---------|---------|---------|------|
```

## 六、智能体→智能体握手

### AI→AI握手标准

味藏智能体之间也需要标准化握手：

```markdown
## 🤖→🤖 路由 #[编号]

**来源智能体**：[name P=XX]
**目标智能体**：[name P=XX]
**路由原因**：[为什么需要交给这个智能体]

### 📦 传递数据
[结构化数据，JSON格式]

### 🔗 上下文
[当前任务的完整上下文链接]

### ⏰ 期望响应时间
- 标准：30分钟
- 紧急：5分钟（需Gate审批）
```

### 跨层路由规则

| 路由方向 | 是否需要Gate | 说明 |
|---------|------------|------|
| 赋能层→执行层 | 不需要 | 专业指令直达一线 |
| 执行层→赋能层 | 不需要 | 一线请求直接支援 |
| 执行层→决策层 | **需要Gate** | 升级必须经过超级店长 |
| 赋能层→决策层 | **需要Gate** | 战略建议需要Gate编排 |
| 决策层→执行层 | 不需要 | 战略指令直达一线 |

### Gate拦截场景

超级店长（P=96）的Gate功能自动拦截：
- 同一任务被重复路由
- 跨层路由缺少必要上下文
- 智能体Trust Score<50时的路由请求
- 涉及S级决策时直接路由尝试绕过人审批
