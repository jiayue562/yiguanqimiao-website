# 写在前面

## 一、一个我答不上来的问题

2026 年，我手上有五个用得很顺的 Skill：象思维、知识学习、五色光思维、人机协同五象限、知行合一。写东西用它，做决策用它，跟 AI 协作也用它。它们各管一段，配合得不错。

有一天有人问我一句：**它到底解决什么问题？**

我张了张嘴，没答上来。

不是没话说，是话太多，反而说不清。我说它可以帮你原创，可以帮你消化材料，可以帮你看全面，可以帮你分工，还可以帮你沉淀。说完我自己都觉得这像在产品发布会上念参数——**每一项都对，但加在一起不等于答案**。

这件事让我难受了几天。因为一个说不清自己解决什么问题的东西，通常只有三种可能：

1. 它其实没什么用，只是我用习惯了；
2. 它太大了，大到没有一句话能装下；
3. 它属于"底层"那一类——**底层的特点就是：你天天用它，但看不见它。**

后来我发现，是第三种。而且第三种里还藏着一个更难的事实：**越是底层的东西，越容易被误认为是"说不清"，其实是"还没找到那个正确的问法"。**

## 二、换个问法，答案就出来了

"它解决什么问题"这个问题之所以答不上来，是因为它问的是**功能**。而一个操作系统恰好不是靠功能立身的——你不会问"Windows 解决什么问题"。

我换了个问法：**没有它，哪件事会变糟？**

这一问，答案立刻具体了：

- 没有它，我那些一闪而过的想法，冒出来就没了；
- 没有它，我学完的东西还是别人的话，变不成我自己的；
- 没有它，我拍脑袋定的事，事后才想起来还有一面没看；
- 没有它，我跟 AI 扯半天，最后不知道该谁干；
- **没有它，我做完了就结束了，下次照样从零开始。**

这五条不是五个功能，是**同一件事的五个漏点**：你花掉的时间换来的东西，本该留下，却漏掉了。

我给这件事起了个名字：**认知资产的蒸发**。

这本书就是围着这五个字写的。前面那五条，一条一章，每章一个引擎；然后讲谁来决定该用哪个；然后讲怎么让它在你没喊它的时候自己动起来；最后讲它干不了什么。

## 三、它不是工具箱，是有机体

这句话是我最早写在设计文档里的，现在还是全书最准的一句：

> **龙心OS 是 AI 系统的心脏。不是工具箱，是有机体。不是被调用，是自己跳动的。**

工具箱和有机体的区别在哪儿？

工具箱里每把工具都很好，但你得自己记得什么时候用哪把——**而接缝处全漏**。想完了没记，学完了没消化，决策完了没复盘，跟 AI 协作完了没沉淀。每一段都有工具，段和段之间是空的。

有机体不是这样。它的五个部分本来就长在一起，血在中间流，做完一件事，血自动把它带走、变成下一件事的养料。**它的价值不在某一个器官有多强，在于循环没有断。**

再往前一步，如果这套东西跑在一个组织里——一个 AI 原生组织里——它就是这个组织 AI 系统的心脏。**结构决定血脉往哪走，心脏决定血到不到得了末梢。** 没有心脏的结构是图纸，没有结构的心脏是空转。

判断它到底是不是心脏，只有一个标准：

> **它停了，这个系统的认知循环会不会停？**

会停，它就是心脏。不会停，它就还只是个好用的工具。

## 四、这本书怎么读

全书 24 章，分五编：

| 编 | 章 | 讲什么 |
|---|---|---|
| 第一编 破题 | 1–3 | 它治的病是什么，它的强项和边界 |
| 第二编 五个引擎 | 4–8 | 每一段谁管，内部怎么构造，什么时候必须用它 |
| 第三编 调度 | 9–13 | 中枢怎么判断该派谁，以及最重要的产出——定题 |
| 第四编 自动触发 | 14–19 | 不说出关键词，它怎么自己动 |
| 第五编 实战与边界 | 20–24 | 一天怎么用、组织怎么用、黑箱怎么办、它干不了什么 |

**如果你只想用它**：读第一编和第二编，够你上手。
**如果你想让它自己动**：第三、四编是核心，尤其第十七章和第十九章。
**如果你想照着搭一套自己的**：第五编第二十三章有完整清单。

每一章末尾都有三栏：**本章能拿走什么**（其中至少一条是可以直接用的模板或表）、**这一章，对 AI 怎么说**（本章机制对应的话术）、**待校准**（我还没实测、或者还拿不准的地方）。

"待校准"这一栏不是客套。这本书里有相当一部分阈值和判据，是我设计出来的，不是跑出来的。**我不打算把它写成已经验证过的样子**——一个连自己会不会误触发都要打问号的系统，如果连这点都不敢承认，它就不值得信。

# 第一章 · 一个说不清自己解决什么问题的系统

## 这一章解决什么

把"我造了它，却说不清它解决什么问题"这件事，从尴尬变成方法。

这一章不急着给龙心OS 下定义。它先做一件更重要的事：**给你一套问法**——当你以后再遇到一个说不清的东西（不管是自己造的系统、一个岗位、还是一段关系），你都能用这套问法把它问清楚。

## 核心内容

### 一、答不上来，通常不是因为它没用

很多人遇到"说不清"会本能地怀疑：**是不是这东西本来就没那么好，只是我用顺手了？**

这个怀疑值得有，但它有个检验办法——**看它在不在场，结果差多少**。

我拿写《象与模》那本书试过。同一批素材，两种写法：

- 不用龙心OS：直接读、直接写。写出来的东西不算差，但每次卡住，卡的地方都一样——素材读完不知道重点在哪，写到一半发现漏了一个角度，写完就完了，下一章又从头开始。
- 用龙心OS：先把材料过一遍"消化三判据"，再用象思维取一个象，五色光把角度扫一遍，最后沉淀一张卡。

差别不在文采，在**返工次数和下一章的起点**。第一种写法，每章起点都是零；第二种写法，上一章留下来的那张卡，就是下一章的起点。

所以它不是没用。它只是**用在了看不见的地方**。

### 二、三种"说不清"，只有一种是真的说不清

| 类型 | 特征 | 例子 | 怎么破 |
|---|---|---|---|
| **没用型** | 拿走它，什么都没变 | 一个你开了但从不打开的功能 | 直接删 |
| **太大型** | 拿走它，什么都变了，说不出哪个最要紧 | 电、语言、操作系统 | 不问"解决什么"，问"没有它哪件事会变糟" |
| **底层型** | 它不直接产出，它让别的东西能产出 | 地基、血液循环、心脏 | 问"它停了，什么会停" |

**龙心OS 是第三种，而且第三种里它还是最特殊的那种**——它不产出内容，它产出的是"下一次的起点"。

### 三、正确的问法：不问"它是什么"，问"它停了会怎样"

这一节是本章最有用的部分。

"它是什么"问的是**定义**，定义要往抽象里走，越走越空。
"它停了会怎样"问的是**依赖**，依赖往具体里走，越走越实。

我把它拆成了四个具体问题，叫**四问定位法**：

| 问 | 具体问法 | 答不上来说明什么 |
|---|---|---|
| **问重复** | 没有它，什么会反复发生？ | 找到它本该消除的重复劳动 |
| **问丢失** | 没有它，什么会永久丢失？ | 找到它本该留下的资产 |
| **问变慢** | 没有它，什么会慢下来？ | 找到它本该节省的时间 |
| **问不可能** | 没有它，什么根本不会发生？ | 找到它独有的能力 |

**第四问最关键**。前三问答得再好，只能说明它是个效率工具；只有第四问有答案，它才是不可替代的。

拿龙心OS 过一遍：

- **问重复**：没有它，同样的背景我得跟 AI 解释一遍又一遍。
- **问丢失**：没有它，这次想到的东西下次就没了。
- **问变慢**：没有它，每次都要重新判断"这事该从哪下手"。
- **问不可能**：没有它，**"做完一次，下次起点更高"这件事根本不会发生**——因为没有任何一个环节在负责"留下"。

第四问的答案，就是这本书的主线。

### 四、一个反例：什么时候"说不清"是真的有问题

我不能把这章写成"说不清都情有可原"，那是不诚实的。

**有一种"说不清"是真的有问题**：当你说不清"它不管什么"的时候。

一个什么都管的东西，等于什么都不管。龙心OS 在设计过程中，最危险的一段就是有人建议"再加一个引擎吧，这个场景也能覆盖"。加了三次之后，它开始变得什么都能干，也什么都不精。

后来立了一条规矩，一直守到现在：**五个引擎，一个不多**。有新场景，先在五个引擎里找归属；找不到，说明这个场景不属于它，交给别的系统去做。

**边界不是限制，边界是它还能用的前提。**

## 本章操作件

### 四问定位法工作表

拿你手上一个"说不清有什么用"的东西（一个工具、一个岗位、一个习惯、一段关系），填满这张表：

| 问 | 我的答案 | 得分（0=没答案，1=有但模糊，2=具体） |
|---|---|---|
| 问重复：没有它，什么会反复发生？ | | |
| 问丢失：没有它，什么会永久丢失？ | | |
| 问变慢：没有它，什么会慢下来？ | | |
| **问不可能：没有它，什么根本不会发生？** | | |

**怎么读这张表**：

- 前三问总分 ≥ 4，第四问 = 0 → 它是个效率工具，可以换，别神化它。
- 四问总分 ≥ 5，且第四问 ≥ 1 → 它有底层价值，值得继续投入。
- 四问全 0 → 该放手了。

### 填写示例：以"写《象与模》时的龙心OS"为例

| 问 | 答案 | 分 |
|---|---|---|
| 问重复 | 同样的素材背景要跟 AI 反复解释 | 2 |
| 问丢失 | 每章的洞察，写完就散在聊天记录里 | 2 |
| 问变慢 | 每次开新章都要重新想"从哪下手" | 1 |
| 问不可能 | **做完一次，下次起点更高**——没有引擎负责留下，这件事不会发生 | 2 |

总分 7，第四问满分 → 继续投入。

## 跨章接口

- 本章的"四问"答案，是第二章五笔账的原始素材——**问丢失**那一条，直接长成了第二章的"认知资产蒸发"。
- 本章划定的"五个引擎，一个不多"，是第二编每章"它不管什么"小节的总依据。
- 第四问的答案（做完一次，下次起点更高），是第八章"血"的引信。

## 待校准与待补

1. 三种"说不清"的分类（没用型/太大型/底层型）是我归纳的，只在三个案例上试过，样本偏少。
2. 四问定位法的分值线（≥4、≥5、全 0）是设计值，**没有经过实测**，请当作提示而不是标准。
3. "五个引擎，一个不多"这条规矩，在设计过程中被挑战过三次，具体挑战场景待补。

# 第二章 · 它治的病：认知资产的蒸发

## 这一章解决什么

给全书立一个"病"。

后面二十二章写的都是药。但在开药之前，得先把病看清楚——**病看错了，药越猛，偏得越远**。

这一章要给"认知资产"下一个能算账的定义，然后把它蒸发的方式拆成五笔。这五笔不是我拍脑袋分的，是**五个引擎的分工依据**。看清楚这五笔，你就明白为什么是五个引擎、为什么不能多也不能少。

## 核心内容

### 一、什么叫认知资产

先说个反直觉的事实：**上下文窗口不等于记忆**。

现在的大模型动不动就 128K、甚至百万级 Token 的上下文，很多人觉得"记忆问题解决了"。没有。上下文窗口像是**桌面**——你可以把很多文件摊在上面，但下班一关机，桌面就空了。真正的记忆是**书架**：东西放上去就在那儿，下次来直接抽出来用。

这个区别看着简单，但它解释了一件事：**为什么你跟 AI 合作三个月，它对你过往的决策还是一无所知**。不是它记不住，是你从来没把东西放上书架。

我把这个"本该放在书架上、却摊在桌面上被清走了"的东西，叫**认知资产**：

> **认知资产 = 你花掉的时间换来的、本该留下却没有留下的东西。**

它有三个特征，缺一个都不算：

1. **花了时间才有的**（不是随手搜来的）；
2. **下次还能用**（不是一次性的）；
3. **丢了会重做**（这是最要命的一条）。

第三条是判据。你可以拿它去测：一个东西丢了，你会不会重做？**会，它就是资产；不会，它就只是记录。**

### 二、蒸发的五笔账

认知资产不是一次性蒸发的，它在五个环节各漏一次。每一笔对应一个引擎：

| 环节 | 蒸发现象 | 一句话 | 谁管 |
|---|---|---|---|
| **无 → 有** | 想法冒出来，没被接住 | 想到了，没了 | 🐉 心·象思维 |
| **外 → 内** | 学了一堆，还是别人的话 | 收藏了，没消化 | 📚 脾·知识学习 |
| **偏 → 全** | 一拍脑袋就定，事后才想起还有一面 | 定了，漏了 | 🌈 眼·五色光 |
| **人 → 机** | 跟 AI 扯半天，不知道该谁干 | 聊了，白聊 | 🤝 手·五象限 |
| **做完 → 留下** | 做完了，下次还是从零 | 做完了，归零 | 🔄 血·知行合一 |

这五笔不是并列关系，是**一条链**：想法没接住 → 接住了没消化 → 消化了没看全 → 看全了分工不清 → 分清楚了做完就散。

**链上每一环都能单独漏，而且漏了后面的就全白搭。**

### 三、为什么第五笔最贵

前四笔做错，损失是**一次的**：这个想法没了，就这一次没了；这次决策漏了一面，就这一次漏了。

**第五笔不做，损失是永久的。**

原因很硬：不沉淀，前四笔的错误会原样重犯。你今年踩的坑，明年换个场景还会踩——因为系统里没有任何东西在提醒你"这个坑你踩过，当时是这样爬出来的"。

我给你算一笔更实在的账。假设一个人一年做 200 次重要判断：

- 每次判断如果从零开始，平均花 30 分钟找感觉；
- 如果有沉淀，平均 10 分钟能接上；
- 差 20 分钟 × 200 次 = **一年 66 小时**。

这还只是时间。**真正贵的是质量**：从零开始的判断，错误率不会因为你更努力而下降——因为你不记得上次错在哪。

所以"自我进化"不是这本书的一个卖点，它是**这本书存在的理由**。前四个引擎决定这一次做得好不好，第五个引擎决定**下一次的起点在哪**。

### 四、三个加速器

蒸发本来就在发生，但有三件事让它变快了：

**第一，AI 让产出变快，蒸发也跟着变快。**
以前写一份方案要三天，你有时间在脑子里过好几遍。现在二十分钟就出来了——**产出快了，沉淀的时间反而没了**。你一天做十件事，就蒸发十次。

**第二，多端切换让东西散落。**
电脑、手机、不同 AI 工具、不同知识库。同一件事的碎片散在四五个地方，任何一端都不完整。散落不是丢失，但**散落的东西跟丢了一样用不上**——你不会为了找一句话翻五个 App。

**第三，没有默认动作，靠自觉必然失败。**
这是最根本的一条。所有"记得要复盘"的机制，三个月后执行率都趋近于零。不是人懒，是**没有默认动作的事，就一定不会有**。

这一条直接决定了第四编为什么要花六章讲"自动触发"：靠你记得喊它，它就不会被喊；它得自己动。

### 五、一个具体的现场

去年做一次组织诊断，前后跑了三周，中间开了七次会。结束时我脑子里很清楚：那个组织真正的问题不是"沟通不畅"，是**三个部门的责任边界在同一件事上互相重叠，谁都能管，所以谁都不管**。

这个判断当时很值钱——它把七个会的信息压缩成了一句话。

然后呢？然后就没有然后了。三个月后另一个客户问了个很像的问题，我想起"我好像遇到过类似的"，但具体怎么判断出来的、当时看了哪几个信号，全忘了。我重新推了一遍，花了一天半。

**那一天半，就是第五笔账的账单。**

# 第三章 · 它不是什么，它是什么

## 这一章解决什么

把期望值钉死。

一个系统被误用，八成不是因为它不好，是因为**人们对它的期待跑偏了**。有人拿它当万能钥匙，有人拿它当搜索引擎，还有人指望它替自己做专业判断。

这一章干两件事：**说清它强在哪三条，说清它不强在哪三处**。后一半比前一半重要——一个敢写自己不行在哪的系统，才配被信任。

## 核心内容

### 一、它不是应用，不是工具，是底层调度系统

先做三个排除：

**它不是应用。** 应用解决特定问题（写文章、做表格、画图）。龙心OS 不直接产出任何一样东西——它决定"这件事该交给谁、按什么顺序办"。

**它不是工具。** 工具是你拿起来用的，用完放下。龙心OS 不是被拿起来的，它一直在。区别就像锤子和血液循环。

**它不是方法论合集。** 把五个引擎各写成一篇文章，装订成册，那叫合集。合集的问题在于**每篇都对，接缝处全漏**——想完了没记，学完了没消化，段和段之间是空的。

它是**底层调度系统**：上面跑什么应用它不管，它管的是"这堆东西怎么协同、做完怎么留下"。

### 二、三条强项

#### 强项一：完整——它是一条流水线，不是一个工具箱

市面上不缺好用的思维工具，缺的是**把它们接起来的那一层**。

工具箱的问题不是工具不好，是**接缝**。你有取象的方法，有分析的方法，有复盘的方法，但：想出来之后到分析之间，谁负责把那个想法记下来？分析完之后到复盘之间，谁负责说"这一步的结论是什么"？

龙心OS 的完整，不在于它有五个引擎，在于**它把"无→有→全→行→留"这条链接通了**。每一段的输出，是下一段的输入；整条链的最后一环，把结果送回第一环当起点。

#### 强项二：会进化——做一次，下次起点更高

这是它跟所有"效率工具"的根本分野。

效率工具让你这次做得更快。**它让你下次做得更好**——因为每一次做完，都有一张卡留下来，那张卡就是下一次的起点。

这一点我在第二章算过账：前四个引擎决定这一次做得好不好，第五个引擎决定下一次的起点在哪。没有第五个，前四个做得再好，也是一次性的。

**这是它最值钱的地方，也是最难被抄的地方。** 工具可以被复制，积累不能。

#### 强项三：会调度——你不用自己记该用哪个

五个引擎，如果你得自己判断"这次该用哪个"，那你得先成为五个引擎的专家。**这就本末倒置了**。

中枢的存在就是为了让你不用记。它感知上下文、识别场景、派引擎、并且告诉你它派了谁。

但请注意这个词：**派**。它派活，它不干活。下一编会专门讲这个边界。

### 三、三处不是强项（照实写）

#### 不强项一：它不解决专业领域的深度

龙心OS 管的是"怎么想"，不是"想什么"。

医学诊断、法律判断、财务测算、工艺参数——这些是行业知识，它需要专业积累，不是换个思考框架就能补上的。**它能帮你把一个医学问题问得更清楚，不能替你把病看出来。**

把这两件事混了，会出事。最常见的事故是：一个人用它把问题问得特别漂亮，然后以为漂亮的问法等于正确的答案。

#### 不强项二：它不替代执行

它出方案，不干活。

龙心OS 里有一个明确的对外接口叫龙爪OS——那是执行层。它负责把方案变成文件、变成代码、变成动作。**心脏不负责搬东西，那是手脚的事。**

这条边界的意义在于：如果有人期待"我装上龙心OS 就自动把事做完了"，那他期待的是一个员工，不是一个系统。

#### 不强项三：它不保证触发正确

这一条是它最大的不确定性，我不打算绕过去。

自动触发靠的是场景识别，场景识别靠的是打分和信号。**打分就会打错，信号就会误判。** 它会：

- 该动的时候不动（漏触发）；
- 不该动的时候乱动（误触发）；
- 动了，但派错了引擎。

这三件事都会发生。第四编用整整六章来处理它们，第十七章专门讲护栏，第十九章专门讲怎么用日志把它调回来。

**但我不会承诺它不会错。承诺不了的东西，我不写。**

### 四、一个判断标准：它停了，什么会停

第一章提出过这个标准，这里把它说完整。

怎么判断一个系统在你那儿到底是"心脏"还是"一个好用的工具"？只有一条：

> **它停了，你的认知循环会不会停？**

- 会停 → 它是心脏。你的想法有人接、学的东西有人消化、做完的事有人留下，这些事都在它上面跑。
- 不会停 → 它还是工具。少了一个工具，你会慢一点，但循环没断。

这个标准也适用于组织：**组织里的 AI 系统停了，组织的认知循环会不会停？** 会停，那龙心OS 在你们那儿就是心脏；不会停，那它现在还只是个高级插件。

### 五、边界不是限制，是它还能用的前提

最后说一句本书的立场。

设计这套系统的过程中，最危险的一段是"再加一个引擎"的诱惑。加了三次之后，它开始变得什么都能干——然后什么都不精。

后来立了一条规矩守到现在：**五个引擎，一个不多**。有新场景，先在五个里找归属；找不到，说明这个场景不属于它。

**一个什么都管的东西，等于什么都不管。**

# 第四章 · 🐉 心·象思维：从无到有

## 这一章解决什么

0→1 那一跃，怎么被接住，而不是被错过。

这是五个引擎里唯一处理"人和 AI 都不知道"的那个。其他四个引擎都在处理"已知"——已知的怎么消化、怎么看全、怎么分工、怎么留下。只有它，处理的是**还没有名字的东西**。

## 核心内容

### 一、它管哪一段：无 → 有

第二章的五笔账里，第一笔是"想法冒出来，没被接住"。

这一笔特别容易被忽略，因为它发生在**语言之前**——你还没想清楚，所以没法记录；等你用语言说清楚的时候，它已经不是原来那个东西了。

象思维管的就是这段：**从模糊的感觉，到一个可以拿来说的象。**

### 二、它的内部构造

#### 三层次：物象 → 意象 → 原象

| 层次 | 定义 | 例子 | 怎么判断自己在哪层 |
|---|---|---|---|
| **物象** | 五感可及的具体形象 | 看到龙、摸到石头、听到风声 | 你还能描述它的具体形状声音 |
| **意象** | 主客融合的象征形象 | 龙龟神将、凤凰、麒麟 | 你在用一个形象承载意思 |
| **原象** | 超越形象的终极本质 | 木生火、天人合一、道法自然 | 你已经不是在说那个形象了 |

**最常见的失败是停在意象。** 说"这个组织像一盘散沙"——这是意象，不是原象。往下再问一层：散沙的本质是什么？是**颗粒之间没有摩擦力**。摩擦力从哪来？从共同承担过事情来。到了这一层，你才有可操作的判断。

#### 六非两核心

六非是它的边界（不是什么），两核心是它的能力（能什么）：

- **六非**：非实体性（不是具体物质，是能量和信息）、非对象性（主客不二，没有"我"看"它"）、非现成性（动态生成）、前语言性（在语言之前）、前逻辑性（在推理之前）、非确定性（开放多元）。
- **两核心**：整体直观性（一次把握整体，不是拼凑）、悟性（直觉洞察，瞬间看到本质）。

六非里最容易被违反的是**非对象性**。象思维要求你跟对象融为一体，而不是站在对面分析它。一旦开始"分析"，你就已经退回概念思维了。

#### 四步法

| 步 | 操作 | 产出 |
|---|---|---|
| **观物取象** | 放下预期，开放五感，记录第一反应 | 一个物象 |
| **立象尽意** | 从物象里提取能承载意涵的意象 | 一个意象 |
| **取象比类** | 用象做类比和关联，往本质走 | 若干候选原象 |
| **观象制器** | 把原象转成可行动的东西 | 一个做法 |

### 三、什么时候必须用它

**判断标准只有一条：这件事，人和 AI 都不知道答案。**

在人机协同五象限里，这叫 Q5（未知探索域）：你不知道，AI 也不知道。这时候其他四个引擎全部失效——没有东西可消化，没有多面可权衡，谈不上分工，更谈不上沉淀。

三种典型场景：

1. **真正的新问题**：没有任何先例可参考，你自己也没想清楚。
2. **跨域原创**：把一个领域的原理，用到一个没人用过的领域。
3. **被卡住了**：试了很多方法都不行，说明你在错误的框架里——象思维的作用不是给你答案，是**帮你看清楚你现在用的框架是什么**。

第三种最实用。当你在一个问题上反复打转，问题往往不在解法，在**你在解题面上就选错了**。这时候停下来取象，比继续硬推有用。

### 四、它的失败模式

| 失败模式 | 表现 | 修法 |
|---|---|---|
| **把意象当原象** | 停在比喻上，觉得"说得挺形象"就完了 | 追问一句：这个形象背后的本质是什么 |
| **把取象当结论** | 取了个象，就以为问题解决了 | 走完四步，尤其别跳过"观象制器" |
| **故意求象** | 为了显得有洞察，硬凑一个象 | 象是冒出来的，不是编出来的 |
| **装玄** | 用"道""气""场"这类词掩盖没想清楚 | 说不出可操作的判断，就是没到原象 |

最后一条要展开说：**象思维最容易被做成玄学。**

判断标准很简单——**你取的这个象，能不能导出一个具体的做法？** 能，它是象思维；不能，它是修辞。

### 五、它在龙心OS 里的位置

它是五引擎中**唯一**处理 Q5 的引擎。这一点决定了它的不可替代性：Q1 到 Q4 都有模型可循，AI 通常比人强；**当且仅当 Q5，人的取象不可替代**。

但它不是独立工作的。它产出的"象"，会变成：

- 五色光绿光发散的原料（第六章）；
- 知行合一"象征符号"的来源（第八章）；
- 定题时"看出这是件什么事"的那一步（第十二章）。

## 本章操作件

### 观物取象记录模板

```
【观察对象】
【五官感知】看到/听到/摸到什么
【第一反应】不加修饰的第一句话
【初步意象】它像什么
【往下再问一层】这个"像"背后的本质是什么
【可操作的判断】因此，我应该……
```

### 「这是物象还是原象」三问判别表

| 问 | 答"是" → 还在物象/意象层 | 答"否" → 接近原象层 |
|---|---|---|
| 我还能描述它的具体形状吗？ | 是 → 物象 | 否 → 往下 |
| 我是在用一个形象打比方吗？ | 是 → 意象 | 否 → 往下 |
| 它能直接导出一个做法吗？ | 不能 → 还没到原象 | 能 → 到原象了 |

### 举例：走一遍三问

"这个组织像一盘散沙"（意象）→ 能描述形状吗？（能，沙子）→ 是打比方吗？（是）→ 能导出做法吗？（不能直接导出）→ **还在意象层**。

往下：散沙的本质是颗粒间没有摩擦力 → 摩擦力来自共同承担过事情 → **做法：先安排一件必须协作才能完成的小事**。到这一层，才是原象。

## 跨章接口

- Q5 判定在第七章（手·五象限）交汇——那里给出"当且仅当 Q5，人不可替代"的完整论证。
- 象思维的产出是第八章"象征符号"的主要来源。
- 它是第十二章"定题"四步里的第二步。
- 定题之后怎么选模型、怎么排序，那是《象与模》的事，本书不涉及。

# 第五章 · 📚 脾·知识学习：从外到内

## 这一章解决什么

"学了很多，还是别人的话"这件事，怎么破。

这一章全部围绕一个字写：**消化**。不是收集，不是摘要，不是收藏——是**变成自己的**。

## 核心内容

### 一、它管哪一段：外 → 内

第二章五笔账的第二笔：学了一堆，还是别人的话。

这一笔的现代版本是**收藏夹**。你收藏了一千篇文章，下次要用还是得重新搜——因为收藏这个动作，只完成了"搬进家门"，没有完成"变成血肉"。

### 二、为什么是脾，不是胃

这是本书唯一一个改过器官位的引擎，值得说说为什么。

最早它叫"脑"。后来发现不对：**脑是容器，不是功能**。而且心、眼、手、血都是脏腑，中间夹一个"脑"，体系不搭。

改成脾，理由在中医：

> **胃主受纳，脾主运化。**

胃负责把东西收进来，脾负责把收进来的东西**变成你自己的、输送到全身**。

**学习的关键从来不在吃进去，在运化。** 你缺的不是信息，是信息变成你的一部分的那个过程。收藏是胃，消化是脾。

这一改，五个引擎就全在脏腑体系里了：心主神明、脾主运化、眼主观察、手主执行、血主营运全身。

### 三、它的内部构造

#### 方法论层：十项认知操作指令（五层递进）

| 层次 | 指令 | 干什么 | 五行 |
|---|---|---|---|
| 第一层 | **剖析 + 解构** | 提取核心问题，拆成零件清单 | 金 |
| 第二层 | **透视 + 阐释** | 看清论证链条和概念本义 | 火 |
| 第三层 | **推演 + 思辨** | 逻辑外推，四维批判 | 水 |
| 第四层 | **溯源 + 融合** | 追学术谱系，做跨域连接 | 木 |
| 第五层 | **启发 + 映射** | 产生新框架、新理论 | 土 |

五层是递进的，不是并列的。你不必每次都走完五层——**走多深，取决于你要拿它干什么**：

- 只为了解 → 前两层够了；
- 为了用 → 到第三层；
- 为了创造新东西 → 走完五层。

#### 工程实现层：LLM Wiki 三层

| 层 | 对应 | 定义 | 特点 |
|---|---|---|---|
| **物象层**（Raw） | 物象 | 原始资料，只读，不可篡改 | 事实来源，可追溯 |
| **意象层**（Wiki） | 意象 | 知识本体，LLM 维护 | 结构化，可演进 |
| **原象层**（Schema） | 原象 | 系统指令，行为准则 | 机器行为规则 |

这三层的关键，是那次**范式转移**：

> **从「人类编写、机器检索」到「机器编译、人类审核」。**

传统的 RAG（检索增强生成）有个"健忘症"：每次检索都重新解析原文，无法积累。而 LLM Wiki 是**编译一次，长期复用**——知识被压缩成 Wiki 条目后，下次直接用，不用再翻原文。

这个类比很贴切：**RAG 是每次都去翻原始档案，LLM Wiki 是先把档案整理成词条，以后查词条就行。**

### 四、消化的三个判据（本章最重要的一节）

怎么知道一样东西你真的消化了？三条，一条都不能少：

| # | 判据 | 自问 | 不合格的表现 |
|---|---|---|---|
| ① | **能说给外行** | 我能不用术语，给一个外行讲明白吗 | 讲的时候还得看原文、还得用它的词 |
| ② | **能指出冲突** | 它跟我已有的知识，哪儿对不上 | "说得挺有道理"——说不出跟什么冲突 |
| ③ | **能说出改变** | 它改变了我哪个具体做法 | 只知道"很有启发"，说不出改了什么 |

**三条里有一条答不出，就是没消化，只是囤积。**

第三条最狠。一样东西如果没改变你的任何做法，那它对你的价值是零——你只是多了个谈资。

### 五、什么时候必须用它

- 拿到一份长材料（文章、报告、书籍、会议纪要）；
- 进入一个陌生领域，需要建立基本盘；
- 需要把散落的信息整合成结构；
- 做定题之前——**材料没消化就定题，定出来的题只是材料的标题**（第十二章会细说）。

### 六、它的失败模式

| 失败模式 | 表现 | 修法 |
|---|---|---|
| **收藏即学会** | 进了收藏夹就等于学过了 | 用三判据卡一遍 |
| **摘要即理解** | 能复述要点，说不出冲突 | 补判据② |
| **术语搬家** | 学会了一堆新词，用来解释旧词 | 判据①：不用术语讲一遍 |
| **五层跳步** | 还没剖析完就想启发 | 按层走，别跳 |
| **只进不出** | 一直在学，从不产出 | 判据③：它改变了你哪个做法 |

## 本章操作件

### 消化三判据自检卡

拿到一样东西，学完之后填：

| 判据 | 我的答案 | 合格 |
|---|---|---|
| ① 不用术语，讲给一个外行听 | | ☐ |
| ② 它跟我已有知识的冲突点 | | ☐ |
| ③ 它改变了我的哪个具体做法（写动作，不写感受） | | ☐ |

**三条全过才算消化。** 卡在③最常见——如果写不出"改了哪个做法"，说明这次学习还没有产出。

### 十项指令选题速查表

| 我要…… | 用哪条 |
|---|---|
| 搞清楚这份材料到底在问什么 | 剖析 |
| 把它拆成零件，看结构 | 解构 |
| 看它的论证链是怎么走的 | 透视 |
| 弄明白一个概念到底什么意思 | 阐释 |
| 换个条件会怎样 | 推演 |
| 找出它的漏洞 | 思辨 |
| 知道这个说法从哪来的 | 溯源 |
| 把它跟别的东西连起来 | 融合 |
| 找出还没人做的地方 | 启发 |
| 造一个新框架 | 映射 |

### RAG 与 LLM Wiki 的差别（一表记住）

| | RAG | LLM Wiki |
|---|---|---|
| 每次提问 | 重新检索、重新解析原文 | 直接查已编译的词条 |
| 会不会积累 | 不会（健忘症） | 会（编译一次，长期复用） |
| 质量谁控 | 取决于原文质量 | 可人工审核后再入库 |
| 适合 | 一次性的事实查询 | 长期的知识资产建设 |

## 跨章接口

- 消化产出是第八章"表示空间"阶段的输入——没消化的经验，沉淀卡写不出核心洞察。
- RAG 与 LLM Wiki 的差别，在第十三章（组合顺序）复用，也在第二十二章（黑箱白箱）复用：前者是"翻档案"，后者是"查词条"，这个差别正好说明为什么流程要外显。

# 第六章 · 🌈 眼·五色光：从偏到全

## 这一章解决什么

"决定下完了，才想起还有一面没看"。

这一章的武器只有一件：**一次只开一种光**。

听起来简单，做起来极难——因为人的默认状态是混着想的：一边摆事实，一边带情绪，一边算风险，最后自己都不知道到底在权衡什么。

## 核心内容

### 一、它管哪一段：偏 → 全

第二章五笔账的第三笔：一拍脑袋就定了，事后才想起还有一面。

漏的往往不是"没想到"，是**想到了但没被认真对待**。会上有人提了风险，但当时大家都在兴头上，那句话飘过去就没了。五色光的作用，是**给每一面一个专属的时间段**，让它不能被跳过。

### 二、它的内部构造

#### 六种模式

| 光 | 思维类型 | 核心问题 | 五行 |
|---|---|---|---|
| ⬜ **白光** | 客观事实 | 是什么？有哪些数据？ | 金·收敛·精准 |
| 🟥 **红光** | 直觉感受 | 我对这事什么感觉？ | 火·炎上·激情 |
| 🟨 **黄光** | 积极价值 | 好处是什么？谁受益？ | 土·稼穑·整合 |
| 🟩 **绿光** | 创新方案 | 还有什么可能？ | 木·生发·创新 |
| 🟦 **蓝光** | 风险控制 | 可能出什么问题？ | 水·润下·冷静 |
| 🎯 **主持人** | 过程控制 | 现在开哪种光？收齐了吗？ | 超越五行 |

**主持人不是第六种颜色，是管颜色的人。** 这是最容易搞混的一点。

#### 三原则

1. **单色聚焦**：同一时间只有一种颜色的声音。进入某色前要宣告，该色任务完成才能切。
2. **序列自由组合**：没有固定顺序，按目的设计。同一个颜色可以用两次。
3. **强制完整性**：要用就全用。至少用完五色，必须有主持人整合。

第三条最反直觉，也最有用。大多数人用五色光是"挑两三个用一下"——那就等于没用。**缺的那一色，通常正是你会漏的那一面**。

#### 六条经典序列（可直接抄）

| 场景 | 序列 |
|---|---|
| 问题分析 | 白 → 蓝 → 绿 → 黄 |
| 决策制定 | 白 → 绿 → 黄 → 蓝 → 红 |
| 创意激发 | 红 → 白 → 绿 → 蓝 → 黄 |
| 复杂决策 | 白 → 蓝 → 绿 → 黄 → 蓝 → 红 |
| 方案评估 | 白 → 绿 → 黄 → 蓝 |
| 冲突解决 | 红 → 白 → 黄 → 蓝 |

#### 三体一心

- **信息体层** = 象思维（提供直觉和整体把握）
- **能量体层** = 五色光场（把直觉转成具体思考）
- **物质体层** = 五色操作工具（让结果可操作）

一句话：**象思维是道，五色光是用。** 象思维给你一个象，五色光负责把这个象展开成五个角度。

### 三、什么时候必须用它

- 要做决定，而且不只一个选项；
- 会上吵起来了——**吵通常是因为不同颜色在同时发言**；
- 你已经有了一个倾向，想确认自己是不是漏了什么（这时最该开的是**蓝光**，不是黄光）；
- 一群人要想一块儿想（五色光是少数能用于集体的工具）。

### 四、它的失败模式

| 失败模式 | 表现 | 修法 |
|---|---|---|
| **混色** | 一句话里既有事实又有情绪又有判断 | 主持人立刻喊停，问"现在开什么光" |
| **用不全** | 只用了白+蓝，觉得够了 | 强制完整性：至少五色 |
| **跳过主持人** | 各说各的，没人整合 | 明确指定一个人当主持人 |
| **不宣布切换** | 悄悄换角度，别人跟不上 | 每次切换必须宣告 |
| **蓝光过敏 / 蓝光缺失** | 要么全是风险啥也干不了，要么全是好处没人提风险 | 检查序列里有没有蓝 |
| **序列僵化** | 每次都用同一个顺序 | 按目的重排 |

### 五、一个现场

一次"要不要上系统"的决策会，开了四十分钟，越开越乱。销售说客户催得急，技术说现在这套还能撑，财务说预算已经超了，老板说不上系统明年怎么增长。

**四个人在四个颜色里同时说话。** 销售是红光（急），技术是白光（事实），财务是蓝光（风险），老板是黄光（价值）。谁也没听谁的，因为大家不在一个频道上。

后来做了两件事：

1. 主持人宣告："现在只开白光，每个人只说事实，不许带判断。"——五分钟，事实摆齐了。
2. 然后按"白 → 蓝 → 绿 → 黄"走了一遍。

结果是**不上**，但先做一件小事：把三个部门的重复录入合并掉。这个结论在四十分钟的乱吵里永远出不来，因为没有一个阶段是专门用来"想还有没有别的办法"的——**绿光从来没开过**。

## 本章操作件

### 序列设计模板

```
【这次的目的是】__________（决定 / 分析 / 创意 / 冲突）
【开的色序】___ → ___ → ___ → ___ → ___
【每色停留】___ 分钟
【主持人】__________
【每色收一句话】
  白：__________
  红：__________
  黄：__________
  绿：__________
  蓝：__________
【主持人整合结论】__________
```

### 主持人四件事清单

1. **定序列并说破**：开工前宣布走哪几色、每色多久。
2. **按光收话**：有人串色立刻喊停，"现在开的是白光，你的判断等黄光再说"。
3. **把情绪当事实接**：红光里说"我担心"的时候，别回"不用担心"，记下来。
4. **替大家取象**：收尾时说一句"所以这件事，本质上是……"。

### 「缺了哪一光」反查表

| 你现在的症状 | 缺的光 | 补一句 |
|---|---|---|
| 大家各说各的，事实对不上 | 白 | "先只说事实，不带判断" |
| 气氛很闷，没人说真话 | 红 | "这事你心里什么感觉，说一句" |
| 全是问题，没人看好 | 黄 | "它带来的好处是什么" |
| 只有 A 和 B 两个选项 | 绿 | "还有没有第三种可能" |
| 一片叫好 | 蓝 | "最坏会坏到哪一步" |

## 跨章接口

- 五色光是 S4（分析决策）和 S5（重大决策）的主力引擎，第十一章路由会用到。
- **主持人这个角色**，在第十三章撞车消解时被复用：谁来拍板让路。
- 五光扫面是第十二章"定题"四步里的第三步。
- 第二十一章组织场景里，主持人角色建议由人承担、系统做记录与提醒。

## 待校准与待补

1. 六条经典序列是既有资产，但**缺少"AI 协作序列"**（跟 AI 一起决策时该怎么排），待补。
2. 主持人由人还是由系统承担，本章倾向"人做主持人、系统做记录"，组织场景在第二十一章有不同建议，两处口径需统一。
3. "每色停留几分钟"的时长建议，本章没给具体值——不同规模会议差别太大，给死值会误导。

# 第七章 · 🤝 手·五象限：从人到机

## 这一章解决什么

跟 AI 协作时，**调度权到底归谁**。

这一章要解决一个很具体的痛：你跟 AI 来回很多轮，最后说不清到底是谁在主导——你觉得在指挥它，其实你在被它带着走。

## 核心内容

### 一、它管哪一段：人 → 机

第二章五笔账的第四笔：跟 AI 扯半天，不知道该谁干。

这一笔在 AI 时代最普遍。因为它不是"不会用 AI"，是**没分工**。没分工的协作，要么人当打字员（把 AI 当搜索框），要么人当观众（AI 说啥是啥）。

### 二、它的内部构造：五个象限

按"人掌握多少信息 × AI 掌握多少信息"分：

| 象限 | 人 | AI | 协作模式 | 谁主导 |
|---|---|---|---|---|
| **Q1 高效助理** | 知 | 知 | 人下指令，AI 高效执行 | 人 |
| **Q2 学习伙伴** | 不知 | 知 | AI 主导输出，人学习吸收 | AI |
| **Q3 共创伙伴** | 半知 | 半知 | 人给种子，AI 发散，共同筛选 | 共担 |
| **Q4 共创导师** | 知 | 不知 | 人外化隐性知识，AI 结构化 | 人 |
| **Q5 未知探索域** | 不知 | 不知 | 象思维先行，共同探索 | 共担（象思维引路） |

#### 君臣佐使的对应

这套分法在中国传统里有个现成的词：**君臣佐使**（中药配伍）。

- **君**（主攻）= Q4 共创导师：你知道 AI 不知道，你来定方向
- **臣**（补盲）= Q3 共创伙伴：双方各补一块
- **佐**（反对）= Q2 学习伙伴：AI 知道你不知道，它来补你的盲区
- **使**（对焦）= Q1 高效助理：把方向变成具体动作

**"佐"这个位置值得单独说。** 佐药在方子里是干什么的？是制约主药之偏的。也就是说，**它的职责是反对**。

人跟 AI 协作时，最缺的就是"佐"——因为 AI 天然迎合你。你说什么它都说有道理，然后在这个基础上展开。**一个不会反对你的协作者，是危险的。**

### 三、诊断三问（30 秒定位）

每次协作前，先答三句：

1. **我掌握多少信息？**（高：目标清楚、有步骤、有背景／中：有大方向，细节缺／低：完全陌生）
2. **AI 掌握多少信息？**（高：有数据、有案例、有文档／中：有通用知识，具体信息不足／低：完全陌生）
3. **最优分工是什么？**（交叉定位，选模式）

### 四、一条硬判定：当且仅当 Q5，人不可替代

这是本章最重的一句，也是全书关于"人还有没有用"的唯一回答。

**Q1 到 Q4，都有模型可循，AI 通常比人强：**

- Q1：指令清楚，AI 执行得又快又准；
- Q2：AI 知道你不知道的，它讲给你听，比你自己查快；
- Q3：发散和组合，AI 的广度远超个人；
- Q4：你有经验它没见过——但**一旦你把经验说出来，结构化和规模化它做得比你好**。

**只有 Q5 不一样**：人和 AI 都不知道。这时候没有模型可循，没有先例可检索，唯一的出路是**取象**——而取象是人的能力（第四章）。

所以：

> **人的不可替代性，不在于知道得更多，也不在于算得更快，而在于能在谁都没有答案的地方，看出这件事"像什么"。**

请注意"当且仅当"这四个字的分量：**Q1 到 Q4 你跟 AI 硬拼，是找死；Q5 你让给 AI，是让出了最后一块阵地。**

### 五、失败模式

| 失败模式 | 表现 | 代价 | 修法 |
|---|---|---|---|
| **全程 Q1** | 把 AI 当打字机，只让它执行 | 浪费了它 90% 的能力 | 遇到模糊问题，先问"这算哪个象限" |
| **全程 Q3** | 什么都"一起想想" | 假共创：你在等它给答案，它在等你给方向 | 先诊断再进 |
| **不敢进 Q4** | 不敢说"这个我知道你不知道" | 你的经验白白流失 | 你的隐性知识是资产，说出来它才能帮你放大 |
| **在 Q2 装懂** | 不懂还下指令，把它带沟里 | 输出质量全废 | 不懂的时候，就把主导权交出去 |
| **没有"佐"** | 它一直顺着你说 | 你在被迎合，不是被协作 | 显式要求它反对你 |

最后一条在《象与模》里有个更狠的说法：**给 AI 也配一个"佐"**。因为 AI 天然迎合，你必须显式给它一个反对位。

### 六、三记号法

协作时把产出标上记号，一眼看清分工：

- **[AI]** = 这部分由 AI 主导
- **[人]** = 这部分必须由人定
- **[⇄]** = 需要来回几轮共同定

示范：

```
这份方案的市场数据部分 [AI]，
定价策略 [⇄]，
最终拍板上不上 [人]。
```

就这么一句，协作效率能翻倍——因为**分歧往往不在内容，在对"谁说了算"的理解不一致**。

## 本章操作件

### 30 秒象限诊断卡

```
【这件事，我掌握多少？】 □高 □中 □低
【AI 掌握多少？】        □高 □中 □低
【所以是】  □Q1高效助理 □Q2学习伙伴 □Q3共创伙伴
           □Q4共创导师 □Q5未知探索域
【主导权】  □我  □AI  □共担
【"佐"位】  我要求它在这一点上反对我：______
```

### 三记号标注模板

把你的任务拆成三到五行，每行标一个记号：

| 任务环节 | 记号 | 理由 |
|---|---|---|
| | [AI] / [人] / [⇄] | |

**检查线**：如果整张表全是 [AI]，你把自己摘出去了；如果全是 [人]，你没用上 AI。

### 给 AI 配"佐"的三句话

1. "这个方案你先别认同，找三个可能不成立的地方。"
2. "如果我这个判断是错的，最可能是错在哪一步？"
3. "你现在扮演反对者，专门挑刺，说够三条再停。"

## 跨章接口

- Q5 判定在第四章（象思维）交汇，两章共同支撑"当且仅当 Q5"这个论断。
- 象限定位是 S6（任务执行）和 S7（系统规划）的入口，第十一章路由会用到。
- 三记号法是第二十二章"白箱包黑箱"的素材——它让"谁干了什么"变得可审计。
- "给 AI 配佐"这个动作，在第二十二章会再出现一次：白箱包不住判断对错，所以要显式设反对位。

2. "当且仅当 Q5"是强论断，目前只在三个案例上验证过，其中一个案例的 Q5 判定有争议。
3. 君臣佐使的对应（君=Q4、臣=Q3、佐=Q2、使=Q1）是本书的推演，**不是既有资产的原文**，需标注这是本书的解读。

# 第八章 · 🔄 血·知行合一：从做完到留下

> **本章是全书的核心章。如果只读一章，读这一章。**

## 这一章解决什么

让"做完了"不等于"结束了"。

前四个引擎决定这一次做得好不好。这个引擎决定**下一次的起点在哪**。

没有它，龙心OS 只是一个好用的工具箱；有了它，它是一个会长的东西。

## 核心内容

### 一、它管哪一段：做完 → 留下

第二章五笔账的第五笔，也是全书最贵的一笔。

前面说过为什么最贵：**不沉淀，前四笔的错误会原样重犯**。你今年踩的坑，明年换个场景还会踩，因为系统里没有任何东西在提醒你。

这一章要给你的是一套**可执行的沉淀机制**，而不是一句"要记得复盘"。

### 二、为什么是血，而且它跟其他四个不一样

其他四个引擎是**器官**：心、脾、眼、手，各管一段，各有一块地盘。

**血不是器官，是循环系统。它流过所有器官。**

这个区别很重要：

- 心、脾、眼、手都有"不归我管"的东西；
- **血没有**——任何器官工作过的地方，血都要流过一次。

这就是为什么它在五个引擎里的符号是 🔄，而且标注"贯穿三层"。你做了一次象思维，血要流过去；你做了一次五色光，血要流过去；你跟 AI 协作了一轮，血也要流过去。

**判断一个系统有没有血，只看一件事：做完之后，有没有东西自动留下来。**

### 三、三阶段转化：表示空间 → 压缩 → 泛化

这是它的操作主线，来自王阳明的"知行合一"，用 AI 表示学习（Representation Learning）的技术逻辑重新实现了一遍。

```
表示空间（标签化拆解） → 压缩（核心化提炼） → 泛化（场景化落地）
```

#### 阶段一：表示空间——这次到底发生了什么

**核心问题**：把完整经验摊开，找到关键转折点。

要记三样：

1. **用了哪些引擎**：心有没有产生洞察？脾学了什么？眼走了哪几光？手在哪个象限？
2. **关键转折点是哪一刻**：突然理解的那一下、想法改变的那一下、决策掉头的那一下。
3. **完整叙述**：三到五句话，把过程说清楚。

**及格线**：能指出关键转折点是哪一刻。
**常见不合格**：写成流水账——"先做了 A，然后做了 B，最后做了 C"。这不是表示空间，这是会议纪要。

#### 阶段二：压缩——最精华的是什么

**核心问题**：一句话，不超过 30 字，而且可以迁移。

要出三样：

1. **核心洞察**（≤30 字）：必须是**可迁移的**，不能是具体情境。
2. **象征符号**（一个词或一个意象）：记忆锚点。以后看到这个词，就能想起整个洞察。
3. **与哪个引擎/已有认知关联**：这个洞察跟什么产生了共鸣。

**及格线**：一句话 ≤30 字，且不是具体情境的复述。
**常见不合格**：写成总结——"本次会议就 X 问题达成 Y 共识"。总结是压缩的反面，总结是保留信息，压缩是丢弃信息只留精华。

**关于象征符号**：这不是文学装饰。它的作用是**给洞察一个能被调用的把手**。人的记忆不是按逻辑索引的，是按意象索引的。三年后你不会记得那句 30 字的洞察，但你会记得"空杯盛茶"这四个字，然后整件事就跟着回来了。

#### 阶段三：泛化——还能用在哪

**核心问题**：这个洞察，在三个别的场景里怎么用。

要出三样：

1. **三个具体场景**：必须具体到能操作，不是"可用于管理""可用于沟通"这种。
2. **系统进化建议**：龙心OS 哪里可以升级？要不要改 Skill？要不要加规则？
3. **存入决策**：进 Obsidian 吗？进 IMA 吗？要不要更新长期记忆？

**及格线**：三个场景具体可执行。
**常见不合格**：写成"可广泛应用于各种场景"——这不是泛化，这是没想。

#### 三阶段及格线总表

| 阶段 | 要回答 | 及格线 | 常见不合格 |
|---|---|---|---|
| 表示空间 | 这次到底发生了什么 | 能指出关键转折点是哪一刻 | 写成流水账 |
| 压缩 | 最精华的是什么 | 一句话 ≤30 字且可迁移 | 写成总结 |
| 泛化 | 还能用在哪 | 三个具体场景，不是三类 | 写成"可广泛用于……" |

### 四、标准沉淀卡

这是全书唯一的沉淀格式，五个引擎共用：

```
【本次引擎】用了哪些引擎（配方名）
【核心洞察】一句话，≤30 字
【象征符号】一个词或一个意象
【泛化场景】
  ① 具体场景一
  ② 具体场景二
  ③ 具体场景三
【系统进化】具体升级点，或"暂无"
【入库】Obsidian：是（路径）/ 否
```

**"系统进化"那一栏最容易被跳过，也最不该跳过。** 它问的是：这次的经验，能不能让系统本身变好一点？能，就写下来；不能，写"暂无"。

这一栏是"自我进化"四个字的落点——**每一次沉淀，都是一次给系统打补丁的机会。**

### 五、三向同步：东西存哪儿

沉淀卡不能只存一处。三处各有分工：

| 端 | 角色 | 存什么 |
|---|---|---|
| **Obsidian** | 主知识库 | 完整沉淀卡、进化日志、双向链接 |
| **WorkBuddy** | 工作记忆 | 每日日志（append-only）、长期记忆、项目状态 |
| **IMA** | 移动端 | 一句话洞察 + 象征符号（手机能看） |

为什么非要三处？

- **只存一处，会丢**（硬盘会坏、账号会变、工具会停）；
- **三处同步 = 天然备份**；
- 更重要的是**场景全覆盖**：桌面（Obsidian）、工作现场（WorkBuddy）、手机（IMA）。你在车上想起一句话，能立刻记到 IMA；回家再补进完整卡。

### 六、为什么它是心脏本身

回到卷首那句话：**不是工具箱，是有机体。不是被调用，是自己跳动的。**

工具箱和有机体的分界，就在血。

- 工具箱里每把工具都好，但你得**自己记得**什么时候用哪把；
- 有机体不用记——**血自己在流**。

这就是为什么第四编要用六章讲"自动触发"：如果沉淀还得靠你记得喊一声，它就不会发生。**默认动作，才是真动作。**

再往前一步：

> **前四个引擎决定这一次做得好不好，血决定下一次的起点在哪。**

一个系统有没有"会进化"这个属性，全看这一条。

### 七、一段必要的澄清：上下文窗口不是记忆

现在很多人觉得"记忆问题已经被大模型解决了"，理由是上下文窗口越来越大。**没有解决。**

上下文窗口是**桌面**——你可以把很多文件摊开，但一关机就清空。记忆是**书架**——放上去就在那儿，下次直接抽出来。

这个区别还有第二层，更重要：

| 层次 | 记住什么 | 谁在做 |
|---|---|---|
| **第一层：个性化记忆** | 你的偏好、你的历史 | 大多数 AI 产品都在做 |
| **第二层：机构知识记忆** | 从经验里提取的教训、领域模型 | **几乎没人做** |

第一层让你不用重复介绍自己。第二层让你**不重复犯同一个错**。

血要解决的是第二层。所以它的产出不是"记住了什么"，是**"下次遇到同类事，起点在哪"**。

### 八、它的失败模式

| 失败模式 | 表现 | 修法 |
|---|---|---|
| **只总结不提炼** | 卡上写满了过程，没有那句 ≤30 字 | 强迫自己先写那句话，再写别的 |
| **只提炼不泛化** | 有洞察，但没有三个场景 | 泛化想不出三个，说明洞察还不够抽象 |
| **只泛化不入库** | 想得挺好，没存下来 | 入库是动作，不是想法 |
| **入库了永不回看** | 库越来越大，从没打开过 | 固定回看动作（周/月），否则库就是坟场 |
| **沉淀了错的** | 一个错误判断被当成经验存下来 | **沉淀卡必须带"事后判定"** |

最后一条最危险，也最少人提：

> **错误的洞察被沉淀下来，只会让你更熟练地犯错。**

所以沉淀卡在入库时，必须留一个"事后判定"字段——过一段时间回来看，这个洞察当时对不对。**不对的，要改，不是删。** 删了等于没学过，改了才知道自己当时错在哪。

## 本章操作件

### 标准沉淀卡模板（可直接复制）

```

【核心洞察】（≤30 字，必须可迁移）
【象征符号】

【系统进化】

```

# 第九章 · 中枢不干活

## 这一章解决什么

把"1"的职责边界划清楚。

龙心OS 是 1+5：1 是总智能体（中枢），5 是五个引擎。**最危险的事，是中枢忍不住自己干活**——一旦它开始产出内容，它就变成了第六个引擎，五引擎的分工体系立刻崩塌。

这一章讲清楚：中枢做什么、不做什么、以及怎么判断它越界了。

## 核心内容

### 一、中枢只做四件事

| 步 | 名称 | 干什么 | 产出 |
|---|---|---|---|
| 1 | **感知** | 这段对话在发生什么 | 一组信号 |
| 2 | **识别** | 它属于哪类场景 | S0–S9 中的一个 |
| 3 | **路由** | 该派谁，派几个 | 引擎组合 |
| 4 | **宣告** | 告诉你我派了谁、为什么 | 一句话声明 |

就这四件。**没有第五件。**

#### 感知：不是读关键词，是读信号

感知要抓的东西分三类：

- **输入形态**：一句话？一份长文？一个链接？一个文件？
- **任务动词**："帮我看看这个" 和 "帮我整理一下"，指向完全不同的引擎。
- **上下文状态**：上一轮在做什么？已经用了几个引擎？有没有新信息产生？

关键词只是其中很小一部分，而且是最不可靠的一部分。第十六章会讲为什么。

#### 识别：归到 S0–S9

场景编号沿用既有体系（S0 简单问答到 S9 系统升级），第十章给完整矩阵。

#### 路由：派谁，派几个

这里有个既有设计叫**分层动员**——不是所有任务都要全员出动：

| 层级 | 动员范围 | 适用 |
|---|---|---|
| **轻载** | 单引擎 | 简单问答、快速检索 |
| **标准** | 2 引擎 + 中枢 | 一般任务、分析建议 |
| **深度** | 全部 5 引擎 + 扩展引擎 | 复杂决策、架构设计、创作 |

**最小可用原则**：能用两个引擎解决，就不要上三个。全员出动看着隆重，实际是浪费——而且上得越多，出错的机会越多。

#### 宣告：必须说破

这一步最容易被省掉，也最不该省。

宣告的标准句式：

> "我判断这是 S4（分析决策），派五色光走完整序列，因为你有三个选项需要权衡。"

**为什么必须宣告？**

因为不宣告的调度就是黑箱。用户不知道系统为什么这么做，就没法纠正；**没法纠正的系统，不可信。**

这是第二十二章"白箱包黑箱"的第一层，也是第十九章四条护栏里的第一条。

### 二、它不做的事

| 不做 | 原因 |
|---|---|
| **不执行** | 执行是龙爪OS 的事，心脏不搬东西 |
| **不产出内容** | 一旦产出，它就变成第六个引擎 |
| **不评判对错** | 它判断"该派谁"，不判断"这个结论对不对" |
| **不替用户做决定** | 它给方案，决定权永远在人 |

**最后一条是红线。** 中枢可以建议，可以说"我倾向于 A，理由是……"，但不能替你拍板。

### 三、完整的调度协议（八步）

既有设计里有一份八步协议，比本章的"四件事"更工程化。两者不冲突：四件事是**职责边界**，八步是**执行流程**。

```
1. 判断任务类型（8 类场景评分）
2. 按分层动员规则激活引擎（轻载/标准/深度）
3. 查询龙脑OS 获取推荐模型（选刃决策树）
4. 调用引擎执行
5. 分发到龙爪OS 执行工作流
6. 组织治理层（瓶颈诊断 → 压缩策略 → 授权）
7. 结果整合输出
8. 异常时自动降级
```

**第 3 步值得展开**：中枢会去龙脑OS（模型库）查"这个场景该配哪个思维模型"。这是"1+5"之外的一层，本书不展开——你只需要知道：**中枢不自己想模型，它去查。**

### 四、降级：出错的时候怎么办

第 8 步是整套系统里最诚实的一步：**承认它会失败，并且提前安排好退路。**

| 故障 | 降级动作 |
|---|---|
| 某个引擎调用失败 | 按备选映射切换到备选引擎 |
| 龙脑OS 不可用 | 用内置基础模型兜底（MECE/第一性原理/逆向思维/系统思维/概率思维） |
| 龙爪OS 不可用 | 跳过执行，直接输出模型推荐 |
| **所有引擎都失败** | 返回"处理失败，建议人工介入"，**并附上已收集的部分结果** |

最后一行是设计里最讲究的一处：**失败也要带着已有的东西失败**。不是甩一句"出错了"，是把走到一半的成果交出来，让人能接着干。

这一条跟第十七章的护栏思路是同一条：**出错不可怕，出错之后什么都不剩才可怕。**

### 五、怎么判断中枢越界了

给你三条自查：

1. **它开始长篇大论地产出内容** → 越界了。它应该派活，不是干活。
2. **它替你做了决定** → 越界了。它可以建议，不能拍板。
3. **它不告诉你它派了谁** → 越界了。宣告是义务，不是恩赐。

## 本章操作件

### 中枢职责边界表

| 它做 | 它不做 | 做了就是越界 |
|---|---|---|
| 感知信号 | 执行任务 | 它开始自己写方案正文 |
| 识别场景 | 产出内容 | 它绕过引擎直接给结论 |
| 路由派谁 | 评判对错 | 它说"这个结论是对的"（它没这个资格） |
| 宣告理由 | 替人决定 | 它说"就这么定了" |

### 宣告句式模板

```
我判断这是 S__（场景名），
派 ________（引擎）走 ________（序列/深度），
因为 ________________（证据）。
```

**"因为"那半句不能省。** 没有理由的宣告，等于没宣告。

### 分层动员速查

| 任务分量 | 动员 | 例子 |
|---|---|---|
| 一句话能答 | 轻载（不启动引擎） | "今天几号" |
| 需要查一查 | 轻载（单引擎） | "这个概念什么意思" |
| 要分析一下 | 标准（2 引擎） | "帮我看看这份材料" |
| 要做决定 / 要创造 | 深度（多引擎） | "我们要不要进入这个市场" |

## 跨章接口

- 感知、识别、路由、宣告这四步，分别在第十、十一、十二、十三章展开；宣告在第十九章（护栏）和第二十章（日志）里再次出现。
- 分层动员是第十三章"最小可用原则"的机制化版本。
- 降级机制是第十七章"可降级"护栏的技术实现。
- "查询龙脑OS 选模型"这一步本书不展开，龙脑OS 是另一套系统。

# 第十章 · 场景识别矩阵

## 这一章解决什么

把"这算什么情况"从直觉，变成一张可以打分的二维表。

中枢的第二步是"识别"，识别靠的就是这张矩阵。**没有矩阵的识别，就是拍脑袋**——而拍脑袋装在中枢里，比没有中枢更危险（因为它会让错误看起来很有条理）。

## 核心内容

### 一、既有资产：S0–S9

场景编号不是本书发明的，是系统里跑了两年多的既有编号。**本书只扩展，不重编**——重编一次编号，所有历史日志和案例就全废了。

| 场景 | 识别特征 | 自动路由 | 声明方式 |
|---|---|---|---|
| **S0 极简问答** | 单句直接问题、闲聊、确认 | 直接回答，不启动引擎 | 静默 |
| **S1 信息查询** | "是什么""告诉我"、定义查询 | 知识学习（浅层） | 静默 |
| **S2 深度理解** | 提供文章、要求深入理解 | 知识学习 → 象思维 → 知行合一 | 声明 |
| **S3 创新突破** | 全新问题、0→1 需求 | 象思维主导 | 声明 |
| **S4 分析决策** | 多选项、需权衡 | 五色光思维 | 声明 |
| **S5 重大决策** | 战略级、影响深远 | 全系统 | 声明 |
| **S6 任务执行** | 明确指令、直接执行 | 人机协同 | 静默 |
| **S7 系统规划** | 项目规划、任务分工 | 人机协同 + 五色光 | 声明 |
| **S8 修行文化** | 心文化、传统智慧 | 象思维 + 知识学习 | 声明 |
| **S9 系统进化** | 龙心OS 自身升级 | 知行合一主导 | 声明 |

**"声明方式"这一列很关键。** 静默的意思是：系统做了，但不告诉你。S0/S1/S6 是静默——因为这些场景启动引擎是常识性的，说出来反而啰嗦。

S2 到 S5、S7 到 S9 必须声明——因为这些判断**可能错**，错了你要能发现。

### 二、本书新增：五维特征打分

S0–S9 解决的是"归到哪一类"，但它有个问题：**分类靠的是特征描述，而描述是模糊的**。"多选项、需权衡"——几个算多？

所以本书在分类之上，加了一层**打分**。五维，各 0–2 分：

| 维度 | 0 分 | 1 分 | 2 分 | 指向引擎 |
|---|---|---|---|---|
| **未知度** | 答案已在已有知识里 | 有一部分现成的 | 谁都不知道 | 🐉 心 |
| **决策度** | 只需执行，不用选 | 有选择但不大 | 要在多面中取舍 | 🌈 眼 |
| **协作度** | 人独立完成 | AI 帮忙查查 | 需 AI 深度参与 | 🤝 手 |
| **摄入度** | 不用看新材料 | 要看一点 | 有一大份材料要消化 | 📚 脾 |
| **沉淀价值** | 用完即弃 | 可能有用 | 值得留下 | 🔄 血 |

**五维跟五引擎一一对应。** 这不是巧合——维度是从"谁负责"反推出来的：负责这件事的引擎，就是这一维该打高分时该派的引擎。

### 三、怎么打、怎么用

**打分规则**：

- 每维 0/1/2 分，五维合计 0–10 分；
- **合计 ≥3 分，且至少有一维 ≥2 → 触发**；
- **合计 ≥5 分 → 触发，并建议组合**（不止一个引擎）；
- 五维全 0 → 不启动任何引擎（L0 静默）。

**为什么要"至少一维 ≥2"这个附加条件？**

因为五个维度各打 1 分，加起来 5 分，看着不低，但**没有任何一件事是真正突出的**——这种通常是闲聊或者泛泛的想法，不值得启动引擎。

**举例**：

| 输入 | 未知 | 决策 | 协作 | 摄入 | 沉淀 | 合计 | 判定 |
|---|---|---|---|---|---|---|---|
| "帮我看看这份 30 页的报告" | 0 | 0 | 0 | 2 | 1 | 3 | 触发 → 脾 |
| "我们要不要进入这个市场" | 1 | 2 | 1 | 1 | 2 | 7 | 触发，组合 → 眼+心+血 |
| "今天天气怎么样" | 0 | 0 | 0 | 0 | 0 | 0 | 不触发 |
| "帮我改个错别字" | 0 | 0 | 1 | 0 | 0 | 1 | 不触发（低于阈值） |

### 四、打分不是一次性的

这是本节最实用的一点。

**对话进行到一半，五维分数会变。** 比如一开始是"帮我看看这份报告"（摄入=2），看着看着，报告里暴露了一个谁都没想到的问题——**未知度突然从 0 变成 2**，这时候中枢应该升档，把心也派进来。

反过来也会发生：本来以为是重大决策，聊了两句发现只是确认个信息——降档。

**升档和降档都必须宣告改判理由**：

> "看到这里，我判断未知度升高了（报告里这个数据反常），所以补派象思维。"

改判不宣告，用户会以为系统一开始就想清楚了，实际上是走了弯路——**这也是一种黑箱**。

### 五、矩阵跟五笔账的关系

有人会问：第二章的五笔账和本章的五维打分，是不是重复了？

不是。它们是**同一件事的两面**：

- **五笔账**看的是"漏在哪"——是**损失视角**，用来诊断；
- **五维打分**看的是"这件事长什么样"——是**特征视角**，用来路由。

五笔账告诉你"你老在第五笔上漏"，五维打分告诉你"这次这笔该不该管"。

## 本章操作件

### 五维打分卡

```
【输入】________________（用户原话或材料描述）

【打分】
  未知度（谁都不知道？）        □0 □1 □2
  决策度（要在多面中取舍？）    □0 □1 □2
  协作度（需 AI 深度参与？）    □0 □1 □2
  摄入度（有大份材料要消化？）  □0 □1 □2

  合计 ____

【判定】

  □ 合计 ≥3 且有一维 ≥2 → 触发，派：______

```

**样例二：S4 分析决策**

# 第十一章 · 路由四问与决策树

## 这一章解决什么

给你一个不用背矩阵也能用的路由方法。

上一章的五维打分很准，但它有个问题：**你没法在心里面打五个数再决定**。真到用的时候，人需要的是几句能默念的话。

这一章给四问。问完，该派谁就出来了。

## 核心内容

### 一、路由四问

| # | 问 | 答"是" → 派谁 | 答"否" → |
|---|---|---|---|
| ① | 答案在不在已有知识里？ | **不在** → 🐉 心·象思维<br>**在** → 📚 脾·知识学习 | — |
| ② | 要不要做决定、有没有多面？ | **要** → 🌈 眼·五色光 | 跳过 |
| ③ | 要不要 AI 参与、谁掌握信息？ | **要** → 🤝 手·五象限 | 跳过 |
| ④ | 做完了要不要留下资产？ | **要** → 🔄 血·知行合一 | 跳过 |

**四问是并联，不是串联。** 这是最容易搞错的地方。

不是"问完第一问再问第二问"，是**四个问题同时问，命中哪个派哪个**。一次对话可能同时命中两个、三个，命中几个就派几个。

### 二、四问与四个引擎的对应

注意：四问对应的是**四个**引擎，不是五个。

第一问是双向的（在/不在 → 脾/心），所以实际上覆盖了五个引擎：

```
                  ┌─ 不在 → 🐉 心（取象）
① 知识在不在？───┤
                  └─ 在   → 📚 脾（消化）
② 要做决定吗？────── 要  → 🌈 眼（五光扫面）
③ 要 AI 参与吗？──── 要  → 🤝 手（分象限）
④ 要留下吗？──────── 要  → 🔄 血（沉淀）
```

**为什么"要留下吗"也要问？**

因为它不是默认"要"的。有很多事做完就完了，不值得沉淀——比如"帮我改个错别字"。硬要给这种事做沉淀卡，是在制造垃圾。

但反过来，第十七章会讲：**有一类情况，不管你答不答"要"，系统都会默认留下**（L3 元触发）。这是两套机制的衔接点，别在这里搞混——四问是**你手动判断**用的，元触发是**系统自动执行**用的。

### 三、完整决策树

```
输入进来
  │
  ├─ 五维全 0？ ── 是 ──→ 【L0 静默】直接回答，不启动引擎
  │
  └─ 否
      │
      ├─ ① 知识在不在已有里？
      │     ├─ 不在 → 🐉 心（S3 创新突破 / Q5）
      │     └─ 在   → 📚 脾（S1 查询 / S2 深度理解）
      │
      ├─ ② 要做决定、有多面？
      │     └─ 要   → 🌈 眼（S4 分析 / S5 重大）
      │
      ├─ ③ 要 AI 参与？
      │     └─ 要   → 🤝 手（S6 执行 / S7 规划）
      │
      └─ ④ 做完要留下？
            └─ 要   → 🔄 血（S9 进化 / 任何场景收尾）
```

**四条分支可以并行命中。** 命中两条以上，按顺序原则排队（第十三章）。

### 四、兜底规则：四问全否 → 不启动

这条规则比四问本身更重要。

**四问全否，说明这件事不需要引擎。** 它是闲聊、是简单查询、是一次性动作。这时候启动任何引擎都是浪费，而且是骚扰。

这就是为什么第十四章要把 **L0 静默定为默认值**——系统的默认状态是"什么都不做"，只有被证据推动了才动。

**宁可少触发，不可乱触发。**

### 五、三个判例

#### 判例一：一句话查询

> "知行合一是什么意思？"

① 在已有知识里 → 脾（浅层）；② 不做决定 → 否；③ 要 AI 参与？边缘；④ 不用留下 → 否。
**结论**：脾浅层回答，静默执行，不声明。

#### 判例二：一份材料

> "帮我看看这份三十页的行业报告。"

① 在（材料里）→ 脾；② 暂时不做决定 → 否；③ 要 AI 参与 → 手（Q2 学习伙伴：它读得快你来审）；④ 值得留下 → 血。
**结论**：脾 + 手 + 血。声明："我判断这是 S2，派知识学习消化材料，人机协同按'学习伙伴'象限分工——我读你审，最后留一张卡。"

#### 判例三：一个没见过的问题

> "我想做一件现在市场上没有的东西，不知道从哪下手。"

① **不在**已有知识里 → 心（取象）；② 还不到做决定 → 否（别急）；③ 要 AI 参与，但**你不知道的比它多** → 手（Q4 共创导师：你说经验它结构化）；④ 要留下 → 血。
**结论**：心 + 手(Q4) + 血。**注意这里没有眼**——还没到权衡的时候，过早开五色光会把一个原创问题压成一个选择题。

第三个判例是全书最重要的一处的伏笔：**顺序错了，比没做更糟。** 第十三章讲这个。

# 第十二章 · 定题：最重要的产出是一个真问题

## 这一章解决什么

把"扔一堆材料给 AI，让它给个结论"这个最普遍的错误用法，换成"扔一堆材料，先让它问出真问题"。

这一章是全书第二支柱。如果说"自我进化"是龙心OS 的价值所在，那"定题"就是它**最核心的能力**。

因为一件很硬的事实：

> **AI 时代，解决问题正在变便宜，定义问题正在变贵。**

## 核心内容

### 一、为什么定义问题比解决问题难

解决问题有路径可循：输入 → 方法 → 输出。你甚至可以把路径外包出去，给人或者给 AI。

**定义问题没有路径。** 它要求你先判断一件事：**这到底是个什么事？**

这一步的难点在于，材料不会自己告诉你它是什么。三十页报告摆在你面前，它不会说"我的核心问题是 X"。你得自己看出来。

而且更难的是：**AI 最擅长 solve，不擅长 find。**

- 给它一个清楚的问题，它经常比人强——检索、比较、推演、成文，样样都快；
- 让它自己找问题，它给你一堆**正确的废话**——"如何提升组织效率？""如何实现数字化转型？"。

这些不是错话，是废话。它们正确到无法反驳，也正确到无法执行。

**所以人（和调度系统）的位置在 find 端，不在 solve 端。**

### 二、定题不是一个引擎的活，是三引擎接力 + 中枢宣告

这是本章最关键的一处修正。

很多人（包括最初的我）以为定题是某个引擎的事——"让象思维定题"或者"让知识学习定题"。**都不对。**

定题是四个步骤的接力：

| 步 | 谁 | 干什么 | 产出 |
|---|---|---|---|
| ① 材料变成自己的 | 📚 脾 | 消化：这份材料到底在说什么 | 三判据过关的理解 |
| ② 看出这是件什么事 | 🐉 心 | 取象：它像什么 | 一个象 |
| ③ 检查漏了哪一面 | 🌈 眼 | 五光扫一遍，找被忽略的面 | 漏面清单 |
| ④ 说出这是个什么问题 | 中枢 | 一句话题面 + 三条证据 + 一句宣告 | **题面** |

**少了哪一步都不行**：

- 跳过脾 → 定出来的题只是材料的标题；
- 跳过心 → 定出来的题是常识；
- 跳过眼 → 定出来的题漏了最关键的一面；
- 跳过中枢 → 前面三步各干各的，没有收敛成一句话。

### 三、题面的四个及格标准

一句话题面出来了，怎么判断它及格？四条，全过才算：

| # | 标准 | 自问 | 不合格的样子 |
|---|---|---|---|
| ① | **可判定** | 什么情况算解决了？ | 说不出"解决"是什么样 |
| ② | **有边界** | 它明确不解决什么？ | 包罗万象，什么都想管 |
| ③ | **非复述** | 这是把材料换个说法吗？ | 把标题改成问句 |
| ④ | **有张力** | 问题里有真正的两难吗？ | 不两难——那叫任务，不叫问题 |

**第四条最容易被忽略，也最见功力。**

> **不两难就不叫问题，叫任务。**

"我们要不要开个公众号？"——这是任务，答案是开或者不开，做完就完了。
"我们要做内容，但没人愿意出镜，怎么在不暴露个人的前提下做起来？"——**这才是问题**，因为里面有张力：要做内容 vs 不愿出镜，两个都成立，互相拉扯。

**张力不是麻烦，张力是题目的能量来源。** 一个没有张力的问题，解法是平庸的——因为没有东西需要被权衡。

### 四、三种假问题

AI 最常给的，也是人自己最常犯的：

#### 假问题一：复述型

> "如何提升组织效率？"

把材料标题换成了问句。这类问题的特征是：**你把它改回陈述句，它就是材料的第一句话**。

**破法**：问一句"如果这句话是我没读材料就能说出来的，它就不算题面"。

#### 假问题二：空泛型

> "如何实现数字化转型？"

没有边界，无法判定。什么是"实现"？转到什么程度算实现？

**破法**：加边界——"六个月之内，把三个部门的手工报表合并成一张自动表，这算不算数字化转型的第一步？"

#### 假问题三：伪两难

> "要不要上系统？"

看着像两难（上/不上），其实是假的。**真问题在后面**：上了之后，谁改工作方式？

伪两难的特征是：**两个选项你都能说出道理，但无论选哪个，真正让你睡不着的那件事都没被碰到**。

**破法**：问一句"这两个选项都实现了之后，我原来担心的事解决了吗？"——如果没解决，那你问错了。

### 五、一个现场判例：同一份材料，三种问法

一份材料：某餐饮公司三店经营数据，人效下降 12%，离职率上升，客单价持平。

| 问法 | 题面 | 解法 | 结果 |
|---|---|---|---|
| **复述型** | "如何提升人效？" | 上绩效、加考核 | 三个月后人效反弹，离职率继续涨 |
| **空泛型** | "如何优化组织架构？" | 请咨询公司做方案 | 方案很好，落不了地 |
| **有张力型** | "三个店的人效都在掉，但客流没掉，说明活还是那么多、人却不够了——是活变重了，还是人留不住？" | 先分清楚是哪一个 | 查出来是活变重了：上了外卖之后后厨多了一道工序，没人加编 |

**差别在哪？**

前两种问法，解法都是"往人身上使劲"——考核、架构。第三种问法把矛头指向了"活"，而真凶就在那儿。

**这就是定题的价值：它不改变你的解法能力，它改变你解法打的方向。**

打错方向的努力，越努力越糟。

### 六、失败模式

| 失败模式 | 表现 | 修法 |
|---|---|---|
| **没消化就定题** | 题面 = 材料标题 | 先过第五章的消化三判据 |
| **跳过心直接定题** | 题面是常识 | 问一句"它像什么" |
| **定完题不复检** | 题面漂亮，跟材料对不上 | 拿题面回材料里找三条证据 |
| **把方案当题面** | "要不要上系统" | 问：上了之后谁改工作方式？ |
| **怕有张力** | 把真两难磨平成一个温和的说法 | 张力不是麻烦，是能量 |

# 第十三章 · 组合与顺序

## 这一章解决什么

多个引擎同时命中时，**谁先谁后，撞车了谁让路**。

上一章讲完定题，题面出来了。接下来的问题很实际：五个引擎可能同时想上场，它们能不能一起上？按什么顺序上？如果互相打架怎么办？

这一章给配方、给排序原则、给撞车消解的三招。

## 核心内容

### 一、五种常见配方

配方是既有资产里跑出来的固定组合，直接用，不用每次现想：

| 场景 | 配方 | 说明 |
|---|---|---|
| **深度学习**（S2） | 脾 → 心 → 血 | 先消化，再取象，最后留 |
| **创意创新**（S3） | 心 → 眼（绿+蓝）→ 血 | 先有象，再发散和收险，最后留 |
| **分析决策**（S4） | 眼（完整序列）→ 血 | 五光走完，最后留 |
| **系统规划**（S7） | 心 → 手 → 眼 → 血 | 先定象，再分工，再扫面，最后留 |
| **系统升级**（S9） | 血 → 心 → 眼 → 落地更新 | **血在最前**（见下文） |

**血永远在最后**——除了 S9。

S9（系统升级）是唯一一个血在开头的配方。为什么？**因为那次任务本身就是复盘**。你要升级系统，第一件事是先把"上次留下了什么"翻出来，所以血在最前。

这是一个正式例外，不是笔误。

### 二、三条排序原则

#### 原则一：取象在前

先把象定下来，后面才不跑偏。

**为什么？** 因为象是"这件事到底是什么"的答案。象没定，后面的每一步都在一个模糊的基础上做，越做越偏。

反例最常见：一上来就开五色光分析。五光扫得很全，但扫的是个错误的"这件事"——**方向错了，再全面也没用**。

#### 原则二：决策在后

信息不全就决策，是最大的浪费。

五色光应该在脾（消化）和心（取象）之后开。因为你得先知道"有什么"，才能权衡"选哪个"。

第十一章的判例三就是这个错误：一个还没想清楚的原创问题，过早开五色光，会把它**压成一个选择题**——本来是要发明一个东西，变成在 A 和 B 之间挑一个。

#### 原则三：血永远在最后（S9 例外）

血是收尾，不是开场。

它收的是什么？是前面所有引擎的产出。前面什么都没做，血没有东西可收。

**唯一例外是 S9**：系统升级时，血在最前——因为要先翻旧账。

### 三、撞车消解三法

两个引擎都要上，但资源不够、或者互相打架，怎么办？三招，按顺序用：

#### 招一：降级

**只做浅层。** 两个都要，但各退一步。

例：脾和眼同时命中，材料又多又要决策。降级方案：脾只走前两层（剖析+透视，不做完整五层），眼只走关键三色（白+蓝+黄，不做完整五色）。

#### 招二：串行

**排队，一个做完再下一个。**

例：心和眼都命中。串行方案：心先取象，象出来之后眼再扫面。不要同时——同时的话，眼扫的还是那个没取过象的模糊对象。

**这是最常用的招。** 大多数"撞车"其实是"没排队"。

#### 招三：仲裁

**交给主持人，或者交给人。**

当降级和串行都解决不了——比如两个引擎给出的结论直接冲突——就需要有人拍板。

**仲裁权永远在人手里。** 这是第九章"中枢不替人做决定"那条红线的延伸：中枢可以建议，不能拍板。

### 四、最小可用原则

最后一条，也是最容易被违反的一条：

> **能用两个引擎解决，就不要上三个。**

全员出动看着隆重，实际是浪费。而且**上得越多，出错的机会越多**——每多一个引擎，就多一次误判的可能，多一层需要协调的地方。

第九章的分层动员表（轻载/标准/深度）就是这个原则的机制化。

## 本章操作件

### 配方速查表

| 我要干什么 | 配方 | 备注 |
|---|---|---|
| 读懂一份材料 | 脾 → 心 → 血 | 想讲给别人听就一定要加血 |
| 想个新东西 | 心 → 眼(绿+蓝) → 血 | 别一上来就开完整五色 |
| 做个选择 | 眼（完整序列）→ 血 | 五光缺一不可 |
| 规划一件事 | 心 → 手 → 眼 → 血 | 先定象，再分工 |
| 升级系统本身 | 血 → 心 → 眼 → 更新 | **血在前，这是例外** |

### 撞车消解决策表

| 情况 | 用哪招 | 具体做法 |
|---|---|---|
| 两个引擎都要，但时间/资源不够 | **降级** | 各走浅层，够用就行 |
| 两个引擎有依赖（一个的产出是另一个的输入） | **串行** | 排队，先出产出再进下一个 |
| 两个引擎结论直接冲突 | **仲裁** | 交给人拍板，系统只负责把冲突摆清楚 |
| 三个以上引擎同时命中 | **先拆任务** | 一次上三个，通常说明任务该拆 |

### 排序自检三问

开工前问三句，全答"是"才动手：

1. **象取了吗？**（没有 → 先取象，别急着分析）
2. **信息够了吗？**（不够 → 先消化，别急着决策）
3. **血留到最后了吗？**（S9 除外；没有 → 调整顺序）

- 配方是第二十章（个人一天）和第二十一章（组织场景）的组织骨架。
- 撞车消解里的"仲裁"，复用了第六章五色光的**主持人**角色——谁来拍板让路。
- 最小可用原则与第九章的分层动员是同一件事的两种表述。
- S9 血在最前这个例外，是第十七章 L3 元触发的预演：那一次任务本身就是沉淀。

## 待校准与待补

1. **五种配方是既有资产，但"S9 血在最前"这个例外是否需要写成正式条款**，既有文档里没有明确表述，是本书的归纳。
2. 撞车消解三招的优先级（降级→串行→仲裁）是设计值，实战中可能有更优顺序。
3. 排序自检三问只覆盖了三条原则中的三条，**没有覆盖"最小可用"**，待补第四问。
4. 配方表里缺少 S5（重大决策，全系统）和 S8（修行文化）的配方，待补。

# 第十四章 · 为什么关键词匹配不够

## 这一章解决什么

先立靶子。

这一章要把现在这套触发机制的**成绩讲足**，再讲它为什么不够。跳过前半段是不诚实的——这套机制跑了两年多，它解决的问题比它造成的问题多。

但它是**不够**的。后面五章讲的新设计，都是从它这三个病灶长出来的。

## 核心内容

### 一、现在这套是怎么工作的

以知行合一（血）的触发规则为例，它有三层：

#### 第一层：直接触发词（权重 5）

出现下列任一词，**立即触发**：

> 知行合一、自我进化、经验沉淀、三阶段转化、表示空间、压缩、泛化

#### 第二层：场景触发词（权重 4）

| 场景 | 触发词 |
|---|---|
| 深度学习完成 | "总结一下""这次的收获""学到了什么""沉淀一下" |
| 系统升级 | "进化升级""系统迭代""记录下来""存入知识库" |

累积到 3 分触发。

#### 第三层：行为信号（权重 3）

- 检测到 S2/S3/S4/S5/S7/S8/S9 场景完成
- 检测到象思维产生 0→1 洞察
- 检测到"这个我没想到"类新认知

≥2 个信号触发。

#### 现在的智能调度三步法

在更新的版本里，还加了后台静默的三步：

```
Step 1 · 意图扫描：他要结果？分析？决策？学习？执行？还是进化？
Step 2 · 场景归类 + 复杂度评估：对应 S0-S9，评估简单/中等/复杂
Step 3 · 引擎路由：匹配最优引擎组合，简洁声明，执行
```

这套设计已经不只是关键词了——它有意图识别，有场景归类。**这是对的，方向是对的。**

### 二、它的成绩（先讲足）

四条，都是真的：

1. **明确**：什么词触发什么，白纸黑字，不靠猜。
2. **可复现**：同样的输入，同样的触发，不会有玄学。
3. **易调试**：触发错了，改词表就行，不用动架构。
4. **新手可预期**：用户说"知行沉淀"，就一定出沉淀卡。**这种确定性是有价值的**——它让人知道系统在干什么。

这四条，任何新设计都不该丢。

### 三、三个病灶

#### 病灶一：说不出词，就触发不了

这是最根本的一条。

用户不会说"我需要表示空间"。**他只会说："这次挺有意思的。"**

真实场景里的表达，跟词表里的词几乎不重叠：

| 用户实际会说的 | 词表里有的 |
|---|---|
| "这次挺有意思的" | 经验沉淀 |
| "这个我没想到" | 三阶段转化 |
| "等下，我得记一下" | 表示空间 |
| "别让我下次又忘了" | 知行合一 |

指望用户记住词表，是本末倒置——**系统该适配人，不是人适配系统**。

而且更要命的是：**最该沉淀的时刻，用户往往说不出话**。那是一个"啊，原来是这样"的瞬间，人在那个瞬间是安静的，不是在喊口令的。

#### 病灶二：词在，但场景不对，也触发

反过来也成立。

"总结一下"这四个字，出现在一句闲聊里，照样触发。比如："帮我总结一下，你刚才是不是说错了？"

**关键词不分辨语境。** 它只认字，不认这件事是什么。

误触发一次的代价，比漏触发一次大得多——漏触发只是没帮上忙，误触发是**打扰**，而且消耗的是信任。用户通常不会说"你别烦我"，他只会慢慢不用。

#### 病灶三：无法处理组合

关键词是**单点**的：一个词指向一个引擎。

但真实任务往往要两三个引擎。你不会说"请同时启动知识学习和象思维然后知行合一"——你会说"帮我把这份材料吃透，下周要讲"。

这句话里，脾（消化）、手（分工）、血（留下讲稿）全都在，但**没有一个词**。

### 四、所以关键词不是要扔，是要降级

这是本章的结论。

关键词这套东西不该被扔掉，它有明确、可复现、易调试、可预期四条好处。**它应该被降级**：

- 从"主力机制"降为 **L1 显式层**的一部分；
- 从"唯一的触发依据"降为"多种信号中的一种"。

**降级，不是删除。**

下一章讲新的四层设计，关键词在新的架构里有它的位置，只是不再是全部。

### 五、一个反例：什么时候关键词反而更好

不能把这一章写成"关键词一无是处"。

**有一种场景，关键词是最好的：调试和兜底。**

当你明确知道要干什么，说一个词比让系统猜快得多。"知行沉淀"四个字，比等系统打完分再判断，快三秒，而且不会错。

所以新设计里保留了快速口令：

| 口令 | 效果 |
|---|---|
| "全系统启动" | 五引擎全序列 |
| "象感知" | 象思维单引擎 |
| "五色分析" | 五色光完整序列 |
| "深度学习" | 十项认知指令全激活 |
| "象限诊断" | 人机协同象限定位 |
| "知行沉淀" | 立即输出沉淀卡 |
| "三体一心" | 象思维 + 五色光整合 |

**保留它们，是因为人有时候就是想直接说要什么。**

## 本章操作件

### 现有触发规则体检表

给你手上的触发规则（不管是 AI 的还是工作流程的）做个体检：

# 第十五章 · 触发四层：L0 / L1 / L2 / L3

## 这一章解决什么

给自动触发一个总体架构。

上一章讲了现有机制三个病灶。这一章给的是新的四层设计——**这是全书技术含量最高的一节，也是"让系统自己动"这件事的完整答案**。

## 核心内容

### 一、四层总表

| 层 | 名称 | 依据 | 是否宣告 | 典型场景 |
|---|---|---|---|---|
| **L0** | 静默 | 默认不启动任何引擎 | 否 | 闲聊、简单问答 |
| **L1** | 显式 | 用户点名（词或口令） | 是 | "知行沉淀""五色分析" |
| **L2** | 特征 | 场景识别矩阵打分命中 | **是，必须** | 一份长文扔进来 → 脾 |
| **L3** | 元触发 | 任务到达某个状态 | **是，必须** | 决策做完 → 血自动收尾 |

### 二、L0 静默：默认值

**这是全书最重要的一条设计原则，没有之一。**

> **系统的默认状态是什么都不做。只有被证据推动了，它才动。**

为什么这条最重要？

因为自动化的最大风险不是"不够聪明"，是**"太积极"**。一个每句话都要启动引擎的系统，两周之内就会被关掉。

L0 的具体规则：

- 五维打分合计 <3 → 不启动；
- 第十六章讲的负向信号命中任一 → 不启动；
- **不确定 → 不启动**（宁可漏，不可错）。

第三条是态度问题，不是技术问题。**不确定时的默认动作，决定了一个系统的性格。**

### 三、L1 显式：你点名

用户说了词，或者说了口令，就触发。

这一层就是上一章讲的关键词机制**降级之后**的位置。它保留四个好处（明确、可复现、易调试、可预期），但不再是主力。

**L1 必须宣告**——哪怕用户已经点名了，系统也要说一句"收到，派 XX"。这不只是礼貌，是让用户有机会发现"我叫错了"。

**L1 与 L2 可以叠加**：用户点名了，而且特征也一致 → 置信度更高，可以走得更深。

### 四、L2 特征：看这件事长什么样

**这是解决"说不出词就触发不了"的那一层。**

它不看用户说了什么，**看输入长什么样**：

- 一份 30 页的 PDF → 摄入度高 → 脾
- 三个选项摆在一起 → 决策度高 → 眼
- 一个从没见过的问题 → 未知度高 → 心

完整机制在第十六章，本章只讲它在架构里的位置。

### 五、L3 元触发：任务状态触发，不是用户请求触发

**这是四层里最特殊的一层，也是"自我进化"这个卖点的机制落点。**

前面三层的触发条件，都是"用户做了什么"：
- L1：用户说了什么；
- L2：用户给了什么；
- L0：用户什么都没给。

**L3 不一样。L3 的触发条件不是用户的动作，是任务的状态。**

四个元触发点（任一到达即触发血）：

1. **一个完整任务产出并被接受**
2. **出现"这个我没想到"类的新认知**
3. **走完五色光完整序列，或象思维产生了原象**
4. **一个引擎链条跑完**（多引擎配方收尾）

请注意第一条里的"被接受"三个字：**产出不等于完成，被接受才算。** 你生成了一份方案，用户说"不对，重来"——这时候不该沉淀，因为还没完。

完整机制在第十七章。

### 六、降级路径：不确定就往回退

四层不是并列的，它们之间有**降级路径**：

```
L1（点名）  ──确定──→  执行
   │
   └─不确定（点名了但特征不符）──→ 退回 L0，问一句

L2（特征）  ──≥阈值──→  执行
   │
   └─差一点（2-3 分之间）──→ 退回 L0，不硬猜
```

**硬猜是最坏的选择。**

因为硬猜对了，用户觉得理所当然；硬猜错了，用户觉得这系统在乱来。**错误的代价远大于不做的代价。**

### 七、四层跟三个病灶的对应

上一章的三个病灶，四层怎么解决：

| 病灶 | 解决它的层 | 怎么解决 |
|---|---|---|
| 说不出词就触发不了 | **L2** | 不看词，看特征 |
| 词在场景不对也触发 | **L0 + 负向信号** | 默认不动；有否决项 |
| 无法处理组合 | **L2 + 第十三章配方** | 打分 ≥5 就建议组合 |

### 八、一个完整例子

同一天里的四次输入，看看四层怎么工作：

| 输入 | 层 | 判定 | 动作 |
|---|---|---|---|
| "今天天气怎么样" | **L0** | 五维全 0 | 直接答，不启动引擎 |
| "知行沉淀" | **L1** | 用户点名 | 出沉淀卡，宣告 |
| （一份 30 页报告发进来，什么都没说） | **L2** | 摄入度 2 → 3 分 | 派脾消化，宣告 |
| （报告看完，用户说"行，就这个方向"） | **L3** | 任务产出并被接受 | 自动出沉淀卡，宣告 |

**注意最后一行：用户什么都没要求，系统自己动了。** 这就是"自己跳动的"那句话的机制实现。

## 本章操作件

```

【先看 L0】五维合计 <3？ □是→不启动  □否→继续
         负向信号命中？ □是→不启动  □否→继续

【再看 L1】用户点名了吗？ □是→执行并宣告  □否→继续

  □ 出现"这个我没想到"
  □ 五色光走完 / 象思维出原象

  → 任一勾中，触发血

【不确定时】□ 退回 L0，问一句，不硬猜
```

### 四层速查

| 我问自己 | 层 |
|---|---|
| 有没有理由不动？ | L0（默认是不动） |
| 他点名了吗？ | L1 |
| 这件事长得像需要引擎的样子吗？ | L2 |
| 这件事是不是做完了/有产出了？ | L3 |

**顺序不能颠倒**：先看 L0（有没有理由不动），再看 L1，再看 L2。L3 全程监听。

# 第十六章 · L2 详解：不看你说什么，看这件事长什么样

## 这一章解决什么

把自动触发做成可以执行的东西。

上一章给了四层架构，这一章给 L2 的完整机制——**就是你要的那个"不用说出关键词，它自己知道"**。

## 核心内容

### 一、特征信号的四个来源

L2 不看词，看什么？看四样：

| 来源 | 看什么 | 例子 |
|---|---|---|
| **输入形态** | 一段话？一份长文？一个文件？一个链接？ | 30 页 PDF → 摄入度高 |
| **任务动词** | "看看"还是"整理"？"想个"还是"算个"？ | "帮我想个" → 未知度高 |
| **上下文状态** | 上一轮在干嘛？已经用了几个引擎？有没有新东西出来？ | 上一轮刚定完题 → 该进解法了 |
| **产出预期** | 要结论？要过程？要材料？ | "给我个结论" → 决策度高 |

**这四样里，第二样（任务动词）最容易被忽略，也最好用。**

同样一句"帮我看看"，后面跟的东西不同，指向完全不同：

- "帮我看看这个数据对不对" → 白光（事实核验）
- "帮我看看这几个方案选哪个" → 眼（五色光）
- "帮我看看这事儿该怎么想" → 心（取象）

### 二、打分与阈值

五维各 0–2 分（第十章已给完整定义）：

- **合计 ≥3 分，且至少一维 ≥2 → 触发**
- **合计 ≥5 分 → 触发，并建议组合**
- **合计 <3 → 不启动（L0）**

#### 为什么要有"至少一维 ≥2"这个附加条件

因为**五个维度各打 1 分，加起来也是 5 分**——但没有任何一维是突出的。

这种情况通常是什么？泛泛的想法、漫谈、还没成形的念头。**它需要一个引擎，但不知道该派谁。**

这时候正确的动作不是硬派，是**不派**，或者**问一句**。

### 三、负向信号：否决项

这一节是本章最实用的部分，也是第十四章"病灶二"的解药。

**以下任一条命中，直接不触发**，不管打了多少分：

| 否决项 | 说明 |
|---|---|
| **闲聊语气** | "今天挺累的""你说呢"——没有任务 |
| **明确要快** | "快点""简单说""一两句话" |
| **单次问答** | 一问一答就结束的 |
| **已触发过同一引擎，且没有新信息** | 防止在一个引擎里打转 |

第四条特别容易被忽略，却特别常见：**五分钟前刚派过脾，材料没变，又派一次脾**——这是在浪费，不是在帮忙。

#### 否决项怎么用

不是"有否决项就永远不动"，是**"有否决项时，除非用户点名（L1）"**。

L1 可以覆盖否决项——因为用户点名是明确意图，比特征更可靠。

### 四、升档与降档

**打分不是一次性的。**

对话进行中，特征会变：

- 一份报告看着看着，发现里面有个反常数据 → **未知度从 0 升到 2** → 升档，补派心；
- 本来以为是重大决策，聊两句发现只是确认信息 → **决策度从 2 降到 0** → 降档，撤掉眼。

**升档降档都必须宣告改判理由：**

> "看到这里，未知度升高了（报告第 12 页这个数据跟常识不符），补派象思维。"

改判不宣告，用户会以为系统一开始就想清楚了——**这也是一种黑箱**。

### 五、三个完整判例

#### 判例一：长文入 → 脾

**输入**：（发来一份 30 页 PDF，没说话）

| 维度 | 分 | 理由 |
|---|---|---|
| 摄入度 | **2** | 30 页材料 |
| 未知度 | 0 | 材料里有答案 |
| 决策度 | 0 | 没说要决定 |
| 协作度 | 1 | 需要 AI 读 |
| 沉淀价值 | 1 | 可能是有用的 |

**合计 4，有一维 ≥2 → 触发脾（消化）**
**宣告**："我判断这是 S2，派知识学习消化材料——30 页，摄入度满分。你没说要决定什么，所以先不派五色光。"

#### 判例二：多选一 → 眼

**输入**："三个供应商，选哪个？"

| 维度 | 分 | 理由 |
|---|---|---|
| 决策度 | **2** | 三个选项要权衡 |
| 摄入度 | 1 | 要看点材料 |
| 沉淀价值 | 1 | 值得留 |
| 未知度 | 0 | 不是没人知道的事 |
| 协作度 | 0 | 主要是自己定 |

**合计 4，有一维 ≥2 → 触发眼（五色光完整序列）**
**宣告**："我判断这是 S4，派五色光走完整序列，因为你有三个选项在权衡。"

#### 判例三：从没见过的开放问题 → 心

**输入**："我想做一件现在市场上没有的东西，不知道从哪下手。"

| 维度 | 分 | 理由 |
|---|---|---|
| 未知度 | **2** | 谁都没有答案 |
| 协作度 | 1 | 要 AI 参与，但象限是 Q4（他知道 AI 不知道） |
| 沉淀价值 | 2 | 这种洞察必须留 |
| 决策度 | 0 | **还没到做决定的时候** |
| 摄入度 | 0 | 没有材料 |

**合计 5 → 触发并组合：心（取象）+ 手（Q4 分工）+ 血（留下）**
**宣告**："我判断这是 S3，未知度满分，派象思维取象；你掌握的信息比 AI 多，按 Q4 共创导师分工——你说经验它结构化；这个洞察必须留，收尾派知行合一。**先不派五色光**，还没到权衡的时候。"

**第三个判例里"先不派五色光"这句，是本章最值钱的一句。** 打分高了就全派，是新手最常见的问题。

### 六、调阈值

阈值 3 和 5 是设计初值，**不是实测值**。

怎么调？第十九章给完整闭环，这里先给个原则：

- **否决率太高**（用户老说"不用"）→ 阈值调高，或者补否决项；
- **漏触发太多**（事后发现该做没做）→ 阈值调低，或者加正向信号；
- **两者都高** → 不是阈值问题，是**信号选错了**，回去改第一维。

## 本章操作件

### 特征信号全表

**正向信号**（加分）：

| 信号 | 指向 | 权重 |
|---|---|---|
| 长材料（>10 页/长文/文件） | 脾 | +2 摄入度 |
| "是什么""告诉我" | 脾 | +1 摄入度 |
| 多选项 / "选哪个" / "要不要" | 眼 | +2 决策度 |
| "全新的""没见过""从没有过" | 心 | +2 未知度 |
| "帮我做""执行""生成" | 手 | +2 协作度 |
| "要讲给别人""下次还想用" | 血 | +2 沉淀价值 |

**负向信号**（直接否决）：

| 信号 | 例子 |
|---|---|
| 闲聊语气 | "今天好累""你说呢" |
| 明确要快 | "快点""一句两句说完" |
| 单次问答 | 问完就走 |

# 第十七章 · L3 详解：做完就留下

## 这一章解决什么

把"自我进化"从一个卖点，变成一个**默认动作**。

前面所有关于沉淀的道理，如果最后还得靠你记得喊一声，那它就**不会发生**。这一章讲怎么让它自动发生，以及——怎么让它自动发生的时候不烦人。

## 核心内容

### 一、元触发：不是用户请求，是任务状态

前面三层的触发条件，都是"用户做了什么"：

- L1：用户说了什么；
- L2：用户给了什么；
- L0：用户什么都没给。

**L3 不是。L3 的触发条件是任务的状态。**

这个区别很小，但它是整个"自我进化"能不能成立的关键。因为：

> **最该沉淀的时刻，用户往往不会说话。**

那是一个"啊，原来是这样"的瞬间，人在那个瞬间是安静的，不是在喊口令的。等系统去等一句"帮我沉淀一下"，就永远等不到最该沉淀的那一下。

### 二、四个元触发点

任一到达，即触发血：

| # | 触发点 | 判定 | 为什么是它 |
|---|---|---|---|
| ① | **一个完整任务产出并被接受** | 用户说"行""就这个""可以" | 注意"被接受"三个字 |
| ② | **出现"这个我没想到"类新认知** | 用户说了这句，或等价表达 | 新认知是最高价值的沉淀对象 |
| ③ | **走完五色光完整序列 / 象思维产生原象** | 引擎自己报告完成 | 完整走完必有产出 |
| ④ | **一个引擎链条跑完**（配方收尾） | 配方执行完毕 | 链尾不留，前面的都白做 |

#### 关于"被接受"

第一条里的三个字要展开说：**产出 ≠ 完成，被接受才算完成。**

你生成了一份方案，用户说"不对，重来"——这时候**不该沉淀**。因为事情还没完，沉淀的是半成品。

反过来，用户说"行，就这个方向"——**这一刻就是沉淀时刻**。此时此刻的记忆最完整，隔一小时再问，已经忘了一半。

### 三、三级降级：怎么自动才不烦人

这是本章最难也最重要的一节。

**自动沉淀最大的风险，是变成骚扰。** 每做完一件小事都弹一张卡让你填，三天你就烦了。

所以必须有降级。三级：

| 级 | 动作 | 什么时候用 |
|---|---|---|
| **一级** | 自动生成完整沉淀卡并入库 | 大任务、有新认知、用户明确重视 |
| **二级** | 只生成一句话洞察 + 象征符号，问要不要展开 | 中等任务 |
| **三级** | 只在日志记一行"本次可沉淀"，不打扰 | 小任务、日常 |

**怎么自动选级？** 目前按两个粗判据：

- **任务时长**：长任务 → 一级；中等 → 二级；短 → 三级；
- **有没有新认知**：出现"这个我没想到" → 至少二级。

### 四、为什么必须是默认的

一句话回答：

> **靠自觉的沉淀，三个月后执行率趋近于零。**

这不是人的问题，是机制的问题。所有"记得要复盘""记得要记录"的系统，都会死在同一件事上：**它依赖人记起一件不紧急的事**。

而人只会记起紧急的事。

所以沉淀不能是一个"可以做的事"，它得是一个**"默认会发生的事"**。

**默认了，才会发生。**

### 五、沉淀之后：回看才是终点

入库不是终点。

一个只进不出的库，三个月后就变成坟场——东西都在，但没人打开过，等于没有。

所以必须有固定的回看动作：

| 频率 | 时长 | 干什么 |
|---|---|---|
| **每周** | 10 分钟 | 数有几张卡；哪张的"系统进化"栏有内容、去做了吗 |
| **每月** | 30 分钟 | 回填"事后判定"；判定错的**改，不删** |

**"改，不删"这三个字要单独说一遍。**

删掉一条错误经验，等于没学过——下次照样踩。改了，才知道自己当时错在哪。**错误经验的价值，高于正确经验**，只要它被改过。

### 六、一个诚实的提醒：沉淀不等于变对

这里有个必须说破的地方：

> **自我进化进化的是"资产的积累"，不是"判断的正确"。**

系统会越来越会沉淀，但不会因此越来越会判断。**如果沉淀下来的判断本身是错的，系统会让你更熟练地犯错。**

这就是为什么沉淀卡必须带"事后判定"字段——它是唯一能拦住这件事的机制。也是第二十二章（黑箱白箱）里"白箱包不住的那一块"的补法。

### 七、L3 与 L2 的配合

有人会问：L2 已经会派血了（第十章五维里"沉淀价值"那一维），为什么还要 L3？

因为**两者问的问题不一样**：

- **L2 问的是**：这件事值不值得留下？（事前判断，看的是输入特征）
- **L3 问的是**：这件事是不是已经做完了？（事后判断，看的是任务状态）

L2 在开头判断"这事可能值得留"，L3 在结尾判断"好了，现在该留了"。

**两个都要。** 只有 L2 会在事情还没做完时就催你沉淀；只有 L3 会在你根本没意识到该留的时候漏掉。

# 第十八章 · 触发的三大风险与四条护栏

## 这一章解决什么

自动化的阴暗面。

前面四章一直在讲"怎么让它自己动"。这一章必须讲**"它自己动会带来什么祸"**——不讲透这个，系统会在三周内失去信任。

## 核心内容

### 一、风险一：过度触发

**表现**：每句话都启动引擎。

你说"今天天气怎么样"，它也给你打个五维分、派个引擎、宣告一遍。你说"帮我改个错别字"，它给你出一张沉淀卡。

**危害**：不是慢，是**烦**。一个过度触发的系统，比没有系统更累——你不但要干活，还要不停地把它的手拨开。

**解药**：

- **L0 是默认值**（第十五章）：默认不动，只有被证据推动才动；
- **最小可用原则**（第十三章）：能用两个引擎就不要上三个；
- **三级降级**（第十七章）：小事只记日志，不打扰。

### 二、风险二：误触发比不触发更糟

这一条最反直觉，要展开说。

**不触发，只是没帮上忙**——你照常自己干，损失的是本该有的帮助。

**误触发，是打扰 + 消耗信任**。而且它的伤害方式很隐蔽：

> **用户通常不会说"你别烦我"，他只会慢慢不用。**

你甚至收不到投诉。系统会觉得"用户没反馈，说明没问题"，然后继续误触发，直到某天用户把整个功能关掉。

**所以误触发的代价，比漏触发大一个量级。**

**解药**：

- 负向信号否决项（第十六章）：闲聊、要快、单次问答、无新信息，任一命中就不动；
- **不确定 → 退回 L0**，绝不硬猜（第十五章）；
- 用户可以一句"不用"撤销，而且撤销本身被记为负样本（第十九章）。

### 三、风险三：黑箱触发最危险

这是三条里最根本的一条。

**表现**：系统做了调度，但不告诉你它为什么这么做。

**危害**：用户不知道系统为什么这么做，就**没法纠正**。而**没法纠正的系统，不可信**。

举个具体的：系统在你聊一个普通话题时，突然开始走五色光完整序列。你不知道它为什么，只能看着它跑完——跑完了你也不知道它对不对，因为你不知道它基于什么判断的。

**这种时候，系统越聪明，越让人不安。**

**解药**：四条护栏，下面讲。

### 四、四条护栏

| # | 护栏 | 具体要求 | 没有它会怎样 |
|---|---|---|---|
| 1 | **打日志** | 每次触发写明"我调了 X，因为 Y（证据）" | 事后无法复盘 |
| 2 | **可否决** | 用户一句"不用"即可撤销，且被记为负样本 | 用户只能关掉整个功能 |
| 3 | **可降级** | 不确定时退回 L0，绝不硬猜 | 硬猜错了更糟 |
| 4 | **可审计** | 日志可回看、可统计、可据此调阈值 | 系统永远不会变好 |

#### 护栏一：打日志，而且要写"因为"

日志的标准句式：

> **"我调了 X，因为 Y。"**

"因为"那半句不能省。只写"调用了脾"的日志，跟没写一样——你不知道它基于什么判断。

完整的触发日志长这样（详见第十九章）：

```
时间 / 触发层 / 命中信号与分值 / 调度的引擎 / 宣告文案 / 用户反应 / 事后判定
```

#### 护栏二：可否决，而且否决要被记住

用户说"不用"，要满足三个条件：

1. **立刻停**，不要解释为什么你觉得该做；
2. **记下来**，作为一条负样本；
3. **下次遇到类似情况，自动降低置信度**。

第三点是这条护栏的真正价值：**否决不是让你闭嘴，是让你学习。**

#### 护栏三：可降级

不确定时退回去。

具体规则（第十五章已给）：

- L2 打分在 2–3 分之间（差一点）→ 退回 L0，**不硬猜**；
- L1 点名了但特征明显不符 → 退回 L0，**问一句**；
- 引擎调用失败 → 按备选映射降级（第九章）。

#### 护栏四：可审计

日志要能看、能统计、能反过来调系统。这是第十九章整章的内容。

### 五、两条兜底原则

如果四条护栏只能记住两条，记这两条：

> **一、宁可少触发，不可乱触发。**
> **二、宁可问一句，不可替用户决定。**

第二条跟第九章"中枢不替人做决定"是同一条红线，在那里是设计原则，在这里是安全原则。

### 六、一个判错的现场

一次真实误触发：用户在聊一个项目的进度，随口说了句"这块得沉淀一下"。

系统听到"沉淀"，L1 直接触发，当场出了一张沉淀卡。

问题在哪？**用户说的"沉淀"是"这件事要好好想想"的意思，不是"给我出沉淀卡"。** 而且当时任务根本没做完，没有东西可沉淀。

用户的反应是什么？**什么都没说**，直接把卡关了，继续聊。

如果只看"有没有投诉"，这次是成功的。但系统错过了一次学习机会——**它不知道自己错了**。

这就是为什么第十九章要求：不只是"否决"要记，**"无反应"也要记**。用户默默关掉，往往意味着"不痛不痒"——这跟"错了"一样是信号。

## 本章操作件

### 四条护栏落地检查表

| 护栏 | 检查 | 是/否 |
|---|---|---|
| **打日志** | 每次触发都写了"因为"吗？ | ☐ |
| | 日志里能看到命中信号和分值吗？ | ☐ |
| **可否决** | 用户说"不用"，系统会立刻停吗？ | ☐ |
| | 这个"不用"被记下来了吗？ | ☐ |
| | 下次同类情况，置信度会降低吗？ | ☐ |
| **可降级** | 有"差一点就不触发"的规则吗？ | ☐ |
| | 引擎失败时有备选吗？ | ☐ |
| **可审计** | 日志能回看吗？ | ☐ |
| | 日志能统计（否决率、无反应率）吗？ | ☐ |
| | 有固定的复盘动作吗？ | ☐ |

**十个"否"里出现三个以上 → 这个系统现在不值得被信任。**

### 否决话术（用户侧三句）

给你三句最短的否决，系统应该都能听懂：

1. **"不用。"** → 立刻停，记为负样本
2. **"这次不用，以后这种也别自动做。"** → 记为负样本，并加否决项
3. **"你为什么调这个？"** → 强制它把理由说清楚（护栏一的手动版）

第三句最有用。当你觉得系统乱来，**先问为什么**，再决定要不要否决——很多时候你会发现它其实是对的，只是没说清楚。

## 跨章接口

- 四条护栏中的"打日志"和"可审计"，由第十九章（触发日志）实现。
- "可降级"是第九章降级机制的行为层表述。
- 黑箱触发这个风险，是第二十二章（白箱包黑箱）要解决的**根本问题**。
- 否决样本是第十九章调阈值的主要依据。

## 待校准与待补

1. **误触发的代价目前只有定性描述，没有量化方式。** 想量化，得先有日志（第十九章）。
2. 四条护栏的优先级（哪个最重要）没排——我倾向"打日志"是第一条，因为其他三条都依赖它。
3. 判错现场那个例子是真实的，但**没有后续**：不知道那次之后系统有没有真的学到，因为当时没有日志。

# 第十九章 · 触发日志与可观测性

## 这一章解决什么

让自动触发可以被改进，而不是一次配置定终身。

前面所有阈值（3 和 5）、所有信号权重，都是设计值，不是实测值。**没有日志，它们永远是设计值。**

这一章给日志格式、给复盘方法、给调阈值的闭环。

## 核心内容

### 一、一条标准触发日志的字段

七项，一项都不能少：

| 字段 | 内容 | 为什么要有 |
|---|---|---|
| **时间** | 时间戳 | 复盘时排序 |
| **触发层** | L1 / L2 / L3 | 看哪层最活跃、哪层最不准 |
| **命中信号与分值** | "摄入度2+沉淀1=3" | **这是"因为"的证据** |
| **调度的引擎** | 派了谁 | 看有没有偏科 |
| **宣告文案** | 当时说了什么 | 看宣告是不是真的说了理由 |
| **用户反应** | 接受 / 否决 / 无反应 | **三种都要记** |
| **事后判定** | 对 / 错 / 勉强 | 回填，系统唯一的自我纠错机制 |

### 二、三种反应都要记

这一节是本章最容易被忽略、也最不该忽略的。

| 反应 | 记什么 | 意味什么 |
|---|---|---|
| **接受** | 正样本 | 这次是对的，信号有效 |
| **否决** | 负样本 | 信号选错，或阈值太低 |
| **无反应** | **也算信号** | **往往意味着"不痛不痒"** |

第三行要重点说。

用户默默关掉你的输出，什么都没说——这**不是"没反馈"，这是"你这次做的事不值得评价"**。它跟"错了"一样是坏信号，甚至更坏：**错了至少有信息量，不痛不痒意味着你做的事没有价值。**

### 三、每周一次小复盘

固定动作，10 分钟。

统计四个数：

| 指标 | 怎么算 | 说明什么 |
|---|---|---|
| **触发次数** | 一周总触发数 | 太多 → 过度触发 |
| **否决率** | 否决数 ÷ 触发数 | **>30% 说明阈值太低或信号选错** |
| **无反应率** | 无反应数 ÷ 触发数 | 高 → 做的事没价值 |
| **偏科检查** | 各引擎被调用次数 | 某个引擎特别少 → 它的信号没被识别出来 |

**否决率 >30% 是最重要的警报线。** 30% 是个经验值，但它的逻辑是硬的：三次里有一次是错的，用户已经在忍了。

### 四、用日志反调矩阵的闭环

这是全书"自我进化"命题的**最后一环**——注意这一环的作用对象：

> **前面所有章节讲的自我进化，进化的是"沉淀的内容"；这一环进化的，是"触发系统本身"。**

闭环四步：

```
① 看日志，找出错例
      ↓
② 判断是哪种错：阈值问题？信号问题？还是层的问题？
      ↓
③ 改信号或改阈值
      ↓
④ 下周验证（看否决率有没有降）
      ↓
   回到 ①
```

#### 怎么判断是哪种错

| 症状 | 诊断 | 处方 |
|---|---|---|
| 否决率高，但看错例觉得"判断挺合理" | **用户不需要这么勤** | 调高阈值 |
| 否决率高，且错例明显不对 | **信号选错了** | 改信号，不是改阈值 |
| 漏触发多（事后发现该做没做） | 阈值太高 | 调低 |
| 否决率高 + 漏触发多 | **信号维度本身有问题** | 回去改第十章的五维定义 |
| 某个层特别不准 | 那层的机制有问题 | 针对性改（比如 L2 的信号表） |

**最后两行是关键**：当调阈值不管用的时候，问题一定在更上层。这时候别死磕阈值。

### 五、日志本身也是认知资产

这一节容易被当成抒情，但它是实的。

触发日志记录的是什么？是**"这个系统在我身上是怎么用的"**。

这东西有三个特点：

1. 花了时间才有（跑了一个月才有）；
2. 下次还能用（调阈值要用它）；
3. 丢了会重做（没有它，每次调参都是拍脑袋）。

**三条全中，按第二章的定义，它就是认知资产。**

所以它也应该进沉淀流程——具体来说，月度复盘时，把"本月触发日志的统计结论"做成一张普通的沉淀卡存起来。

**这就是血把触发系统自己也进化了。** 全书讲的所有自我进化，在这一刻闭环。

### 六、一个诚实的边界

日志能告诉你"系统做了什么、用户什么反应"，但它**不能告诉你"那个判断对不对"**——这需要"事后判定"字段，而事后判定得等你过一段时间回头看。

所以日志不是万能的。它能解决"过度触发"和"误触发"，**解决不了"判断质量低"**。

后者要靠第八章说的"事后判定"，以及第二十二章讲的——**白箱包不住的那一块**。

### 触发日志模板

```

                    ↓

```

- 月度统计结论做成沉淀卡，是第八章沉淀机制的又一处应用。

2. 统计口径问题：否决率以**次数**计还是以**会话**计？两者差别很大，本章默认按次数，但没论证。

4. 日志存哪儿、存多久、怎么跟三向同步配合，本章没写，属部署问题（第二十三章）。

# 第二十章 · 一个人的龙心OS：一天的真实运行

## 这一章解决什么

把前面十九章的所有机制，放进一天里跑一遍。

前面讲的全是零件。这一章给你看**它们咬合起来是什么样**——包括咬得好的地方，也包括咬得不好的地方。

## 核心内容

### 一、08:20 读到一篇长文（L2 特征触发）

你刷到一篇三十多页的行业报告，顺手转发进去，什么都没说。

**系统做了什么**：

| 步 | 动作 |
|---|---|
| 感知 | 输入形态＝长文件；任务动词＝无；上下文＝新会话 |
| 打分 | 摄入度 2、沉淀价值 1、协作度 1 → **合计 4** |
| 判定 | ≥3 且有一维 ≥2 → **触发 L2**，派脾 |
| 宣告 | "我判断这是 S2，派知识学习消化材料——30 页，摄入度满分。你没说要决定什么，先不派五色光。" |

**然后它做了什么**：按消化三判据走——先不用术语讲一遍这份报告在说什么，再指出它跟你已有认知的冲突点，最后问"它改变了你哪个做法"。

读到第 12 页，报告里有个数据跟你的经验严重不符。**未知度从 0 升到 2**。

系统升档：

> "看到第 12 页这个数据（客单价涨了但复购降了），我判断未知度升高，补派象思维——这件事可能不是'经营变好'，是别的事。"

取象的结果：**它像"透支"**——不是变好，是提前把老客户的钱收上来了。

**血自动收尾**（L3 触发点②：出现了"这个我没想到"）：出一张二级卡（一句话 + 象征符号），问你要不要展开。你说"展开"，它出完整卡，入库。

### 二、10:40 一个多选一的决定（L2 + L3）

你要定一件事：三个合作方，选哪个。

**系统做了什么**：

| 步 | 动作 |
|---|---|
| 打分 | 决策度 2、摄入度 1、沉淀价值 1 → **合计 4** |
| 判定 | **触发 L2**，派眼 |
| 宣告 | "我判断这是 S4，派五色光走完整序列，因为你有三个选项要权衡。" |

按"白 → 绿 → 黄 → 蓝 → 红"走了一遍。走完发现：三个里有两个根本不在同一个量级，真正的问题不是"选哪个"，是"第三个要不要直接放弃"。

**这就是五色光的价值**：它把"三个选一个"，变成了"其实只有两个，而且第三个的问题在别处"。

你说"行，就这个方向"。

**L3 触发点①（产出被接受）命中** → 系统自动出沉淀卡。这次是一级（长任务 + 有新认知），直接入库。

### 三、14:15 跟 AI 一起写材料（手 + L3）

下午你要写一份材料，跟 AI 一起。

**系统做了什么**：

| 步 | 动作 |
|---|---|
| 三问诊断 | 我掌握多少？**高**（我知道要写什么）／AI 掌握多少？**中** → **Q4 共创导师** |
| 判定 | 派手（五象限），模式＝你出经验，它结构化 |
| 宣告 | "我判断这是 Q4 共创导师——你知道要写什么，它不知道，你来说它来整理。不派五色光，因为这不是在权衡。" |

三记号标注：

```
核心观点 [人]
论据组织 [AI]
案例选择 [⇄]
最终定稿 [人]
```

写完，你说"可以了"。

**L3 触发点① + ④（引擎链跑完）同时命中** → 沉淀。

### 四、16:50 一次误触发（本书最重要的一段）

你跟它闲聊，说了句"这块得沉淀一下"——你指的是"这件事得好好想想"，不是"给我出沉淀卡"。

**系统听到"沉淀"，L1 直接触发，当场出了一张卡。**

你的反应：**什么都没说，把卡关了，继续聊。**

这次误触发暴露了三件事：

1. **L1 关键词触发没有分辨语境**——"沉淀"这个词的日常用法跟系统用法不一样；
2. **任务根本没做完**，没有东西可沉淀；
3. **最要命的是**：你没有投诉，所以如果只看"有没有人骂"，这次是"成功"的。

事后补救：把"沉淀"这个词的触发条件从 L1 降为 L2 辅助信号——**只有同时命中"任务已完成"这个状态时，它才算数**。

### 五、22:30 一天结束

清点一下：

| 项 | 数量 |
|---|---|
| 沉淀卡 | 3 张（早上 1、上午 1、下午 1） |
| 负样本 | 1 条（16:50 那次误触发） |
| 阈值调整 | 1 次（"沉淀"词降级） |
| 升档 | 1 次（早上读到第 12 页） |
| 入库 | 3 张卡进 Obsidian，一句话进 IMA |

**再看一遍这五项**：三张卡是你今天赚的，一条负样本 + 一次阈值调整是系统今天赚的。

**第二天会发生什么？** 明天早上打开，昨天那三张卡就是起点——不是从零开始。而系统因为那条负样本，明天不会再在你闲聊时弹卡。

**双方都在长。这才是"共生"。**

### 六、一天运行全记录表

|---|---|---|---|---|---|---|
| 08:20 | 30 页报告 | L2 | 4 | 脾→心 | 三判据 + 一个象 | 二级→一级卡 |
| 10:40 | 三选一 | L2 | 4 | 眼 | 五色序列 + 结论 | 一级卡 |
| 14:15 | 写材料 | L2 | — | 手(Q4) | 三记号分工 + 成稿 | 一级卡 |

| **本章能拿走什么** | ① **一天运行全记录表**（自用版），每晚填一次，一周就能看出自己的模式。② **一天自检三问**：有没有留下、有没有误触发、明天起点是不是更高。③ 四个时段的完整跑法：长文→脾+心、多选一→眼、写材料→手(Q4)、闲聊→误触发。④ 最值钱的一段是 16:50：**用户不投诉，不代表没问题**。⑤ 结尾那个对照：三张卡是你赚的，一条负样本是系统赚的——**双方都在长，这才叫共生**。 |

# 第二十一章 · 一群人共用一个心脏

## 这一章解决什么

组织场景下的调度，跟个人有什么不同。

这不是把个人的那套放大十倍那么简单——组织里有三个新变量，每一个都会让原来的机制变形。

## 核心内容

### 一、龙心OS 在组织里的正式身份

先把定位钉死：

> **龙心OS 不是"给员工配的 AI 助手"，是这个组织的 AI 系统的心脏。**

《AI原生组织》那本书讲的是结构——一群人怎么搭。而**那个组织要跑起来，需要一个 AI 系统；龙心OS 就是这个 AI 系统的心脏。**

- **结构决定血脉往哪走**；
- **心脏决定血到不到得了末梢**。

没有心脏的结构是图纸，没有结构的心脏是空转。

**判断标准只有一条**：

> **它停了，这个组织的认知循环会不会停？**

会停，它就是心脏。不会停，它现在还只是个高级插件。

### 二、三个新变量

个人用得顺的东西，到组织里会变形，因为多了三样：

#### 变量一：多人输入——谁的话算信号

一个人用的时候，输入只有一个来源。组织里，一个会议有八个人说话，**系统该听谁的？**

具体问题：

- 老板随口一句和一个工程师的正式发言，权重一样吗？
- 三个人在同一个会上提了三个不同的"关键问题"，算三个信号还是一个？
- 有人说话带情绪（红光），系统该当成事实还是当成情绪？

**目前的处理**：信号按**人**加权（发言权重由角色定），情绪一律按红光接（第六章：把情绪当事实接，但不当成结论）。

#### 变量二：角色差异——同一个词意思不同

同一个词，在不同人嘴里是不同意思：

| 词 | 老板说的 | 一线说的 |
|---|---|---|
| "效率" | 人效产出比 | 别让我加班 |
| "流程" | 规范化 | 又多了个要填的表 |
| "系统" | 管理工具 | 一个要学的新东西 |

个人场景里，系统可以从上下文推断词义；组织场景里，**同一个会话里有两套上下文**。

**这是目前最难的一个变量**，没有成熟解法。

#### 变量三：共识成本——宣告要所有人听得懂

个人场景里，宣告写给你一个人看，怎么写都行。

组织场景里，宣告是给一群人看的。它必须：

- 用所有人都能懂的话（不能出现"我派了脾"这种内部黑话）；
- 说清楚派了什么、**为什么**；
- 让不同意的人有机会当场否掉。

### 三、五色光在组织里的主场

五色光是五个引擎里**最适合组织的**一个，因为它是少数能用于集体思考的工具。

关键问题：**主持人由人承担，还是由系统承担？**

**建议：人做主持人，系统做记录与提醒。**

理由：

| 主持人的活 | 人 | 系统 |
|---|---|---|
| 宣布开什么光 | ✓ 人（有权威，大家肯听） | |
| 按光收话、喊停混色 | ✓ 人 | 可辅助提醒 |
| 记录每光的产出 | | ✓ 系统 |
| 提醒"绿光还没开" | | ✓ 系统 |
| 最后整合出结论 | ✓ 人 | 可出候选稿 |

**为什么不能让系统当主持人？** 因为"喊停"是一个需要权威的动作。系统喊停，没人理；人喊停，大家停。

系统的角色是**第二主持人**：不抢话，但在旁边提醒"这一色还没收""绿光今天没开过"。

### 四、组织里的血：沉淀归谁

个人场景里，沉淀卡归你一个人。

组织里有个新问题：**洞察归个人，还是归组织？**

**建议的分法**：

| 归个人 | 归组织 |
|---|---|
| 核心洞察（那句 ≤30 字的话） | **判据**（我们判断这类事的标准） |
| 象征符号 | **序列**（我们讨论这类事的固定色序） |
| 个人反思 | **清单**（踩过的坑、该带的装备） |

为什么这么分？

**洞察是个人体验，拿走就变味了。** 一句"这件事本质上是透支"，只有当时在场的人能体会它的分量。

**但判据、序列、清单是可迁移的**——它们不依赖个人体验，可以直接给下一个人用。

这三类组织资产积累起来，就是**机构知识记忆**（第八章提过的第二层记忆）：不是"记住了什么"，是"下次遇到同类事，起点在哪"。

### 五、触发在组织里要更保守

一条硬规则：**组织场景的阈值要上调。**

原因很简单：**误触发的成本被人数放大了。**

- 个人误触发，烦一个人；
- 组织误触发，烦一屋子人，而且是在所有人面前出错。

具体建议：

| 设置 | 个人 | 组织 |
|---|---|---|
| L2 触发阈值 | ≥3 | **≥4** |
| 组合阈值 | ≥5 | **≥6** |
| L3 沉淀级别 | 一级/二级 | **默认二级**（先问再展开） |
| 宣告 | 一句话 | **两句话**（多了"不同意的现在说"） |

最后一行是组织特有的：宣告的结尾要加一句**"不同意的现在说"**——这是把一个自动动作变成一次共识确认。

### 六、组织版的定题

一份材料进来，组织要先有"这是个什么问题"的共识，才有后面的解法。

> **共识不了题面，后面全是白干。**

个人定题是四步（消化→取象→扫面→题面）。组织定题要多加一步：

| 步 | 个人 | 组织多做的 |
|---|---|---|
| ① 消化 | 自己读懂 | 各人读到的不一样，要先对齐"材料说了什么" |
| ② 取象 | 一个象 | 会有多个象，要收敛 |
| ③ 扫面 | 自己扫 | 各人看到的面不同，要合并 |
| ④ 题面 | 一句话 | **要所有人点头** |
| ⑤ **共识确认** | — | **"这就是我们要解决的问题吗？"** |

第五步是组织独有的，也是最容易被跳过的。**跳过它的后果是：会开完了，每个人回去干的事都不一样**——因为每个人心里的题面是不同的。

# 第二十二章 · 它不改变模型，它把黑箱包进白箱

## 这一章解决什么

正面回应一个绕不开的质疑：

> **AI 是靠预测下一个词工作的，这是个黑箱，谁也不知道结论是怎么得出来的。**

这个质疑是对的。这一章不打算绕过去，也不打算装作能解决它。

它要给的是另一件事：**在黑箱改不了的前提下，怎么让结果可信。**

## 核心内容

### 一、先承认：黑箱是真的，而且改不了

大模型的底层机制是**预测下一个词**（next-token prediction）。这是它的训练方式，决定了它内部是怎么"想"的。

三个事实，必须先接受：

1. **它的内部推理路径不可完全追溯**——不是不愿意给你看，是连它自己都不完全"知道"（如果能说清楚，那就不是神经网络了）。
2. **这不是 bug，是这类技术的固有属性。**
3. **改不了，也没必要装作能改。**

市面上有很多"可解释 AI"的工作，试图打开这个黑箱。那些工作有价值，但**它们不是本书要做的，也不是龙心OS 能做的**。

### 二、但这是两件事

关键的一步在这里：

> **"结论怎么算出来的不可知"，和"我能不能信任这个结论"，不是一回事。**

打个比方。你去一家餐厅吃饭，你看不见后厨（黑箱），但你能看见：

- 谁点的菜（派谁）
- 点了哪几道（看了哪几面）
- 每道菜端上来什么样（中间产物）
- 吃完留没留下记录（留下什么）

你不需要把后厨的灶台拆开研究，你也能判断这顿饭能不能吃。

**你不需要让模型透明，你需要让流程透明。**

### 三、白箱包黑箱的四层外显

这是本章的核心，也是龙心OS 的核心价值之一。

| 层 | 留在黑箱里 | 必须外显到白箱 |
|---|---|---|
| **① 派谁** | 模型内部怎么算 | 中枢宣告"我调了 X，因为信号 Y" |
| **② 看了哪几面** | — | 五色光走了哪几光、缺哪光 |
| **③ 中间产物** | — | 脾的消化三判据、心的象、眼的序列产出 |
| **④ 留下什么** | — | 沉淀卡 + 触发日志（可否决、可统计） |

#### 第一层：派谁

模型怎么算出那个答案的，你管不了。但**"为什么派这个引擎"必须说清楚**。

这就是第九章的宣告义务。它是白箱的第一层，也是最容易做的一层。

#### 第二层：看了哪几面

一次决策，到底考虑了几个角度？**五色光的序列就是这个问题的答案。**

如果某一光没开（比如没开蓝光），你立刻知道：这次没考虑风险。这不是模型的责任，是流程的责任——而流程是可见的、可追的、可补的。

#### 第三层：中间产物

不要只给结论，把中间的东西摆出来：

- 脾的消化三判据（讲给外行/冲突点/改了哪个做法）
- 心取的象（它像什么）
- 眼每色的一句话结论

**中间产物的价值在于：结论可能是错的，但中间产物能让你看出它错在哪一步。**

#### 第四层：留下什么

沉淀卡 + 触发日志。这一层让整个过程**可回看、可统计、可否决**。

### 四、可审计 > 可解释

这是本章最重要的一句：

> **可审计 > 可解释。**

| | 可解释 | 可审计 |
|---|---|---|
| 问的是 | 模型内部怎么算的 | 这次调用干了什么 |
| 谁的责任 | 模型厂商 | **系统层（你和我）** |
| 能不能做到 | 目前只能部分做到 | **完全能做到** |
| 做到了有什么用 | 知道原理 | **能发现错、能纠正、能统计** |

**解释模型内部，是模型厂商的事。让每一次调用可回看、可否决、可统计，是系统层的事——也正是龙心OS 能做的事。**

这个转向很重要，因为它把一个"暂时做不到"的问题，换成了"现在就能做"的问题。

### 五、对 AI 原生组织的意义

这一节是本章分量最重的地方。

一个组织敢不敢把决策交给 AI 系统，前提不是"它够不够聪明"，而是：

> **它够不够可审计。**

为什么？因为组织里的决策是要担责的。担责的前提是**能说清楚这个决定是怎么来的**——不是对模型说清楚，是对人、对上级、对客户、对监管部门说清楚。

所以：

> **可审计是信任的基础设施。没有它，AI 只能干可重来的活，干不了要担责的活。**

"可重来的活"是什么？写个初稿、整理个表格、查个资料——错了就重来，代价小。

"要担责的活"是什么？定价、用人、投入一大笔钱——错了没法重来。

**AI 现在被大量用在前者，卡在后者。卡的不是能力，是可审计性。**

这一条也是把龙心OS 放进 AI 原生组织（第二十一章）的真正理由：结构决定血脉走哪，心脏决定血到不到末梢，而**可审计决定这个组织敢不敢把命交给它**。

### 六、一个诚实的边界：白箱包不住的那一块

必须说破。

白箱包住了"派谁、看哪几面、中间产物、留下什么"，但**包不住一样东西**：

> **模型给你的那个具体判断，到底对不对？**

流程全对，宣告清楚，五光齐全，中间产物完整，沉淀卡规范——**但那个结论是错的。**

这完全可能。而且白箱拦不住它。

**补法只有一条：事后判定。**

这就是为什么第八章要求沉淀卡必须带"事后判定"字段——过一段时间回头看，这个判断对不对。

**而且错了要改，不能删。** 因为：

> **错误的洞察被沉淀下来，只会让你更熟练地犯错。**

这是全书最不愿意承认、也最该承认的一条。一个会自我进化的系统，如果进化的是错误，那它比不会进化更危险。

### 七、三句话收尾

1. 模型是黑箱，改不了，别装能改。
2. **可审计 > 可解释**——让流程透明，比让模型透明有用，而且现在就能做到。
3. **白箱包不住判断对错**，所以沉淀卡必须留"事后判定"那一栏。

## 本章操作件

### 四层外显检查表

拿到一次 AI 输出，按四层查：

| 层 | 检查 | 是/否 |
|---|---|---|
| ① 派谁 | 它说了"我调了什么、因为什么"吗？ | ☐ |
| ② 看了哪几面 | 能看出它考虑了哪几个角度吗？ | ☐ |
| | 能看出它**漏了**哪个角度吗？ | ☐ |
| ③ 中间产物 | 除了结论，它给了中间的东西吗？ | ☐ |
| | 如果结论错了，我能从中间产物看出错在哪步吗？ | ☐ |
| ④ 留下什么 | 这次有沉淀卡吗？ | ☐ |
| | 有触发日志吗？ | ☐ |
| **边界** | 沉淀卡上有"事后判定"栏吗？ | ☐ |

**八个"否"里出现三个以上 → 这次调用不可审计，别拿它去担责。**

### 一次调用的完整审计样例

```
【时间】2026-__-__ 10:40
【触发层】L2　【命中信号】决策度2 + 摄入度1 + 沉淀1 = 4
【调度引擎】眼（五色光）
【宣告】"我判断这是 S4，派五色光走完整序列，因为你有三个选项要权衡。"
【中间产物】
  白：三个合作方的客观条件（资质/报价/工期）
  绿：还有第四种可能——先小范围试一家
  黄：选 A 的好处是工期最短
  蓝：A 的问题——他们同时在接另外两个大单
  红：我对 A 的直觉是不踏实，说不清为什么
【结论】先小范围试 B
【用户反应】接受
【事后判定】（一周后）对——A 果然延期了
```

**再看一遍这份记录**：模型的内部推理你看不见，但**派谁、看了哪几面、中间产物、留下什么**，一层不缺。这份记录拿给任何人看，他都能判断"这次能不能信"。

## 跨章接口

- 四层外显的第一层（派谁）＝第九章的宣告义务。
- 第二层（看了哪几面）＝第六章五色光。
- 第四层（留下什么）＝第十九章触发日志。
- "可审计是信任的基础设施"＝第二十一章组织敢不敢用 AI 的前提。
- "白箱包不住判断对错"＝第八章事后判定字段的存在理由，也是第二十四章边界章的正面表述。

## 待校准与待补

1. **审计样例是构造的，不是真实数据。** 需要真实调用记录替换。
2. "可审计 > 可解释"这个提法是否要在术语表里立为正式表述，待定。
3. 本章没有讨论一个反对意见：**过度强调流程透明，会不会让人误以为流程对了结论就对了？** 这个风险存在，本章第六节承认了，但需要更醒目的位置。

# 第二十三章 · 怎么搭一套自己的

## 这一章解决什么

给想复现的人一条能走的路。

前面二十二章讲的是"它是什么、怎么运作"。这一章讲"你要是想要一套，从哪下手"。

## 核心内容

### 一、先建五个引擎，最后建中枢

这是本章最重要的一条顺序建议，也是最反直觉的：

> **先有器官，再有调度。**

理由：中枢的职责是"派活"，如果它派下去没有引擎接，你根本没法测它对不对。反过来，五个引擎单独都能用——你可以一个一个建、一个一个试，最后再装调度。

**反面案例**：很多人一上来就写"总控 Prompt"，写得极其详尽，然后发现下面没有能干活的东西。那个总控最后只能自己干——**这就是第九章说的"中枢越界"**。

### 二、文件结构

一个可用的最小结构：

```
skills/
├── 龙心OS/                    ← 1：中枢（最后建）
│   └── SKILL.md
├── 象思维/                    ← 心
│   ├── SKILL.md
│   ├── references/
│   ├── templates/
│   └── triggers/
├── 知识学习Skills/             ← 脾
│   └── （同上结构）
├── 五色光思维/                 ← 眼
│   └── （同上结构）
├── 人机协同五象限/             ← 手
│   └── （同上结构）
└── 知行合一/                  ← 血
    └── （同上结构）
```

**每个引擎目录里必须有四样**：

| 目录 | 放什么 |
|---|---|
| `SKILL.md` | 主文件（唯一入口） |
| `references/` | 方法论原文、案例库 |
| `templates/` | 可复制的模板 |
| `triggers/` | 触发配置 |

### 三、五个 SKILL.md 的最小必写字段

每个引擎的 SKILL.md，至少要写这六块。少一块，它就跑不起来：

| # | 字段 | 内容 | 缺了会怎样 |
|---|---|---|---|
| 1 | **核心定位** | 一句话：它管哪一段 | 中枢不知道该不该派它 |
| 2 | **触发规则** | 什么信号下启动 | 只能靠手动 |
| 3 | **操作流程** | 分几步，每步干什么 | 产出不稳定 |
| 4 | **输出格式** | 固定模板 | 结果没法被下一环接 |
| 5 | **与其他引擎的整合协议** | 它的输出给谁、它接谁的输出 | 接缝处全漏 |
| 6 | **失败模式** | 什么情况下它会出错 | 错了不知道 |

**第 5 条最容易被漏。** 而它恰恰是"流水线 vs 工具箱"的分界线——没有整合协议的五个引擎，就是五个工具。

**第 6 条是本书特别加的。** 一个不敢写自己失败模式的 Skill，用起来是危险的。

### 四、自主学习：四层能力

如果你想要的不只是"五个引擎"，还要"它会自己学"，那还要配四层能力：

| 层 | 能力 | 干什么 |
|---|---|---|
| **第一层** | 持久记忆 | 写入长期记忆 / 调取 / 定期蒸馏 |
| **第二层** | 实时获取 | 联网搜索 / 深度研究 |
| **第三层** | 文件与知识库读取 | 读本地文件（多格式）/ 批量读知识库 |
| **第四层** | 自主进化 | 每日沉淀 / 定时学习任务 |

对应的九条指令：

| 层 | 指令 |
|---|---|
| 一（记忆） | ① 写入记忆 ② 调取记忆 ③ 记忆蒸馏（**每月一次**） |
| 二（获取） | ④ 联网搜索（单话题） ⑤ 深度研究（多角度） |
| 三（读取） | ⑥ 读取本地文件 ⑦ 批量读取知识库 |
| 四（进化） | ⑧ 每日知识沉淀 ⑨ 设置定时学习任务 |

**第三条（记忆蒸馏）最容易被忽略，也最不该忽略。** 记忆积累多了会变臃肿——重复的、过时的、冗余的。不蒸馏，三个月后你的记忆库就变成垃圾场，检索什么都慢，而且会检索出互相矛盾的东西。

**第九条（定时任务）是"系统在你不用它时也在工作"的实现。** 设一次，之后每周自动跑。

### 五、上线自检 12 项

装完之后，逐项打勾。**有"否"就别上线**：

| # | 检查项 | 是/否 |
|---|---|---|
| 1 | 五个引擎各自能单独跑通吗？ | ☐ |
| 2 | 中枢派活之后，引擎真的接住了吗？ | ☐ |
| 3 | **L0 真的是默认吗？**（闲聊时它会不会乱动） | ☐ |
| 4 | L2 打分能跑出来吗？（分数对不对） | ☐ |
| 5 | **L3 真的是默认吗？**（任务做完会不会自动沉淀） | ☐ |
| 6 | 每次触发都有宣告吗？ | ☐ |
| 7 | 宣告里有没有"因为"？ | ☐ |
| 8 | 日志真的在写吗？（去翻文件确认，别看它说） | ☐ |
| 9 | 用户说"不用"，它真的停了吗？ | ☐ |
| 10 | 那个"不用"被记下来了吗？ | ☐ |
| 11 | 沉淀卡真的入库了吗？（去 Obsidian 里看一眼） | ☐ |
| 12 | 三向同步真的通了吗？（三端各查一次） | ☐ |

**第 3、5、8、11 项是最容易"以为做了其实没做"的四项。** 尤其第 8 项：系统会告诉你"我记了"，你要去文件里看。

### 六、三种常见失败

| 失败 | 表现 | 根因 |
|---|---|---|
| **一次建六个** | 中枢和五个引擎同时上，哪里错了都不知道 | 没有实测，一步登天 |
| **只建引擎不建中枢** | 五个都好用，但你得自己记什么时候用哪个 | **这就是工具箱，不是有机体** |
| **建了中枢但中枢亲自干活** | 中枢开始大段大段写内容 | 越界了（第九章） |

第二种最可惜：东西都建好了，就差一个调度层，结果还是得靠人记——**而靠人记的东西，三个月后就不记了**。

# 第二十四章 · 龙心OS 不能干什么

## 这一章解决什么

边界章。

第三章预告过三处不是强项，这一章把它们展开成完整的边界——**并且再加两条第三章没写的**。

写这一章的理由只有一个：**一个不写自己边界的系统，不值得被信任。**

## 核心内容

### 一、不解决专业领域的深度

它管"怎么想"，不管"想什么"。

| 它能做 | 它不能做 |
|---|---|
| 帮你把一个医学问题问清楚 | 帮你诊断 |
| 帮你把一个法律问题的争点拆出来 | 给你法律意见 |
| 帮你看清一个财务决策漏了哪一面 | 替你算准一个数 |

**最常见的事故**：一个人用它把问题问得特别漂亮，然后以为漂亮的问法等于正确的答案。

不会。**问得对和答得对，是两件事。**

### 二、不替代执行

它出方案，不干活。第九章讲过：心脏不搬东西，那是手脚的事。

如果有人期待"装上它，事就自动做完了"，那他期待的是一个员工，不是一个系统。

**这个边界的意义在于**：它让你知道，方案出来之后还有一段路。那段路它陪不了你全部。

### 三、不保证触发正确

这是它最大的不确定性。

它会：该动的时候不动（漏触发）、不该动的时候乱动（误触发）、动了但派错引擎。

第四编用六章处理这件事，第十八章讲护栏，第十九章讲日志——**但那是降低出错率，不是消除出错**。

**我不承诺它不会错。承诺不了的东西，我不写。**

### 四、不替代人的取象

这一条第三章没写，是这里新加的。

Q1 到 Q4，它可以很强，AI 通常比人强。**但 Q5（谁都不知道）不行。**

> **它能帮你把已知的整理好，不能替你去未知里看那一眼。**

那一眼叫取象，是第四章的事，也是人的事。

所以如果你把整个 Q5 也交出去——让 AI 替你决定"这件事像什么"——你不是在用系统，你是在**把自己的最后一块阵地交出去**。

### 五、不自动变对

这一条也是第三章没写的，而且是最容易被误解的一条。

> **自我进化进化的是"资产的积累"，不是"判断的正确"。**

系统会越来越会沉淀，但不会因此越来越会判断。

**如果沉淀下来的判断本身是错的，系统会让你更熟练地犯错。**

这就是第八章坚持沉淀卡要带"事后判定"字段的原因，也是第二十二章说"白箱包不住那一块"的原因。

**一个会自我进化的系统，如果进化的是错误，它比不会进化更危险。**

### 六、边界总表

| 不能 | 说明 | 去哪章 |
|---|---|---|
| 不解决专业深度 | 管怎么想，不管想什么 | 第三章 |
| 不替代执行 | 出方案，不干活 | 第九章 |
| 不保证触发正确 | 只能降低出错率 | 第十八、十九章 |
| 不替代人的取象 | Q5 是人的阵地 | 第四章、第七章 |
| 不自动变对 | 进化的是积累，不是正确 | 第八章、第二十二章 |

### 七、全书三句话回收

如果只能记住三句：

**第一句：它治的是认知资产的蒸发。**
不是让你更快，是让你做完一次，下次起点更高。

**第二句：五个引擎各管一段，血决定下一次的起点在哪。**
没有血，前四个做得再好也是一次性的。

**第三句：会调度是聪明，会留下是本事，会承认自己会错才可信。**
第三句是这套系统最不显眼、也最不能省的部分。

### 八、最后一句

回到卷首那个答不上来的问题：**它到底解决什么问题？**

现在可以答了：

> **它解决的是"做完就归零"。**

你每天都在想、在学、在决定、在跟 AI 协作。这些事花掉的时间，本该变成你的本钱，但大部分蒸发了。

它把这条链接住，让每一次做完，都留下一点东西——**那点东西，就是下一次的起点**。

这不是一个功能。这是一个系统存在的理由。

## 本章操作件

### 边界自查表：我现在想让它干的事，越界了吗

六问，任一答"是"就是越界：

| # | 问 | 是 |
|---|---|---|
| 1 | 我是不是指望它给专业结论（医疗/法律/财务）？ | ☐ |
| 2 | 我是不是指望它把活干完，而不只是出方案？ | ☐ |
| 3 | 我是不是指望它一次就调对，从不误触发？ | ☐ |
| 4 | 我是不是让它替我取象（决定"这件事像什么"）？ | ☐ |
| 5 | 我是不是以为沉淀得越多，判断就越对？ | ☐ |
| 6 | 我是不是因为它流程走得漂亮，就相信结论一定对？ | ☐ |

**第 6 问最阴险。** 流程漂亮（四层外显齐全）跟结论正确，是两件事——第二十二章专门讲过。

### 边界速记

```
专业深度 —— 不解决
执行落地 —— 不替代
触发正确 —— 不保证
取象       —— 不替代（这是人的阵地）
自动变对 —— 不会
```

## 四、组合与顺序规则

### 三条排序原则

1. **取象在前** —— 象没定，后面全在模糊基础上做
2. **决策在后** —— 信息不全就决策，是最大的浪费
3. **血在最后** —— S9 例外（血在最前）

### 撞车消解（按顺序用）

| 招 | 什么时候用 |
|---|---|
| **降级** | 两个都要但资源不够 → 各走浅层 |
| **串行** | 有依赖关系 → 排队，先出产出 |
| **仲裁** | 结论直接冲突 → **交给人拍板** |

### 最小可用原则

> 能用两个引擎，就不要上三个。

## 六、降级路径

```
L1（点名）──确定──→ 执行
   └─点名了但特征明显不符 ──→ 退回 L0，问一句

L2（特征）──≥阈值──→ 执行
   └─2~3 分之间（差一点）──→ 退回 L0，不硬猜

引擎调用失败 ──→ 按备选映射降级
龙脑OS 不可用 ──→ 用内置基础模型兜底（5 个）
龙爪OS 不可用 ──→ 跳过执行，直接输出推荐
全部失败 ──→ "处理失败，建议人工介入" + **附上已收集的部分结果**
```

## 七、待校准

1. 主决策树中"2~3 分之间"这个模糊带的边界未定。
2. L1 覆盖负向信号的具体条件未细化（所有点名都覆盖？还是只覆盖部分否决项？）。
3. Q3（共创伙伴）在决策树里的位置偏弱——它通常不是独立终点，而是过渡态。
4. S5 全系统配方的内部顺序（心→眼→手→血）未实测。

## 二、五个 SKILL.md 最小字段

每个引擎的 SKILL.md 必须写这六块：

| # | 字段 | 内容 | 缺了会怎样 |
|---|---|---|---|
| 1 | **核心定位** | 一句话：它管哪一段 | 中枢不知道该不该派它 |
| 2 | **触发规则** | 什么信号下启动 | 只能靠手动 |
| 3 | **操作流程** | 分几步，每步干什么 | 产出不稳定 |
| 4 | **输出格式** | 固定模板 | 结果没法被下一环接 |
| 5 | **整合协议** | 输出给谁、接谁的输出 | **接缝处全漏** |
| 6 | **失败模式** | 什么情况下会出错 | 错了不知道 |

**第 5 条最容易漏，也最关键**——它是"流水线 vs 工具箱"的分界线。
**第 6 条是本书特别加的**——不敢写失败模式的 Skill，用起来危险。

### 中枢 SKILL.md 额外要写

| 字段 | 内容 |
|---|---|
| 职责边界 | **只做感知·识别·路由·宣告，不干活** |
| 宣告义务 | 每次调度必须说"派了谁、因为什么" |
| 分层动员 | 轻载/标准/深度的判定标准 |
| 降级映射 | 引擎失败时切谁 |
| 越界禁止 | **不产出内容、不评判对错、不替人决定** |

## 三、上线自检 12 项

装完之后逐项打勾。**有"否"就别上线。**

| # | 检查项 | 是/否 |
|---|---|---|
| 1 | 五个引擎各自能单独跑通吗？ | ☐ |
| 2 | 中枢派活之后，引擎真的接住了吗？ | ☐ |
| 3 | **L0 真的是默认吗？**（闲聊时它会不会乱动） | ☐ |
| 4 | L2 打分能跑出来吗？（分数对不对） | ☐ |
| 5 | **L3 真的是默认吗？**（任务做完会不会自动沉淀） | ☐ |
| 6 | 每次触发都有宣告吗？ | ☐ |
| 7 | 宣告里有没有"因为"？ | ☐ |
| 8 | 日志真的在写吗？（**去翻文件确认，别看它说**） | ☐ |
| 9 | 用户说"不用"，它真的停了吗？ | ☐ |
| 10 | 那个"不用"被记下来了吗？ | ☐ |
| 11 | 沉淀卡真的入库了吗？（去 Obsidian 里看一眼） | ☐ |
| 12 | 三向同步真的通了吗？（三端各查一次） | ☐ |

**重点盯 3、5、8、11 项**——这四项最容易"以为做了其实没做"。
