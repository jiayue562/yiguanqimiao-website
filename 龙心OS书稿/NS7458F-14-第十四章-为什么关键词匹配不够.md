# 第十四章 · 为什么关键词匹配不够

## 这一章解决什么

先立靶子。

这一章要把现在这套触发机制的**成绩讲足**，再讲它为什么不够。跳过前半段是不诚实的——这套机制跑了两年多，它解决的问题比它造成的问题多。

但它是**不够**的。后面五章讲的新设计，都是从它这三个病灶长出来的。

## 核心内容

### 一、现在这套是怎么工作的

以知行合一（血）的触发规则为例，它有三层：

#### 第一层：直接触发词（权重 5）

出现下列任一词，**立即触发**：

> 知行合一、自我进化、经验沉淀、三阶段转化、表示空间、压缩、泛化

#### 第二层：场景触发词（权重 4）

| 场景 | 触发词 |
|---|---|
| 深度学习完成 | "总结一下""这次的收获""学到了什么""沉淀一下" |
| 系统升级 | "进化升级""系统迭代""记录下来""存入知识库" |

累积到 3 分触发。

#### 第三层：行为信号（权重 3）

- 检测到 S2/S3/S4/S5/S7/S8/S9 场景完成
- 检测到象思维产生 0→1 洞察
- 检测到"这个我没想到"类新认知

≥2 个信号触发。

#### 现在的智能调度三步法

在更新的版本里，还加了后台静默的三步：

```
Step 1 · 意图扫描：他要结果？分析？决策？学习？执行？还是进化？
Step 2 · 场景归类 + 复杂度评估：对应 S0-S9，评估简单/中等/复杂
Step 3 · 引擎路由：匹配最优引擎组合，简洁声明，执行
```

这套设计已经不只是关键词了——它有意图识别，有场景归类。**这是对的，方向是对的。**

### 二、它的成绩（先讲足）

四条，都是真的：

1. **明确**：什么词触发什么，白纸黑字，不靠猜。
2. **可复现**：同样的输入，同样的触发，不会有玄学。
3. **易调试**：触发错了，改词表就行，不用动架构。
4. **新手可预期**：用户说"知行沉淀"，就一定出沉淀卡。**这种确定性是有价值的**——它让人知道系统在干什么。

这四条，任何新设计都不该丢。

### 三、三个病灶

#### 病灶一：说不出词，就触发不了

这是最根本的一条。

用户不会说"我需要表示空间"。**他只会说："这次挺有意思的。"**

真实场景里的表达，跟词表里的词几乎不重叠：

| 用户实际会说的 | 词表里有的 |
|---|---|
| "这次挺有意思的" | 经验沉淀 |
| "这个我没想到" | 三阶段转化 |
| "等下，我得记一下" | 表示空间 |
| "别让我下次又忘了" | 知行合一 |

指望用户记住词表，是本末倒置——**系统该适配人，不是人适配系统**。

而且更要命的是：**最该沉淀的时刻，用户往往说不出话**。那是一个"啊，原来是这样"的瞬间，人在那个瞬间是安静的，不是在喊口令的。

#### 病灶二：词在，但场景不对，也触发

反过来也成立。

"总结一下"这四个字，出现在一句闲聊里，照样触发。比如："帮我总结一下，你刚才是不是说错了？"

**关键词不分辨语境。** 它只认字，不认这件事是什么。

误触发一次的代价，比漏触发一次大得多——漏触发只是没帮上忙，误触发是**打扰**，而且消耗的是信任。用户通常不会说"你别烦我"，他只会慢慢不用。

#### 病灶三：无法处理组合

关键词是**单点**的：一个词指向一个引擎。

但真实任务往往要两三个引擎。你不会说"请同时启动知识学习和象思维然后知行合一"——你会说"帮我把这份材料吃透，下周要讲"。

这句话里，脾（消化）、手（分工）、血（留下讲稿）全都在，但**没有一个词**。

### 四、所以关键词不是要扔，是要降级

这是本章的结论。

关键词这套东西不该被扔掉，它有明确、可复现、易调试、可预期四条好处。**它应该被降级**：

- 从"主力机制"降为 **L1 显式层**的一部分；
- 从"唯一的触发依据"降为"多种信号中的一种"。

**降级，不是删除。**

下一章讲新的四层设计，关键词在新的架构里有它的位置，只是不再是全部。

### 五、一个反例：什么时候关键词反而更好

不能把这一章写成"关键词一无是处"。

**有一种场景，关键词是最好的：调试和兜底。**

当你明确知道要干什么，说一个词比让系统猜快得多。"知行沉淀"四个字，比等系统打完分再判断，快三秒，而且不会错。

所以新设计里保留了快速口令：

| 口令 | 效果 |
|---|---|
| "全系统启动" | 五引擎全序列 |
| "象感知" | 象思维单引擎 |
| "五色分析" | 五色光完整序列 |
| "深度学习" | 十项认知指令全激活 |
| "象限诊断" | 人机协同象限定位 |
| "知行沉淀" | 立即输出沉淀卡 |
| "三体一心" | 象思维 + 五色光整合 |

**保留它们，是因为人有时候就是想直接说要什么。**

## 本章操作件

### 现有触发规则体检表

给你手上的触发规则（不管是 AI 的还是工作流程的）做个体检：

| # | 检查项 | 是/否 |
|---|---|---|
| 1 | 它只认关键词，还是也认场景特征？ | |
| 2 | 你能说出最近一次**误触发**是什么时候吗？（说不出的，通常是没有记录，不是没有发生） | |
| 3 | 你能说出最近一次**该触发没触发**是什么时候吗？ | |
| 4 | 用户不说口令时，它还会动吗？ | |
| 5 | 触发之后，它会告诉你为什么吗？ | |
| 6 | 触发错了，用户有地方说"不用"吗？ | |
| 7 | 有没有一条规则是"什么情况下不触发"？ | |

**怎么读**：

- 第 1 题答"只认关键词" → 需要升级到特征识别（第十七章）；
- 第 5、6 题答"否" → 黑箱触发，第十八章会解决；
- **第 7 题答"否" → 最危险**。没有"不触发"规则的机制，一定会过度触发。

| 现象 | 对应病灶 | 去哪一章 |
|---|---|---|

| 闲聊里被误触发 | 病灶二 | 第十八章护栏 |
| 复杂任务只派了一个引擎 | 病灶三 | 第十三章组合 |

## 跨章接口

- 三个病灶，第十五章（触发四层）要逐一解决：病灶一 → L2 特征识别，病灶二 → L0 默认静默 + 负向信号，病灶三 → 组合触发。
- 保留的快速口令，是 L1 显式层的主要内容。
- 体检表第 7 题（有没有"不触发"规则），是第十五章 L0 层的设计起点。
- 第十六章讲 L2 特征触发时，会直接对比本章的三个病灶。

## 待校准与待补

1. **P0/P1/P2 权重的实际命中率没有统计。** 本章只讲机制，不写数字——因为我没有数字。
2. 三个病灶的排序（说不出词 > 误触发 > 无法组合）是我的判断，未经用户验证。
3. 快速口令表是既有资产，但部分口令的实际使用情况不明。
