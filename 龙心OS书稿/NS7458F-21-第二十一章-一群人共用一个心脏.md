# 第二十一章 · 一群人共用一个心脏

## 这一章解决什么

组织场景下的调度，跟个人有什么不同。

这不是把个人的那套放大十倍那么简单——组织里有三个新变量，每一个都会让原来的机制变形。

## 核心内容

### 一、龙心OS 在组织里的正式身份

先把定位钉死：

> **龙心OS 不是"给员工配的 AI 助手"，是这个组织的 AI 系统的心脏。**

《AI原生组织》那本书讲的是结构——一群人怎么搭。而**那个组织要跑起来，需要一个 AI 系统；龙心OS 就是这个 AI 系统的心脏。**

- **结构决定血脉往哪走**；
- **心脏决定血到不到得了末梢**。

没有心脏的结构是图纸，没有结构的心脏是空转。

**判断标准只有一条**：

> **它停了，这个组织的认知循环会不会停？**

会停，它就是心脏。不会停，它现在还只是个高级插件。

### 二、三个新变量

个人用得顺的东西，到组织里会变形，因为多了三样：

#### 变量一：多人输入——谁的话算信号

一个人用的时候，输入只有一个来源。组织里，一个会议有八个人说话，**系统该听谁的？**

具体问题：

- 老板随口一句和一个工程师的正式发言，权重一样吗？
- 三个人在同一个会上提了三个不同的"关键问题"，算三个信号还是一个？
- 有人说话带情绪（红光），系统该当成事实还是当成情绪？

**目前的处理**：信号按**人**加权（发言权重由角色定），情绪一律按红光接（第六章：把情绪当事实接，但不当成结论）。

#### 变量二：角色差异——同一个词意思不同

同一个词，在不同人嘴里是不同意思：

| 词 | 老板说的 | 一线说的 |
|---|---|---|
| "效率" | 人效产出比 | 别让我加班 |
| "流程" | 规范化 | 又多了个要填的表 |
| "系统" | 管理工具 | 一个要学的新东西 |

个人场景里，系统可以从上下文推断词义；组织场景里，**同一个会话里有两套上下文**。

**这是目前最难的一个变量**，没有成熟解法。

#### 变量三：共识成本——宣告要所有人听得懂

个人场景里，宣告写给你一个人看，怎么写都行。

组织场景里，宣告是给一群人看的。它必须：

- 用所有人都能懂的话（不能出现"我派了脾"这种内部黑话）；
- 说清楚派了什么、**为什么**；
- 让不同意的人有机会当场否掉。

### 三、五色光在组织里的主场

五色光是五个引擎里**最适合组织的**一个，因为它是少数能用于集体思考的工具。

关键问题：**主持人由人承担，还是由系统承担？**

**建议：人做主持人，系统做记录与提醒。**

理由：

| 主持人的活 | 人 | 系统 |
|---|---|---|
| 宣布开什么光 | ✓ 人（有权威，大家肯听） | |
| 按光收话、喊停混色 | ✓ 人 | 可辅助提醒 |
| 记录每光的产出 | | ✓ 系统 |
| 提醒"绿光还没开" | | ✓ 系统 |
| 最后整合出结论 | ✓ 人 | 可出候选稿 |

**为什么不能让系统当主持人？** 因为"喊停"是一个需要权威的动作。系统喊停，没人理；人喊停，大家停。

系统的角色是**第二主持人**：不抢话，但在旁边提醒"这一色还没收""绿光今天没开过"。

### 四、组织里的血：沉淀归谁

个人场景里，沉淀卡归你一个人。

组织里有个新问题：**洞察归个人，还是归组织？**

**建议的分法**：

| 归个人 | 归组织 |
|---|---|
| 核心洞察（那句 ≤30 字的话） | **判据**（我们判断这类事的标准） |
| 象征符号 | **序列**（我们讨论这类事的固定色序） |
| 个人反思 | **清单**（踩过的坑、该带的装备） |

为什么这么分？

**洞察是个人体验，拿走就变味了。** 一句"这件事本质上是透支"，只有当时在场的人能体会它的分量。

**但判据、序列、清单是可迁移的**——它们不依赖个人体验，可以直接给下一个人用。

这三类组织资产积累起来，就是**机构知识记忆**（第八章提过的第二层记忆）：不是"记住了什么"，是"下次遇到同类事，起点在哪"。

### 五、触发在组织里要更保守

一条硬规则：**组织场景的阈值要上调。**

原因很简单：**误触发的成本被人数放大了。**

- 个人误触发，烦一个人；
- 组织误触发，烦一屋子人，而且是在所有人面前出错。

具体建议：

| 设置 | 个人 | 组织 |
|---|---|---|
| L2 触发阈值 | ≥3 | **≥4** |
| 组合阈值 | ≥5 | **≥6** |
| L3 沉淀级别 | 一级/二级 | **默认二级**（先问再展开） |
| 宣告 | 一句话 | **两句话**（多了"不同意的现在说"） |

最后一行是组织特有的：宣告的结尾要加一句**"不同意的现在说"**——这是把一个自动动作变成一次共识确认。

### 六、组织版的定题

一份材料进来，组织要先有"这是个什么问题"的共识，才有后面的解法。

> **共识不了题面，后面全是白干。**

个人定题是四步（消化→取象→扫面→题面）。组织定题要多加一步：

| 步 | 个人 | 组织多做的 |
|---|---|---|
| ① 消化 | 自己读懂 | 各人读到的不一样，要先对齐"材料说了什么" |
| ② 取象 | 一个象 | 会有多个象，要收敛 |
| ③ 扫面 | 自己扫 | 各人看到的面不同，要合并 |
| ④ 题面 | 一句话 | **要所有人点头** |
| ⑤ **共识确认** | — | **"这就是我们要解决的问题吗？"** |

第五步是组织独有的，也是最容易被跳过的。**跳过它的后果是：会开完了，每个人回去干的事都不一样**——因为每个人心里的题面是不同的。

### 组织版阈值调整建议表

| 设置 | 个人 | 组织 | 理由 |
|---|---|---|---|
| L2 触发阈值 | ≥3 | **≥4** | 误触发成本被人数放大 |

| 主持人 | 可系统 | **必须人** | 喊停需要权威 |

### 会议场景序列模板

```
【会前】
主持人宣布：今天走 ___ → ___ → ___ → ___ → ___
每色约 ___ 分钟，最后留 5 分钟整合

【会中】
每色结束，主持人收一句：这色的结论是 ______
系统旁听，提醒：___ 色还没收 / 今天还没开过 ___ 光

【整合】
主持人念出各色结论，给一句整合判断
系统出候选稿（仅供参考，不作结论）

【共识确认】
主持人："所以我们要解决的问题是：______"
"不同意的现在说。"
```

## 跨章接口

- 本章是第六章（五色光）在多人场景下的变体，主持人角色的分人与系统，与第六章口径需保持一致。
- 组织版定题的第五步（共识确认），是第十二章定题四步的扩展。
- "它停了认知循环会不会停"这个标准，来自第一章和第三章，本章是它在组织场景的应用。
- 机构知识记忆这个说法，来自第八章。

## 待校准与待补

1. **组织场景的真实案例待补。** 本章所有内容都是推演，没有实测。
2. 三个新变量里的"角色差异"（同一个词意思不同）**目前没有解法**，本章只承认了问题。
3. 组织版阈值的具体数字（≥4、≥6）是推演值，比个人版的经验值更不可靠。
4. "人做主持人、系统做记录与提醒"这个建议，跟第六章的口径需要确认一致。
