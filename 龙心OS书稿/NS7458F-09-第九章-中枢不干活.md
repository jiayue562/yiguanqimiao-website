# 第九章 · 中枢不干活

## 这一章解决什么

把"1"的职责边界划清楚。

龙心OS 是 1+5：1 是总智能体（中枢），5 是五个引擎。**最危险的事，是中枢忍不住自己干活**——一旦它开始产出内容，它就变成了第六个引擎，五引擎的分工体系立刻崩塌。

这一章讲清楚：中枢做什么、不做什么、以及怎么判断它越界了。

## 核心内容

### 一、中枢只做四件事

| 步 | 名称 | 干什么 | 产出 |
|---|---|---|---|
| 1 | **感知** | 这段对话在发生什么 | 一组信号 |
| 2 | **识别** | 它属于哪类场景 | S0–S9 中的一个 |
| 3 | **路由** | 该派谁，派几个 | 引擎组合 |
| 4 | **宣告** | 告诉你我派了谁、为什么 | 一句话声明 |

就这四件。**没有第五件。**

#### 感知：不是读关键词，是读信号

感知要抓的东西分三类：

- **输入形态**：一句话？一份长文？一个链接？一个文件？
- **任务动词**："帮我看看这个" 和 "帮我整理一下"，指向完全不同的引擎。
- **上下文状态**：上一轮在做什么？已经用了几个引擎？有没有新信息产生？

关键词只是其中很小一部分，而且是最不可靠的一部分。第十六章会讲为什么。

#### 识别：归到 S0–S9

场景编号沿用既有体系（S0 简单问答到 S9 系统升级），第十章给完整矩阵。

#### 路由：派谁，派几个

这里有个既有设计叫**分层动员**——不是所有任务都要全员出动：

| 层级 | 动员范围 | 适用 |
|---|---|---|
| **轻载** | 单引擎 | 简单问答、快速检索 |
| **标准** | 2 引擎 + 中枢 | 一般任务、分析建议 |
| **深度** | 全部 5 引擎 + 扩展引擎 | 复杂决策、架构设计、创作 |

**最小可用原则**：能用两个引擎解决，就不要上三个。全员出动看着隆重，实际是浪费——而且上得越多，出错的机会越多。

#### 宣告：必须说破

这一步最容易被省掉，也最不该省。

宣告的标准句式：

> "我判断这是 S4（分析决策），派五色光走完整序列，因为你有三个选项需要权衡。"

**为什么必须宣告？**

因为不宣告的调度就是黑箱。用户不知道系统为什么这么做，就没法纠正；**没法纠正的系统，不可信。**

这是第二十二章"白箱包黑箱"的第一层，也是第十九章四条护栏里的第一条。

### 二、它不做的事

| 不做 | 原因 |
|---|---|
| **不执行** | 执行是龙爪OS 的事，心脏不搬东西 |
| **不产出内容** | 一旦产出，它就变成第六个引擎 |
| **不评判对错** | 它判断"该派谁"，不判断"这个结论对不对" |
| **不替用户做决定** | 它给方案，决定权永远在人 |

**最后一条是红线。** 中枢可以建议，可以说"我倾向于 A，理由是……"，但不能替你拍板。

### 三、完整的调度协议（八步）

既有设计里有一份八步协议，比本章的"四件事"更工程化。两者不冲突：四件事是**职责边界**，八步是**执行流程**。

```
1. 判断任务类型（8 类场景评分）
2. 按分层动员规则激活引擎（轻载/标准/深度）
3. 查询龙脑OS 获取推荐模型（选刃决策树）
4. 调用引擎执行
5. 分发到龙爪OS 执行工作流
6. 组织治理层（瓶颈诊断 → 压缩策略 → 授权）
7. 结果整合输出
8. 异常时自动降级
```

**第 3 步值得展开**：中枢会去龙脑OS（模型库）查"这个场景该配哪个思维模型"。这是"1+5"之外的一层，本书不展开——你只需要知道：**中枢不自己想模型，它去查。**

### 四、降级：出错的时候怎么办

第 8 步是整套系统里最诚实的一步：**承认它会失败，并且提前安排好退路。**

| 故障 | 降级动作 |
|---|---|
| 某个引擎调用失败 | 按备选映射切换到备选引擎 |
| 龙脑OS 不可用 | 用内置基础模型兜底（MECE/第一性原理/逆向思维/系统思维/概率思维） |
| 龙爪OS 不可用 | 跳过执行，直接输出模型推荐 |
| **所有引擎都失败** | 返回"处理失败，建议人工介入"，**并附上已收集的部分结果** |

最后一行是设计里最讲究的一处：**失败也要带着已有的东西失败**。不是甩一句"出错了"，是把走到一半的成果交出来，让人能接着干。

这一条跟第十七章的护栏思路是同一条：**出错不可怕，出错之后什么都不剩才可怕。**

### 五、怎么判断中枢越界了

给你三条自查：

1. **它开始长篇大论地产出内容** → 越界了。它应该派活，不是干活。
2. **它替你做了决定** → 越界了。它可以建议，不能拍板。
3. **它不告诉你它派了谁** → 越界了。宣告是义务，不是恩赐。

## 本章操作件

### 中枢职责边界表

| 它做 | 它不做 | 做了就是越界 |
|---|---|---|
| 感知信号 | 执行任务 | 它开始自己写方案正文 |
| 识别场景 | 产出内容 | 它绕过引擎直接给结论 |
| 路由派谁 | 评判对错 | 它说"这个结论是对的"（它没这个资格） |
| 宣告理由 | 替人决定 | 它说"就这么定了" |

### 宣告句式模板

```
我判断这是 S__（场景名），
派 ________（引擎）走 ________（序列/深度），
因为 ________________（证据）。
```

**"因为"那半句不能省。** 没有理由的宣告，等于没宣告。

### 分层动员速查

| 任务分量 | 动员 | 例子 |
|---|---|---|
| 一句话能答 | 轻载（不启动引擎） | "今天几号" |
| 需要查一查 | 轻载（单引擎） | "这个概念什么意思" |
| 要分析一下 | 标准（2 引擎） | "帮我看看这份材料" |
| 要做决定 / 要创造 | 深度（多引擎） | "我们要不要进入这个市场" |

## 跨章接口

- 感知、识别、路由、宣告这四步，分别在第十、十一、十二、十三章展开；宣告在第十九章（护栏）和第二十章（日志）里再次出现。
- 分层动员是第十三章"最小可用原则"的机制化版本。
- 降级机制是第十七章"可降级"护栏的技术实现。
- "查询龙脑OS 选模型"这一步本书不展开，龙脑OS 是另一套系统。

## 待校准与待补

1. 八步协议是既有设计，本章只做了转述，**第 3 步（查询龙脑OS）和第 6 步（组织治理层）在本书中无法展开**，需要标注这是外部依赖。
2. 分层动员的"轻载/标准/深度"判定标准是什么，既有文档没写死，本章给的是我的理解。
3. "失败也要带着已有的东西失败"这条原则，实际实现程度未知。
