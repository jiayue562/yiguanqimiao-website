## 1. 战略原点与立项背景

### 1.1 为什么是"岗位"
组织的终极形态无论怎么演进（AI 原生组织的数据飞轮，还是后工业化时代的科层组织），**最后都会落在一个岗位上**——岗位是企业的最小不变单元，这一点不会变。因此：

> 谁掌握了"岗位"这个最小单元的标准化 AI 载体，谁就掌握了组织数字化的入口。

### 1.2 从"味藏具象"到"通用模板"的跃迁
- 味藏已有 **26 个在用岗位智能体**（POS-MGR + DU-DS / FM-ALL / FIN-MGR / SM-JYT / 味藏总智能体 …），深度绑定餐饮，是"具象实现"。
- 龙爪里的「岗位智能体」Skill 经 v1→v4 多次迭代，已沉淀出"造龙爪的龙爪"元方法论（六维框架 + 五行 + 7S + 复盘画布 + 龙爪断语）。
- **本项目的本质**：把第 1 条的具象实现中**与行业无关的架构骨架**抽出来，填进第 2 条的元方法论，产出一个**跨行业的"岗位智能体通用模板"**，再升级为"生成器"——以后任何人 + 龙龟 AI 共生系统 = 自己的超级个体工具。

### 1.3 与龙龟 AI 共生系统的关系
- 每个人拿到的"个人版技能"**跑在龙龟 OS 之上**，是龙龟 AI 共生系统的具体应用实例。
- 生成器产出的 SKILL.md 必须强制引用龙龟 OS 四维（龙心/凤心/凤脑/凤爪）+ 龙龟共生OS，确保"底座正确"。

## 3. 公共 DNA 抽取结果（8 块 · 通用化形式）

> 每块给出：① 定义 ② 味藏抽取实例 ③ 通用化占位符（生成器填什么）。

### 块 1 · Frontmatter 参数化 Schema
- **定义**：每个岗位智能体的元信息声明。
- **味藏实例**（DU-DS）：`title / description / version / type:application_skill / ecosystem_layer:L2_赋能层 / os_priority:95 / status / manager_name / manager_element:金 / haic_mode:I·AI主导型(85%AI+15%人)`
- **通用化**：`{{行业}} / {{岗位}} / {{五行}} / {{ecosystem_layer}} / {{os_priority}} / {{haic_mode}}` 全部参数化。

### 块 2 · 核心公式模板
- **定义**：用一行公式表达"该岗位 = 五行特质 × 岗位方法论 × 7S × KPI × 协同 × 路由 = 范式跃迁"。
- **味藏实例**：`DU-DS = 金行人特质 × 楼面运营七步法 × 7S绩效考核 × 22项KPI × 前厅后厨协同枢纽 × P-01路由引擎 = 范式跃迁`
- **通用化**：`{{岗位}} = {{五行特质}} × {{岗位N步法}} × {{7S权重}} × {{KPI}} × {{协同接口}} × {{路由引擎}} = 从"{{旧定位}}"到"{{新定位}}"的范式跃迁`

### 块 3 · 7S 权重矩阵（含五行差异化规律）
- **定义**：7 维（战略/结构/制度/风格/人员/技能/价值观）权重分配，体现五行差异化。
- **味藏实例**：金行人→S战略35%★+St制度20%★；木行人→S1+S6↑；火行人→S4+S2↑；土行人→S3+S5↑；水行人→S2+S5↑。S7 价值观所有类型占 10%。
- **通用化**：`{{五行}} → {{核心7S维度}}权重↑ / {{次要维度}}权重↓`，并保留"聚焦而非平均"原则（核心维度≥25%）。

### 块 4 · 核心 KPI / 三层指标体系
- **定义**：结果指标（考核·绿）/ 过程指标（监控·蓝）/ 风险指标（预警·红）+ P0/P1 优先级 + 分层关联规则。
- **味藏实例**：DU-DS 22 项 KPI（堂食营业额/利润/SOP执行率/客户满意度/食品安全零事故…），五档 S/A/B/C/D 评分。
- **通用化**：`结果层{{指标}} / 过程层{{指标+阈值}} / 风险层{{指标+P0/P1}}`，评分标准模板化。

### 块 5 · 岗位红线（通用化约束体系）
- **定义**：不告诉你怎么做，但告诉你绝对不能触碰的底线（"堤坝"）。
- **味藏实例**：F1-F5 五大铁律（客户体验/核心品质/团队健康/经营红线/安全底线）+ DU-DS 六条专属红线（R-01 食安一票否决…）。
- **通用化**：`岗位红线 N 条 = ①{{行业通用红线}} ②{{岗位接触深度决定权重的红线}} ③{{安全/合规零容忍}}`，从"F 铁律"升级为参数化"岗位红线"。

### 块 6 · 工作流 / SOP / 时间块
- **定义**：岗位每日/每周的标准动作流（七步法/五大SOP/日时间块）。
- **味藏实例**：DU-DS 楼面运营七步法（07:00-23:00 含 HB1-HB7 日反馈节律）+ 五大 SOP（开档/早会/午市/晚市/日结）。
- **通用化**：`{{岗位N步法}} + {{时段化时间块，含日反馈节律锚点}}`，时间块注入五行节奏特色（金=标准执行、水=柔性渗透…）。

### 块 7 · 五行差异化协作矩阵 + 禁止行为（拔阴取阳）
- **定义**：与上下游岗位的五行生克协作关系 + 该五行"阴面过刚/过柔"的禁止行为与拔阴取阳对照。
- **味藏实例**：DU-DS 协作矩阵（金克木/金金共鸣…）+ 禁止行为（阴金：标准僵化→拔阴用 SV 仪式柔化；批判过度→开鱼仪式激励）。
- **通用化**：`{{五行}} → 协作矩阵({{生克关系}}) + 禁止行为(阴{{行}}对照) + 提倡行为(阳{{行}})`，复用现有"五行阴阳面分析表 + 借力路径"。

### 块 8 · 质量自检清单 + 龙龟 OS 引用锚点
- **定义**：产出 SKILL 的 16 项质量检查 + 必须锚定龙龟 OS 四维。
- **味藏实例**：DU-DS 第十二节质量自检清单（12 项 YAML/frontmatter/公式/矩阵…）+ POS-MGR 协同矩阵。
- **通用化**：`质量自检清单（16 项，参数化）+ 龙龟OS引用锚点（龙心/凤心/凤脑/凤爪 + 龙龟共生OS 强制引用）`。

## 5. 生成器工作流（核心 SOP）

```
【输入采集】
  六维框架：行业 / 企业简介 / 岗位 / 五行人格 / 核心任务 / 适用模型
  + 行业特点（关键维度：如餐饮→食安；互联网→迭代速度/数据埋点；销售→拓客转化）
  + 岗位职责（职责清单 + 上下游协同关系）
        ↓
【Step 1 · 行业基因抽取】
  识别行业关键维度 → 映射到"公共 DNA 8 块"的通用占位符
  （行业通用红线、行业核心 KPI 类型、行业协作节律…）
        ↓
【Step 2 · 五行适配】
  根据五行画像 → 生成阴阳面 + 借力路径 + 协作矩阵（复用五行阴阳面分析表）
        ↓
【Step 3 · 组装个人版 SKILL】
  套用 templates/个人版技能SKILL模板.md 八大区块，逐块填充
        ↓
【Step 4 · 龙龟 OS 锚定】
  强制引用 龙心OS / 凤心OS / 凤脑OS / 凤爪OS + 龙龟共生OS（缺一则不通过）
        ↓
【Step 5 · 质量校验】
  跑 质量自检清单（16 项，参数化版）
        ↓
【Step 6 · 输出】
  生成 个人版 SKILL.md（可一键部署到 ~/.workbuddy/skills/{{岗位}}-{{五行}}/）
```

### 5.1 工作流走通示例（非味藏岗位验证通用性）

## 7. 行业适配层设计

### 7.1 味藏作为"行业实例之一"
原 v4.0 的全部味藏内容（核心参数、八岗位五行映射、7S案例、F1-F5、课程映射）整体迁入 `references/cases/味藏行业实例.md`，正文不再出现味藏硬编码。

### 7.2 中性行业预设（生成器自带，非交付实例，仅参数预设）
| 行业 | 关键维度（基因） | 典型岗位示例 |
|------|----------------|------------|
| 互联网/SaaS | 迭代速度、数据埋点、需求三角、A/B | 产品经理（木/水）|
