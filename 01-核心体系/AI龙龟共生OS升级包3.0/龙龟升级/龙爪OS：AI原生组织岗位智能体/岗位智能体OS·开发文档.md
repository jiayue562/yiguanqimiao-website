## 1. 产品定义与范围

### 1.1 一句话定义

岗位智能体OS是一个**输入岗位属性+个人连续数据+性格特征 → 自动输出专属岗位智能体**的生产系统。不是手动开发26个独立的智能体，而是用一套引擎动态拼装，为每一个岗位按需输出一个与AI原生组织架构严格对齐、可运行、可校准、可进化的智能体。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 公共因素提取 | 从多人连续数据中自动提取共性模版（L0-L3四层），一次提取多次复用 |
| 个性化校准 | 自动比对个人数据偏差，校准目标值/预警线/瓶颈模式/沟通风格/成长阶段 |
| 五维对齐校验 | 输出前自动校验层级归属/编码/六元组绑定/L1-L4匹配/5Gate门禁 |
| 智能体输出 | 产出SKILL.md+人设基座+方案文档三件套 |
| 持续进化 | 每月一次增量校准，新模式自动注入公共因素仓库 |
| 三层结构附着 | 每个产出物锚定决策层/数据层/执行层，明确权力等级与汇报线 |

### 1.3 与现有系统的关系

| 系统 | 关系 |
|------|------|
| 岗位智能体 v4.0 | **升级对象**——剥离味藏硬编码→参数化→重写为生成器 |
| POS-MGR v1.0 | 具象实现参考——方法论来源，保留为餐饮实例 |
| 味藏26岗位智能体 | 公共DNA采样来源，本体不改动 |
| 龙心OS/龙脑OS/龙爪OS | 运行底座（详见第8章接口设计） |

### 1.4 范围边界（MVP·三不做）

- ❌ 不做产品化路线图/商业模式/收费设计
- ❌ 不改动味藏26个现有岗位智能体本身
- ❌ 不删除味藏POS-MGR（保留为餐饮行业实例参考）

### 1.5 名词定义

| 术语 | 定义 |
|------|------|
| 公共因素 | 从多人数据中提取的共性模版，所有岗位的基座 |
| 个性化校准 | 根据个人数据修正公共模版中的偏差参数 |
| 人设基座 | 个性化校准档案（瓶颈模式/校准参数/成长方向/不适合的干预） |
| 五维对齐校验 | 输出前自动校验五维（层级/编码/六元组/L1-L4/5Gate） |
| 六元组 | 数据节点/业务渠道/数据值/时间戳/7S映射/责任锚点 |
| 楔子触发条件 | 人作为"楔子"介入的边界条件 |
| L0/L1/L2/L3模版 | 通用能力/层级能力/职能能力/门店差异——四层公共模版 |

## 4. 核心模块设计

### 4.1 模块一：公共因素提取引擎（extractor.py）

**功能**：从多人的连续数据中提取共性模版，存储为L0-L3四层模版仓库。

**输入**：多人连续数据（周报/日报）+ 岗位/层级/职能/门店标签
**输出**：L0-L3四层模版

**算法流程**：
```
1. 逐份周报结构化（复盘画布：目标→结果→原因→经验→行动）
2. 标注7S维度（每项任务归属至少1个S维度）
3. 跨周对比识别共性（连续3周同频 → 模式）
4. 按岗位/层级/职能/门店聚类
5. 提取公共特征 → 存入模版仓库
```

**四层模版**：

| 层级 | 内容 | 来源 |
|:----|------|------|
| L0·通用能力 | 日反馈采集、下周计划生成、复盘画布格式化、数据预警追踪、7S自评输出 | 12人共同模式 |
| L1·层级能力 | 决策层（战略推演/文化布道）、赋能层（跨部门协同/智能体路由）、执行层（运营追踪/异常处理） | 按层级提取 |
| L2·职能能力 | 财务AI工作流、采购TCO比价、培训三阶段体系、市场会员运营、人事onboarding SOP | 各职能专有特征 |
| L3·门店差异 | 金月湾（业绩锚点·土行）、狮山（标准推手·金行）、松山湖（社区连接·水行） | 三店差异化配置 |

### 4.2 模块二：个性化校准引擎（calibrator.py）

**功能**：根据个人连续数据校准公共模版中的偏差参数。

**校准维度**：五行校准、能力基线校准、瓶颈模式校准、成长轨迹校准、表达风格校准。

**校准流程**：
```
Step 1：加载公共模版（按岗位/层级/门店匹配）
Step 2：加载人设基座（有连续数据→数据推断性格；新人→岗位默认值）
Step 3：偏差校准（对比个人数据与公共模版默认值 → 生成校准参数）
Step 4：瓶颈模式识别（连续数据中重复出现的同一类型问题 → 标记瓶颈模式）
Step 5：输出个性化智能体（公共模版+校准参数）
```

**校准算法细节**：
- 目标值：`个人4周加权完成率 × 岗位历史均值`（加权平均，近期权重高）
- 预警线：`岗位标准阈值 ± 个人4周偏差幅度 × 1.5σ`
- 瓶颈模式：同一问题连续出现3周 → 判定为模式（区别于单次偶发）
- 沟通风格：周报语言特征NLP分类（结论先行度/数据密度/详细程度）
- 成长阶段：7S自评得分趋势线判断（L1-L4）

### 4.3 模块三：五维对齐校验引擎（verifier.py）

**功能**：输出前自动执行五维校验，全部通过才允许输出。

```
校验通过条件（全部满足）：
1. 层级归属正确——与智能体清单中的层级一致
2. 智能体编码正确——编码与清单一致，P值在85-99之间
3. 六元组数据链绑定正确——责任锚点字段有明确定义
4. L1-L4人才链匹配正确——技能等级不低于L1
5. 宪法5Gate门禁全部通过：
   - Gate1: 7S维度覆盖验证——每项任务至少归属1个S维度
   - Gate2: 核心公式一致性——产出与核心公式不冲突
   - Gate3: 文化价值观——贯穿可追溯
   - Gate4: 人机分工边界——AI不替代人判断/决策/例外处理
   - Gate5: 执行偏差门禁——承诺兑现率≥80%
全部通过 → 智能体输出 | 任意未通过 → 自动标记偏差 → 推送宪法守护进程
```

### 4.4 模块四：生成器调度核心（scheduler.py）

**功能**：编排四环节——公共因素提取→个性化校准→五维校验→智能体输出。

```
scheduler.run(input):
  1. 解析输入（六维+层级+连续数据）
  2. query_brain_os(model)           # 龙脑OS选刃组方 → 推荐思维模型
  3. extractor.run()                 # 公共因素提取 → 模版拼装
  4. calibrator.run()                # 个性化校准 → 校准参数
  5. verifier.run()                  # 五维对齐校验 → 门禁
  6. output.assemble()               # 输出三件套
  7. dispatch_to_claw_os()           # 分发龙爪OS部署
  8. registry.register()             # 注册回味藏总智能体
异常时自动降级：
  - 引擎调用失败 → 切换备选引擎（FALLBACK_MAP）
  - 龙脑OS不可用 → 内置基础模型兜底（MECE/第一性原理/逆向/系统/概率思维）
  - 数据不足4周 → 使用岗位默认值并标注置信度
```

### 4.5 模块五：输出装配器（output.py）

**功能**：装配输出三件套。

```
岗位智能体-[岗位]-[姓名]/
├── SKILL.md          ← 可运行的智能体文件（11大区块）
├── 人设基座.md        ← 个性化校准档案
└── 方案文档.md        ← 向用户交付的方案说明
```

## 7. 生成器工作流SOP

### 7.1 核心生成流程（8步）

```
【输入采集】
  六维框架：行业/企业/岗位/五行/任务/适用模型
  + 三层结构层级（决策层/数据层/执行层）
  + 行业特点（关键维度）
  + 岗位职责（职责清单+上下游协同关系）
        ↓
【Step 1 · 行业基因抽取】
  识别行业关键维度→映射到"公共DNA 11块"的通用占位符
  根据三层结构层级确定权力等级、数据责任、汇报线
        ↓
【Step 2 · 五行适配】
  根据五行画像→生成阴阳面+借力路径+协作矩阵
        ↓
【Step 3 · 六元组数据标准定义】
  定义六元组六个字段——节点类型/渠道类型/数据值/时间戳/7S映射/责任锚点
        ↓
【Step 4 · 人机分工边界划定】
  拆解为"AI可执行功能"+"人必须判断的功能"
  定义楔子触发条件（什么情况下人介入）
        ↓
【Step 5 · 组装个人版SKILL】
  套用templates/个人版技能SKILL模板.md 11大区块，逐块填充
        ↓
【Step 6 · AI原生组织OS锚定】
  强制引用《顶层设计》《数据结构》《人才设计》《哲学底层》四份文件（缺一则不通过）
        ↓
【Step 7 · 质量校验】
  跑质量自检清单（20项，参数化版）
        ↓
【Step 8 · 输出】
  生成个人版SKILL.md（可一键部署）
```

### 7.2 月度增量校准流程

```
收集新数据（N周新周报）
→ 与现有校准参数做偏差对比
→ 偏差超过阈值 → 自动更新校准参数
→ 偏差未超过阈值 → 维持现有参数
→ 新数据中发现新模式 → 添加到公共因素仓库
```

### 7.3 数据流闭环

```
输入（N周连续数据+五行+层级）
  → 生成（公共模版+校准参数→岗位智能体）
  → 采集（智能体按六元组标准采集新数据）
  → 回流（月度增量校准：新数据对比校准参数）
  → 进化（超阈值更新参数/新模式注入公共仓库）
  → 再生成
```
