## 第一章：概述

### 1.1 为什么需要动态组方引擎

思维模型的真正力量不在于单个模型，而在于**组合**。但传统的模型组合方式是**硬编码链条**——固定的场景映射固定的模型序列，缺乏灵活性和适应性。

然而，现实世界的问题具有以下特征：
- **同类型不同质**：同样是"经营分析"，"毛利下降"和"客流减少"需要不同的模型组合
- **最优解动态变化**：今天有效的组合明天不一定有效
- **问题相互缠绕**：一个经营问题可能根源在团队沟通，需要跨类型组合

因此，需要一种**动态组方机制**——不预设固定链条，而是根据每个问题的具体特征，实时组合最适合的思维模型。

### 1.2 核心概念

动态组方引擎围绕三个核心概念构建：

| 概念 | 类比中医 | 定义 |
|------|---------|------|
| **辨证** | 望闻问切 | 龙心OS分析问题后，输出结构化的问题特征向量，而非单一标签 |
| **组方** | 开方配药 | AI根据问题特征向量，实时挑选主模型+辅模型+串联逻辑+验证模型 |
| **存案** | 记录医案 | 每次组方和执行的结果被记录为"医案"，供下次参考但不绑定决策 |

### 1.3 龙心+龙脑+龙爪三层协作

```
龙心OS（诊断）
  │ 分析问题 → 输出问题特征向量
  ▼
龙脑OS（组方） ← 本文档定义的核心
  │ 根据特征向量 → 动态组合思维模型 → 输出双面方案文档
  ▼
龙爪OS（执行）
  │ 接收方案 → 执行步骤 → 记录结果 → 反馈给龙脑
  ▼
龙脑OS（存案）
  记录医案 → 更新置信度 → 沉淀经验
```

### 2.2 数据流

```
Step 1: [龙心] 用户问题 → 问题特征向量
  ↓
Step 2: [龙脑·辨证] 特征向量 → 匹配问题画像
  ↓
Step 3: [龙脑·组方] 问题画像 → 动态挑选模型组合
  ↓
Step 4: [龙脑·输出] 模型组合 → 双面方案文档
  ↓
Step 5: [龙爪] 方案文档 → 执行步骤 → 记录结果
  ↓
Step 6: [龙脑·存案] 执行结果 → 生成医案 → 更新置信度
  ↓
Step 7: [循环] 下次类似问题时，参考医案但不绑定
```

### 2.3 模块职责边界

| 模块 | 所属 | 职责 | 不做什么 |
|------|------|------|---------|
| 辨证 | 龙脑 | 接收龙心的问题特征，匹配问题画像 | 不执行分析，不生成方案 |
| 组方 | 龙脑 | 根据问题画像动态组合思维模型 | 不负责具体分析步骤，不写执行细节 |
| 输出 | 龙脑 | 将组方结果生成为双面结构文档 | 不替龙爪做执行决策 |
| 存案 | 龙脑 | 记录医案，管理经验沉淀 | 不固化决策规则，不强制下次沿用 |
| 龙心 | 自身 | 分析问题，输出特征向量 | 不直接调用思维模型 |
| 龙爪 | 自身 | 执行方案，记录结果 | 不负责模型组合决策 |

```yaml
# 金月湾店毛利下降分析方案

## 一、问题定位

金月湾店7月毛利环比下降8%，经初步排查，问题不在营收端（营收基本持平），而在于成本端——损耗异常。当前有完整的进销存数据，需要在1周内出分析方案。

**关键假设**：损耗异常是毛利下降的主因。如果分析后发现损耗正常，则需重新定位问题。

## 二、组方逻辑

本次分析使用四个模型的组合，形成一条完整的"定位→追溯→对比→验证"链条：

1. **瓶颈理论（主模型）** — 损耗是一个笼统的概念，涉及食材报废、人工效率、能源消耗等多个环节。瓶颈理论的作用是：不分散精力，先找到当前最大的约束点。如果食材损耗占总损耗的70%，那就先聚焦食材。

2. **5Whys（辅模型1）** — 瓶颈理论告诉你"哪是瓶颈"，但不告诉你"为什么是"。找到最大损耗点后，需要5Whys逐层深挖根因。比如：食材损耗高→验收标准不严→验收人员未培训→培训体系缺失。

3. **决策矩阵（辅模型2）** — 找到根因后，通常有多个解决路径。决策矩阵用多维度（成本/效果/时间/可执行性）量化对比，让决策有依据。

4. **逆向思维（辅模型3）** — 选定方案后，不是直接执行，而是先问"如果这个方案失败了，最可能的原因是什么"，提前发现盲区，做预案。

**为什么这个顺序？** 这是一个从"面"到"点"再到"面"的过程——先收缩聚焦（瓶颈→根因），再展开对比（方案→验证），确保既有深度又有广度。

## 三、执行步骤

### Step 1：瓶颈定位
- 调取金月湾店7月完整成本数据，按「食材/人工/能源/其他损耗」分类
- 计算各类成本占比，找出占比最高且环比增幅最大的类别
- **产出**：损耗结构饼图 + 最大的1-2个损耗点
- **预期耗时**：0.5天

### Step 2：根因追溯
- 对Step 1锁定的最大损耗点，用5Whys逐层深挖
- 每次追问"为什么"必须基于可验证的数据，不凭猜测
- 直到找到**可干预**的根因（而非"行业特性""天气原因"等不可控因素）
- **产出**：5Whys因果链 + 可干预的根因列表
- **预期耗时**：1天

### Step 3：方案对比
- 针对根因，每个根因至少提出2-3个解决方案
- 用决策矩阵对比方案（维度：实施成本、预期效果、落地周期、执行难度）
- 每个维度按1-5分评分，加权汇总
- **产出**：决策矩阵表 + 推荐方案及备选方案
- **预期耗时**：1天

### Step 4：压力测试
- 对Step 3选定的方案，用逆向思维做失败预演
- "如果这个方案彻底失败，最可能的3个原因是什么"
- 针对每个原因，准备预防措施或快速响应预案
- **产出**：失败预演表 + 配套预案
- **预期耗时**：0.5天

## 四、验证标准

| 指标 | 目标值 | 时间窗口 |
|------|--------|---------|
| 综合毛利 | 回升≥5个百分点 | 方案执行后30天 |
| 损耗率 | 回归正常范围（参照6月水平） | 方案执行后15天 |
| 执行完成率 | ≥80%的步骤已执行 | 方案下达后7天 |

## 五、可选调整

> 此区域预留给人审阅和修改。如果你不同意某个模型选择、步骤顺序或验证标准，请在此说明。

示例：*"瓶颈理论先锁定最大损耗点是对的，但我认为损耗可能不是主因——建议在Step 1之前加一个'损耗 vs 其他成本对比'的前置排查。"*
```

## 第四章：辨证模块

### 4.1 问题类型识别（8类+扩展机制）

辨证模块的第一步是将龙心OS分析后的问题归类。当前支持8种问题类型：

| 类型代码 | 类型名称 | 识别关键词 | 典型问题 |
|---------|---------|-----------|---------|
| JY | 经营分析型 | 毛利、下降、增长、数据、异常、损耗、复购率、成本 | "为什么毛利下降了？" |
| ZL | 战略决策型 | 该不该、要不要、选择、开店、人选、投资 | "该不该开新店？" |
| FA | 方案设计型 | 怎么做、如何设计、方案、计划、策略 | "储值活动方案怎么做？" |
| WD | 问题诊断型 | 为什么、根源、症结、执行力差、评分低、招不到 | "团队执行力差在哪？" |
| GT | 沟通协作型 | 怎么沟通、如何说服、协调、矛盾、推动 | "怎么跟料理长沟通？" |
| XX | 学习研究型 | 理解、学习、这个理论、深层逻辑、分析 | "这理论怎么用在味藏？" |
| CZ | 自我成长型 | 我的、状态不好、短板、成长、人格、五行 | "五行人格是什么？" |
| CY | 创意创新型 | 除了、还有什么、新、突破、可能、创新 | "除了金枪鱼还能做什么？" |

**扩展机制**：
- 当遇到无法归入8类的问题时，归入"UNKNOWN"，使用默认模型链
- 允许在`sub_type`字段中扩展子类型，例如`经营分析型 → 成本分析/收入分析/效率分析`
- 子类型不影响主模型的分类，但可以优化辅模型的选择

### 4.2 特征维度提取

除了问题类型，辨证模块还需提取以下特征维度：

| 维度 | 提取方法 | 示例值 |
|------|---------|--------|
| **complexity** | 根据问题中涉及的变量数量判断 | 单因素="毛利下降是因为食材涨价" → 单因素 |
| | 单因素=1个变量；多因素=2-3个；系统级=3个以上+反馈回路 | 多因素="毛利下降、客流减少、员工离职" → 多因素 |
| **urgency** | 根据时间相关词判断 | "立刻""马上" → 紧急 |
| | 紧急=包含时间紧迫词；重要=无时间词但影响大；常规=日常事务 | "下周前" → 重要 |
| **domains** | 根据领域关键词映射 | 涉及财务（成本/毛利）→ 财 |
| | 人/财/事/客/产/战略/技术/其他 | 涉及运营（损耗/流程）→ 事 |
| **info_completeness** | 根据描述中的数据相关词判断 | "有完整数据""数据充分" → 数据充分 |
| | 数据充分=有明确数据；部分模糊=有数据但不完整；完全未知=无数据 | "可能有数据" → 部分模糊 |

### 4.3 参考实现（引用选刃引擎.py）

选刃引擎.py中已有`classify_task()`的参考实现。核心逻辑：

```python
# 关键词评分法（简化示意）
def classify_task(context: str) -> TaskType:
    score = {type: 0 for type in TaskType}
    
    # 每类有10-15个关键词，匹配则加分
    for keyword, types in KEYWORD_MAP.items():
        if keyword in context:
            for t in types:
                score[t] += 1
    
    # 取最高分类型
    max_type = max(score, key=score.get)
    return max_type if score[max_type] > 0 else TaskType.UNKNOWN
```

## 第五章：组方模块

### 5.1 组方四步法

组方不是随意排列模型，而是遵循"主→辅→串→验"的四步逻辑：

```
Step 1: 选主模型（解决核心矛盾）
  ↓ 主模型确定后，识别其固有盲区
Step 2: 选辅模型（弥补盲区）
  ↓ 主 + 辅形成完整覆盖后，确定衔接方式
Step 3: 定串联逻辑（定义衔接顺序和因果关系）
  ↓ 完整的模型链确定后，需要验证标准
Step 4: 定验证模型（如何判断方案是否有效）
```

### 5.2 八类场景的组方参考原则

以下为每类场景的**推荐组方原则**。注意：这不是固定链条，而是AI agent应遵循的组合逻辑——每次需根据具体特征向量动态调整。

#### 经营分析型

```
主模型方向：
  单因素 → 5Whys（简单的因果追溯）
  多因素 → 瓶颈理论（先找最大约束）
  系统级 → 系统思维（识别反馈回路）

辅模型方向：
  bottleneck的盲区：能定位"哪是瓶颈"，但不能回答"为什么"
  → 搭配5Whys
  root_cause的盲区：找到根因后缺乏方案设计路径
  → 搭配决策矩阵/5W2H
  verification的盲区：方案缺乏验证手段
  → 搭配PDCA/概率思维

示例（金月湾店，多因素+数据充分）：
  主：瓶颈理论 → 辅：5Whys + 决策矩阵 + 逆向思维
  → 锁定最大损耗点 → 追溯根因 → 对比方案 → 压力测试
```

#### 战略决策型

```
主模型方向：
  两个选项 → 决策矩阵（量化对比）
  多个选项 → 易经错综复杂（多维审视）
  极高不确定性 → 概率思维（期望值计算）

辅模型方向：
  矩阵的盲区：忽略长期连锁反应
  → 搭配二阶思维
  概率的盲区：过度理性，忽略直觉
  → 搭配双系统理论（检查直觉判断）

示例（"该不该开新店？"，多因素+部分模糊）：
  主：决策矩阵 → 辅：二阶思维 + 逆向思维
```

#### 方案设计型

```
主模型方向：
  从零开始 → 5W2H（全面扫描）
  已有框架需要优化 → SCAMPER（七维度改造）
  需要结构化表达 → 金字塔原理

辅模型方向：
  5W2H的盲区：什么都列了，但缺乏优先级
  → 搭配价值聚焦
  框架的盲区：结构完整但缺乏创新
  → 搭配SCAMPER

示例（"储值活动方案"，单因素+数据充分）：
  主：5W2H → 辅：价值聚焦 + 逆向思维
```

#### 问题诊断型

```
主模型方向：
  模糊复杂 → 系统思维（全面诊断）
  单一故障 → 5Whys（线性追溯）
  涉及认知偏差 → 苏格拉底式提问（反问检验）

辅模型方向：
  系统思维的盲区：分析太宏观，缺乏切入点
  → 搭配瓶颈理论（先找到最关键的子系统）
  5Whys的盲区：线性思维忽略多因一果
  → 搭配系统思维

示例（"服务评分持续低"，系统级+部分模糊）：
  主：系统思维 → 辅：瓶颈理论 + 苏格拉底式提问
```

#### 沟通协作型

```
主模型方向：
  需要说服对方 → 拉波波特法则（四步说服）
  需要统一认知 → 六顶思考帽（平行思考）
  需要明确分工 → RACI矩阵

辅模型方向：
  拉波波特的盲区：逻辑完备但缺乏表达技巧
  → 搭配SBI反馈模型
  思考帽的盲区：结构化讨论但缺乏决策推动
  → 搭配三的法则（快速收敛）

示例（"跟料理长沟通成本"，多因素+部分模糊）：
  主：拉波波特法则 → 辅：SBI + 换位式提问
```

#### 学习研究型

```
主模型方向：
  需要深度理解 → 十种知识整合方式
  需要回归本质 → 第一性原理
  需要结构化 → 金字塔原理

辅模型方向：
  十种整合的盲区：太多选择不知道用哪种
  → 搭配框架思维（先定框架再选整合方式）
  第一性原理的盲区：拆到底了但不知道怎么重建
  → 搭配类比思维（跨领域借鉴）

示例（"理解新商业模式"，多因素+完全未知）：
  主：十种知识整合方式 → 辅：框架思维 + 类比思维
```

#### 自我成长型

```
主模型方向：
  需要自我剖析 → 五层分析法（从信息到意义）
  需要突破认知 → 观比体化（象思维感知）
  需要价值锚定 → 价值聚焦

辅模型方向：
  五层分析的盲区：分析到位但缺乏行动转化
  → 搭配从锚定到破局（行动路径）
  价值聚焦的盲区：知道要聚焦但不知道怎么做
  → 搭配动力来自行动（微行动启动）

示例（"状态不好"，系统级+部分模糊）：
  主：五层分析法 → 辅：观比体化 + 从锚定到破局
```

#### 创意创新型

```
主模型方向：
  需要原创灵感 → 观比体化（象思维·无中生有）
  需要系统创新 → SCAMPER（七维度改造）
  需要突破常规 → 逆向思维（反过来想）

辅模型方向：
  观比体化的盲区：灵感太多缺乏筛选标准
  → 搭配第一性原理（回归本质检验）
  SCAMPER的盲区：改造了但可能偏离核心
  → 搭配第一性原理

示例（"除了金枪鱼还能做什么爆品"，单因素+完全未知）：
  主：观比体化 → 辅：SCAMPER + 第一性原理
```

### 5.3 模型组合原则

无论具体场景如何，所有组方必须遵守以下原则：

| 原则 | 说明 | 违反示例 |
|------|------|---------|
| **互补性** | 辅模型必须弥补主模型的盲区，不能重复 | 主模型用5Whys（根因追溯），辅模型也用5Whys → 重复 |
| **最小有效** | 能用2个模型解决问题就不要用3个 | 简单问题用4个模型 → 过度复杂化 |
| **可衔接** | 模型之间必须有清晰的串联逻辑 | 瓶颈理论→SCAMPER（无法自然衔接） |
| **可验证** | 组合链中必须包含验证环节 | 没有验证标准 → 不知道方案是否有效 |
| **冲突检测** | 两个模型不能给出相互矛盾的指引 | 观比体化（直觉）和双系统理论（理性）同时用需声明优先级 |

### 5.4 动态调整机制

当问题特征向量变化时，组方应相应调整：

| 特征变化 | 组方调整 |
|---------|---------|
| 复杂度上升（单因素→系统级） | 主模型从5Whys切换到系统思维，辅模型增加至2-3个 |
| 紧急度上升（重要→紧急） | 缩短模型链（2-3个→1-2个），偏向效率型模型 |
| 信息完备度下降（数据充分→部分模糊） | 从分析型模型切换到探索型模型（如苏格拉底式提问） |
| 领域扩展（单→多领域） | 增加跨领域的类比/翻译环节 |

## 第六章：方案输出双面结构

### 6.1 设计原理

方案文档采用**双面结构**，核心原因：

1. **人需要理解"为什么"** — 如果只给AI一个JSON数据，人看不懂决策逻辑，无法提修改意见。完整的思考链让人可以质疑、补充、调整。
2. **AI需要结构化** — 如果只有Markdown正文，AI agent无法自动解析元数据，无法流转到龙爪OS执行。
3. **双面是同一份文档** — YAML frontmatter + Markdown正文，既有结构化又有可读性，不割裂。

### 6.2 元数据层字段详解

参见3.2节。补充说明：

- `composition.primary.reason` 和 `composition.auxiliary[].complement` 是关键字段——它们记录了组方的**每一步选择理由**，让人可以理解和质疑
- `chain_logic.flow_description` 是整个方案的精简摘要，方便快速理解
- `status` 字段用于龙爪OS追踪执行状态
- `version` 和 `iteration_of` 字段用于追踪方案迭代：如果人提出了修改意见，AI调整后生成v2，`iteration_of`指向原方案ID

### 6.3 正文层五段结构详解

**一、问题定位** — 作用：确认认知对齐

- 用自然语言复述问题
- 包含关键假设（如有）
- 如果理解有偏差，人在这里第一眼就能发现

**二、组方逻辑** — 作用：展示思考过程

- 为什么选这个主模型
- 每个辅模型弥补什么盲区
- 为什么是这个顺序
- 这是整个文档最核心的部分——人从这里判断AI的思路是否合理

**三、执行步骤** — 作用：给出可操作的行动指引

- 每步包含：做什么、怎么做的指引、预期产出、预期耗时
- 步骤之间说明衔接逻辑
- 如果人不同意某一步，可以直接修改

**四、验证标准** — 作用：定义"什么叫成功"

- 量化指标（如果有数据）或定性标准
- 时间窗口（什么时候验收）
- 如果标准不合理，人可以调整

**五、可选调整** — 作用：开放的修改入口

- 预留修改空间，让人可以提不同意见
- 如果没有修改意见，这个区域保持空

### 6.4 输出格式的渲染规则

AI agent生成方案时，应遵守以下渲染规则：

```
1. 如果是紧急问题 → 正文可以精简（2-3段），元数据保持完整
2. 如果是复杂问题 → 正文需要详细展开，每步说明理由
3. 如果信息完备度高 → 执行步骤尽量量化
4. 如果信息完备度低 → 执行步骤需要包含"信息收集"环节
5. 验证标准至少包含1个可测量的指标（即使只是主观评分）
```

## 第七章：存案模块

### 7.1 核心设计原则

```
┌─────────────────────────────────────────┐
│        核心原则：非固化                   │
│                                         │
│  医案是参考，不是规则                     │
│  每次组方必须重新辨证                     │
│  置信度只影响推荐权重，不决定选择         │
│  最优解是动态的，今天的有效组合           │
│  明天不一定有效                           │
└─────────────────────────────────────────┘
```

### 7.2 医案生命周期

```
创建（组方完成）
  │
  ▼
待执行（方案已发送给龙爪）
  │
  ▼
执行中（龙爪开始执行）
  │
  ▼
反馈到达（龙爪返回执行结果） ← 关键节点
  │
  ├── 用户主动标注 → 直接设置标签
  ├── 完成率信号 → 更新completion_rate
  ├── 效果信号 → 更新effectiveness
  └── 引用信号 → 后续被参考则增加references
  │
  ▼
置信度更新（融合多信号）
  │
  ▼
沉淀为经验参考
```

### 7.3 置信度计算机制

置信度不是点击"有效/无效"的二元判断，而是多信号融合：

```
confidence = w1 * user_label + w2 * effectiveness + w3 * completion_rate + w4 * references_norm

其中：
  user_label: 有效组合=1.0, 一般=0.5, 无效组合=0.0, 未标注=0.3
  effectiveness: 显著有效=1.0, 部分有效=0.6, 无效=0.0, 负效果=-0.5, 未评估=0
  completion_rate: 直接使用0-1的完成率
  references_norm: 被引用次数的归一化值（min-max归一化到0-0.5区间，防止频繁引用过度膨胀）
  w1+w2+w3+w4=1.0（初始权重：w1=0.4, w2=0.3, w3=0.2, w4=0.1）
```

**权重的动态调整**：
- 如果用户经常主动标注 → w1权重增加（用户标注可信度高）
- 如果用户不标注 → w1权重降低，更多依赖客观指标（完成率+效果）
- 如果某个来源的信号持续缺失 → 权重重新分配

### 7.4 存案的参考价值（而非规则价值）

当AI agent下次遇到类似问题时，可以参考医案：

```
参考方式（不是直接复用）：
  1. 从医案库中检索特征向量相似度top-3的医案
  2. 参考它们的组方逻辑（而不是直接复制模型列表）
  3. 结合当前问题特征，决定是否采纳类似思路
  4. 在方案文档中声明："本方案参考了历史医案 case_xxx"
```

**禁止行为**：
- ❌ 直接复制过去医案中的模型列表
- ❌ 因某个医案置信度高而直接使用其方案
- ❌ 医案中的"无效"标签导致某个模型被永久弃用

### 7.5 存案模块的参考实现

```python
class MedicalRecord:
    """医案类——记录每次组方的完整信息"""
    
    def __init__(self, problem_feature, solution):
        self.id = f"case_{datetime.now():%Y%m%d}_{seq()}"
        self.problem_feature = problem_feature
        self.solution = solution
        self.execution_result = None
        self.references = 0
        self.confidence = 0.3  # 初始置信度
        self.created = datetime.now()
        self.updated = datetime.now()
    
    def update_feedback(self, result):
        """更新执行反馈"""
        self.execution_result = result
        self._recalculate_confidence()
    
    def _recalculate_confidence(self):
        """多信号融合计算置信度"""
        signals = []
        weights = []
        
        if self.execution_result.user_label != "未标注":
            label_map = {"有效组合": 1.0, "一般": 0.5, "无效组合": 0.0}
            signals.append(label_map.get(self.execution_result.user_label, 0.3))
            weights.append(0.4)
        
        eff_map = {"显著有效": 1.0, "部分有效": 0.6, "无效": 0.0, "负效果": -0.5}
        if self.execution_result.effectiveness in eff_map:
            signals.append(eff_map[self.execution_result.effectiveness])
            weights.append(0.3)
        
        signals.append(self.execution_result.completion_rate)
        weights.append(0.2)
        
        # references归一化
        ref_norm = min(self.references / 20, 0.5)
        signals.append(ref_norm)
        weights.append(0.1)
        
        self.confidence = sum(s * w for s, w in zip(signals, weights))
```

### 8.3 跨层调用路径

组方时可能涉及跨层调用（象思维→思维模型→理论），调用路径如下：

```
问题特征分析 → 需要创新突破
  → 调用第一层：象思维（观比体化）产生原创灵感
  → 调用第二层：思维模型（SCAMPER）系统化改造
  → 调用第三层：理论（积极情绪的拓展-建构理论）验证可行性
  
问题特征分析 → 需要深度根因
  → 调用第二层：思维模型（5Whys）追溯根因
  → 调用第三层：理论（认知吝啬者理论）理解为什么会出这个错
```

跨层调用的原则：**从内向外**——先调用靠近内核的层（象思维），再向外扩散（思维模型→理论），确保思考有深度。

```python
    """选刃引擎——根据问题类型推荐思维模型组合"""

        self.circuit_breaker = BladeCircuitBreaker()

                combination_logic="先用瓶颈理论锁定最大约束，再用五层分析法穿透到根因，最后用PDCA闭环验证"
            ),
            TaskType.ZL: BladeChain(
                primary="易经错综复杂",
                auxiliary=["决策矩阵", "二阶思维"],
                verification="逆向思维压力测试",
                alternative=["概率思维 + 逆向思维 + 机会成本"],
                combination_logic="先用易经错综复杂多角度审视，再用决策矩阵量化对比，然后用二阶思维考虑后续影响"
            ),
            # ... 其他类型类似
        }
    
    def classify_task(self, context: str) -> TaskType:
        """根据上下文关键词分类问题类型"""
        if not context or not context.strip():
            return TaskType.UNKNOWN
        
        context_lower = context.lower()
        scores = {t: 0 for t in TaskType}
        
        # 8类各10-15个关键词，匹配则加1分
        for task_type in TaskType:
            if task_type == TaskType.UNKNOWN:
                continue
            keywords = self._get_keywords(task_type)
            for kw in keywords:
                if kw.lower() in context_lower:
                    scores[task_type] += 1
        
        max_type = max(scores, key=scores.get)
        return max_type if scores[max_type] > 0 else TaskType.UNKNOWN
    
    def recommend(self, task_type: TaskType) -> Optional[BladeChain]:
        """根据问题类型推荐模型链"""
        if self.circuit_breaker.is_open():
            return None
        
        try:
            chain = self._chains.get(task_type)
            if not chain:
                return None
            return chain
        except Exception:
            self.circuit_breaker.record_failure()
            return None
    
    def format_output(self, task_type: TaskType) -> dict:
        """生成结构化的方案输出"""
        chain = self.recommend(task_type)
        if not chain:
            chain = self._get_default_models()
        
        return {
            "task_type": task_type.value,
            "primary_model": chain.primary,
            "auxiliary_models": chain.auxiliary,
            "verification_model": chain.verification,
            "alternative_chain": chain.alternative,
            "combination_logic": chain.combination_logic,
            "confidence": chain.confidence,
            "rationale": self._generate_rationale(task_type, chain)
        }
    
    def _get_default_models(self) -> BladeChain:
        """降级兜底：系统不可用时使用的基础模型链"""
        return BladeChain(
            primary="五层分析法",
            auxiliary=["MECE原则", "第一性原理"],
            verification="逆向思维",
            alternative=[],
            combination_logic="默认降级：用五层分析法逐层穿透，MECE确保无遗漏，第一性原理回归本质",
            confidence=0.3
        )
```

```python
# 熔断器
class BladeCircuitBreaker:
    """防止级联故障的熔断器"""
    def __init__(self, max_failures=3, timeout=60):
        self.failures = 0
        self.max_failures = max_failures
        self.timeout = timeout
        self.last_failure = None
        self.state = "CLOSED"  # CLOSED / OPEN / HALF_OPEN
    
    def is_open(self) -> bool:
        if self.state == "OPEN":
            if time.time() - self.last_failure > self.timeout:
                self.state = "HALF_OPEN"
                return False
            return True
        return False
    
    def record_failure(self):
        self.failures += 1
        self.last_failure = time.time()
        if self.failures >= self.max_failures:
            self.state = "OPEN"
    
    def reset(self):
        self.failures = 0
        self.state = "CLOSED"
```
