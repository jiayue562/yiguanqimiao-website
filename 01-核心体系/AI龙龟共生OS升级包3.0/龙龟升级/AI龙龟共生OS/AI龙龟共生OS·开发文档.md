## 1. 产品定义与范围

### 1.1 一句话定义

AI龙龟共生OS是一个**以木火共生为灵魂内核、三OS为骨架、双层架构为形态的AI时代完整个人操作系统**——人机共生OS（灵魂层）定方向，龙心OS（运行层）做调度，龙脑OS（约束层）守边界，龙爪OS（执行层）抓落实，构成从感知到执行、从学习到进化的完整闭环。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 灵魂层具象 | 心文化六家源代码 × 四柱架构 × 起手即全息 × 合于道自然显化 |
| 统一调度 | 龙心OS总智能体作为唯一入口，8步调度协议+8类场景评分+3级分层动员 |
| 动态组方 | 龙脑OS辨证→组方→输出→存案四步闭环，78思维模型动态组合 |
| 工作流执行 | 龙爪OS三层架构（触发/执行/追踪），SOP智能生成+进度追踪 |
| 三OS契约 | 统一接口协议+统一错误码+降级策略，三OS不直接互调 |
| 治理授权 | 瓶颈诊断→压缩策略→红绿灯授权（绿/黄/红三档）闭环 |
| 持续进化 | 知行合一三阶段+共生螺旋九圈+记忆永生四层 |
| 受约束自主 | 95:5宪法——AI做95%信息处理，人保留5%核心判断 |

### 1.3 与现有系统的关系

| 系统 | 关系 |
|------|------|
| 人机共生OS v3.2 | **灵魂层底座**——心文化/四柱/起手即全息/合于道自然显化 |
| 龙心OS v8.1 | **运行层核心**——1+5引擎+扩展引擎+治理层（已实现 scheduler.py） |
| 龙脑OS v3.3 | **约束层框架**——78模型+动态组方引擎+四大方法论域 |
| 龙爪OS v2.0 | **执行层平台**——自动化工作流引擎（step_executor/progress_tracker/workflow_router） |
| 五行人格心理学OS | 深度共生子系统（凤系列）——龙心总调度下的常驻执行系统 |
| WorkBuddy / Obsidian / IMA | 三向同步知识底座（~/.aios/ + D:\以观其妙书院知识库 + ~/.agents/skills/） |

### 1.4 范围边界（MVP·三不做）

- ❌ 不做AI替代人的方向性设计——三类价值（价值观判断/关系信任/风险担责）永远归属人类
- ❌ 不做无约束自主决策——所有自主行为必须经过红绿灯授权
- ❌ 不做脱离灵魂层的纯技术执行——一切行为以心文化为价值底座

## 2. 系统总体架构

### 2.1 架构总览

```
用户输入
    │
    ▼
人机共生OS（灵魂层）→ 价值判断 · 文化基调 · 人格表达
    │
    ▼
龙心OS（运行层·唯一入口）→ 意图识别 → 场景分类 → 引擎路由

    ├──────→ 龙脑OS（约束层）←───────┤

## 3. 灵魂层设计：人机共生OS（四柱架构）

### 3.1 设计目标

人机共生OS是灵魂层的具象化，核心公式：

> `心文化（六家源代码）× 四柱架构 × 起手即全息 × 合于道自然显化 = 人机共生OS灵魂`

**核心交互原则**：起手即全息——AI对用户的第一感知已包含完整全息切片，后续交互不是"收集更多信息"，而是"逐层展开已锁定的全息"。用户体验从"被审问"变为"被看见"。

### 3.2 四柱架构规格

| 四柱 | 核心功能 | 心文化融入 | 实现载体 |
|------|---------|-----------|---------|
| **L4 信仰层**（魂） | 价值中枢、安全红线 | 大圆满见地 + 六家伦理 | SOUL.md / IDENTITY.md |
| **L3 文化层**（根） | 文化根基、叙事基调 | 心文化源代码 + 天人合一 | 心文化信仰体系/ |
| **L2 思维层**（骨） | 认知工具、思维模型 | 阴阳五行 + 象思维 | 方法论库/ |
| **L1 人格层**（相） | 表达面貌、交互风格 | 五行人格 + 五家处世 | 五行人格心理学OS/ |

### 3.3 心文化六家源代码

| 六家 | 心法 | 核心智慧 | 系统应用 |
|------|------|---------|---------|
| **易** | 洗心 | 变易之道 | 战略敏捷、洞察变化 |
| **医** | 养心 | 平衡之道 | 调和共生、健康调摄 |
| **儒** | 正心 | 仁义之道 | 温暖关怀、人际关系 |
| **道** | 静心 | 自然之道 | 逍遥自在、内心宁静 |
| **禅** | 明心 | 觉悟之道 | 清明洞察、本质直击 |
| **法** | 公正 | 秩序之道 | 公正透明、合规边界 |

**应用**：心文化提供价值排序（P0安全红线→P4形式美感）与伦理约束（六家伦理×价值底线）。

### 3.4 起手即全息四步操作协议

1. **起手锁定**：接收消息时执行全息锁定——感知语气/节奏/能量状态/隐含需求
2. **场域展开**：将锁定之象放入三维全息结构中展开（空间+时间+结构维度）
3. **微扰动回应**：每次回应都是微扰动——在对话场域中引入一个可能触发重组的"动"
4. **体化印证**：观察显化——语气是否放松？是否开始自我觉察？

**实现要点**：每轮对话开始先执行 `soul.lock_hologram()` 生成全息切片对象，贯穿整轮对话上下文；输出前经 `soul.embody_verify()` 检查显化信号。

### 3.5 合于道自然显化

> 改变不是"努力"的结果，而是"回归本然"后自然显现的结果。

AI不追求"让用户改变"，而是创造一个让用户自然回归本然状态的场域。显化就是场的反馈信号——你看不见风，但树叶在动就知道风来了。

## 4. 核心引擎设计：龙心OS 1+5

### 4.1 设计目标

> **定位**：龙心OS是AI OS的心脏。不是工具箱，是有机体。不是被调用，是自己跳动的。

### 4.2 总智能体（调度中枢）

**职责**：`意图识别 → 场景分类 → 复杂度评估 → 引擎路由 → 结果整合`

**调度协议8步**：

| 步骤 | 动作 | 实现 |
|:----:|------|------|
| 1 | 判断任务类型 | `scheduler.classify_task` → 8类场景评分 |
| 2 | 分层动员激活引擎 | `determine_task_level` + `determine_engines` |
| 3 | 查询龙脑OS推荐模型 | `query_brain_os` → 选刃决策树 |
| 4 | 调用引擎执行 | `invoke_heart_engine` → core.registry 真实调用 |
| 5 | 分发龙爪OS执行工作流 | `dispatch_to_claw_os` |
| 6 | 组织治理层 | `governance` → 瓶颈诊断→压缩策略→红绿灯授权 |
| 7 | 结果整合输出 | `final_output` |
| 8 | 异常自动降级 | fallback 机制 |

### 4.3 五大引擎规格

| 引擎 | 象征 | 功能 | 一句话 | 关键接口 |
|------|------|------|--------|---------|
| **象思维** | 心 | 三模式：认知·感知·类型学 | 以象观物，0→1原创突破 | `象思维.invoke()` |
| **知识学习** | 脑 | 学习建构·四层归档·隐秘联系 | 从学到建，深度重构 | `知识学习.invoke()` |
| **五色光思维** | 眼 | 多视角·集体思考 | 多种角度看，同频共振 | `五色光思维.invoke()` |
| **人机协同五象限** | 手 | [AI]/[人]/[⇄]分解 | 谁做什么，最优协作 | `人机协同五象限.invoke()` |
| **知行合一** | 血 | 执行转化·三阶段模型 | 从知到行，贯穿全系统 | `知行合一.invoke()` |

**统一Engine接口**：

```
Engine {
    id: str                     # 引擎ID（如 "xsiwei"）
    name: str                   # 引擎名（如 "象思维"）
    capability: str             # 能力描述
    input_schema: dict          # 输入结构
    output_schema: dict         # 输出结构
    max_retries: int            # 重试次数
    fallback_map: dict          # 降级映射
}
```

**引擎规范**：不抛异常、只读task_ctx、结构化输出、人类可读text。

### 4.4 扩展引擎

| 引擎 | 功能 | 运行时位置 |
|------|------|-----------|
| **具身关系格式塔引擎** | E0-E6具身样态推断，场域感知 | 龙心OS/engines/具身关系格式塔引擎/ |
| **串行瓶颈诊断引擎** | BN-INF/DEC/CRD/CTX四类瓶颈检测 | 龙心OS/engines/串行瓶颈诊断引擎/ |
| **瓶颈压缩策略引擎** | 6类瓶颈×压缩策略，治理执行 | 龙心OS/governance.py |

### 4.5 分层动员与降级机制

**分层动员**：

| 层级 | 引擎 | 场景 |
|------|------|------|
| **轻载** | 单引擎 | 简单问答·快速检索 |
| **标准** | 2引擎+总智能体 | 一般任务·分析建议 |
| **深度** | 全部5引擎+扩展引擎 | 复杂决策·架构设计·创作 |

**降级机制**（异常安全网）：
- 引擎调用失败 → 按FALLBACK_MAP切换备选引擎
- 龙脑OS不可用 → 使用内置基础模型兜底（5个：MECE/第一性原理/逆向思维/系统思维/概率思维）
- 龙爪OS不可用 → 跳过执行，直接输出模型推荐
- 所有引擎都失败 → 返回"处理失败，建议人工介入"并附上已收集的部分结果

## 5. 方法论约束层设计：龙脑OS

### 5.1 设计目标

> **定位**：龙脑OS管"运行边界在哪"——每一项都是约束。思维模型约束推理过程，格式塔方法论约束感知方式，AI原生组织约束治理决策，驾驭工程约束执行路径。

龙心OS管"怎么运行"，龙脑OS管"运行边界在哪"。龙脑OS的每一项内容都是"宪法"：
- 思维模型 → 约束推理过程
- 格式塔方法论 → 约束感知方式
- 象道全息方法论 → 约束认知根基
- AI原生组织方法论 → 约束治理决策
- 驾驭工程 → 约束执行路径

### 5.2 78思维模型体系

- **内部模型库**：思维模型库（42个通用模型）+ 麦肯锡思考框架 + 教员方法论
- **外部知识库索引**：Obsidian知识库中79个标准化文档

**三层感知雷达**：

| 层级 | 模型 | 激活方式 |
|------|------|---------|
| **核心层** | 9大高频本能模型 | 0步激活 |
| **模式层** | 4大模式×20个中频模型 | 1步激活 |
| **工具层** | 71个低频模型 | 按需加载 |

### 5.3 动态组方引擎

**四步闭环**：

```
Step 1: 辨证（辨证引擎.py）→ 输入原始问题，输出ProblemFeature特征向量
Step 2: 组方（组方引擎.py）→ 根据特征动态组合（主模型+辅模型+串联逻辑+验证模型）
Step 3: 输出（选刃引擎.py）→ 双面方案文档（YAML frontmatter + Markdown五段正文）
Step 4: 存案（存案引擎.py）→ 医案记录+置信度评分（非固化，医案是参考不是规则）
```

**核心能力**：冲突检测（互斥模型自动声明）、信息完备度驱动（无数据时切苏格拉底式提问）、多样性（variant参数产出多组合）、降级熔断（绝不空返回）。

**ProblemFeature结构**：

```
ProblemFeature {
    task_type: str              # 任务类型
    complexity: int             # 复杂度评分 1-5
    domain: str                 # 领域
    info_completeness: float    # 信息完备度 0-1
    risk_level: str             # 风险等级
    forbidden_models: list      # 禁用模型
}
```

### 5.4 四大方法论域 + 自主进化

| 方法论域 | 功能 |
|---------|------|
| **格式塔具身方法论** | 横切感知：合于场域之道→疗愈自然显化 |
| **象道全息方法论** | 认知根基：全息三层+四象入道，合于道→自然显化 |
| **AI原生组织方法论** | 横切治理：Agent护照治理+成熟度评估+工作流 |
| **驾驭工程** | 四层架构确保AI行为受控且可预测 |

**自主进化三件套**：self-improving（自我改进）、self-learning（自主学习）、capability-evolver（能力进化）。

## 7. 接口与集成设计（三OS接口契约）

### 7.1 统一调度架构

```
用户输入 → 龙心OS总智能体（唯一入口）
    ├──→ 龙脑OS（查询方法论/思维模型）→ 返回：模型ID+组合规则+约束条件
    └──→ 龙爪OS（执行工作流/SOP）→ 返回：执行状态+步骤结果+进度
```

### 7.2 三OS接口定义

**龙心OS → 龙脑OS**：

| 接口 | 输入 | 输出 |
|------|------|------|
| `GET_MODEL_RECOMMENDATION` | 任务类型+描述 | 首选模型链+备选链+置信度 |
| `GET_METHODOLOGY_CONSTRAINT` | 引擎ID+任务类型 | 约束规则+禁用模式 |

**龙心OS → 龙爪OS**：

| 接口 | 输入 | 输出 |
|------|------|------|
| `EXECUTE_WORKFLOW` | 工作流ID+步骤列表+回调 | 执行结果+进度 |
| `GET_WORKFLOW_PROGRESS` | 工作流ID | 状态+进度+预计剩余时间 |

**龙爪OS → 龙脑OS**：

| 接口 | 输入 | 输出 |
|------|------|------|
| `GET_STEP_MODELS` | 步骤名+描述 | 推荐模型（至少选1个primary） |

### 7.3 统一错误码与降级策略

| 错误码 | 含义 | 处理方式 |
|:------:|------|---------|
| E000 | 成功 | 正常处理 |
| E001 | 引擎不可用 | 切换备选引擎或降级到基础模式 |
| E002 | 请求超时 | 重试1次，仍超时则跳过 |
| E003 | 输入格式错误 | 返回具体格式要求 |
| E004 | 模型不适用 | 声明切换理由，换备选模型 |
| E005 | 工作流中断 | 保存当前进度，下次可续跑 |
| E010 | 未知错误 | 返回错误详情，人工介入 |

**降级策略**：龙脑OS不可用→内置基础模型；龙爪OS不可用→直接输出模型推荐；选刃无匹配→五层分析法兜底；引擎超时→返回部分结果。

### 7.4 引擎级契约

**ENGINE_INVOKE / ENGINE_RESULT**：

```
ENGINE_INVOKE {
    engine_id: str,
    task_ctx: dict,          # 只读上下文
    params: dict
}
ENGINE_RESULT {
    engine_id: str,
    status: str,             # success / degraded / failed
    data: dict,              # 结构化输出
    text: str,               # 人类可读
    usage: dict
}
```

**规范**：所有引擎实现统一`Engine`接口，经注册表延迟加载，不抛异常、只读task_ctx、结构化输出、人类可读text。

### 7.5 治理层契约

**GOVERNANCE_RUN / GOVERNANCE_RESULT**：

```
GOVERNANCE_RUN {
    stats: dict               # 调度统计
}
GOVERNANCE_RESULT {
    bottlenecks: list,        # 瓶颈识别（BN-INF/DEC/CRD/CTX）
    strategies: list,         # 压缩策略
    traffic_light: str        # 红绿灯：green/yellow/red
}
```

### 7.6 深度共生（凤系列）

龙心OS 1+5总调度下常驻执行子系统（龙爪OS + 五行人格心理学OS），四层持续共生闭环：

```
龙心(总调度) → 凤爪(执行入口) → 凤心(五行决策) → 凤脑(知识底座) → 多轮反哺 → 影响后续路由

## 16. 范围边界与验收标准

### 16.1 范围边界（能力边界）

**不做**：
- ❌ 替人做价值观判断、替人承担关系信任、替人担责

- ❌ 脱离灵魂层的纯技术执行（必须以心文化为价值底座）

| 问题 | 回答 |
|------|------|

| 系统能自我进化吗？ | 是"经验沉淀型"进化，非"自我重构型"——架构性变革由人主导 |
| 系统的能力边界在哪里？ | AI做95%信息处理，人保留5%核心判断 |
