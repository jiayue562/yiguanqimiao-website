# AIOS自进化引擎 v2.0 · 双螺旋

> **一句话**：知识从弹药库流进来变成可调用的内容，经验从对话里沉下来变成龙爪，**两条链咬着转**，不是两条平行线。
> **v1.0 的病**：只有"应该这样"，没有"已经这样"——没经验卡实体、没缺口清单、龙爪 runtime feed 里 21 条真实执行记录躺在那没人用。**v2.0 把它做实。**

---

## 〇、双螺旋与三咬合

```
        知识链 ─────────────────────────────────────────────
  弹药库 → 分层分流 → 模块 references → 可调用索引
 (IMA·Obsidian·核心资料)                    │
                                      咬合① │ 用了哪份弹药
                                            ↓
                                      龙爪执行（runtime feed）
                                            │
                                      咬合② │ 缺什么弹药
                                            ↓
                                      知识缺口清单 GAPS ──→ 下次定向补
        经验链 ─────────────────────────────────────────────
  对话·memory·feed → 经验捕获 → 经验卡 EXP → 判定 → 龙爪
                                            │
                                      咬合③ │ 命中次数回流
                                            ↓
                        热度高 → 升格进 SKILL 正文 ／ 长期零命中 → 归档（自动瘦身）
```

### 三个咬合点（螺旋的关键，缺一个就是两条平行线）

| 咬合 | 字段/机制 | 解决什么 | 不做的后果 |
|---|---|---|---|
| **① 用了哪份弹药** | 经验卡的 `ammunition_used` | 知识→经验可追溯：这次长本事，是因为哪份资料 | 经验成了无源之水，下次复现不了 |
| **② 缺什么弹药** | 经验卡的 `ammunition_missing` → `knowledge/gaps.md` | 经验→知识反哺：干活时发现的空缺，变成下次同步的采购清单 | 弹药库越攒越多却总缺关键那几份 |
| **③ 命中回流** | 经验卡的 `hits`，`_evo_index.py` 定期统计 | 龙爪自动瘦身：热经验进正文，冷经验归档 | 龙爪只增不减，最终变成肥宅 |

> **判据**：一张经验卡如果 `ammunition_used` 和 `ammunition_missing` 都空，说明它跟知识链没咬上——**要么是纯粹的操作手感（可以），要么是你懒得填（不行）**。

## 一、实体目录（真的有，不是写在纸上的）

```
~/.workbuddy/aios-evolution/

└── reports/
    └── EVO-2026-W37.md          # 周进化报告
```

## 二、经验卡模板（一卡一事，不许一卡装三件事）

```yaml
---
id: EXP-20260909-01
title: deep 复制要"先过滤有落点再截断"
date: 2026-09-09
type: 坑 | 方法 | 判据 | 口径        # 四选一
severity: 高 | 中 | 低
source: 对话 | memory日志 | 龙爪feed   # 从哪来的
ammunition_used: [AI原生组织 v3.0-3.5]  # 咬合①：这次用了哪份弹药
ammunition_missing: [味藏组织诊断原始周报]  # 咬合②：这次缺什么弹药
landing: 组织诊断OS v2.0（已落）| 未落
hits: 0                              # 咬合③：被复用次数
---

## 现场（当时发生了什么）
## 做法（怎么解决的）
## 判据（下次怎么一眼认出）
## 落点（落到哪了，没落说明原因）
```

**四型说明**：

| 型 | 装什么 | 举例 |
|---|---|---|
| **坑** | 踩过的雷、返工 | deep 先截断后过滤，只复制 5 份 |
| **方法** | 可复用的做法 | 建设蓝图 → 诊断量表的转化 |
| **判据** | 判断标准、一眼认出的标志 | 编号大小是假象，以日期+内容覆盖为准 |
| **口径** | 术语与说法的统一 | 三层结构（决策/数据/执行），不用"四层" |

## 三、判定：经验往哪落

```
经验卡 → 三问：
  ① 换个对话重来，还要摸索一遍吗？     否 → 只记日志，不建卡
  ② 现有龙爪能装吗？                  能 → SkillManage 加强（改 SKILL.md 的规程段）
  ③ 需要独立运行、有自己的骨架吗？     是 → 新建龙爪（parent 必须是龙爪OS）
```

| 情形 | 动作 |
|---|---|
| 现有龙爪覆盖 | 加强现有（写入对应 SKILL 的 references 或规程段）+ 版本号 +1 |
| 全新能力领域、需独立运行 | 新建龙爪（模板见下） |
| 一次性琐碎 | 只记日志，不建卡 |
| **涉及架构级变更** | **不自动生效，先问悟空**（铁律） |

**新建龙爪最小骨架**（共享自龙爪OS，不自己造）：
```
定真问题（调龙心OS）→ 供刃（调龙脑OS 选刃）→ 出方案
```

## 四、三只脚本（在 `Claw/`）

| 脚本 | 作用 | 用法 |
|---|---|---|
| `_evo_capture.py` | 从 memory 日志 + 龙爪 feed 抓候选经验 → 生成草稿卡落 `_queue.md` | `python _evo_capture.py --days 7` |
| `_evo_index.py` | 重建 `_index.md` + `00-状态盘.md`（热度排序、缺口汇总、落点统计） | `python _evo_index.py` |
| `_evo_weekly.py` | 生成本周进化报告（知识入库量/经验沉淀量/缺口/建议动作） | `python _evo_weekly.py` |

**两个真实数据源**（v1.0 没接上，v2.0 接上）：
1. **`Claw/.workbuddy/memory/YYYY-MM-DD.md`** —— 每次对话的工作日志，是经验的主矿
2. **`~/.workbuddy/skills/龙爪OS/runtime/longzhao_symbiosis_feed.jsonl`** —— 龙爪每次跑项目的执行记录（项目类型/用了哪些模型/闭环是否完成），是**"哪些龙爪真在用"**的证据

## 五、飞行周期

| 周期 | 动作 | 自动化 |
|---|---|---|
| **每次深度对话后** | 沉淀经验卡（当场，不隔夜） | 手动触发 |
| **每日** | 弹药库同步（味藏/AIOS-IMA/Obsidian 三条已有任务） | 已有定时 |
| **每周日 20:00** | 跑 `_evo_weekly.py` → 周进化报告 + 缺口清单 + 建议动作 | 本轮新建 |
| **每月** | `_evo_index.py` 跑热度 → 热卡升格进 SKILL 正文、零命中卡归档 | 手动 |

## 六、安全边界（不可越）

- **不删不改核心内核**：龙心OS 规则体系、龙脑OS、龙爪OS 的架构定义不可变
- **不越权**：新龙爪的 `parent_skill` 必须是 `龙爪OS`，不能挂到 AIOS 总入口
- **不静默**：所有变更必须告知悟空去向
- **不自动生效架构级变更**：骨架级新资料、跨模块口径改动，**先问再动**
- **可回滚**：改 SKILL.md 前备份到 `_trash_backup/`
- **版本号先查**：改版本号前 grep changelog 头部，别覆盖他人条目（今天踩过）
