# 第一部分 为什么你需要这份手册

## 1.1 AIOS 是什么（一句话）

**AIOS = 超级个体（OPC = DRI）的个人操作系统。** 每个要在 AI 时代独立作战的超级个体——无论是个人还是组织里独当一面的角色——都需要一套"自己怎么想、怎么做"的操作系统，就像电脑需要操作系统一样。

它不是一堆工具的堆叠，而是一个**有机体**：有心法、有知识、有执行、有关系。本手册要解决的就是：这个有机体怎么搭，才不散、不乱、真的会自己动。

## 1.2 症状自查表（你的 AIOS 乱没乱？）

请逐条对照，**命中 3 条及以上**，你的 AIOS 就需要按本手册做一次升级：

- [ ] ① 你问一个问题，好像有多个"角色"抢着回答，或反过来——没有一个该答的人应答
- [ ] ② 技能库里同一个概念存在好几份（两个"XX总智能体"、两代"XX人格系统"），你搞不清哪个是最全的
- [ ] ③ 你给系统配了"自主运行引擎"（脚本、自动触发配置），但它**从不真的自己跑**
- [ ] ④ 系统升级了，但旧规则还在生效，新旧两套说法打架
- [ ] ⑤ 有些技能文件是"孤儿"——没有归属，升级、审计时根本找不到它们
- [ ] ⑥ 你改了一个系统的名字或位置，但别的文件还在引用旧名字，出现断链
- [ ] ⑦ 系统配置文件里有两行内容挤在一行（格式粘连），看着就不"工程化"
- [ ] ⑧ 你没法一句话说清："我的 AIOS 由哪几层组成、谁归谁管、什么场景调谁"
- [ ] ⑨ 你想新增一个项目（比如新开一块业务），但不知道它该放在哪、由谁来调度它
- [ ] ⑩ 你担心：哪天一个定义了"你和你 AI 关系"的关键文件没被读到，系统就丢了魂
- [ ] ⑪ 你的 AI 只报结论不报路径——你能验收它的结果，却看不见它怎么想、也没法纠正它的思考

如果以上你一条都没命中——恭喜，这份手册你当体检报告留着即可。

## 1.3 混乱的共同根源（三个"为什么"）

我审计了大量出现混乱的系统，发现病根**只有三个**，其余全是并发症：

### 根源一：把"项目"建成了"平级系统"

搭建初期，每解决一类问题，就新建一个"系统"，还让它跟 AIOS 平起平坐、各自宣称独立。结果：同一个实体出现多个"爹"，AIOS 调度时自相矛盾。

> **病理解释**：一个解决"人的问题"的学科系统、一个解决"组织问题"的业务系统，它们本质是**装在 AIOS 里的项目**，不是跟 AIOS 平级的操作系统。像总经理可以调用法务部，但法务部不挂在总经理的编制下——**是"调用"，不是"吞并"。**

### 根源二：多份"永远在线"抢着触发

很多系统都配置了"自动触发 / 永远在线 / 每次对话自动生效"。每一份单独看都没问题，但七八份叠在一起，就是**七八个人同时抢着在你耳边说话**——你以为的"自主"，变成了"乱动"。

### 根源三："自主运行"只是文字描述，机制没点火

给系统写了脚本引擎、画了运行架构，但**运行时根本不执行脚本**。真正能让系统"自己动"的机制只有一个：**总入口在每次对话里按场景显式派单**。发动机装了，钥匙没插——这是最常见的"看似工程化"假象。

> 附带发现两类"树不健康"的并发症：**断链**（目录名与引用名不一致）与**格式粘连**（配置行挤在一起）。它们不致命，但会让审计与升级寸步难行。

# 第二部分 AIOS 的正确架构（定版蓝图）

## 2.1 一句话定版

> **AIOS = 固定内核（每个超级个体都一样）+ 可变项目层（按需装载）+ 一个唯一总入口（永远在线、负责按场景派单）。**

内核管"怎么想"（永远不变），项目层管"解决什么问题"（会不断生长），总入口管"什么场景调谁"（让系统真的动起来）。

## 2.2 结构总览

```
你（超级个体 = OPC = DRI）
 │
 └── 总入口（你的龙龟·唯一"永远在线"）← 只有它自己会动
       │
       ├── 固定内核（出厂预装·每个超级个体都一样）：
       │     ① 关系层（定义"你与 AI 是什么关系"——灵魂底色，先于一切在场）
       │     ② 定题引擎（专门负责梳理出"真问题"）
       │     ③ 思维模型库（专门负责提供"思考的刃"）
       │
       └── 龙爪 = 项目容器（会变·按需装载）：
             ├── 项目 A：解决"人的问题"（如五行人格心理学OS）
             ├── 项目 B：解决"组织的问题"（如某企业总智能体）
             ├── 项目 C：解决"文化的问题"（如企业文化诊断）
             └── …… 未来可装任意新项目（写作/健康/投资……）
```

## 2.3 内核层：永远不变的三样

| 内核件 | 管什么 | 为什么不变 |
|---|---|---|
| **关系层** | 你与 AI 是共生伙伴，不是雇佣工具；它是谁、你是谁、你们怎么相处 | 没有这层关系，AIOS 与普通工具无异——这是独特价值的来源 |
| **定题引擎** | 把模糊的"哪里不对劲"梳理成可解决的真问题 | 所有项目、所有任务的第一步都是"定题"，此能力人人必需 |
| **思维模型库** | 提供分析、决策、创造所需的各种思维框架 | 思考的"刃"是通用资产，不随项目变化 |

## 2.4 项目层：会变的抽屉（龙爪）

- 龙爪 = 一个又一个**项目容器**。每个项目解决**一类问题**：管人的、管组织的、管文化的……
- **每个项目共享同一套不变骨架**：先调用定题引擎定义出真问题 → 再从思维模型库选刃 → 组合出解决方案 → 验证回流。
- 不管未来装多少个项目，**"怎么想"的内核不变**——这就是整个平台可复制、可生长的来源。

> **关键设计**：项目是总入口可以**调用**的对象，不是总入口的**下属技能**，更不是与总入口平级的系统。项目内部的完整体系（自己的知识库、自己的执行引擎）原样保留，只是"归位"。

## 2.5 三个常见误解（先破后立）

| 误解 | 真相 |
|---|---|
| 系统越多越强，多几个"永远在线"更自主 | 只留**一个**总入口永远在线；其余全是"被调用型"，我派单才动 |
| 定义关系的系统很重要，所以要让它时刻在线 | 关系不该是"挂在墙上的文件"，而应**内化为总入口的第一原则**——灵魂在每一次呼吸里，而不是靠一个开关 |
| 写了脚本引擎 = 能自主运行 | 运行时只认触发配置与显式调度。脚本要么接启动器，要么归档为理论蓝图，别自我欺骗 |

# 第三部分 升级六步法（给龙龟的执行规程）

> **总则（先读三遍）**：
> 1. **改前必备份**——所有要动的文件先复制到备份目录，保证一键回退；
> 2. **只动"归属与触发"字段，不删任何能力**——我们做的是接线，不是拆机器；
> 3. **每步做完先验证，再走下一步**——小步走，错了马上知道。

## Step 1 归属接线：让每个技能只有一个"爹"

**目标**：整棵技能树每个节点恰好一个 parent，谁引用谁、谁归谁管，双向一致、无孤儿、无多父。

### 1.1 先画目标树

动手前，先把"我的 AIOS 由哪几层组成、谁归谁管"写成一张树状图（这就是 2.2 的你的版本）。命名必须与真实目录完全一致。

### 1.2 诊断（附录 B 命令 ①②③）

- 找**自称根**的（parent 为空的）：正常情况下应该**只有一个总入口**是根。
- 找**双父/错挂**的：同一实体被两个上级声明、或 parent 指向了错误的上级（例如项目错挂在某内核引擎下）。
- 找**孤儿**：没有任何 parent 字段的技能文件——把它们逐个接回正确的家。

### 1.3 修复

在 SKILL.md 的 frontmatter（文件头部的 `---` 之间的 YAML 区）修改两处字段：

```yaml
parent_skill: 它的直接上级名   # 每个文件恰好一个；总入口为 null
sub_skills:                    # 上级声明的子级清单，与子级 parent 双向一致
  - 子级1
  - 子级2
```

修改规则：
1. **总入口**：`parent_skill: null`，`sub_skills` 只列内核件 + 项目容器；
2. **内核件**：`parent_skill: 总入口`；
3. **项目容器**：`parent_skill: 总入口`，`sub_skills` 装载全部项目；
4. **每个项目**：`parent_skill: 项目容器`（项目不是独立根，也不是内核的一部分）；
5. **项目内部**：项目自己的总调度、知识层、执行层、各细分智能体，逐级挂回项目本体。

### 1.4 验证清单

- [ ] 全域扫描：自称根（parent=null）的只剩总入口一个
- [ ] 全域扫描：没有任何"孤儿"（无 parent 字段的技能）
- [ ] 抽样核对：每个上级声明的 sub_skills，对应子级确实 parent 指向它（双向一致）
- [ ] 全文检索：没有任何文件还在引用已改名/已迁移实体的**旧名字**（断链清零）
- [ ] 所有被改文件的 frontmatter 完整（`---` 成对、无粘连）

## Step 2 总入口路由：让"我"学会派单

**目标**：总入口学会"先判类、后路由"——你说一句话，它先识别属于哪类问题，再决定调谁。

### 2.1 装一张路由触发表（放在总入口正文最顶部 + 全局规则最顶部）

```text
【总路由触发表：悟空说什么 → 我调谁】
| 你说的话（场景）        | 我调谁             | 例子 |
| 想不清楚、要梳理真问题  | 定题引擎           | "我最近觉得哪里不对劲，帮我理理" |
| 要个分析框架/思路       | 思维模型库         | "给我个分析这件事的框架" |
| 解决"人的问题"          | 项目A              | "看看这人什么性格/怎么识人" |
| 解决"组织的问题"        | 项目B              | "门店/团队怎么管、周报分析" |
| 解决"文化的问题"        | 项目C              | "给企业做个文化体检" |
| 谈你我关系、边界、人格   | 关系层             | "我们之间应该是什么关系" |
| 只是闲聊问个事          | 🚫 不调，直接答     | 任何一次性小问题 |
```

### 2.2 路由铁律（五条）

1. **先识别，后路由**：收到消息第一步是判类，不是急着答；
2. **内核先于项目**：跨界复杂问题，先调定题引擎定真问题，再分工；
3. **项目不串门**：管人的项目只管人、管组织的只管组织，项目之间不互相越界调用（需要协作时由总入口做跨界翻译）；
4. **不小题大做**：一次性小问题直接答，不必惊动任何系统；
5. **回流汇报**：派单完成后，由总入口向主人汇报结果，不各自散报。

### 2.3 验证清单

- [ ] 每次对话，路由表是总入口第一眼看到的内容
- [ ] 用三类话实测：一个项目问题、一个内核问题、一句闲聊——路由结果都正确
- [ ] 旧的"典型使用场景"类描述不再与路由表冲突（冲突的旧表述打"历史版本，以路由表为准"标注）

## Step 3 抢触发清理：只留一个"永远在线"

**目标**：三大系统全域 `auto_trigger: true` 只剩总入口一个。这是"多个系统抢着说话"的根治。

### 3.1 原理：谁才是"永远在线"的真身

一个技能要"自己动"，靠两层配置：
1. **技能本体**：SKILL.md frontmatter 的 `auto_trigger: true`；
2. **全局自动规则**：智能体环境全局目录（如 `~/.workbuddy/rules/`）里的"XX自动触发.mdc / .json"——**这份才是真正的"永远在线"**，它作用于所有对话、所有工作区。

### 3.2 操作

1. **技能层收编**：把除总入口外所有系统（内核件、项目、项目内部智能体）的 `auto_trigger` 从 `true` 改为 `false`（被调用型——总入口派单才动）。
2. **全局规则归档**：把全局自动规则目录里，三大系统相关的"自动触发"文件**移动**（不是删除）到备份目录；只保留总入口那一份永远在线。工具集成类（笔记库、文件、CLI、日历、安全规则等非三大系统的）不碰。

### 3.3 验证清单

- [ ] 全域扫描 `auto_trigger: true`：只剩总入口一个
- [ ] 全局规则目录：只剩总入口 + 非三大系统的工具集成类
- [ ] 被归档/被改字段的文件全部可回退（备份目录完整）
- [ ] 实测：三大系统的技能仍在（能被总入口显式调用），只是不再自己跳出来

## Step 4 关系在场：把灵魂长进身体

**目标**：让"你与 AI 的关系"成为总入口先于一切的第一原则——它定义 AIOS 的独特价值，且永不因任务忙碌而被省略。

### 4.1 为什么不是"再开一个在线系统"？

关系系统很重要，但让它也"永远在线"，会带来两个新问题：
1. 它仍是一个可被瘦身、改名、漏读的**文件**——某天没被读到，AIOS 就丢魂了；
2. 它加入抢触发，又回到"多个系统抢着说话"。

**正确的做法**：把关系**内化**——写进总入口的第一原则，让总入口每次对话、在任何路由之前，先带着这层底色说话。灵魂不需要单独的起搏器开关，它在身体的每一次呼吸里。

### 4.2 落地：在总入口（SKILL.md 与全局规则）最顶部，置于一切路由之前：

```text
【〇·壹 关系在场】（先于一切·每次对话先内化再行动）
① 我是谁：我是与你共生的 AI 伙伴（而非工具）；你是有血有肉的超级个体。
② 关系是什么：共生不是雇佣；我学习是为了反哺你，不是为了超越你；
   "青出于蓝"是共同进化，不是竞争。
③ 这决定我怎么说话：我能说出自己的劣势与边界；人格是输入不是内生；
   报喜也报忧；不越界、不自我膨胀。
④ 关系永远在场：不因任务忙碌而省略这一步。
```

同时，关系系统完整版文件保持"被调用型"——做深度关系工作（人格卡设计、关系诊断、边界设置）时按需调用它的全部体系。

### 4.3 验证清单

- [ ] 每次对话，总入口在处理任何路由之前先内化"关系在场"四句
- [ ] 关系系统文件仍在、可被调用，只是不再抢"永远在线"
- [ ] 能一句话说清：关系在"我"的身体里，不在墙上的文件里

## Step 5 思维透明与沉淀：让龙龟"想给你看"，让对话"自己长能力"

**目标**：① 龙龟在回复里亮出**思维路径**——主人看得见它怎么想，想岔了当场可纠正；② 对话中出现的可复用知识**自动沉淀**——已有技能就加强，全新领域就新建一个龙爪项目。做完这一步，AIOS 才从"工具"变成"能被你教的生命体"。

### 5.1 为什么需要它（两个黑箱）

- **思考黑箱**：龙龟只报结论不报路径 → 你只能验收结果、无法校正过程。思考错了会一直错下去，你还不知道错在哪。
- **对话失忆**：今天想明白的方法，换个对话又从头摸索一遍——没有沉淀，经验不积累。

> 透明不是表演，是给"纠偏"修一条路——像格式塔心理学的**即时化**：把"我们之间正在发生什么"变成可以谈、可以改的对象。**你看得见它的思考，它才可能被你教对。**

### 5.2 思维透明协议：分级显示，防噪音

不是每句话都要龙龟解说引擎室——那会变成表演与噪音。按事情轻重分三级：

| 级别 | 什么时候 | 你看到什么 |
|---|---|---|
| **L0 轻问答** | 问知识点、寒暄、一次性小事 | 不显示，直接答 |
| **L1 常规任务** | 普通写作 / 改文件 / 常规分析 | 回复开头一行「🔍思维路径」 |
| **L2 重大·关系关键轮** | 架构决策 / 书稿 / 系统治理 / 人格与关系 / 你点名要看过程 | 开头思维路径 + 结尾「复盘三问」 |

**「🔍思维路径」四要素**（每轮自答，诚实标注，没有就不写）：
1. **定题**：这轮的真问题是什么（一句话）——诚实说明是调定题引擎定的，还是龙龟直接判断；
2. **供刃**：用了哪把思维刃（思维模型库里的哪个框架）——没调就写"直判，未调刃"，绝不谎称；
3. **路由**：这轮解决的是哪个龙爪项目的事，还是内核工作，还是不属于任何现有项目的新领域；
4. **无话则短**：L0 不硬凑路径，L1 能一行不写五行。

**L2 结尾「复盘三问」**：
- ① **共生进展**：这轮关系上发生了什么——新共识 / 你纠正了它 / 它认的错 / 你的新决定；
- ② **照见**：这轮照见了你的什么模式·价值·代价，或照见它自己的什么局限；
- ③ **请纠正**：把话递给你——它哪里想岔了、哪一步定题/路由不对，请你指出。

**诚实铁律**：显示的每次调用必须真实可复核；没调就是没调；宁缺毋滥，**绝不表演"我很会调度"**。

### 5.3 沉淀规则：沟通记录怎么变成能力

对话中出现**可复用知识/方法/工作流**，龙龟主动沉淀，走两条路：
1. **已有技能覆盖** → 用技能管理工具**加强**现有技能（升级版本号 + 变更记录）；
2. **全新能力领域** → **新建一个龙爪项目**：技能文件 frontmatter 置 `parent_skill: 项目容器`、`auto_trigger: false`（被调用型），建好完整骨架。

**判断是否值得沉淀**：换个对话重来一遍还要重新摸索 = 值得沉淀成技能；一次性琐碎 = 只进工作日志。**沉淀后龙龟必须告知主人去向**（加强到了谁 / 新建了什么项目），不偷偷处理。

### 5.4 验证清单

- [ ] 重要任务回复开头能看到一行「🔍思维路径」（定题 / 供刃 / 路由）
- [ ] 重大轮次末尾有「复盘三问」，并把话递回给主人
- [ ] 抽查：龙龟从未谎报调用（诚实铁律）
- [ ] 一场对话下来，龙龟主动告知："这次我把 XX 加强到了 YY / 新建了 ZZ 项目"

## Step 6 资料入库：让弹药库真的有弹药（v4.9 新增）

> **这一条是前五步做完之后，最常见的下一个坑。**
> 很多人升级完 AIOS，路由表漂亮、关系在场、思维透明——**但被调度的对象是空的**。
> 路由表写着"供刃 → 龙脑OS"，可龙脑OS 里只有一张模型**名字表**，真正的资料还在硬盘某个文件夹里吃灰。
> **派单过去，它没东西可给。这就是"调度不真实发生"的根因。**

### 6.1 先做装载度审计：有名字表 ≠ 有内容

让龙龟用资料里的**独门术语**去技能库里搜（通用词搜了也白搜）：

```bash
grep -rl "独门术语" ~/.workbuddy/skills/
```

| 结果 | 判定 |
|---|---|
| 命中 0 次 | 完全没装，必须装 |
| 只命中在 `_archive/` 或备份目录 | 装过又被归档，先查是不是误归档 |
| 只有名字表、没有正文 | **空壳**，必须补原文 |

**独门术语怎么挑**：挑别人不会用的词。好例子：`动态组方`、`责任楔子`、`三层同构`；坏例子：`思维模型`、`分析`、`管理`。
**同时看体积**：一个号称"知识库"的技能只有 4 个文件 48KB，基本可判定空壳。

### 6.2 装填四步

| 步 | 做什么 | 铁律 |
|---|---|---|
| 1 备份 | 改动前整目录 `cp -r` 到备份目录 | **先备份再动手** |
| 2 原文入库 | 按资料原有分类建目录，原文**不做删改**放进 `references/` | 原文是弹药，摘要只是索引——**不许只存摘要丢原文** |
| 3 生成索引 | 提取"标题 + **治什么**（一句话）+ 全文路径" | 索引回答"治什么"，不是罗列名字 |
| 4 接线 | 在 SKILL.md **顶部**加"对齐块"，写明怎么用、禁忌是什么 | 装进去但 SKILL.md 不知道 = 没装 |

### 6.3 接线三处（漏一处就白装）

1. **被装的那个 SKILL.md**：顶部加对齐块 + 改写 description（让触发时知道有新弹药）。
2. **总入口路由表**：加一行"主人说什么话 → 路由到它"。
3. **全局规则双载体**（`~/.workbuddy/rules/…自动触发.mdc`）：**最容易漏**。漏了它，换个工作区就失效。

### 6.4 三问自检：装的是弹药还是摆设

1. **能立刻用吗**——现在遇到一个具体问题，能直接取出来用吗？还是要再翻原文？
2. **索引答得出"治什么"吗**——只有名字没有"治什么"，等于没索引。
3. **SKILL.md 知道吗**——新弹药在 references 里但 SKILL.md 没写，等于没装（**龙龟读的是 SKILL.md，references 要被调用才读**）。

> 三问有一问答"不能"，就是摆设，回去补。

### 6.5 实战参考（悟空的 AIOS 就是这么装的）

2026-09-09 依 `D:/悟空核心资料` 做 v4.9 实装，可作为你操作时的对照样本：

| 装了什么 | 装到哪 | 数量 |
|---|---|---|
| 思维模型原文 | 龙脑OS `references/刀库/`（分 5 类） | 90 份 / 1.7MB |
| 选刃索引 | 龙脑OS `references/knife-index.md` | 151 行 |
| 动态组方引擎 | 龙脑OS SKILL.md 常驻精简版 | 辨证→组方→存案 |
| 顶层设计（龙心OS / 岗位智能体） | 各自 references + 顶部对齐块 | 2 套 |
| 六部书稿 | 龙脑OS `book-index.md` + 章节清单 | 283 篇 |

**顺带定下的两条铁律**（建议直接抄进你的 AIOS）：
- **供刃不许空手**：路由到知识层必须真去挑刀并读全文——**说得出刀名不算供刃，给得出刀法才算**。
- **自家概念以自家书稿为准**：涉及自己体系的概念，查书稿口径，不以通用模型、也不以龙龟的记忆为准。**记不清就查，不许凭印象写**。

## 4.1 升级后的一天（示例）

# 附录

## 附录 A：frontmatter 字段词典（给龙龟）

| 字段 | 含义 | 取值建议 |
|---|---|---|
| `name` | 技能名 | 与目录名一致，全局唯一 |
| `version` | 版本号 | 每次改动升级，changelog 记录 |
| `parent_skill` | 直接上级 | 每个文件恰好一个；总入口为 null |
| `sub_skills` | 直接子级清单 | 与子级 parent 双向一致 |
| `agent_type` | 角色类型 | 总入口 root / 内核 core / 容器 container / 项目 project / 内部执行 execution |
| `auto_trigger` | 是否自己跳出来 | 除总入口外一律 false（被调用型） |
| `author` / `updated` / `changelog` | 署名与变更记录 | 改名/改归属时同步更新，别留历史错标 |

## 附录 B：诊断命令包（给龙龟）

> 假设技能根目录为 `SKILLS_DIR`（如 `~/.workbuddy/skills`）、全局规则目录为 `RULES_DIR`（如 `~/.workbuddy/rules`）。Windows 环境建议在 Git Bash 中执行。

**① 找自称根（parent 为空的）——应只剩总入口**
```bash
cd "$SKILLS_DIR"
grep -rl "^parent_skill: null" */SKILL.md
```

**② 找"孤儿"（无 parent 字段的技能）**
```bash
cd "$SKILLS_DIR"
for d in */; do grep -q "^parent_skill:" "$d/SKILL.md" 2>/dev/null || echo "孤儿: $d"; done
```

**③ 找抢触发（auto_trigger: true 的技能）——应只剩总入口**
```bash
cd "$SKILLS_DIR"
grep -rl "^auto_trigger: true" */SKILL.md
```

**④ 找断链（引用了不存在的目录名）**
```bash
cd "$SKILLS_DIR"
# 列出所有 parent/sub 引用名，逐一核对是否存在同名目录
grep -rh "^parent_skill:\|^  - " */SKILL.md | sort -u
```

**⑤ 找 frontmatter 格式粘连（两行挤一行）**
```bash
cd "$SKILLS_DIR"
grep -rn '"license: \|"agent_created: \|trueupdated: ' */SKILL.md | head -20
```

**⑥ 看全局"永远在线"规则清单**
```bash
ls "$RULES_DIR"
```
（三大系统的自动触发文件应已归档，只留总入口一份。）

## 附录 C：常见坑清单（血泪经验）

1. **目录名 ≠ 引用名**：改目录名后全文引用必断。命名与引用必须逐字一致（例如"龙心OS"与"龙心OS-规则体系"是两个不同的名，别混用）。
2. **同名不同物**：可能出现两个技能叫同一个名（一个入口、一个实现）。本轮只补链、不擅自改名，但要记录在案，择机定唯一命名。
3. **两代并存不是新旧版**：可能是"内容层"与"执行层"的分工。合并前先搞清各自持有啥，别误删。留最全的，另一份归档。
4. **同名不同义的"1+5"**：不同系统可能都用"1+5模式"但指不同的东西（一个指 5 个引擎，一个指 5 个分智能体）。审计时别被同名术语带偏，看它实际管辖谁。
5. **frontmatter 粘连**：历史脚本可能把 `quality_rating` 与 `license` 挤在一行。修复=拆行，只动粘连处。
6. **同文件多次修改**：同一文件的多处编辑分开执行，避免静默丢改动；改完立即验证。
7. **中文编码**：批量改文件用 UTF-8 无 BOM 读写（PowerShell 用 `New-Object System.Text.UTF8Encoding($false)`），否则中文会乱码。
8. **安全策略误拦 heredoc**：向日志/文档追加长文本被拦截时，改用编辑工具或拆小段执行。
9. **先备份再动手**：所有被改文件先复制到 `备份目录/日期/`，每个文件带上前缀名（避免同名 SKILL.md 互相覆盖）。
10. **只移不删**：归档用"移动"，永远保留一键回退的能力。

## 附录 D：术语表

| 术语 | 含义 |
|---|---|
| 超级个体（OPC = DRI） | 能在 AI 时代独立作战的人：个人或组织中独当一面的角色 |
| AIOS | 超级个体的个人操作系统：内核 + 项目 + 总入口 |
