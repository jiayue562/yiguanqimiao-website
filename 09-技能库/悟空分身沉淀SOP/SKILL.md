# 悟空分身沉淀 SOP（v1.0 · 分身持续生长机制）

> **本 SOP 是「悟空语言风格与思维」SKILL.md v1.4 中"分身本体论·4. 分身的生长机制"的实现层。**
> **每一次悟空发新材料，就执行一次本 SOP，让分身进化一次。**

---

## 一、触发条件

满足以下任一条件即触发：

| 触发 | 来源示例 |
|---|---|
| 悟空发 long-text 文本块 | 聊天记录 / 会议转写 |
| 悟空发 docx 文件 | 讲稿 / 录音文字稿 |
| 悟空说"继续发你很多我的真实讲话材料" | 显式授权 |
| 悟空说"沉淀出我"、"建立分身" | 显式指令 |
| 悟空说"把这个沉淀一下" | 单次沉淀指令 |

---

## 二、沉淀链路（八步走，每步都不能省）

### Step 1 · 原始材料入库

**目标**：把悟空发的所有材料原文落到 `references/语料样本-YYYY-MM-DD第N批-XXX.md`。

**操作**：
1. 若悟空发 docx → 用 venv python + python-docx 全文读取，存为 `.md`（保留原话 P 编号位置）
2. 若悟空发 long-text → 直接存为 `.md`（按上下文已显示部分）
3. 若材料是 chat 片段 → 单独切片归档，注明出处

**文件命名**：`语料样本-YYYY-MM-DD第N批-{材料简称}.md`
- 例：`语料样本-2026-09-10第三批-分身训练语料.md`

**SKILL.md 不动，仅做引用**。

---

### Step 2 · P 编号切片

**目标**：把原文切成可定位、可引用的最小单元。

**规则**：
- P 编号 = `P{来源缩写}-{四位序号}`
- 来源缩写：
  - 五色光思维会议 → `P五-`
  - 普陀山共修 → `P普-`
  - 聊天记录1 → `P聊1-`
  - 聊天记录2 → `P聊2-`
  - 聊天记录3 → `P聊3-`
  - 贾老师讲稿3 → `P讲3-`
  - 组织向 AI 原生转型研讨会 → `P转-`
- 新批次用新缩写（如 `P{场景名}-{序号}`）

**每个 P 编号必须配**：
- 原文（含语气词）
- 说话人（悟空 / 芳芳 / 其他人）
- 时间或场景锚点

---

### Step 3 · 候选沉淀抽取

**目标**：从 P 编号切片里**抓**出可沉淀的条目——思维 / 情感 / 方法论。

**操作**：
1. 通读切片，找**反复出现**的模式（一处是金句，三处是思维）
2. 找**现场生成并命名**的资产（悟空当场说"这个就叫 X"）
3. 找**反常的话**（"别 X"、"不是 X 而是 Y"——这些是边界，最有信息量）
4. 找**带代价的判断**（不是"应该 X"而是"不 X 会 Y"）

**候选条目 = `思维/情感/方法论名 + 主张（一句话）+ P 编号引用（≥2 处）+ 判据（什么时候用）`**

**禁忌**：
- ❌ 从悟空书稿归纳（违反本体论铁律）
- ❌ 凭印象合并两条（必须有原话对照依据）
- ❌ "按框架猜他会这么想"——这是猜不是抓

---

### Step 4 · 自主决策进卡

**目标**：按悟空授权"你自主决定"决定哪些进 SKILL.md。

**决策标准**：
| 候选 | 进卡决策 | 理由 |
|---|---|---|
| 配 ≥2 处原话 | ✅ 默认进 | 实证足够 |
| 配 1 处原话 | ⚠️ 看密度 | 若该批材料整体密度高，可进；否则留底 |
| 配 0 处原话 | ❌ 不进 | 违反本体论铁律 |
| 与已沉淀条目重合 | ⚠️ 看是否新角度 | 新角度则进并保留旧；纯重合则弃 |

**输出**：本批沉淀决策表（markdown 表格，存入 references 索引文件）

---

### Step 5 · SKILL.md 升版

**目标**：把进卡的条目写入 SKILL.md，对应章节。

**操作**：
1. 在思维节末尾追加新条目（编号顺延）
2. 在情感节末尾追加新条目
3. 在方法论节末尾追加新条目
4. 更新 frontmatter：
   - `version: 1.X → 1.Y`
   - `description` 同步扩展（触发词+条目数）
5. 更新升级记录（在 SKILL.md 末尾"沉淀"行追加本次）
6. 更新思维图谱节标题条目数（如"四十五条"）
7. 更新 references 节指向新的索引文件

**同文件多次 Edit 必须分消息执行**（避免静默丢失）。

**每次 Edit 后必须 Python 直读验证**（Read 工具有缓存，可能看不到最新状态）。

---

### Step 6 · references 留底

**目标**：本批所有决策、原话、候选全部留底到 references/。

**操作**：
1. 更新 `references/语料样本-{本批名}.md`（本次沉淀的全量明细）
2. 创建/更新 `references/语料样本-{本批名}-索引.md`（P 编号索引）
3. 不修改已沉淀的旧 references 文件（保留历史）

## 五、常见错误（写在这里防再犯）

| 错误 | 表现 | 修复 |
|---|---|---|
| **Edit 工具静默失败** | 报告 success 但 Read 看不到 | 用 Python 直读验证 |
| **frontmatter 字符串不匹配** | description 与已修改版不一致 | 重 Read 后精准 Edit |
| **章节编号顺延** | 插入新节后没改后续编号 | 全文件 Grep `^##` 检查 |
| **思维条目数不一致** | description 写"三十四条"但实际四十五条 | description 与标题同步更新 |
| **三处同步遗漏** | 只改了主技能库 | 必须 Obsidian + LLM Wiki + Claw 三处 |
| **归纳当沉淀** | 没原话就进卡 | 退回 Step 3 重抽 |

## 六、本 SOP 的"自体进化"

**本 SOP 本身也会进化**。每次沉淀跑出新经验：
1. 沉淀链路如果发现新坑 → 在第五节"常见错误"追加
2. 触发条件如果发现新场景 → 在第一节追加
3. 验证方法如果发现新手段 → 在第七步追加

**版本号永远递增（v1.0 → v1.1 → …）**，永不"沉淀完成"——和分身本体同步。
