## 三、目录结构决议（关键适配·需悟空知悉）

### 你的原始设计
```
C:\Users\jia'yue\.workbuddy\skills\五行人格心理学OS\
├── SKILL.md
├── 凤爪OS\SKILL.md
├── 凤心OS\SKILL.md + 五行分智能体\
├── 凤脑OS\SKILL.md + references\
└── triggers\
```

### 实测约束（侦察发现）
1. **WorkBuddy 仅从顶层 `~/.workbuddy/skills/<name>/SKILL.md` 加载技能**——嵌套子技能（如 `五行人格心理学OS/凤心OS/SKILL.md`）**不会被自动加载**。
2. **现有 凤心OS / 凤脑OS / 凤爪OS 已被 192 个文件引用**（含 `AI龙龟共生伙伴操作系统` 主路由、`L1·一心·统摄`、CHMN-BRAIN 等）——移动或合并会断裂整个技能生态。

### 决议：顶层协调者模式（适配后）
```
C:\Users\jia'yue\.workbuddy\skills\
├── 五行人格心理学OS\        ← 新增·顶层可加载·总智能体入口（协调者）
│   └── SKILL.md             （声明三层调用协议，路由到下方三者）
├── 凤心OS\                  ← 保留·现有 v3.2（不移动，保护192处引用）
├── 凤脑OS\                  ← 保留·现有 v3.1
└── 凤爪OS\                  ← 保留·现有 v1.3
```
- **Obsidian 端**仍严格按你的规范归集于 `05-五行人格心理学/`（凤爪OS-一心统摄/、凤心OS-智能发动机/、凤脑OS-知识地基/ 等子目录）。
- 这样既实现"统一包"的调度意图，又**兼容加载机制与现有生态**，零破坏。

> 若悟空后续坚持要物理合并为单一嵌套包，需先完成 192 处引用的重定向改造——列入 P3 优化迭代，不在首批。
