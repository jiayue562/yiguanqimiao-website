> 生效：2026-11-14　|　适用：`D:\以观其妙书院知识库\以观其妙书院`　|　维护者：龙龟神将
> 本文件是**硬性协议**，不是建议。任何 AI（含本会话后续调用、外部 Agent、脚本）调用本库内容时都必须遵守。

## 一、唯一入口

| 角色 | 文件 | 说明 |
|---|---|---|
| **唯一检索入口** | `kb-query.py` | 所有定位、取正文、取关联的唯一合规通道 |
| **唯一索引** | `kb-index.jsonl` | 逐行扁平索引，AI 检索只读它 |
| 完整索引（含关联图） | `kb-index.json` | 需要 outlinks/inlinks 明细时用 |
| **编码映射** | `code-map.json` | 唯一规范码表 + 裸编码歧义表 |
| UID 持久化 | `uid-map.json` | 保证文章改名/移动/新增时 UID 不漂移 |
| 底层全量清单 | `ai-index.jsonl` | 历史统一索引，**不再是 AI 检索入口** |

**一句话**：定位文章先查索引；读正文只能读索引命中的那几篇；答案只能由这些正文及其关联信息生成。

## 二、五条硬约束（违反即视为答案无效）

1. **索引唯一入口**：必须先经 `kb-query.py` 的 `search` / `resolve` 得到 UID 或唯一规范码，才允许读任何文章正文。
2. **禁止裸编码定位**：`001` / `01` / `1` 这类裸编码共 **232 组**（126 组对应多篇文章、106 组仅对应 1 篇）。**无论对应几篇**，`resolve` 一律返回 `AMBIGUOUS` 候选表且 `reject_single=true`；裸编码本身永远不是定位键。**绝不允许凭编码猜一篇、取最像的一篇、或取第一篇**。
3. **禁止逐篇遍历**：不得用 `rglob` / `list` / `Get-ChildItem -Recurse` 扫全库 md 来找文章，不得以文件名模糊匹配代替索引检索。`search` 阶段脚本本身只读索引、不碰磁盘。
4. **禁止绕过索引读正文**：只有 `get <uid>` / `context <uid>` 返回的 `path` 才可读取；读取结果必须带 `via=index` 与 `source_uid` 溯源。
5. **答案基于文章内关联**：`context` 返回的 `articles[].body` 与 `relation`（outlink / inlink / both）是答案的唯一依据；不得引用未出现在 `articles` 中的文章，不得把关联信息当作"另行翻库"的许可。

## 三、标准调用流程（四步）

```bash
# 1 检索（只读索引，不读正文）
python kb-query.py search "五行到坐标" --limit 10

# 2 消歧（裸编码会返回候选表，必须从中挑 code 或 uid，不能自选单篇）
python kb-query.py resolve 001                 # → AMBIGUOUS，6 个候选
python kb-query.py resolve FY2610-001          # → UNIQUE

# 3 取上下文：正文 + 文章内关联
python kb-query.py context FY2610-001 --body --max-related 8

# 4 基于 articles 生成答案，并在答案里标注所用 uid
```

`resolve` 返回 `AMBIGUOUS` 时的正确做法：把候选连同 `code` / `title` 呈现给人，或按查询词语义从候选中选一个**唯一规范码**再调用一次 `resolve`；**不得**直接把候选中的某篇当作答案来源。

## 五、活的知识库：新增文章与关联后怎么演化

```bash
# 只读体检：看有多少新增 md 尚未进索引
python kb-reindex.py --check

# 一键演化：重建统一索引 → 重建规范索引 → 继承 UID → 重算关联 → 检测新编码冲突
python kb-reindex.py

# 独立复验（任何时候可跑）
python kb-verify.py
```

`kb-reindex.py` 的行为：

- 新增文章 → 分配新 UID；已有文章按 `by_id` 继承，改名/移动的按 `by_code` 或正文 sha256 继承，**UID 不漂移**；
- 新增带编号的文章 → 自动生成带命名空间的唯一规范码；若与既有码冲突，自动加确定性后缀，并把裸编码登记进歧义表；
- 文章内新增/修改双链 → 重建后的 `outlinks` / `inlinks` / `related` 自动反映；
- 索引重建**不改动任何笔记正文**，只写 `00-索引与导航/AI统一索引/` 内的索引文件。

> 建议：每次批量新增文章或修改关联后跑一次 `kb-reindex.py`，再跑 `kb-verify.py`。不需要常驻服务，本地保持整洁。
