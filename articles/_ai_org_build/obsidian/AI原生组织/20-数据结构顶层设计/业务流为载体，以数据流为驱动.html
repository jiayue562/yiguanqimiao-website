0001│# 业务流为载体，以数据流为驱动
0002│
0003│根据味藏知识库长期累计的日反馈、周复盘、月度总结资料，帮我深度剖析出整个味藏的业务流和数据流，实现数据支撑业务
0004│
0005│​
0006│
0007│基于味藏知识库中长期积累的日反馈、周复盘、月度总结等资料，为您深度剖析味藏的“业务流”与“数据流”咬合体系。本剖析严格遵循“以业务流为载体，以数据流为驱动”的原则，展示数据如何精准支撑业务决策。
0008│
0009│### 一、 全局架构：业务流与数据流的交汇体系
0010│
0011│味藏的整体经营以“总营业额”为目标，拆解为堂食、酒水、外卖三大业务模块。其业务流沿着“引流获客→门店交付→留存复购→供应链支撑”的路径流转；而数据流则贯穿其中，通过“数据采集→指标监控→归因分析→行动指令”的闭环，实现数据对业务的实时支撑。
0012│
0013│***
0014│
0015│### 二、 核心业务流与数据流深度剖析
0016│
0017│#### 1. 引流与获客流（漏斗顶端：精准蓄水）
0018│
0019│* 业务流：线上平台（抖音/小红书/美团）内容曝光（如开鱼秀短视频） → 线下门店地推（免费试吃立牌） → 客户进店/外卖平台点击。
0020│* 数据流： 
0021│  * 采集指标：曝光人数、播放量、点击率、进店转化率、每日进店人数/开台数。
0022│  * 数据支撑业务：通过对比“活动效果环比”验证营销策略有效性。例如，金月湾店通过抖音视频获得52万播放量、18%点击率，数据直接支撑了“线上爆款钩眼球”策略的复制；若进店转化率低于阈值，则立即触发线下地推或套餐优化动作。
0023│
0024│#### 2. 门店交付与变现流（三大创业单元协同变现）
0025│
0026│① 堂食业务流（品牌体验中心）
0027│
0028│* 业务流：客户入座 → 桌桌链接推荐 → 核心爆品（金枪鱼开鱼秀）展示与体验 → 成交。
0029│* 数据流：金枪鱼实收/完成率、渗透率（卖出桌数÷总桌数）、桌桌链接转化率、人均/单均、翻台率。
0030│* 数据支撑业务：日复盘数据直接指导次日动作。例如狮山店日总结显示“金枪鱼渗透率36%，未达标因开台数少”，数据支撑门店将次日核心动作调整为“桌桌链接酒水饮料、演练推荐话术”；若某时段翻台率低，则联动前厅经理优化点餐与收银效率。
0031│
0032│② 酒水业务流（利润贡献中心）
0033│
0034│* 业务流：兴趣激发（15ml试饮钩子） → 场景化推荐（刺身+清酒套餐绑定） → 成交 → 复购。
0035│* 数据流：酒水营业额/完成率、试饮转化率、四季酒占比/渗透率、套餐销售占比。
0036│* 数据支撑业务：建立“漏斗健康仪表盘”，当试饮转化率＜20%时，系统预警并强制优化话术；周复盘若发现“酒水销售普遍疲软”，则数据倒逼门店启动“侍酒师学徒通关计划”或推出“清酒九宫格套餐”以降低决策门槛。
0037│
0038│③ 外卖业务流（规模扩张中心）
0039│
0040│* 业务流：平台曝光 → 进店下单 → 专送履约（高端订单专人专送） → 满意度回访。
0041│* 数据流：外卖营业额/占比、有效订单、实收客单价、进店/下单转化率、复购率、评价分、刺身占比。
0042│* 数据支撑业务：监控“外卖占总营业额比例”评估增量贡献；若某店闪购下单转化率环比大幅下滑（如金月湾店曾环比-49%），数据直接指向需优化产品描述或包装体验；针对1000元以上高端订单，通过“专送回访满意度”数据闭环，验证品质与定价的市场接受度。
0043│
0044│#### 3. 客户留存与裂变流（全生命周期运营）
0045│
0046│* 业务流：非会员 → 转化普通微会员 → 储值会员 → 交叉复购（堂食+酒水+外卖） → 转介绍裂变。
0047│
0048│
0049│
0050│* 数据流：新增会员数、储值金额/完成率、老客/新客消费占比、复购率、沉睡会员占比、LTV（生命周期价值）。
0051│* 数据支撑业务：通过RFM模型对会员分层。当数据发现“待唤醒高价值会员”群体规模大时，业务端立即设计专属“唤醒套餐”与温情沟通进行定向触达；评估“老带新”裂变系数（目标1:1.5），若代金券核销率＜30%，业务端迅速调整为“赠招牌菜”以维持裂变效能。
0052│
0053│#### 4. 后端供应链与生产流（以金枪鱼为最小切口）
0054│
0055│* 业务流：采购 → 储存 → 取用 → 加工 → 损耗核销。
0056│* 数据流：采购权重/价格、冰箱储存量/温度、取出放回次数、出品率、超5天转损耗量、食材成本率（红线≤28%）。
0057│* 数据支撑业务：后端数据直接决定毛利水平。采购部通过“食材成本波动监控台”预测价格波动对毛利的影响，指导期货套保或寻找替代品；当单品毛利变化异常时，通过总毛利深度拆解（菜品结构/单品毛利/损耗异常），精准定位是后厨切配损耗过大还是打折退菜所致，倒逼加工流程优化。
0058│
0059│***
0060│
0061│### 三、 保障机制：数据驱动业务的日/周/月闭环
0062│
0063│数据流并非静止的报表，而是通过严密的复盘机制不断反哺业务流：
0064│
0065│1. 日反馈闭环（敏捷纠偏）：
0066│    每日营业后召开夕会，依据《日总结框架》录入核心数据。如狮山店日汇报中明确记录“营收21736元，完成率72%，四季酒渗透率45.5%”，并据此生成“明日计划：酒水目标2061元，核心动作推广新酒”。数据确保每日的动作指令精准指向未达标指标。
0067│2. 周复盘闭环（趋势归因）：
0068│    将一周的日数据“连点成线”。如8月第三周复盘发现“堂食高企、酒水疲软”的剪刀差，数据倒逼管理层发起“酒水销售破局战”、“服务体验优化战”。通过过程动作数据（如试饮桌数飙升是否伴随业绩上升）验证动作有效性。
0069│3. 月度总结闭环（战略校准）：
0070│    如9月经营分析报告，系统检视年度目标达成率、各项成本率（食材/人力）与目标差异。数据不仅用于考核，更用于解决“客流不足、成本超标”等系统性问题，并清理账务挂账等管理死角。
0071│
0072│### 四、 总结：数据支撑业务的底层逻辑
0073│
0074│味藏实现数据支撑业务的核心在于“先业务流后数据节点、全员数据裁定员”：
0075│
0076│不盲目堆砌系统，而是先理清业务流的自然顺序（如金枪鱼五节点、客户流转四步法），再在关键节点植入数据采集点。从前厅服务员记录“试饮转化桌数”，到后厨记录“出品损耗率”，再到店长依据“客流时段分布”优化排班。每一个业务动作产生数据，数据经AI中台归因后生成行动指令，最终又回到业务端执行，形成了“业务产生数据→数据指导业务”的增强型闭环。
0077│
