# 味藏水单数据化管理落地方案 v4.0

> 基于 2026-10-30 下午会议（水单数据化 + 店长 14 条）整理，接续《味藏水单诊断执行手册 v3.0》与《以一张水单为最小单元：三驾马车贯通方案》。新增三块：skill 搭建、日反馈自动化路径、店长 14 条与水单咬合。

## 一句话

一张水单是营业额的最小单位，也是店长能力的唯一考场。水单负责产出证据，skill 负责把证据变成判断，日反馈负责把判断变成第二天的动作，店长 14 条负责判断谁配得上这个岗位。四件事共用同一张单，不另起体系。

## 一、这张单要装什么

现在的水单是结账凭证，只记结果。字段由涛涛设计，但装什么由「要判什么问题」倒推。

**第一层 定位层（判这张单是谁的）**

- 人数、桌型、时段
- 客群四类：新中产 / 家庭客 / 商务宴请 / 朋友小聚
- 是否会员、会员等级、是否有小孩
- 客户来源：团购 / 私域 / 自然到店 / 转介绍

**第二层 结构层（判这桌点得对不对）**

- 客单价、道数
- 18 道招牌菜点击占比（出了几道、缺哪几道）
- 高毛利菜数、酒水占比
- 五类菜品结构是否齐全

**第三层 异常层（判这桌有没有出事）**

- 退菜：几道、哪道、缘由
- 赠菜：几道、谁签字
- 折扣、加菜、挂账
- 每道菜毛利

硬规矩：每个字段必须能回答「它和谁组合、判什么问题」。答不上来的先别加。

## 二、组合规则库

核心原则：单一数据能看到的问题很少，数据组合才能暴露问题。规则不写「客单价低于 282」，而写「哪两个字段一起看，说明什么」。

规则写法固定五段，少一段不成立：

编号｜触发条件（至少 2 个字段组合）｜说明什么问题｜谁负责｜对应什么动作

已跑通的例子：

| 组合 | 说明什么 | 归谁 |
|---|---|---|
| 客单价 200 + 招牌菜占比 30% | 点得太少，不敢推 | 前厅经理 |
| 高级会员 + 客单低于均价 282 | 客情没做到位 | 前厅经理 |
| 客单 500+ + 招牌菜 0 道 | 花了钱吃的全是常规菜 | 料理长 |
| 毛利达标 + 结构畸形 | 侥幸赚到，下次会漏 | 店长 |
| 有退菜 + 未定位到菜与原因 | 异常没闭环 | 店长 |

规则库分两张表：

- 表 A 单张诊断表：一张单就能判的（结构、毛利、客情、推荐、异常），每晚逐张跑
- 表 B 周度池表：必须跨单才判得出的（同一组合一周 ≥3 次、高频客未升级、首次到店占比），每周汇总跑

表 B 那条「同一组合一周触发 ≥3 次」是整套体系的方向盘。一旦触发，判定不是「这个人不行」，而是「这条规则还没磨好」——追责方向从人转向规则。

## 三、skill 这一层怎么搭：两份文件 + 一张单

**文件一 字段字典**：每个字段的名字、口径、取值范围。招牌菜占比分母是菜品金额（不含酒水服务费），赠菜按标准售价计不能记 0，退菜和赠菜分开记。

**文件二 规则-动作对照表**：第二节那张表的完整版，每条规则配一个标准动作。这是 skill 的知识库，也是唯一需要持续更新的文件。

**一张单 水单模板**：字段按三层排布，一眼扫完。

**skill 怎么跑**

1. 水单进系统（POS 直读优先，拍照其次，语音补录兜底）
2. skill 按表 A 逐张跑，输出诊断卡
3. 诊断卡推到主责人手机
4. 主责人写三句话，回填
5. 当晚汇总成日反馈

关键设计：AI 出建议，人做定案。skill 判出「招牌菜占比不足」，不写「前厅经理不合格」，写「这张单招牌菜只出了 2 道，客单 480，建议明天早会练推菜话术」。

必须写进规则的一条：判不了就写判不了。缺字段导致结论不成立时，输出「本单此项无法判定，缺 XX 字段」，不降级凑结论。凑一次，一线就不信了。

## 四、日反馈：从人写变成人只添加

招培那套已跑两个多月，路径直接复制。

**日反馈（每晚 30 分钟）**

- 系统自动出 3 张单：一张大单（5000+）、一张偏离本线最远的、一张招牌菜缺席或赠菜异常的
- 每张附诊断卡，主责人各写三句话：哪里对、哪里错、明天早上改哪一件事
- 第三句禁止出现：加强管理、提升意识、注意服务、多关注、加强培训
- 店长汇总发群，格式固定：单号｜规则编号｜第三句动作

**周总结（每周 60 分钟）**

- 本周所有单归堆，跑表 B
- 找出重复 ≥3 次的同一组合
- 决定哪条升级成规则、哪条废掉
- 输出一行：本周改了哪条规则。改不出记「本周未改」，连续两周未改触发警报

**月度分析（每月，接绩效会）**

- 三店横向：各客群毛利区间、招牌菜出现率、规则命中率、首次到店占比
- 复购与客诉单独看一次，不进毛利考核
- 输出：下月三条规则调整 + 一个必须堵住的漏点

自动化顺序：先跑通日反馈自动生成，再叠周反馈（把日反馈投进去提炼），最后叠月反馈（把 30 天日反馈拉进去提炼）。一次只上一级。

## 五、店长 14 条：让这张单成为门槛的考场

**第一层 门槛（3 条，一项不过则不过）**

| 条目 | 内容 | 怎么验 |
|---|---|---|
| 懂管理 | 排班、带教、处理人 | 排班零投诉、带教有记录、人员异动有归因 |
| 成本意识 | 看懂毛利表、人工表、损益表 | 能说清每个指标背后的原因，不只是念数字 |
| 执行力 | 定了的事有时间有结果 | 闭环率，上次定的三件事现在在哪 |

提醒：会上已有人担心「卡这么死店长可能都要站到这边」。建议先当尺子用，不当刀用——前三个月只出诊断结果，不挂工资。否则第一周大家就开始表演。

**第二层 味藏特色**：统筹、巡检、立标准

**第三层 水单动作**：条目最多，不用一条条背——这一层全部由诊断卡自动出结果。店长每周被系统判出几次「判断对了」、几次「判断错了」，比任何自评都硬。

指标化别一次全补，先挑三条能立刻量化的：

- 管理：员工因排班问题离职数 = 0（当前投诉高发点）
- 成本：能独立讲清损益表三项异常原因，季度考核一次
- 执行：闭环率 ≥90%

跑一个月，再补下三条。

## 六、第一周逐日动作

| 日 | 动作 | 产出 | 谁 |
|---|---|---|---|
| D1 | 定客群四类、来源四项，一页纸 | 分类卡 | 陈总 |
| D1 | 拉 100 张历史单，按客群分线算毛利区间，看 71% 落在哪 | 分线区间表 | 涛涛 |
| D2 | 18 道招牌菜对照表（菜名、成本、适配客群、卖点、别名） | 对照表 | 料理长 |
| D2 | 开一线会，逐条录「哪两个数一起看代表什么问题」 | 规则原料清单 | 店长 |
| D3 | 规则库建表 A + 表 B | 规则库 v1 | 陈总 |
| D3 | 改水单模板，三层字段落地 | 新模板 | 涛涛 |
| D4 | 50 张真实单跑识别测试，招牌菜命中率 ≥95% 才上线 | 识别报告 | 涛涛 |
| D5 | 单店试跑第一晚：3 张单、三句话、发群 | 首日台账 | 店长 |
| D6–D7 | 连跑两天，记录哪里判不了、哪里判错 | 问题清单 | 店长 |

第二周起：每晚 3 张单稳定跑，周末第一次周总结，只做一件事——找出重复三次以上的错。

顺序上的坑：不要先建系统再想规则。规则库是资产，系统是壳。壳能换，规则换一次成本极高。

## 七、分工

- 陈总：客群与来源定义、规则库定稿、月度分析统筹、申诉裁决
- 涛涛：字段设计与系统实现、识别测试、数据打通
- 曹操：skill 开关的搭建与调试，跑通后组织大家判断
- 店长：每晚三张单、三句话、汇总发群、周总结主持
- 前厅经理：点单过程补录、招牌菜卖点、三套搭配模板
- 料理长：18 道招牌菜对照表、每单回答「这单的菜我有没有责任」

## 八、这套东西量不出的地方

水单是单次交易的切片，量不出客人为什么来、下次还来不来。补上来源路径，也只补上半条复购线。

如果全店所有事都往水单上收，一线会学会为了毛利好看牺牲体验——「没点贵的但客人很满意」的单会被判成错单。

配一条：每月单独看一次复购和客诉，不进毛利考核。两张表分开看。

## 九、三个最容易翻车的地方

1. 规则库建得太全——一开始就想覆盖所有情况，结果每条都不准。先 20 条，跑一个月再补
2. 卡出得太多——每张单都出卡，一线就不看了。每天只推 3 张
3. 绩效直接挂工资——前三个月只做诊断不做扣钱

第四条：手册发给所有人，但一线不需要读手册，只需要一张卡、三句话、一个群。手册是给店长和上面的人看的。

## 待定

前三个月是否真不挂工资，还是分层挂？这个决定会改第六节的落地节奏。
