**《味藏水单诊断执行手册 v3.0》**

v2.0 已经把骨架立住了：字段清单、26 条规则、四维判定、主责三句话。v3.0 只做一件事——把"能跑"变成"跑得动"。改动集中在六处：规则拆两张表、阈值跟着分线走、每条数值标状态、补三张空白表单、补异常与升级路径、补第一周的逐日动作。

---

### 第一章 三条硬纪律与门禁（保留，加一条）

1. 结论必须有依据：每条结论写清由哪几个字段推出，取不到标「待补充」，不得臆断。
2. 未定稿数值标【建议初值·待校准】，用 200–300 张历史单实测替换。
3. 三条红线：前三个月只诊断不扣钱；不得用全场均值 71% 判单张单；严禁从照片硬猜客户来源。
4. **新增：判不了就写"判不了"。** 缺字段导致结论不成立时，输出"本单此项无法判定，缺 XX 字段"，不降级凑结论。这条比前三条更救命。

**门禁四道**（每道有明确判据，不达标不进下一阶段）：

| 门禁 | 判据 | 谁来验 |
|---|---|---|
| 识别门禁 | 50 张真实水单，招牌菜识别命中率 ≥95% | 数据层 |
| 标签门禁 | 每周抽 10 张回访，客群标签准确率 ≥80% | 店长 |
| 规则门禁 | 连续 4 周，每周至少 1 条规则被改 | 陈总 |
| 扩店门禁 | 前三条全过，且单店跑满 3 个月 | 陈总 |

---

### 第二章 数据输入：9 类 44 项（补状态标注）

原清单保留，每项后加一个状态标记：**定 / 初 / 待**。

- **定**：口径已确认，可直接用
- **初**：建议初值，需校准
- **待**：字段还没打通，暂不可用

三类字段的缺失处理不变（缺核心不出经营结论、缺增强降级为参考、可选缺失不影响）。补两条口径细则：

- 招牌菜占比分母 = 菜品金额（不含酒水、服务费）；赠菜按标准售价计，不得计 0
- 退菜与赠菜分开记，不合并成一个"异常数"

**补录优先级**：系统直读 ＞ POS 客群单选键 ＞ 语音补录。每晚只补抽中的 3 张，不做全量。这条要写进一线操作卡，不然第一周就会有人想补全量，然后放弃。

### 第三章 客群与来源：两层交叉（v2.0 最大缺口）

v2.0 有客群，没有来源。**来源不剥开，按客群分的毛利区间依然是混的**——团购单有平台折扣和佣金，毛利天然低一截，会被误判成点单有问题，冤枉前厅，然后前厅开始抵抗这套系统。

**第一层 渠道（四项）**：线上到店（美团/点评/抖音团购/小红书/小程序）、私域（社群/老客微信/员工邀约）、自然到店（路过/商场客流）、转介绍（老客带新/员工推荐）

**第二层 到店次数（四档）**：首次 / 2–3 次 / 4 次以上 / 储值会员

**两层交叉才是完整来源画像。** 只分渠道不分次数，会把"团购买了四次的老客"和"第一次被团购拉来的新客"算成一类，这两类人的毛利结构、点单结构、复购价值完全不同。

**客群判定**（沿用 v2.0 三级信号）：

- 强信号（单凭即可判）：儿童人数 ≥1 或儿童餐具记录 → 家庭聚餐；自带酒水或挂账/单位开票 → 商务宴请；团购核销记录 → 团购到店；开鱼仪式等 → 仪式单
- 中信号（需 2 项以上联合）：用餐时段、桌型、人均、菜品结构
- 弱信号：仅辅助，不单独定案

**消费能力 A/B/C/D**：按「本来源 × 本客群」的 P25/P50/P75 分位划，不用统一绝对值。写字楼午市 120 元/人可能是 A 档，周末商务宴请 400 元/人可能只算 B 档。

**推断三纪律**：强信号优先；推断链在第一个缺字段处终止，不跳步补齐；AI 出建议、人做定案。

**一个必须先说清的坑**：客户来源在结账水单上常常不显示。团购核销单显示券名，但不会告诉你这是不是这个客人的第一次；自然到店彻底没痕迹。所以来源这一栏不能指望识别，只能靠系统字段加人补——取不到就在拍照那句语音里带出来。**不要为了让 AI 全自动，硬从照片里猜来源。猜错一次，整张卡的结论就废了，一线就不信了。**

### 第四章 四个诊断维度（保留，加反推动作）

四维不变：①客单价与菜品结构 → 点菜人专业水平；②会员等级与消费匹配 → 客情判断；③客群识别与推荐匹配 → 推荐合规；④会员转化储值 → 营销动作。

**维度①的反推要写成动作，不是标签。** v2.0 写了"不敢推、不会搭、不懂菜、不看人"四个短板，但没说怎么补。补上：

| 短板 | 判断信号 | 补法 |
|---|---|---|
| 不敢推 | 招牌菜占比低但客单达标 | 话术演练，只练"推"这一句，练到能自然说出 |
| 不会搭 | 五类结构缺项、高低不配 | 给三套标准搭配模板，按客群各一套 |
| 不懂菜 | 高毛利菜缺席、卖点答不上 | 招牌菜卖点考核，不看稿用自己的话讲 |
| 不看人 | 客单与客群档位不匹配 | "一眼定客群"实操，每周复盘 3 张单 |

**维度④两条红线不变**：营销动作不得强制（拒绝即止）；考核只看"是否发起并留痕"，不看成交。

### 第五章 规则库：拆成两张表（v2.0 最大结构问题）

v2.0 的 26 条规则混了两类：**单张单就能判的**，和**必须跨单历史才判得出来的**。每天只抽 3 张单，跨单类规则永远判不出来，会一直显示"未触发"，让人误以为体系在跑、其实有一半在睡。

**表 A：单张诊断表（每晚抽 3 张，逐张跑）**

| 组 | 规则 | 判据 |
|---|---|---|
| A1 结构 | 招牌菜整单缺席 | 招牌菜数 = 0 |
| A2 结构 | 招牌菜占比不足 | 占比 < 20%（A 档 <3 道）【初】 |
| A3 结构 | 组合与客单不相称 | 客单档位 vs 招牌菜数不匹配 |
| A4 结构 | 点单量不足 | 道数 < 人数×0.8【初】 |
| A5 结构 | 高毛利缺席 | 高毛利菜数 = 0 |
| A6 结构 | 五类结构失衡 | 缺 ≥2 类 |
| A7 毛利 | 毛利偏离本线区间 | 偏离本来源本客群区间【初】 |
| A8 客情 | 高卡低单 | 会员等级 vs 本次人均 <80% |
| A9 客情 | 低卡高单未升级 | 人均 >130% 且未提升级 |
| A10 客情 | 会员未识别 | 有会员记录但单上未关联 |
| A11 客情 | 升级门槛未提示 | 距升级 <20% 未提示 |
| A12 推荐 | 客群标签缺失 | 标签 = 空 |
| A13 推荐 | 标签与数据冲突 | 标签 vs 强信号矛盾 |
| A14 推荐 | 饮品推荐缺失 | 商务/小聚且酒水占比 <15%【初】（自带酒水除外） |
| A15 推荐 | 套餐未给方案 | 人数 ≥4 且 C/D 档 |
| A16 数据 | 自带酒水单误入常规线 | 有自带酒水但按常规线判 |
| A17 转化 | 首访高值未转化 | 首次到店且 A 档，未发起入会 |
| A18 转化 | 储值未邀约 | 满足储值条件未邀约 |
| A19 转化 | 有储值未动用 | 储值余额 >0 但本单未用 |
| A20 红线 | 赠菜超限 | 赠菜 >2 道无店长签字 |
| A21 红线 | 退菜异常 | 有退菜且未定位到菜与原因 |

**表 B：周度池表（每周汇总全部单，跑跨单规则）**

| 规则 | 判据 | 谁看 |
|---|---|---|
| B1 高频未升级 | 到店 ≥10 次仍入门级 | 店长 |
| B2 目标客单未推进 | 同客群连续 3 周客单未上行 | 前厅经理 |
| B3 同组合重复 | 同一规则组合本周触发 ≥3 次 | 店长 |
| B4 首次到店占比 | 首次占比过高、二次转化过低 | 店长 |
| B5 抽中单未留痕 | 抽中但无三句话记录 | 店长 |
| B6 异常单未入池 | 异常单未进周池 | 数据层 |

**B3 是整套体系的方向盘。** 触发 B3 时，判定为"规则问题而非人的问题"，按三次升级制写入新规则。这一条把追责方向掉了个头——规则的敌人不是员工，是还没磨好的规则。

**规则写法固定格式**：编号｜触发条件（至少 2 个字段组合）｜说明什么问题｜谁负责｜对应什么动作。触发组合为空的规则一律不成立。

### 第六章 阈值与风险等级：跟着分线走（v2.0 口径打架处）

v2.0 的"高 ≥5000 元 / 中 1000–5000 / 低 <1000"是绝对数，可客单档位是按分位划的。同样一张 5000 元的单，在二楼商务宴请里是常态，在一楼家庭聚餐里就是异常。**阈值不跟分线走，风险等级会把正常商务单反复标红。**

**改法：金额阈值改为"本来源本客群区间的倍数"**

| 等级 | 判据（满足任一即取该级，就高原则） |
|---|---|
| 高 | 触发红线规则（A20/A21/A17）／同组合 ≥3 次/周／金额 ≥ 本线 P75×2【初】／难逆转（客户流失、口碑受损、系统性误判） |
| 中 | 金额在 本线 P50–P75×2【初】／2 次/周／需 1–4 周整改 |
| 低 | 金额 < 本线 P50【初】／1 次/周／当场可纠正 |

校准前先用绝对数兜底（≥5000 元算高），校准后换成倍数。**这个切换日期要写进手册，不能一直悬着。**

### 第七章 输出：诊断卡与主表（补成可打印的空白表）

**诊断卡（一屏，四区块）**：

1. 这张单的画像：来源（渠道+次数）、客群、人数、客单、招牌菜命中几道、赠菜几道
2. 命中的规则：最多 3 条，每条一句人话，不写指标名
3. 明天早上改的一件事：必须是动作
4. 谁来做、什么时候验

卡上不出现"综合得分""健康度"这类模糊指标。要么指出具体问题，要么明说这张单没问题。

**诊断主表（五列，每条结论可回指规则编号）**：

| 数据依据 | 推断结论 | 风险等级 | 整改要求 | 责任人 |
|---|---|---|---|---|

**主责三句话（必填，缺一句视为未留痕）**：

① 这张单哪里对 ② 哪里错 ③ 明天早上改哪一件事

第三句禁止出现：加强管理、提升意识、注意服务、多关注、加强培训。**这五个词是空话检测器，写进去就打回。**

### 第八章 三个节奏怎么跑（补具体动作）

**日反馈（每晚 30 分钟）**

1. 系统出 3 张单：一张大单、一张偏离本线最远的、一张招牌菜缺席或赠菜异常
2. 主责人各写三句话（大单归店长，常规单归前厅经理，料理长每单必答"这单的菜我有没有责任"）
3. 店长汇总发群，格式固定：单号｜规则编号｜第三句动作

**周总结（每周 60 分钟）**

1. 本周所有单归堆，跑表 B
2. 找出重复 ≥3 次的同一组合
3. 决定哪条升级成规则、哪条废掉
4. 输出一行：本周改了哪条规则（改不出就记"本周未改"，连续两周未改触发警报）

**月度分析（每月，接绩效会）**

1. 三店横向：各来源各客群毛利区间、招牌菜出现率、规则命中率、首次到店占比
2. 复购与客诉单独看一次，不进毛利考核
3. 输出：下月三条规则调整 + 一个必须堵住的漏点

### 第九章 异常与升级路径（v2.0 缺）

| 情形 | 处理 | 谁决定 |
|---|---|---|
| 字段缺失导致判不了 | 输出"无法判定"，不凑结论 | 系统自动 |
| 规则误杀（结构正常但被判错） | 主责人申诉，24 小时内回，成立则改规则 | 店长 |
| 同组合一周 ≥3 次 | 认定为规则问题，进升级流程 | 店长 → 陈总 |
| 规则改了但下周还犯 | 说明不是规则问题，回到人 | 陈总 |
| 一线拒绝录入 | 先查是不是录入方式太麻烦，不先骂人 | 店长 |
| 标签失真率 >20% | 修录入方式，不是修人 | 数据层 |

**申诉机制必须有。** 没有申诉，一线第一周就会学会"按系统喜欢的方式填"，而不是"按真实情况填"。

### 第十二章 这套东西量不出的地方（保留，加一句）

水单是单次交易的切片，量不出客人为什么来、下次还来不来。补上来源路径，也只补上**半条**复购线，真实体验仍然量不出来。

如果全店所有事都往水单上收，一线会学会为了毛利好看牺牲体验，那些"没点贵的但客人很满意"的单会被判成错单。

所以配一条：每月单独看一次复购和客诉，不进毛利考核，两张表分开看。

**加一句**：这套手册最大的风险不是写得不细，是写得太细以至于没人读完。所以第一周只发两页——分类卡 + 三句话模板。26 条规则先存在台账里，不发给一线。

---

### 第十三章 三个最容易翻车的地方（保留）

1. 规则库建得太全——一开始就想覆盖所有情况，结果每条都不准
2. 卡出得太多——每张单都出卡，一线就不看了，每天只推 3 张
3. 绩效直接挂工资——前三个月只做诊断不做扣钱

**加第四条**：手册发给所有人。一线不需要读手册，只需要一张卡、三句话、一个群。手册是给店长和上面的人看的。
