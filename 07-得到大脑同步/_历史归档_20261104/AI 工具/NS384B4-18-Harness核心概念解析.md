# Harness核心概念解析

今天的 Harness 内容一共 6 篇，按从"是什么"到"怎么搭"到"具体产品"的顺序，串起来是这样的：

---

## 一、先搞懂概念：Harness 到底是什么

**一句话定义**：Agent = 大模型 + Harness。把 Agent 里的大模型拿掉，剩下的所有东西就是 Harness——规则、记忆、工具、思考-行动-检查的工作循环、上下文管理……全算。

Harness 不是某个具体文件或开关，它散落在 Agent 的各处文档里（Cloud.md、Agents.md、Soul.md、skill 里都有），是和 Agent 融为一体的"灵魂"。它的唯一目的：**让大模型稳定、高效地为人类干活**。

核心判断：
- 模型有多强，决定了 Agent 的**能力上限**
- Harness 搭得好不好，决定了这些能力**能不能稳定发挥出来**

---

## 二、再升一层：Harness Engineering = 束导工程

用都江堰做类比，一下就通了——岷江是大模型，都江堰整个水利工程就是 Agent，鱼嘴、金刚堤、飞沙堰、宝瓶口这些工事就是 Harness。

李冰修都江堰的指导思想，就是 Harness Engineering，翻译成**束导工程**（约束+引导）。四大支柱：

| 束导工程支柱 | 都江堰对应 | 干什么用 |
|---|---|---|
| 分流分布 | 鱼嘴 + 金刚堤 + 离堆 | 把大任务拆成小任务，或拆成多个 Agent 协作 |
| 控量约束 | 宝瓶口 | 每一步输出、最终成果都要满足要求才能放行 |
| 兜底机制 | 飞沙堰 | 死循环、异常时降级、超时拦截、自我修复，多余能量泄洪 |
| 成长维护 | 岁修制度 | 根据模型能力变化、业务需求变化持续迭代维护，才能千年不废 |

> 我们今天在用 AI 的时候，也是在给大模型修一座属于它的都江堰。

---

## 三、落到产品：DeepSeek Harness 怎么做的

**核心理念：一切皆插件**
- 微内核架构，连 loop、plan mode、Go 这些最基础的能力全都是插件
- 好处：配置层自由组合，不用改源代码，加几个配置文件或用 SDK 就能拼出新东西
- 每次运行有"轨迹"可查——每一步用了什么 prompt、调了哪些工具、thinking 过程是什么，全部透明

**四种工作模式**：
1. **标准模式**：工具完备（Shell、文件编辑、网页检索等）
2. **PTC 模式**：通过 TypeScript 代码做多步工具调用，擅长编码、自主运行时间长
3. **极简模式**：只保留 Shell 和文件编辑，环境干净
4. **创造模式**：可以用自然语言直接定制新的 Agent preset 和插件——最有想象力的一个

---

## 四、实践方向：工作台、插件、企业定制

**BI 工作台理念**：未来的工作界面应该是 **Harness 嵌信息系统**，而不是信息系统右下角加个聊天窗。聊着聊着界面就变了，数据看板实时跟着对话更新。

更深一层：
- 人盯数据是少数情况，**未来一定是 Agent 去盯数据**
- 专门的会话盯利润率、盯中部数据，触发阈值就自动发消息、自动处理
- 工作台慢慢接管手头工作，人去干更有价值的事

**插件生态的爆发**：
- 用创造模式对话方式就能做出侧边栏聊天插件（热启动→封装成真正的 plugin→分享）
- 好的架构能大幅降低 harness 定制门槛，GitHub 上很快会出现大量插件市场
- 低代码会被淘汰，但**好架构依然重要**

**企业落地机会**：
- 企业不满足于现成的通用产品，定制化 harness 需求会非常旺盛
- 围绕同一套架构标准生产插件、互相协同流转，市场会很快欣欣向荣

---

## 五、一句话收束

大模型是岷江，能力已经够强了。接下来真正决定 AI 生产力能不能落地的，不是模型再大几号，而是我们能不能像李冰修都江堰那样，把 Harness（束导工程）搭好——分流、控量、兜底、岁修，让这股强大的力量稳定地流向该去的地方。
