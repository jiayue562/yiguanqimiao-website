# AI互动方法论

先说一个发现：**你今晚这条口述，已经在你的取象落子 v0.3 里了，而且是以最核心的那条约束出现的。**

v0.3 的交互协议写的是：「每取一个象，先确认『你取的是这个象吗』，确认了再往下走，不确认，不往下走」。这条规则的本质，就是你说的「未确定 → 确定」——**把 AI 抛出的可能性收窄，靠的是你每一次的确认动作。** 确认一次，一种可能落地；不确认，它就悬着。

所以你要的这套「跟 AI 互动的方法论」，不用另起炉灶。它跟取象落子是同一个东西的两面：

- 取象落子管的是**内容**——从混沌里取出结构，落到动作。
- 你现在要的这套管的是**过程**——你和 AI 之间，怎么一轮一轮把「未定」收成「已定」。

## 这套互动方法论该长什么样

我按你的体系给你搭个骨架，四个动作，每个都能落到一句话：

**1. 抛象（未定态）** — 你先给一个还没成形的想法，允许它是模糊的、口述的、有重复的。这一步的价值不是信息量，是**把脑子里的未定外化出来**。你今晚这条就是标准的抛象。

**2. 收窄（AI 的动作）** — AI 不做判断，只做三件事：找到这个想法在你已有体系里的落点（今晚我找的是张维迎那条笔记）、指出它没说清的那一步（下注的依据是什么）、给出 2-4 个可走的方向。**AI 的职责是把可能性摊开，不是替你选。**

**3. 确认（你的动作）** — 这就是 v0.3 那条交互协议。你说「就是这个」或「不是，是那个」，一次确认消掉一批可能性。**这是整个流程里唯一不可让渡的一步**——因为确认背后是价值判断，AI 没有你的价值坐标系。

**4. 落子（已定态）** — 确认完立刻要产出一个能装的东西：一条笔记、一段口播稿、一个 Skill 版本号。没有落子，前面三步都是悬空的。

## 有一个缺口，你得自己补

这套流程目前有一个洞：**「收窄」这一步，AI 摊开的可能性质量取决于它有没有你的原料。** 今晚我能接上张维迎，是因为你下午刚记过那条笔记；如果我搜不到，就只能给通用回答。

所以这套方法论要真正跑起来，前面得加一条前置动作：**抛象之前，先让 AI 去你的笔记里找相关原料**——这恰好是你自己已经定下的约定（发芽前先搜知识库和笔记）。这条约定其实就是这套互动方法论的第 0 步，只是你还没把它写进去。

## 一个可验证的形式

这套东西最适合的载体不是文档，是 **Skill**——你已经有做 Skill 的全部经验了。它跟取象落子的分工可以这样划：

| | 取象落子 | 互动方法论（待命名） |
|---|---|---|
| 管什么 | 一个问题怎么想清楚 | 一个想法怎么跟 AI 磨出来 |
| 输入 | 混沌的问题 | 模糊的口述 |
| 输出 | 明天早上的动作 | 一个可装的东西（笔记/稿/Skill） |
| 关键约束 | 不确认不往下走 | 不落到东西不算完成 |

要不要我把这套互动方法论按你 v0.3 的规格写成一份可安装的 Skill？动笔前想跟你确认一件事——你更想让它**只管「想法 → 交付物」这一段**（窄，但马上能用），还是**从「抛象」一路管到「落子」全流程**（宽，但容易跟取象落子重叠）？
