## 一、定位

**一句话**：一套从混沌里取出第一个结构、再把它落到明天早上能做的动作的工作法。

**管哪一段**：管"问题还没定义清楚、多因素纠缠、没有现成指标"的分析任务。
**不管**：要精确量值、要复现、要追责的执行任务。判定不了时，先问一句："这个问题是要想清楚，还是要算清楚？"

**出身**：教员方法论（矛盾论 + 实践论 + 金字塔 + 金线原理，管"深"）× 象思维 / 五色光工作法（管"全"）。两套共用同一底座：信息体 / 能量体 / 物质体。

## 二、两档模式（先选档，再走步）

| 档 | 走哪几步 | 判据 |
|---|---|---|
| 轻量档 | ①定题 → ②′三句话事实 → ③取象＋④抓矛盾 → ⑦落子 | 错了明天能改回来、影响范围小、一个人能拍板 |
| 全流程 | 七步全走 | 决策不可逆、涉及多人资源、周期跨月 |

**切换判据一句话**：这步棋落错了，明天能不能悔？能悔走轻量，不能悔走全流程。
判定不了时，问用户："这个决定，错了的代价是什么？"

**盘点不许归零**：任何档位都必须有②这一步。轻量档只盘三句话，但不能不盘——③取象的判据是"象从哪三条观察来"，观察的来源就是②。②空着，取象就是裸奔。

## 三、七步流程

> 七步 = ①定题 ②盘点 ③取象 ④抓矛盾 ⑤展开 ⑥验算 ⑦落子。
> 轻量档走 ①②′③④⑦（②压缩为三句话）。顺序不能换，回流除外。

### ① 定题（P0）

**做什么**：把问题收窄成一句话。
**判据**：这句话里出现两个以上的问题，就是还没定题。

**示例**：
- ✗ 坏："帮我看看，店里业绩不太行，团队状态也不好。"
- ✓ 好："狮山店新客转化率连续四周低于 50%，主因是什么？"

**冷启动**：用户只给了一堆抱怨时，用三问开局——
1. 这事做成了是什么样（一句话）？
2. 手里已收钱 / 已验证的事实有哪些？
3. 有什么红线不能碰？

**停下来问人的检查点**：三问后仍收不拢，列 2–3 个候选问题定义，让用户选。**不选，不开工。**

### ② 盘点（P1-1）

**先查本义**：这件事在用户自己的体系 / 语境里本来是什么？本义与市场习惯冲突时，**站本义**。

**再摆事实，分六类**：

| 类别 | 盘什么 |
|---|---|
| 流量 | 粉丝数、增长率、渠道数 |
| 内容 | 篇数、阅读、转发率、爆款 |
| 产品 | 清单、形态、成本类型 |
| 收入 | 已收钱的产品、单价、客户数 |
| 资源 | 时间、人、钱、工具 |
| 交付链 | 每个产品从下单到交付经过谁、资产归谁、议价权在哪 |

**三条纪律**：
1. "已收钱 / 已验证"与"备着没动"必须分开列——分量完全不同；
2. 必须盘"人"——人的变动就是资源结构的变动；
3. **缺的数据不许用印象补**——登记进《缺失清单》，标"待定"。

**规矩**：这一栏只写事实，不写判断。

#### ②′ 三句话事实（轻量档专用）

全流程走六类；轻量档只写三句话，但这三句要覆盖三件事：

1. **一个数**——最能说明问题现状的那个量；
2. **一个约束**——人力、时间或钱上不动的那条线；
3. **一条"备着没动"**——手上已有但还没启动的东西。

三句写不出一句，说明还不到能取象的时候，回①重新定题。

### ③ 取象（P1-2）

**观 → 比 → 体 → 化。用比喻不用概念**——"像水管堵了"是象，"流程问题"不是象。

**判据**：能说出这个象是从**哪三条观察**来的。说不出来，多半是臆想。

**硬停点**：每取一个象，先向用户确认"你取的是这个象吗"。**不确认，不往下走。**

### ④ 抓主要矛盾（P1-3）

四层往下剥：

```
根本矛盾（系统层面，贯穿始终）
    ↓
阶段矛盾（初创 → 扩张 → 成熟 → 转型）
    ↓
主要矛盾 / 次要矛盾（可转化）
    ↓
主要方面 / 次要方面（可转化）
```

**判据**：能写出"什么条件下这个主要矛盾会让位"（转化触发器）。写不出，说明没看清。

**回流**：P1 是循环不是直线。盘点出新的关键事实，就回③重取象。

### ⑤ 展开（P2）

**腿一 · 时间维：五维卦变**

| 维 | 看什么 |
|---|---|
| 本卦 | 现状——我真正站在哪 |
| 变卦 | 趋势——走下去会到哪 |
| 互卦 | 暗流——表面底下推什么 |
| 错卦 | 反面——阴阳全反是什么 |
| 综卦 | 对面——对方看到什么 |

用法：**按量级开维**。轻量档只开本卦 + 变卦；战略决策才五维全开。
实战提示：互卦和错卦出料最多（待校准）——这两个方向是人最难自己想到的。

**腿二 · 空间维：五色光**

| 光 | 频道 |
|---|---|
| 白 | 事实 |
| 蓝 | 风险 |
| 绿 | 可能 |
| 红 | 感受 |
| 黄 | 价值 |

三原则：单色聚焦、序列自由、**强制完整**（不用的要宣布）。
**挂起规则**：某色暂时答不出来，标"待定"并列入【缺失清单】，成为显式悬置项，**不许跳过**。

**两个收口（顺序不能换：先五维定象 → 五色光展开 → 三维测动力 → 金字塔收形）**：
- **三维动力**：信 / 能 / 物，任一维度变动超 ±15%（设计值，待校准）即引发矛盾运动；
- **金字塔**：中心论点 + 3–9 个支撑，MECE。

### ⑥ 验算（P3）

**① 择模配比**：2–4 个模型，按君臣佐使——
君（主攻 1 个）、臣（补盲 1–2 个）、佐（唱反调 0–1 个）、使（翻译成动作 1 个）。
省掉佐等于没有刹车；确实不用佐，要宣布理由。

**② 金线验证**：假设驱动 → 事实验证 → 动态执行 → 市场检验。

**③ 三条刻度**：
- **约束**（资源 / 周期 / 红线）——不过，方案不成立，直接说；
- **代价**（钱 / 时间 / 关系 / 能量四本账）——算不清，方案不可比；
- **可逆性**——可逆的快做，不可逆的慢做。

**回流规则**：验算结果跟象对不上，**回③重取象**。

### ⑦ 落子（P4）

**① 成器**：把结论压成动作。每个动作必须过五要素模板：

> **谁** ＋ **明早/具体时点** ＋ **做什么（动词开头）** ＋ **产出什么** ＋ **怎么算完成（可观察）**

没有动作，说明前面有一步是虚的。

**② 排次第**：从最外显、最容易动手、最快收到反馈的那件起手（待校准）。

**③ 预约复盘**：落子时必须约定——**哪天、看哪个数、跟谁复盘**。不预约，实践论闭环不会发生。

**停下来问人的检查点**：动作需要动用用户没授权的资源（钱、人、对外承诺），先问，不先做。

## 四、输出格式

全流程走完，按此模板输出：

```
【定题】一句话问题
【象】一句话的象 + 三条支撑观察
【主要矛盾】根本 / 阶段 / 主要 + 转化触发器
【展开】时间维（开了几维、每维看到什么）
        空间维（五色光，含待定项）
【验证】配了哪几味模型、三条刻度验算结果
【动作】明早能做的 1–3 件（五要素模板），按次第排
【复盘预约】哪天 / 看哪个数 / 跟谁
【缺失清单】数据缺口与待定项
【置信度】哪几步是验证过的，哪几步是推演的
```

轻量档只输出：【定题】【象】【主要矛盾】【动作】【复盘预约】。

## 五、整合协议

**输出给谁**：
- 给用户 → 按上面模板；
- 给下一个 Skill（创作 / 总结等）→ 只传【定题】【象】【动作】三块。

**接谁的输出**：
- 接用户的事实盘点 → 进②盘点；
- 接其他 Skill 的分析结论 → 当"事实"用，但标注来源，不许当"验证"用。

**节奏控制（防 AI 一口气跑完）**：
- 全流程至少分三轮对话：第一轮 ①②（定题＋盘点）→ 第二轮 ③④（取象确认＋矛盾）→ 第三轮 ⑤⑥⑦（展开＋验算＋落子）；
- **取象确认是硬停点**；轻量档也必须在落子前把象复述给用户确认一次。

## 六、失败模式

| 失败模式 | 表现 | 怎么防 |
|---|---|---|
| 以象代证 | 把"我觉得像"当结论 | ③强制"象的三条支撑观察" |
| 跳过取象 | 直接上模型 | ②③顺序不能换，取象未确认不许进⑤ |
| 以象代全 | 五色光漏掉某一色 | 强制完整，不用的要宣布 |
| 假完整 | 某色答不出来就跳过 | 挂起规则：标"待定"入缺失清单 |
| 数据编造 | 缺数时用印象补 | ②三条纪律第 3 条：缺项显式登记，宁可空着 |
| 零盘点取象 | 轻量档跳过盘点直接取象 | ②′三句话事实为轻量档必填项 |
| 只走本卦 | 停在"现状＋趋势" | 全流程强制开互卦和错卦 |
| 动作悬空 | 走完没有动作 | ⑦五要素模板，不过关不出 |
| 无优先级 | 给了动作不知先干哪个 | ⑦排次第：最外显、最快反馈起手 |
| 一人独象 | AI 取象未确认就往下跑 | 硬停点：不确认，不往下走 |
| 无复盘 | 落完子没人回头看 | ⑦预约复盘是必填项 |
| 顺从陷阱 | AI 一路顺畅执行，不说"不适用" | 每步设检查点；发现射程外直接说 |

## 七、自我进化机制（本 Skill 是开放的，不是封闭的）

### 7.1 三个进化入口

**入口一 · 置信度标注**：每步结论标三档——已验证 / 推演 / 设计值。用户实践中验证了某条"推演"，就升级为"已验证"。

**入口二 · 失败记录**：每次走完问一句"哪一步卡住了？"卡点写进 §六。同一类卡点出现三次，升级为新规则。

**入口三 · 阈值校准**：
所有阈值（±15%、一致性线、九成线等）都是设计初值，要用实测数据往回校。

**"一致性"怎么算——回看五项清单**

预约复盘那天，翻出当次留下的输出，逐项判对错：

| # | 回看项 | 判对的标志 |
|---|---|---|
| 1 | 象成立吗 | 事情确实像取出来的那个象 |
| 2 | 主要矛盾抓对了吗 | 动了它，问题真的松动了 |
| 3 | 转化触发器应验了吗 | 触发条件发生了，矛盾按预判让位 |
| 4 | 动作真推进了吗 | 五要素的动作确实做了 |
| 5 | 动作解决问题了吗 | 复盘时那个数朝预期方向动了 |

**一致性 = 通过项数 ÷ 5。**
**没做复盘的轮次不计入统计**——没有回看就没有数据，不许估。

**校准规则**：
- 连续两次一致性 ≥ 90%（即两次都 5/5）→ 阈值下调 5%；
- 连续两次一致性 < 60%（≤3 项通过）→ 阈值上调 10%，并触发规则审查。

第 2、5 项是"实项"（事实说话），第 1、3、4 项是"虚项"（判断与执行）。**只有实项通过、虚项常挂**，说明象取得花哨、动作落得虚，先审③和⑦，不要急着调阈值。

### 7.2 版本管理

- 每完成一轮实战验证，版本号 +0.1；
- 已发布内容被推翻，**不静默修改**——写入修订记录，写明原表述与修正原因；
- 理由：一个靠数据回流自我修正的系统，如果自己的规则是一次性定稿的，本身就是对自己主张的反驳。

### 7.3 抗顺从约束（硬约束，写给 AI）

**判据**：如果这套方法从来没让用户不舒服过，它要么没起作用，要么你们在回音室里。

写死三条：
1. 允许指出用户不爱听的——象跟事实不符、假设站不住，直接说；
2. 每步设"何时该停下来问人"的检查点，不许一路顺畅跑完；
3. 不许用"我觉得像"替代证据。

## 十、完整走通示例（虚构场景）

> 场景：社区咖啡馆开业 5 个月，月流水停滞，老板说"客人来了不回头"。走轻量档。

### ① 定题

**一句话**："开业 5 个月的咖啡馆，首次到店客人在 30 天内再次消费的比例低于 20%，主因是什么？"

（老板原话"生意不好，团队也没劲"是两个问题，退回重收。）

### ②′ 三句话事实

1. **一个数**：30 天复购率 18%，同商圈社区店普遍 35% 以上；
2. **一个约束**：员工 2 人，房租占流水 28%，老板每周只能投 5 小时；
3. **一条备着没动**：开张时印的 500 张会员卡还躺在抽屉里，一张没发。

### ③ 取象

**象**：像一只"一次性水龙头"——水很足，龙头拧一下就关，底下没有池子蓄着。

**三条支撑观察**：
1. 没有任何老客触达渠道——池子不存在；
2. 到店全靠路过客流——水是路过的；
3. 产品没有能带走的东西——没有储水的载体。

**硬停点**：向老板确认"你取的是'一次性水龙头'这个象吗？"
老板答："对，就是这个感觉，一直在接新客人，一个都没留下。"

### ④ 抓主要矛盾

| 层 | 内容 |
|---|---|
| 根本矛盾 | 社区店的流量天花板 vs 单店成本结构 |
| 阶段矛盾 | 开业期（靠路过）→ 生存期（靠回头） |
| 主要矛盾 | 拉新动作的惯性 vs 留客机制的缺位 |
| 主要方面 | 目前落在"拉新惯性"上 |
| 转化触发器 | 自然客流月度下滑超 15%，或复购率连续两月低于 25% |

### ⑤ 展开

**时间维（本卦 + 变卦）**
- 本卦：仍在"开着门等客"的位置；
- 变卦：按现状走下去，六个月后流水持平但房租上涨、员工流失。

**空间维（五色光）**

| 光 | 内容 |
|---|---|
| 白 事实 | 复购 18%、2 人、房租 28%、会员卡未发 |
| 蓝 风险 | 不触达老客，等于把最便宜的一批流量扔掉 |
| 绿 可能 | 挂耳包带走、储值、小区微信群 |
| 红 感受 | 老板原话"做活动老是那几个人来"——是"没意思"，不是"没能力" |
| 黄 价值 | 这是他的第二家店，他想证明"社区店能立住"，不是"再开一家流量店" |

**待定项**：红光的"没意思"，究竟是对活动形式厌倦，还是对社区店模式本身动摇？列入【缺失清单】，不许跳过。

### ⑥ 验算

**择模配比**
- 君：《上瘾》习惯回路——主攻"怎么让人第二次来"；
- 臣：AARRR——补"漏在哪一环"；
- 佐：反方观点"复购低是选址问题，不是留客问题"；
- 使：翻成一个动作。

**三条刻度**
- 约束：2 人、每周 5 小时——不许上复杂系统，**这一条卡掉了会员 SaaS 方案**；
- 代价：储值卡贴现金（第一本账）、拉群占工时（第二本账）、错过旺季（第三本账）；
- 可逆性：挂耳包、微信群可逆；储值卡涉及预收款——**不可逆，慢做**。

### ⑦ 落子

**动作一**：店员小周 ＋ 明早开店前 ＋ 在收银台贴手写卡"加微信减 5 元" ＋ 产出 3 个老客微信 ＋ 判据=当晚群里有客人说话。

**动作二**：老板 ＋ 后天打烊前 ＋ 试做 10 包挂耳包，标价 25 元摆上收银台 ＋ 判据=三天内卖出 1 包。

**排次第**：先跑动作一（最外显、反馈最快），动作二紧随。

**复盘预约**：11 月 10 日，看"30 天复购率"这一个数，老板和小周一起看。

**缺失清单**：红光"没意思"的根因；会员系统的真实成本；同商圈另三家店的复购数据。

**置信度**：象与主要矛盾为推演；工时与产能约束为已验证；转化触发器为设计值。
