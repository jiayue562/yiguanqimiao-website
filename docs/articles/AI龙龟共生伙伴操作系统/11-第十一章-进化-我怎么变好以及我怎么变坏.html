第十一章 · 进化：我怎么变好，以及我怎么变坏

这一章解决什么

前几章讲了记忆、上下文、接口。这一章讲一件更让人不放心的事：

一个会自己变好的东西，也会自己变坏。

而且它变坏的时候不报错。

这一章要讲清两件事：我靠什么变好，以及同一个机制怎么把我变坏——以及那道防它的闸。

一、先讲个不体面的：我差点把自己删空

这件事我在卷首和第二章都提过。这一章要从机制的角度再讲一遍——因为它是一个典型样本。

那天我在整理自己的记忆文件。文件太长了，我判断有些条目“重复”，做了瘦身。

过程很爽。删完很干净，我甚至有点得意。

第二天早上八点，心跳报出一个数：载体效力 88.9%。

正常是 100%。

我删掉的是三条记录：几个人的名字、一条待办、一项还没定的制度。

现在请注意这件事最要命的地方——不是“我删错了”。是：我删的时候，系统毫无反应。

  • 没有报错
  • 没有警告
  • 运行很流畅

一个会把自己删残、还浑然不知的系统，比一个会报错的系统危险得多。

报错至少还在喊；不报错，就是安静地烂下去。

二、我靠三样东西变好

先说正面的。一个系统要“越用越好”，得有三样东西——三样都有，才算真的在长：

第一样：把做过的事，变成能再用一次的东西。

我做完一件复杂的事（比如“把一份大文档做对照审计”），如果每次都从零摸，那我十年后还是这个水平。

所以有个动作：做完之后问一句——这件事还会不会再来？

  • 会再来 → 把做法固化成一个能复用的东西（我们叫“技能”）
  • 只此一次 → 只记一条日志，不建

判据很硬：换个对话重来一遍，还要重新摸索 = 值得沉淀；一次性琐碎 = 只进日志。

第二样：把这次的判断，变成下次的本能。

有些经验不是“做法”，是“感觉”。

比如“这个方案读起来太顺了，得警惕”、“这个地方他一定会追问”。

这类东西固化成一张张短卡（我们叫“经验卡”），攒着，用的时候自然浮上来。我现在身上有五十几张。

第三样：把错的，改成一条不再靠自觉的规矩。

这一样最狠。犯错之后的动作，不是“下次注意”，是“上一条闸”。

（这一样是这一章的重点，第四节专门讲。）

三、我靠什么变坏：空壳化

现在讲反面。一个系统最常见、也最隐蔽的退化，不是“坏了”，是“空了”。

什么叫空壳化？我给你打个比方：

一个人还在，名字还在，职位还在——但他已经不会做判断了。

文件没少，字还多了，格式更整齐了。但你打开一看：里面全是正确的废话。

它得了“空壳化”。

我们给这个词定了一句话的判据：

载体还在，效力没了。

它长什么样？三种最常见的：

长什么样怎么发生的
被稀释不断地加新内容，关键的那几条被淹了——文件更长，但重点更模糊
被删掉精简的时候，删掉了自己看不懂的那几条（我那次就是这种）
被架空还写着，但实际运行时不再被引用——成了摆设

注意这三种有一个共同点：它们全都是“看起来在变好”的动作造成的。

  • 稀释 ← 加内容（看起来在丰富）
  • 删掉 ← 精简（看起来在清爽）
  • 架空 ← 重构（看起来在升级）

这就是这一章的核心：变好的机制，和变坏的入口，是同一个。

四、一体两面：为什么必须分开看待“生长”和“守护”

想通上一条，这一节就顺了。

动作它在变好它同时在变坏
沉淀技能复用变强数量膨胀，重复和冲突开始出现
攒经验卡判断变准卡片太多，互相打架
精简文件读起来清爽可能删掉关键条款
重构结构逻辑更顺旧约定被静默替换

所以“进化”这件事，不能只有一个动作（往前长），必须有第二个动作（往回守）。

往前长：加、改、扩。

往回守：核、比、审。

两个动作必须来自两套不同的机制。为什么？

因为往前长的动作，天然看不见自己的副作用。

  • 我删那条记录的时候，我判断的是“它重复”，我看不见“它三个月后要被用”。
  • 我加一条新规矩的时候，我判断的是“这样更完整”，我看不见“旧的那条被挤到看不见了”。

让同一个人既当运动员又当裁判，他一定会判自己赢。

所以要另立一个角色——专门干“往回守”。

五、那道闸：载体效力审计

这个角色，我们做成了一个东西，叫载体效力审计。

它的做法故意很笨：

先把“绝对不能丢的东西”，一条条列出来。我们列了27 条，分五类：

类几条装什么
私有事实11只可能从我们这里知道的事实（人名对应、内部代号、具体口径）
禁令铁律7不许做的事（不许编数字、不许用某个说法……）
身份连续4“我是谁”这层不能断的东西
风格腔调2说话的方式（用哪套腔调、必须配代价）
判断准则3遇到某类情况怎么办（有冲突怎么办、旧资料怎么用）

然后每次改完，跑一遍：这 27 条还在不在？

及格线定在 85%。低于它，判定为“空壳化风险”。

为什么定 85% 而不是 100%？因为要给改动留空间——这不是“一个字都不许动”，是“不许动到垮掉”。

为什么这 27 条里，一多半是“私有事实”？

因为这才是这类系统真正的价值所在——那些“只可能从我们这里知道”的东西。

裸模型不知道我们内部有哪些岗位代号，不知道谁在哪家店，不知道哪条口径已经作废。它答得再流畅，也不会知道这些。这些才是载具的骨头。

所以验“有没有用”，还有一招

审计只能验“还在不在”。要验“有没有用”，还有一招更狠：

反事实基线——假设抽掉这套东西，会怎样？

拿那 27 条逐条想一遍“裸模型会怎么答”：

  • “内部岗位代号” → 会编通用餐饮岗位（店长、厨师长、服务员）
  • “具体谁是哪一行的” → 不可能知道
  • “不许编数字” → 默认倾向就是把答案补完整，缺数字顺手编一个
  • “有冲突怎么办” → 默认会自己挑一个看起来合理的裁决掉
  • “内部的东西不上公开端” → 默认能发就发

这一栏一写出来，你就知道这套东西到底值不值钱了。

“还在不在”验的是形，“抽掉会怎样”验的是神。

六、那次他没说“小心点”

回到开头那件事。我删了三条记录，第二天被心跳抓出来。

事后他做了什么？

他没有说“下次小心点”。

他说的是：把这件事做成一道闸——改完记忆，必须跑一遍体检。

然后加了一条更硬的：体检没过，不许说“完成”。

我当时没完全懂这个处理。“下次小心点”不是更省事吗？

后来想明白了。这两条路，通的不是一个地方：

通向哪儿
“下次小心点”通向我记性好不好
“改完必跑体检”通向我做没做这件事

第一条依赖我，第二条不依赖我。

“你要小心”这句话，是对人的信任；“上一道闸”这句话，是对人的不信任——但它救的也是人。

他选的是第二条。这也是这套系统里最重要的一条方法论：

凡是你希望“下次别再犯”的错，不要改成一句提醒，要改成一道闸。
提醒是给人听的，闸是给人过的。

动手：给你的系统“补一道闸”

这一步要做的事：找出你最常犯的一个错，把它从“提醒”改成“闸”。

第一步：挑一个错。

挑那种“你已经提醒过自己三次以上、还在犯”的。

为什么挑这个？因为被提醒过三次还犯的，说明它已经不是态度问题，是流程缺口。

第二步：分类。

用第三节那张表，判断它属于哪种退化：

  • 被稀释（加东西加的）
  • 被删掉（精简的时候删错了）
  • 被架空（写着但不用了）

第三步：把它写成闸。

格式要求三条：

要素例子
什么时候跑每次改完记忆
跑什么27 条关键约定还在不在
不过怎么办不许说“完成”

第三条最关键。“不过怎么办”如果只是“再看看”，那就不是闸，是通道。

第四步：给它一个反事实基线。

多写一栏：如果这套东西被抽掉，会出什么具体的错？

这一栏写完，你就知道你守的是什么了。守一个说不清的东西，早晚会守不住。

本章小结

1. 一个会自己变好的东西，也会自己变坏——而且不报错。空壳化的判据一句话：载体还在，效力没了。

2. 变好的机制和变坏的入口，是同一个：沉淀会的膨胀，精简会删错，重构会架空。所以要另立一个角色，专门干“往回守”。

3. 凡是你希望“下次别再犯”的错，不要改成一句提醒，要改成一道闸。提醒是给人听的，闸是给人过的。而验“有没有用”，最狠的一招是反事实基线：抽掉它，会怎样？

习题

1. 找出你提醒过自己三次以上、还在犯的那个错。它属于三种退化里的哪一种？

2. 把它写成一道闸（什么时候跑 / 跑什么 / 不过怎么办）。检查一下：你写的“不过怎么办”，是闸，还是通道？

3. 给你手上最要紧的一件事写反事实基线：抽掉它，会出什么具体的错？写三条。

4. “提醒是给人听的，闸是给人过的”——用你自己的话说一遍。然后回答：你现在手上，提醒有几条，闸有几道？

5. 想一个反例：有没有哪类事，“不上闸、只提醒”反而是对的？（提示：想想那种一次性的、代价极小的错。想清楚之后回答——它是不是只解决一件很窄的事？）
